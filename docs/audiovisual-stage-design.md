# 舞台多系统编排、外部控制与监听／监看

日期：2026-09-11。状态：按用户最新边界修订的设计与资料调查；无外部设备连接、真实媒体回传或实测结果。StageMaster 原则上不处理演出的音频／视频，负责灯光核心、统一编排、外部系统控制、状态反馈和实时监听／监看。旧内置播放提案已于 2026-09-18 从当前文件树移除；本文为现行边界，旧提案仅在 Git 历史中追溯。

同日再评估补充：手动设备控制与节目自动动作使用不同上下文；监看保存稳定源键，重连时解析；布局不属于灯光执行绑定。完整约束见[架构再评估 C01—C05](architecture-evolution-review.md)，调用草案已同步到 0.3。

## 1. 职责与术语

| 职责 | 由谁完成 |
| --- | --- |
| 灯光编程、求值、合成、DMX／网络灯光输出 | StageMaster 核心与输出适配 |
| 音频素材播放、混音、效果、主扩路由与正式输出 | 外部播放器、调音台或 DSP |
| 视频剪辑、合成、实时内容、映射／融合及正式屏幕输出 | 外部媒体服务器、播放器或视频系统 |
| 激光图形生成、扫描优化与正式激光输出 | 外部激光软件／控制器；普通 DMX 控制仍按具体设备档案接入 |
| Cue、时间线、联动、准备状态和动作回执 | StageMaster 演出协调与外部适配 |
| 监听／监看、仪表、来源与新鲜度、虚拟舞台呈现 | StageMaster 监看模块与可选 UE 后端 |

“不处理音视频”指不承担演出内容处理和正式音视频输出。监看仍需接收、解码、缩放、显示；监听需接收采样并送到指定耳机／监听设备。必要的监看格式桥接可作为独立、受预算限制的服务，不能悄悄扩展成主节目混音台或媒体服务器。

音频波形、标记和参考片段用于编排；优先导入外部提供的波形／缩略图与参考代理，保留资源身份和时间映射。外部播放器即使与我们装在同一台 Mac 上，仍是独立执行系统。离线无外部源时可以用明确标记的参考素材预览或只做逻辑模拟，不伪装现场回传。

## 2. 三条独立通路

| 通路 | 传什么 | 约束 |
| --- | --- | --- |
| 控制 | 播放指定 Cue、暂停／定位、调用预设、切源、允许的参数变化 | 类型化动作、能力检查、控制租约、顺序、截止时间；不传音视频大帧 |
| 反馈与同步 | 播放状态、实际位置、设备状态、时间码、就绪、错误与仪表 | 保留来源、观测时间和可信度；命令确认不等于状态已应用 |
| 监听／监看 | 音频回传、视频流／纹理、采集画面、激光预览数据 | 独立会话、权限、缓冲与质量预算；无控制租约也可按查看权限监看 |

灯光实时循环只投递有界、预校验的外部动作意图；网络适配器异步发送。服务器等待外部应答、网络抖动或监看解码都不能阻塞灯光线程。关闭监看不会暂停外部播放；视频冻结不会自动触发全场停止。

## 3. 功能覆盖与公开资料

| --- | --- | --- | --- |

| AV07 激光软件／控制器 | 通过实际提供的 OSC／DMX 等调用 Cue、区域或参数，反馈另核实 | 状态、二维预览、三维扫描数据、现场摄像机是不同能力；OSC 不自动提供激光扫描点流 | [BEYOND OSC](https://wiki.pangolin.com/doku.php?id=beyond:osc_in_beyond)、[FB4 OSC](https://wiki.pangolin.com/doku.php?id=hardware:fb4:osc_commands) |
| AV08 摄像机／PTZ／现场观察 | 视频源发现与选择；PTZ、预设或切换台控制按实际能力独立授权 | 原始机位与节目总输出分开；可调查 ONVIF／网络视频／采集输入，不能默认每台设备支持音频或 PTZ | [ONVIF Profile T](https://www.onvif.org/profiles/profile-t/)、[能力条件说明](https://www.onvif.org/conformance-faq/) |

尽量绑定外部稳定 ID 和文档／工程身份，不把按钮位置、列表序号、IP 或窗口名称作为唯一永久身份。外部系统不提供可靠修订／原子比较时，适配器记录观察代次并明确限制，不能宣称消除了远端同时编辑的竞争。

## 4. 实时监听／监看的接入方式

| 接入 | 用途 | 跨平台与来源约束 |
| --- | --- | --- |
| Syphon／Spout | 同机视频纹理回传 | Syphon 对应 Mac、Spout 对应 Windows 路线；不是跨网协议，消费者支持与 GPU 格式需测试 |
| NDI 及可用低带宽代理 | 局域网视频／音频监看 | 逐源核对实际提供的流、授权和资源；优先选择可用的代理档，不能假定每个源都有代理 |
| 音频设备输入／返回总线 | 耳机监听、电平、通道检查 | 通道映射与监听输出独立设置；Dante 可经已安装授权驱动呈现为系统音频设备 |
| HDMI／SDI 等采集输入 | 观察链路某个实际信号取点 | 单独适配采集设备；输入采集不表示 StageMaster 输出主节目，采集点后面的设备仍未被验证 |
| 网络摄像机／现场拾音 | 观察屏幕、投影面或现场实际声光效果 | 摄像机曝光／白平衡和拾音位置影响观感，不作为未经标定的测光／声学结果 |
| 浏览器可播放回传 | 手机／平板／Web 监看 | 浏览器不直接使用本机纹理或原生网络 SDK；由边缘桥接选择兼容流，如 WebRTC。控制与媒体鉴权分别建立 |

依据：[Syphon／Spout](https://resolume.com/support/syphonspout)、[NDI 代理](https://docs.ndi.video/all/getting-started/white-paper/bandwidth/ndi-proxy-and-bandwidth-optimization)、[Dante Virtual Soundcard](https://www.getdante.com/products/software-essentials/dante-virtual-soundcard/)。浏览器回传架构为我们的设计，具体网关和编解码库未选定。

监听默认静音，用户选择指定的本地监听端点后开启；本地监听音量、mute 和通道选择不改变外部系统主扩增益或 mute。远程平板的耳机属于该平板宿主，不能误把本机监听请求送到舞台服务器输出。反馈仪表不等于收到声音，客户端播放器显示成功也不代表观众听到声音。

## 5. 必须呈现的证据层级

| 信息 | 能说明什么 | 不能据此推断 |
| --- | --- | --- |
| 请求已接受 | StageMaster 已登记动作 | 已发到外部系统 |
| 已发送／对端确认 | 适配器完成发送／对端应答 | 对端已播放，灯或屏幕已变化 |
| 状态已报告 | 对端报告播放、位置或设备值 | 实物声光正确；也不能仅凭状态相符证明是本次命令造成 |
| 节目输出回传 | 声卡／服务器／采集点有信号 | 后续功放、扬声器、投影机或屏幕正常 |
| 现场视听 | 摄像机／拾音端捕捉到实际现场 | 未经标定的照度、色彩、声压或精确同步 |

每个监看窗口显示来源与取点（素材预览／输出前／输出后／采集／现场摄像机／模拟参考）、源身份／版本、分辨率／帧率或声道、最新接收时间、源时间是否可信、延迟估计与依据、断流／冻结。最后一帧可保留，但必须标记陈旧；没有端到端时钟映射时显示“延迟未知”，不能简单相减不同设备时间戳。

状态与媒体流允许分别在线／离线。例如 API 可用但 NDI 中断，界面同时显示“控制在线、画面中断”。监看开启成功只表示建立会话；必须观察收到帧／样本才能报告正在监看。

## 6. 编排、准备与同步

时间线保存外部对象引用、动作、目标位置、触发时刻、截止时间、重放政策和每项动作的能力要求。控制时刻、对端媒体位置、回传呈现时刻分别建模。波形和代理片段用于编排参考，不自动成为正式音频／视频输出轨。

每个同步组独立选择内部单调时钟或已验证的外部时间／位置观测作为参考。时间码来自独立适配；包到达次数、监看帧率与耳机播放速度都不能充当主时钟。只有支持提前调度的目标才承诺相应调度语义；只支持立即命令的目标按测量误差声明能力。

准备分开“本地控制计划可用”“外部对象可解析”“对端明确报告已准备”“监看已收到数据”；仅接受 Load 命令不等于外部媒体就绪。缺乏就绪反馈的目标标记为未验证，可按节目政策阻断或由用户明确选择有限保证，不制造统一的 ready=true。

Seek 只影响指定同步组。外部不支持定位／预滚／倒放时，拒绝依赖该能力的动作或展示缺失；不能悄悄用 Stop＋Start 模拟等价定位。组内部分成功必须逐目标报告；没有跨所有系统的原子事务保证。

对本地 commandId 去重只覆盖本服务接纳。已发送但回执丢失、外部进程重启或只提供 UDP 触发的情况，不能保证外部恰好执行一次；离散 Go 不自动重发。适配器将端点重连代次、能力版本、外部工程／对象身份纳入检查，恢复后先读状态再恢复调度；不用 toggle 代替可表达的绝对设置。

监看通常为旁路。只有用户在节目中明确配置了某个反馈条件，才可影响演出调度；不默认因某台平板断流而停演。采集到的真实流不能拖回任意历史时刻，拖动时间线要明确切换到外部测试播放或参考模拟上下文。

## 7. 模块、伪 API 与 UE

外部控制提供设备目录、目标能力、准备检查、范围授权、动作提交、回执查询和状态读取。监看提供源目录、格式协商、会话打开／关闭、状态、传输授权与本地呈现。二者采用不同令牌；普通查看者不能利用监看 token 调用外部控制。

ExternalControlContext 的 manual 使用宿主操作会话，允许演出前明确的设备调试；show 携带 TransportCursor，在真实发送前检查计划和同步组代次。手动操作也要验证权限及目标租约；已发送的旧节目动作不能因本地 Seek 而被宣称已经撤销。MonitorSourceKey 用于保存布局，resolve 返回当次连接的 MonitorSourceRef。

具体调用草案见 [external-contracts.ts](module-api/external-contracts.ts) 与 [external-examples.ts](module-api/external-examples.ts)。网络只传声明的数据、ID 和短期授权；帧、PCM、GPU 句柄走独立数据通路。客户端不得任意指定外部 URL 或携带凭据写入节目；源与端点由授权目录解析。

UE 接收灯光／设备仿真状态，以及外部媒体监看绑定。虚拟 LED 屏展示对应回传；投影模拟使用受控纹理与投影几何，不在 UE 重做外部服务器的节目合成。激光三维预演需要提供几何／扫描数据的实际接口，否则只显示可用的二维预览、摄像机或带限制标记的参考模拟。

预演摄像机和视频导出属于设计展示输出，继续与演出视频系统分开。原 UE 方案中“现场视频内容生成”不纳入当前范围。远端系统没有隔离测试上下文时，盲编预演不能为求画面而操作其现场播放；使用只读回传或参考数据。

## 8. 云端与依赖

云端保存工程、场地、外部引用／版本、控制计划、资源清单和按需参考代理。外部系统资源部署单列负责人／目标与就绪证据；给 StageMaster 下发节目，不自动意味着 QLab／媒体服务器的文件已安装。允许只分发控制包，现场可脱离云端继续运行。

Rust＋TypeScript 主语言不变。接收 SDK、监听音频 I/O、采集卡和浏览器回传按目标选装；没有监看界面的盒子不带解码／UE 依赖。GStreamer／FFmpeg 如后续有需要，只评估接收或监看桥接用途，当前不安装，也不再作为内置节目播放方案。

## 9. 首批可验收闭环

先选同机 Mac：一个外部音频播放器＋明确音频返回，一个媒体服务器＋Syphon 或 NDI 回传，以及 StageMaster 灯光模拟。验证一次时间线／Cue 控制、状态读取和双通路监看，再加入一种投影机状态适配与激光预览接口调查。具体软件、许可证和设备必须在实施时核对，不因列在表里就宣称已支持。

验收至少包含：外部控制与画面分别断开；命令超时不重复 Go；换外部工程后旧目标拒绝；本地监听 mute 不影响主扩；不同取点正确标识；帧陈旧和延迟未知可见；手机监看不控制服务器扬声器；盲编不影响现场；受压解码不阻塞 DMX；外部资源未就绪不伪报成功。记录时序、偏差、恢复和资源预算，当前没有以上实测结果。
