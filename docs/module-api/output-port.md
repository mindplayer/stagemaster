# 单端口输出权

OUTPUT-001／[ADR-103](../development/decisions/PRODUCT-ADR-103-output-port-authority.md)。`stagemaster-output-port` 默认无第三方运行依赖、no_std、无堆分配；可选队列适配使用 Embassy。一个 `Port<D>` 独占一个 Driver。当前已接真实工程／安装／Runtime／队列的完整软件验收及 S3 UART 构建，尚未接正式运行固件或启用物理输出。它不负责属性混合、网络认证、商业授权或灯具安全动作。

## 所有权和调用

| 入口 | 作用 |
| --- | --- |
| `Port::new(config, driver, now)` | 声明启动身份、物理端口、逻辑线路、帧新鲜度和驱动确认期限；启动状态尚未确认静默 |
| `select(source, takeover, now)` | 可信宿主选择本地、外部或合成来源；已有来源须明确接管。立即撤销旧许可／待发帧并要求驱动停止，返回停止票据 |
| `poll(now)` | 处理期限、最多 4 项驱动回执、最多提交 1 帧；精确的静默回执后才授予新 Permit |
| `state()` | 读取许可、停止请求、待发／在途以及最后接纳／提交／完成的帧身份；只代表最后观察状态 |
| `submit(permit, sample, now)` | 校验并复制完整 512 槽帧，替换唯一待发帧。只有 `poll` 提交帧；期限和故障处理仍可能立即要求驱动停止 |
| `stop(permit, now)` | 只有当前来源能停止端口；旧来源不能停止新来源，不生成全零帧 |
| `shutdown(now)` | 可信宿主关闭端口，取消正在等待的接管。返回值只代表请求，继续轮询确认 |
| `with_quiescent(|| { ... })` | 仅在当前已确认静默、无来源且无故障时同步执行维护；不返回可跨时刻复用的静默证明，闭包返回类型必须为 `()` |

来源 ID 非零，类别只是业务角色，不自行提供权限。Permit 与驱动 Ticket 字段私有、不可反序列化；宿主仍须验证远程调用身份，并确保一个端口只有一个实例／驱动所有者。`Config.boot` 每次构造使用新身份，不能用同一身份反复重建后复用旧许可。

完整的可执行组合见[真实工程验收](../../crates/stagemaster-output-port/tests/cases/runtime.rs)：

1. 工程编译、Archive 校验、Installer 写入／校验／提交；Runtime 初始待维护。
2. Port 关闭并收到真实软件驱动静默回执，在 `with_quiescent` 内确认 Runtime 的当前维护请求并绑定快照。
3. 载入／开始节目；选择本地输出来源、轮询得到 Permit。
4. 每周期 Runtime 推进／生成 Some(FrameInfo)，绑定同一来源，带递增帧号提交；端口和驱动报告各自实际状态。
5. 输入控制租约释放不改变输出来源；只要独立运行器继续发布，节目持续。
6. 接管外部来源时撤销旧许可，等待驱动清理后才允许新来源。Runtime 停止只产生档案默认值，不能凭旧许可停止外部输出。
7. Runtime 进入维护等待后，宿主协调所有相关输出端口；当前单端口测试先停止、确认静默，再绑定安装快照。多端口维护须汇总全部端口，不能拿一个端口代替整机证明。

未来把 HOST-001 的观察帧接入时，适配层还须验证宿主状态、启动／节目身份和采样时间，只消费有效快照；不能把 `render(None)` 后保留的旧缓冲当新帧，也不能把网络客户端当自主运行器的输出来源。

## 时间、内存和来源丢失

帧序号非零且严格递增，允许跳号；新许可重新从自己的序列开始。线路必须一致，采样毫秒不得晚于当前时间、不得倒退于同许可上一已接纳采样；到 `sampled_ms + max_age_ms` 即失效。外部时钟先映射到宿主单调时间；无效、重复或陈旧帧不能延长更新期限。

新来源获权后有一个 `max_age_ms` 首帧窗口；随后由最后接纳采样时间决定期限。到期撤销许可并请求停止，收到静默后允许显式重新选来源，不因迟到帧自动恢复。两个预算均由宿主按实际设备声明，范围 1～60,000 ms，没有默认协议时序，也不是商业限时。轮询必须足够频繁；晚于确认期限才读取到的回执不会回溯消除故障。

端口本体只保留一份待发 512 槽数据、一个在途帧的元数据和固定状态；驱动另持有至多一个待发送或在途帧。生产模块无 Vec／Box；测试的记录数组用于验收，不是生产队列。发布快于物理发送时只保留最新完整帧，不积压补发历史。只合并完整帧，绝不逐字节取最大值以免破坏 16 位属性。多执行器和推子由上游语义合成器先处理。

## Driver 的真实责任

异步 DMX 单帧事务及 S3 UART 适配准备已由 [OUTPUT-002](dmx-transmission.md)补充；同步 Driver 与异步发送之间的[有界队列](queued-dmx.md)已通过完整帧／背压／停止／故障和独立线程唤醒测试，实际 Xtensa 实验构建通过。正式固件接线及实物输出仍未完成。不能用同步阻塞等待替代该交接。

`submit(ticket, slots, valid_until_ms)` 成功仅表示接纳；驱动须复制／拥有数据，实际开始前再检查同源单调时钟。无隐式自动重发，无隐藏帧队列；过期未开始发送报告 `Expired(ticket)`，实际完成才报告 `Sent(ticket)`。对于未来网络适配，写入套接字不等于远端完成 DMX 发送，必须明确定义并验证实际边界。

`quiesce(ticket)` 必须禁止新发送、丢弃排队工作并结束／取消在途操作，之后才能报告 `Quiet(ticket)`。静默可以取消尚未完成的帧，此时不会伪造 Sent。事件由 `poll()` 非阻塞提供，适配层自己的事件队列必须有界；溢出报告故障。

票据绑定启动／端口与不回绕序号；旧的已结算回执忽略，不会完成新帧或恢复新来源。错误端口／启动、未来票据及当前操作类型错误导致故障。最后一个计数保留给关闭操作，不能用于新帧或授予新来源。

驱动错误（包括“可能接纳但返回错误”）、回执超时、宿主时钟倒退或计数／时间溢出均撤销许可、清除待发并尝试关闭。状态保持故障，晚到的真实 Quiet 可更新静默观测，但不会恢复来源或打开维护门。无 `clear_fault` 捷径；恢复须由平台独立确认／重置硬件后，以新身份构造。关闭失败不重复声称成功；丢弃 Rust 对象也不构成物理停止证明。

宿主停顿时，驱动还须独立执行截止期／看门狗，不能靠未被调用的 Rust 轮询保证硬件关闭。可选队列已验证独立发送期限与空闲帧到期关闭，UART 适配已构建；真实 RS485 波形、网络输出和整核／外设卡死时的板卡看门狗尚未验证。停止发帧不代表灯具熄灭；档案默认值、黑场、机械急停也不等价。
