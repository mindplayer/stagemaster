# 设备运行与本地输出协调

[ADR-137](../development/decisions/PRODUCT-ADR-137-runtime-output-coordination.md)／[OUTPUT-002](../development/tasks/OUTPUT-002-dmx-transmission.md)。`stagemaster-install-worker/output` 是可选组装能力，提供 `output::LocalOutput<D>`；运行语义仍属于 ManagedWorker 内的 Runtime，输出权仍属于原 Port，UART 仍由独立发送任务持有。

| 调用 | 结果与职责 |
| --- | --- |
| `LocalOutput::new(config, driver, now)` | 绑定同一 Runtime 启动身份与端口／线路预算；不自动输出 |
| `service(&mut worker, now)` | 先处理当前停止／维护意图，再轮询原端口；真正 Quiet 后在原同步静默门内确认当前维护请求；独立于帧采样持续调用 |
| `publish(&mut worker, info, &slots, now)` | 服务当前控制状态，核对本次 render(Some) 的身份和采样，只向现有许可提交完整帧；返回 true 是接纳而非物理发送完成 |
| `disable(now)` | 撤回输出意图，丢弃原待发帧、请求停止；继续 service 等待真实静默，不把当前旧播放实例当重启指令 |
| `state()`／`fault()` | 原端口的接纳／提交／真实驱动完成及静默状态，加协调层锁存故障；不暴露可变端口，不等于灯具的光学反馈 |

这是本地播放器的一种组装，不是网桥或多来源混合策略。只观察到新的、原 Runtime 已经通过许可检查的 Instance 时，才申请本地来源。只载入节目、连接／读取目录不开始输出；初次申请期间节目已停止，则先撤销意图再读取排队回执，防止迟到 Quiet 重新授予输出。

协调器与 Runtime 在同一启动生命周期创建一次；不得用相同启动身份原地重建端口来清除故障或重复使用旧票据。恢复需平台确认硬件关闭后，以新的启动身份重新构造整套本地执行组装。

输出建立后，暂停仍持续发布暂停值；释放输入控制权或断连不停止自主运行。停止节目仍发布原 Runtime 的档案默认值，不插入原始全零帧。关闭发送不保证灯具熄灭，黑场／信号丢失策略与机构安全仍由各自模块负责。

维护请求先关闭输出，再等完整清理；只有当前端口无故障、无来源且已静默，才能确认原 ManagedWorker 的当前 Quiescence。确认会按原运行器释放计划及安装快照，然后才允许存储写入。取消维护不恢复旧输出；新的开始可等待先前停止完成，再申请新许可。来源过期也须新开始，不凭旧实例自动重连输出；端口／协调故障不能用新开始清除。

发布时核对启动身份、Operation 模式、修订、已载入节目、实例与准确采样时间；线路和新鲜度由原 Port 复核。render(None) 不提交旧数组。序号严格递增、不回绕；错误会关闭输出意图并请求停止。锁存故障之后仍可观测晚到 Quiet，但不据此授予维护。调用者继续持有运行器、控制入口和存储的唯一写入权。

S3 的 `runtime-dmx-probe` 组装复用原认证 GATT／安装服务／第二核运行器，第一核独立任务拥有 UART1／GPIO17／GPIO21，通过既有跨核队列连接；第一核不参与节目解析。GPIO17 不再同时充当蓝牙连接指示灯。实验 Line 强制 GPIO21 低，不改变已安装实板固件或公开物理输出能力。诊断中的 `UART LOGIC ONLY` 记录的是逻辑 UART 提交／完成，明确附带 RS485 禁用标记。

当前静态绑定一个端口、一条逻辑线路 1；其他设备输出映射后续显式组装，不能自动截断／改写工程线路。正常 `runtime-gatt` 构建仍采用原持续禁用引脚模式，旧连接指示行为保留。独立 `dmx-queue` 示例复用同一个实验线路模块。

软件验收覆盖真实工程编译／安装后的完整动态帧、暂停／停止默认值、控制租约释放、初次及后续维护拒绝提前写入、取消维护、来源超时、新开始等待旧排空、错误帧和失败排空；S3 实际服务组装严格检查与链接单独记录。当前没有新线路波形／CPU 负载或内存峰值证据，未刷机或打开设备。接续独立硬件看门狗、逻辑侧实板时序与资源观测，再启用经过电气确认的真实 RS485 和完善产品输出状态。
