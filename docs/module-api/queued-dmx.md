# 有界 DMX 驱动交接

[OUTPUT-002](../development/tasks/OUTPUT-002-dmx-transmission.md)／[ADR-136](../development/decisions/PRODUCT-ADR-136-queued-dmx-driver.md)。启用 `stagemaster-output-port/queued-dmx` 后使用 `dmx::queued`，把原同步 `Port<QueuedDriver>` 接到原异步 `Transmitter`，没有新增节目状态机或输出权威。

## 组装与生命周期

1. 宿主创建 `Queue<M>`，S3 的 M 使用既有 Embassy `CriticalSectionRawMutex`；`NoopRawMutex` 只适合单执行器环境。
2. `queue.split()` 取得唯一 `QueuedDriver` 和 `Receiver`。同一队列仅能绑定一次，两端不能克隆；关闭后重新绑定返回错误。
3. 原 `Port::new` 持有 Driver。独立发送任务执行 `receiver.run(transmitter)`，在每次线路 Future 轮询前检查停止／关闭；不在节目计算任务里同步等待整帧。
4. 上层仍按原控制权流程选择来源、提交完整帧、轮询回执；停止必须收到当前票据的 Quiet，才能使用原维护门。不能把队列接纳当发送完成。

Driver 只做固定大小复制、状态发布与回执读取；锁内没有 UART、文件解析、await 或无界循环。固定一个帧请求槽、一个完成槽和一个独立停止槽。在途帧、未消费完成或停止存在时，新帧接纳返回 Busy，原 Port 的唯一待发槽仍合并最新帧。不存在隐式历史补发、逐字节混合或自动重发。

发送任务只在原事务真正完成后发布 Sent，未开始就过期发布 Expired。停止会清除待发帧和旧完成，优先取消当前线路操作，关闭方向、排空后才发布当前停止票据的 Quiet。发送完成与新停止同时到达时重新核对共享状态，旧完成不得覆盖新停止；更新的停止票据可替代旧停止，失败排空不无限重试。

故障锁存，Driver 先报告故障，再允许读取后续真实 Quiet；不能通过消费错误恢复新帧许可。原 Port 在故障后仍禁止维护／新来源。发送任务取消或销毁会销毁其 Transmitter 并关闭队列，不伪造 Quiet；控制端销毁只发布关闭并唤醒发送任务，物理清理仍依赖该任务获调度。

## 期限和资源

线路操作总期限仍由原 Transmitter 执行。成功发送后的空闲任务独立等待最后一帧的新鲜度期限；即使 Port 不再轮询，到期也会关闭方向脚，不产生虚假 Quiet。正式静默仍需原停止／排空回执。毫秒期限无法转成同原点微秒时，在接纳前拒绝；时钟倒退或提前唤醒锁存故障，合法的“检查过程中跨过期限”不会误判。

生产路径无堆分配。队列留一份 512 槽存储，发送任务另有固定工作帧及原 513 字节串行包；不是把多个节目缓存在队列。本机测试的 Noop 队列对象为 712 字节，含软件线路／时钟的接收 Future 为 3,496 字节，并有 1 KiB／8 KiB 布局预算检查；这些不是 S3 栈峰值。真实静态区、任务栈、中断和运行器总预算继续实板验收。

默认 output-port 仍无第三方运行依赖；此可选功能复用固件已有 embassy-sync 0.8.0。主工作区新增对应版本及其三项传递依赖，原有版本没有升级／移除；固件锁文件只增加该本地模块的同步依赖边。

软件已覆盖实际 JSON／安装／Runtime → Port → 队列 → 单帧事务 → 完整字节，以及独立线程的真实唤醒、未读取完成时停止、取消／故障与空闲过期。实际 S3 `dmx-queue` 独立实验镜像已完成严格检查和链接：复用真实 UART，但实验 Line 始终禁用 GPIO21，不能作为正式 RS485 发送证据。正常 runtime-gatt 固件尚未组装此驱动，本轮未刷机／打开串口或蓝牙。接续正式运行快照、显式输出激活、静默维护、看门狗与物理时序。

异步期限依赖独立唤醒及驱动合作，无法抢占 HAL 的同步最后字节等待或整核卡死。固定队列解决交接和背压，不代替独立硬件看门狗，也不保证灯具在信号停止后熄灭。
