# 本机三维预演接口（PREVIS-001）

依据 [ADR-018](../development/decisions/PRODUCT-ADR-018-local-preview-bridge.md) 与 [ADR-019](../development/decisions/PRODUCT-ADR-019-embedded-previsualization.md)。Rust 投影／桌面 HTTP 桥、UE 消费端、进程管理及应用内视窗已接通。Mac 已实测三维选灯／拖动、草稿保护、历史／保存重开及列表执行画面联动；已覆盖固定调光／RGB 与相交正交两轴的静态指向和动态姿态，客户独立打包及专业光学／性能验收另行推进。

## 公共三维视窗（PREVIS-002）

依 [ADR-055](../development/decisions/PRODUCT-ADR-055-single-previs-workspace.md)，工作台公共区域只有一个 SharedPrevis／PrevisPanel／PrevisViewport。音频、舞台、编排等页面不再创建自己的观看连接。UX-017 将唯一视窗固定在中央舞台区。切页保持视频实例和镜头；切到平面或管理页时视频继续挂接原 DOM，以 visibility／inert 隐藏并禁用交互，避免 WKWebView 视频重新挂接后空白。普通编辑面板仍可停放到 document 外以保持辅助树正确。恢复可见时还处理浏览器对直播视频的自动暂停；不重建连接、不重载音频、不改变播放时钟。停止预演才关闭渲染器。只有舞台页可移动安装位置，编排页可选灯，其他页只查看。上下文变化取消移动，延迟的进入移动／位置提案失效。

“当前场景 · 静态值”在编排页按显式选择跟随当前场景，使用 Rust 的静态投影；离开编排取消自动跟随，切页本身不修改来源。“跟随播放预览”读取共享执行器；音频播放／定位仍由 Rust 切到该源，公共状态轮询观察此变化并取消旧静态跟随。监看不隐式载入或执行场景。播放面板的“三维监看”只打开同一公共视窗并明确切到播放来源。换来源／选灯／收起等操作沿用草稿队列，无效草稿保留并聚焦；相机导航只改变查看状态。监看状态不写入工程历史或格式。

工作区显示由独立 WorkspaceSurface 管理：固定 React portal 容器保留组件状态，非当前工作区从 document 中移出，防止其参加辅助树或键盘导航；切回挂回同一个容器。原生 20 次跨工作区切换、三维重连及错误恢复通过，完整 VoiceOver／跨平台读屏仍需专项验收。详见 [UX-015](../development/tasks/UX-015-editing-monitor.md)。

## 模块归属

- `stagemaster-spatial`：安装变换、固定射线、静态双轴指向与轮廓三角化，无 UI／网络依赖。
- `stagemaster-previs`：从 `Document` 派生 `Scene` 与 `LightRig`；不修改文件，不持有播放时钟。`scene(&document)` 生成房间构件及既有灯位；`LightRig::new(&document)` 缓存同版本灯具与场景，`editing(scene_id)` 解析场景／预设，`playback(&output)` 读取现有播放器的归一化灯值。
- `apps/desktop/src/session/previs.rs`：权威工程版本、预演来源、灯位编辑与统一撤销的衔接。
- `apps/desktop/src/previs/`：本机监听、凭据、协议、请求界限、缓存及连接状态；不解析第二套节目逻辑。
- `apps/previs-unreal`：消费中立几何／灯值、导航与拾取，提供受限的安装请求；不得私自计算节目时间、复杂档案或真实设备输出。
- `apps/desktop/src/previs/renderer.rs`：拥有 UE 离屏子进程和本机信令服务，退出／禁用时回收；开发环境与分发组件路径分离。
- `tools/previs/signalling.mjs` 与 `PrevisViewport.tsx`：复用 Epic 官方信令／前端库传输视频及查看输入，独立于工程 HTTP 协议。

## 通信

工程桥仅 `127.0.0.1` 随机端口。每次启用生成新 `bridgeId` 和独立随机 Bearer 凭据；凭据不通过前端返回、不写工程／日志，由宿主进程环境传给 UE。拒绝 `Origin`、缺失／重复／错误 Authorization；无 CORS。禁用撤销身份并关闭监听。端口启用不等于 UE 已连接；最近 2 秒收到有效帧读取才显示连接活动。

桌面 `previs_request` 支持 `status/enable/disable/source`，状态新增可空 `viewerUrl`。它只带当前观看会话的独立凭据，允许 Tauri 前端连接本机视频服务，不能访问工程桥或渲染器信令入口。信令绑定本机动态端口、校验 Tauri Origin、限制一个观看者和 256 KiB 消息，不配置外部 STUN／TURN。正常关闭回收两个子进程；轮询发现任一子进程退出时关闭整个预演连接，保留工程与播放器。画面连接状态与工程桥连接状态分别显示。

查看动作经官方数据通道传输，`UIInteraction` 接受单字段 `{ "action": "top" }`，允许 `perspective/top/all/selected/workLight/cancel/move/inspect`，以及下述严格定形的选择和提交反馈。任意控制台命令入口关闭。渲染器以 5 Hz 返回中文查看状态、所选灯具描述和工作照明状态；这些是临时查看状态，不写工程。键盘转发仅在视窗获得焦点时启用，离开或卸载立即关闭；未开启麦克风、摄像头或真实硬件控制。

### 内嵌位置提案（e50cfbd 后增量，已接通）

按 ADR-019 补充决策，产品的拖动编辑使用当前窗口统一队列，不启用持久 HTTP 编辑资格。渲染器松手发送 `{kind:"placement", requestId, generation, version, placement}`；位置保留六位小数文本，版本保持十进制字符串。前端校验结构／范围／大小并去重，在 `run()` 中先处理草稿，再调用 `project_request` 的 `previsPlacement`。其参数为 generation、version 和 placement，返回完整 `Snapshot`。Rust 的 `place_from_viewport` 复用既有灯位、预演源可用性和版本检查，禁止更改空间或安装旋转，调用同一 `Session.edit` 形成一次历史记录。

无效草稿保留在原字段；若草稿应用导致版本变化，旧拖动提案拒绝，用户重新拖动即可。视窗卸载／连接变化或提案排队超过 2.5 秒，前端不再执行。UE 的临时拖动位置最多等待 3 秒或下一次权威场地更新，失败恢复原位置。前端返回 `{action:"placementResult", requestId, accepted}`，不能以接受通知替代实际工程快照。

查看协议补充 `move/inspect` 切换交互模式；`select` 带 fixtureId 将舞台工作区选择同步到三维，UE 选择事件 `{kind:"selection", fixtureId}` 经过工作区草稿处理再显示属性。周期状态新增 `kind:"state"` 与 `move`。这些查看命令不具备直接工程写入权限。UE 5.8 默认 MouseUp 消息忽略最终坐标，本适配器通过官方消息处理器扩展先更新松手位置，再调用原处理器释放捕获，避免短手势丢失末端移动。官方前端的 `(65535,65535)` 越界标记和 MouseLeave 必须取消拖动，不能当作右下角坐标提交；已加入协议回归并原生复测。

所有成功响应包含：

```json
{ "protocol": 2, "bridgeId": "每次连接的新身份", "generation": 17, "version": "12" }
```

`generation` 用于所有工程编辑的乐观并发检查；保存也可能改变它。`version` 为内容版本的十进制字符串，仅内容变化才增长；UE 按完整字符串比较，不转成浮点数。撤销也产生新版本，不能复活旧编辑凭据。

| 接口 | 结果／限制 |
| --- | --- |
| `GET /v1/scene` | `scene` 包含项目身份、空间、三角网格、固定灯最终射线和原始安装参数；米制右手坐标，光束原始轴为局部 −Z。最多 100000 三角面、32 MiB JSON。 |
| `GET /v1/frame` | 同版本 `source`、`status`、`canEdit`、`lights`。缓存缺失或内容变化返回 409，消费端重新读取场地。每灯为 `fixtureId`、0–1 `intensity`、独立 RGB `color`。 |
| `POST /v1/placement` | 提交下述单灯安装请求；只支持既有灯位，不能创建／删除灯具、改变空间归属或控制播放。成功返回新版本并发出桌面 `project-updated` 通知。 |

```json
{
  "bridgeId": "连接身份",
  "generation": 17,
  "version": "12",
  "placement": {
    "fixtureId": "既有灯具标识",
    "spaceId": null,
    "positionMeters": { "x": "2.1", "y": "3", "z": "5.2" },
    "rotationDegreesXYZ": { "x": "25", "y": "0", "z": "0" }
  }
}
```

源为 `defaults`、`scene`（附 `sceneId`）或 `playback`。它只由桌面宿主命令设置，无 HTTP 修改来源／执行节目接口。`editing` 为孤立场景／默认值预演，不隐式继承场景列表的跟踪。播放器 `idle/running/paused/finished` 直接来自共享 Rust 执行器；`unloaded/stalePlayback/missingScene` 明确无可用灯值，不能回退到上一次画面并显示为正常。消费端必须显示对应中文状态、清除旧灯光，并禁止过期状态下提交编辑。

400／422 表示格式、投影能力或尺寸错误；403 表示连接无效；409 表示版本／操作前提冲突；503 表示宿主忙。错误体为 `{"message":"中文说明"}`。请求体上限 8192 字节，HTTP 等待上限 3 秒，最多两个实际计算任务；超时／断开不提前归还仍在执行任务的容量。无网络请求队列，宿主被文件对话框占用时立即返回忙。

## 消费端必须实现的交互约束

1. 最多一个在途帧请求，目标约 30 Hz；慢响应略过采样，不补播历史。几何与灯值必须匹配 bridgeId／version，未知 protocol 拒绝；更换工程清空旧画面。
2. 位置变换仅在 UE 边界转厘米、反转 Y；本协议经反射后的顶点顺序已经匹配 UE 正面约定，不能再次交换三角索引。法线与 UE 自带盒网格核对；射线沿同样基变换，不再实现灯光语义或指向求解。
3. 相机、选择与拖动草稿属于渲染器查看状态。拖动中就地反馈，松手只提交一次；Esc 取消，版本变化／断线撤销草稿。禁止每帧写入工程。
4. HTTP 编辑资格默认关闭；其诊断路径需桌面按当前 generation 确认，内容修改、保存、撤销和每次提交都会撤销资格。产品内嵌视窗改走上述统一队列和 `project_request.previsPlacement`，没有持久 HTTP 授权，不能绕过草稿与精确版本检查。
5. 禁用、断线、过期计划和渲染器退出都不改变工程或播放器；播放源仍由原 Instant 时钟推进。真实 DMX 输出权限不属于此接口。

## 已有验证与剩余验收

投影测试覆盖凹轮廓正反绕序体积、极薄／短墙、真实固定灯安装射线、场景和播放器灯值一致、未布置灯不凭空出现在原点、未支持属性及网格超预算的原子拒绝。真实回环 HTTP 测试覆盖身份／来源拒绝、连接过期、更换凭据、既有灯位限制、一次撤销／重做、重放拒绝、过期场地／计划、已删除场景、锁竞争和计算背压。独立时间测试证明轮询与无渲染器轮询得到相同播放结果。

Mac 原生 Tauri 内嵌画面已验证真实保存的房间／舞台／两灯、场景来源、蓝光、透视／俯视、双向选灯／聚焦、工作照明、平面往返与渲染器退出隔离。三维快速拖动、拖出取消、一次撤销／重做、保存重开、无效输入保留／定位、列表渐变／暂停／继续／停止画面均通过。4 项 UE 测试验证响应原子拒绝、坐标边界、鼠标释放端点／越界和官方库实际加载；3 项信令测试验证角色／来源隔离、日志路径脱敏与真实 WebSocket 握手。

剩余专项验收：帧率／延迟和规模负载、光学色彩精度、按住拖动时的 Esc 原生手势、辅助功能子树反复切换恢复及独立安装包。通用视效不等于实际灯具光学／照度；两轴静态指向已由 POSITION-001 接通；非相交轴、多头、连续目标跟随、轮盘和实灯校准仍未实现。

## UX-013 剖视显示增量

按 [ADR-020](../development/decisions/PRODUCT-ADR-020-modeling-view-controls.md)，投影网格新增 `viewRole`（`solid`／`enclosureShell`）；围护拆为 `id:floor` 与 `id:shell` 两个网格，平台仍保留原 ID。消费者缺省按 solid 处理，未知值拒绝。接收上限为 1024 个网格，合计 100000 个三角面预算不变。投影可重建，不更改工程文件格式。

`{action:"cutaway"}` 切换临时剖视；周期 `state.cutaway` 为 boolean，旧消息缺省 false。外壳隐藏、隐藏阴影开启、不阻挡选择射线；地板和舞台照常可见。查看状态不产生工程历史，不更改实际输出。该模式便于布置，不等于已完成物理照度标定。

## POSITION-001 姿态投影

按 ADR-025 升级为协议 **2**。桌面与 UE 必须同时更新；旧协议明确拒绝，不能让旧渲染器忽略运动仍显示固定光束。

场地灯具包含 `moving:boolean`；帧内摇头灯包含 `pose:{base,pan,head,direction}`。前三项各为 `[localX,localZ]` 两个世界单位向量，direction 是三分量出光方向。无姿态的固定灯沿用场地射线。Rust `LightRig` 缓存工程安装和档案，按场景或播放器实际量化值生成姿态；UE 不解析通道、不求逆解、不另建时钟。

UE 校验基向量单位性／正交性、水平轴 Z 与底座 Z 相同、灯头 X 与支架 X 相同、出光为灯头 -Z；单位分量仅允许 `1e-9` 浮点舍入裕量，颜色和强度仍严格在 0–1。共同指向的真实 Rust 帧曾产生 `1.0000000000000002`，现有跨端回归保留此例和超限拒绝。每次仅将 Y 反射一次，再构造 UE 姿态。移动灯位草稿只平移整灯；底座不随水平／垂直通道旋转。

通用关节显示不包含真实尺寸／光心偏移，不能用于安装净空或碰撞验算。
