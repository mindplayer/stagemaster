# 固定来源组与统一合成入口

HOST-003 已将该来源组接入原有后台线程及公共控制权，见[共享宿主](shared-live-host.md)；下文 MIX-003 的未接线说明是该工单当时边界，HTTP／桌面／物理端口仍未迁移。

MIX-003／[ADR-106](../development/decisions/PRODUCT-ADR-106-prepared-source-compositor.md)。代码在 `crates/stagemaster-live/`。这是标准宿主软件后端，调用者持有调度、控制租约和端口权限；本模块不创建线程、网络端点或物理输出。

## 准备与归属

`Session::prepare(&Document, fresh_boot, &[SourceSpec], now_ms)` 从同一个不可变工程快照准备 1–64 个固定来源；`SourceSpec.playback` 为场景／列表选择或手动层。至少一个播放来源提供属性布局与唯一编码器。身份非零且唯一；每次重建必须用新的启动身份，旧 `Key` 无效。准备不会启动播放或生成可用输出。

准备复用 `Document::compile_live_source` 和既有 Player，不另建效果／时间引擎。全组最多 512 个语义属性、262144 个步骤目标值、16384 条效果通道、131072 个关键帧；后面三项是全部播放器的累计预算，并保留每个计划的原有限制。准备逐个编译、检查后保留，发现错误整体不返回 Session。排序空间预留来源数×属性数；正常推进不扩容。此预算用于桌面／ARM 类标准宿主，未据此承诺 ESP32 容量、系统分配器永不失败或硬实时截止时间。

## 调用面

| API | 语义 |
| --- | --- |
| `key(source_id)` | 查询属于当前固定来源组的内部身份；不等于远程授权或端口许可 |
| `control(key, Command, now_ms)` | 执行／下一步／暂停／继续／停止；先统一推进所有自动边界，再应用人工命令 |
| `patch(key, &[Change], now_ms)` | 可信手动层的稀疏属性操作；`Some(0)` 控制零值，`None` 归还；重复／越界属性整体拒绝 |
| `set_level(key, level, now_ms)` | 普通亮度推子，仅缩放亮度，零电平仍保有属性，不重新声明位置控制权 |
| `tick(now_ms)` | 同一单调毫秒推进所有来源，一次发布完整合成帧 |
| `frame()`／`values()`／`winner(index)` | 最近成功的软件帧／语义值／胜出来源；只读不改变时间，不表示真实灯具反馈 |
| `sources()`／`fault()` | 来源诊断与锁存故障；故障后的局部来源状态只供排错，不代表已提交的有效输出 |

手动属性是上层灯具语义适配器已转换和校验的 `u16`，本模块检查身份、形状和索引；不把数字范围检查冒充色盘功能／危险动作验证。未经认证的客户端不能直接调用此对象。停止只释放目标来源；暂停／列表结束保持贡献，连接生命周期不会自动停止节目。当前来源集合与优先级准备后固定，不支持运行中增删／工程热替换。

## 生效顺序

Player 增加兼容旧观察者的 `Activation { step, reassert, at_ms }`，报告真正结束延时的时间；暂停期间不推进节目。遗漏完整循环时只报告最后一个完整圈的起点，所有权侧车按计划激活偏移折叠一次，保留各属性最新声明时间。释放会清掉待声明事件，成功提交后才确认清除。

每轮先以之前完整合成为共同渐变起点推进所有播放器，再取得稀疏贡献。内部先更新最终值和释放，再按 `(生效时刻, 来源身份, 属性索引)` 排序接管；同来源同时刻合并发布。中间状态不可查询。实际取高／后者优先、来源优先级和推子运算继续交给 LiveMixer。普通采样值改变不取得新的控制权。

同毫秒自动事件按稳定来源身份排序；人工命令在该时刻所有自动边界之后执行，连续人工命令按宿主调用顺序。来源准备顺序不影响时间排序。渐变起点取本轮前完整快照，不声称长时间停顿后精确重建每个历史物理采样；不突发补发历史帧。

## 失败与输出

倒退时钟、错误来源、无效步骤和无效手动批量在推进前拒绝，原帧保留原序号／时间，不伪装新结果。内部求值、发布、序号耗尽或编码失败锁存故障，撤回 `frame/values/winner` 的有效结果；后续命令拒绝，须显式重新准备。不会公开半个来源组的新帧。

`Frame { sequence, sampled_ms, universe, slots[512] }` 是软件完整快照。端口新鲜度、驱动接受／发送完成、静默维护仍属于 [输出端口](output-port.md)。本次没有将组对象接入 [独立执行进程](local-execution-process.md)、桌面或真实端口。下一步抽取现有宿主的执行后端接口并复用原线程／租约，不能每个来源各起线程或各占同一端口。

## 验证依据

`stagemaster-live` 测试使用真实工程编译：倒序准备、不同／同刻自动接管、人工同刻接管、继承值不抢占、跳转／暂停／停止、完整循环折叠、动态保持场景／多个列表／手动层、统一编码、优先级／亮度、错误原子拒绝和跨实例身份。累计预算用 32 灯、129 步、15／16 来源分别验证通过／拒绝。内部故障注入覆盖来源与帧序号耗尽，确保有效观察整体撤销。另验证 Player 暂停后的真实时刻和极大单调时间，不削弱旧观察者回归。
