# 预备音乐灯光来源

TIME-001／[ADR-116](../development/decisions/PRODUCT-ADR-116-prepared-audio-lighting-source.md)。本接口是宿主内存契约，复用[来源合成](prepared-source-compositor.md)、[媒体同步组](media-source-groups.md)和[后台媒体入口](media-host-ingress.md)。独立进程的音频所有者及桌面控制尚待接入；不是设备包或远程协议。

## 准备与状态归属

`SourceSpec.playback` 使用 `Option<PlaybackSelection>`：`None` 为手动层，`Program(PackageSelection)` 为既有场景／列表，`AudioTimeline` 为工程中的音乐灯光编排。旧 Rust 调用可用 `PackageSelection::… .into()` 转换；设备 `PackageSelection`、工程 JSON 和现有 HTTP 清单不变。

音乐来源只能通过 `Session::prepare_with_media` 准备，必须属于一个明确的媒体组。`Session::prepare` 或未将音乐来源绑定到组的调用拒绝，不默认使用系统时钟。普通列表中间等待人工的步骤仍不能作为媒体跟随来源。

`Document::compile_live_audio()` 编译默认段、所有启用灯光片段，或旧格式中的绑定卡点。复用 `compile_audio_segment`、原效果和渐变计算；静态单段通过 `HeldScene` 采样，动态交叉通过 `SceneCrossfade` 采样。保存完整工程摘要、统一语义布局及编码器，不在执行线程读取可变工程。

`LiveSourceBudget` 累加驻留计划的目标值、效果通道、关键帧。动态交叉的两侧分别计入，全组音乐与普通来源共用原有上限 262144／16384／131072。预算描述已有计划容量，不等于操作系统总内存保证；在途准备和音源缓存另由宿主限定。准备失败不会更换运行内容。

## 求值与属性贡献

`LiveAudioTimeline::apply_timeline(command, position_ms)` 由媒体组调用。有效位置在音乐时长内；向后定位需要新代次准备。成功采样复用固定缓冲，不编译、不克隆计划、不分配或访问文件。`Stop` 释放贡献；暂停、继续保留当前位置和效果相位。来源的 `index()` 为进程内观察：空白段 0、预备片段索引加 1，停止为 None；不是可直接执行的列表步骤编号。

音乐来源拥有启用编排涉及的属性集合，包括场景明确赋值、效果、交叉来源和历史进入快照。集合内未赋值或空白段使用现有完整场景默认值，显式释放也遵循原完整场景语义；集合外输出 None，不遮挡自主来源。现场列表的稀疏跟踪／释放规则保持。

明确激活、片段切换和跨过启用片段的结束会产生一次属性接管。一次前进跨越整个片段，前后都是空白，也必须处理结束后的默认值；这里只合成最终属性值，没有机构等外部动作派发能力。同段连续采样、停用片段及普通暂停／继续不反复抢回手动层。事件由原合成器转换为宿主接纳时刻排序，媒体位置不替代单调宿主时间。

`copy_contribution` 在写入前检查目标切片形状；合成完成后 `acknowledge_contribution` 清除待处理接管。媒体观测超过音乐时长时，在推进其他来源前拒绝，保持现有完整帧和组状态。错误工程、旧代次、回退、过期和失联仍走原媒体组校验。

## 验证与后续

测试逐点对照原片段编译器，覆盖历史切片、效果偏移、动态交叉、卡点、空白／停用和终点。真实 Session 检查自主效果、手动接管、完整编码帧与准备失败；真实 WAV 解码源进入原 Host，操作者退出后持续更新，暂停／失联不影响自主来源。64 灯及连续片段验证单轨和跨来源累计效果预算。

以上软件用例没有打开物理声卡或灯具输出。独立应用音频所有权、桌面入口、提供方重启重绑定、素材循环回跳和普通试听统一仍属 TIME-001；当前测试不证明声卡呈现延迟或跨设备同步精度。
