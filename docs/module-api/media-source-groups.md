# 独立时钟与媒体跟随组

状态：TIME-001 的软件运行增量；依据 [ADR-111](../development/decisions/PRODUCT-ADR-111-independent-clock-mapping.md)／[ADR-112](../development/decisions/PRODUCT-ADR-112-media-following-source-groups.md)／[ADR-113](../development/decisions/PRODUCT-ADR-113-audio-consumption-observation.md)。正式音频已有原生消费与回调健康观测（[ADR-115](../development/decisions/PRODUCT-ADR-115-audio-render-health.md)），[后台媒体准备／观测入口](media-host-ingress.md)已接原宿主线程。独立进程与桌面音频已接通，参见[后台应用契约](background-audio-application.md)；真实设备同步仍未验收，本接口不是已发布的远程协议。

## 状态归属与调用

`stagemaster-time` 是无分配、no_std 的时钟区间转换。`Clock` 包含非零身份和代次，`Instant` 的单位为纳秒；`Mapping::measure` 接受双方四个时间戳及明确能力上界，`convert` 返回最早／最晚时刻。往返非对称、漂移与采集误差进入区间；重复读取不刷新有效期。适配层负责认证、请求关联、时钟唯一性与真实精度，不能把任意时间戳包装成可信观测。

`stagemaster-live::Session` 继续拥有全部来源、属性合成及唯一完整帧。媒体组只是来源的时间控制方式，自主来源及手动层保留原入口。宿主时间仍以原有毫秒为单位，`host_clock()` 返回其时钟身份；适配层换算纳秒时必须沿用同一原点。媒体组的 `position_ms` 是节目位置，不是系统时间或控制期限。

| 调用 | 作用及边界 |
| --- | --- |
| `Session::prepare_with_media` | 固定来源、组成员、提供方时钟与观测预算；调用已有工程编译和累计资源检查；不开始播放 |
| `media_key`／`media_groups` | 读取当前执行实例绑定的组键、播放代次、实际位置及状态；读取不续期 |
| `media_preparer` | 在移交调度所有权前取出独立、不可变的准备器；它不引用运行中的 Session |
| `Preparer::prepare` | 工作线程根据当前组键、同一不可变工程、目标位置及绝对截止时间编译和求值；失败不触碰现行播放 |
| `Prepared::advance_to` | 在调度外追赶到更新的实际消费位置；失败对象不会进入调度，回退须重新准备 |
| `activate_media(&mut Prepared, sample, mapping, now_ms)` | 先核对准备代次、期限、首个实际游标与时钟质量，然后整组切换；旧播放器交换进借入对象，成功或失败都由调用者在调度外释放 |
| `observe_media` | 接纳递增序号和提供方时间戳，按实际消费位置推进／暂停；不外推、不编译、不访问文件 |
| `stop_media` | 释放本组贡献并更换代次，其他组、自主来源及端口所有权不变 |
| `tick`／`frame` | 自主来源持续求值、媒体失联检查、统一合成及原有 512 通道编码；不直接操作驱动 |

准备对象的字段不可伪造。一次成功激活后其旧键已失效，不能重复交换旧播放器回来。准备器可复用到该组的新代次；调用端负责限制在途准备与待回收对象数量，当前没有创建无界准备队列。准备对象不是跨设备原子事务凭证。

## 时间与控制规则

- 媒体组接明确可按位置求值的连续灯光计划及[真实音乐灯光编排](audio-timeline-source.md)：列表中间步骤不能等待人工推进，末尾可以保持。音乐片段、历史渐变和动态交叉在调度外完整准备，观测不得超出音乐时长。人工剧本推进仍由自主来源承担，混合段落调度另接。
- 跟随观测携带提供方单调时间、递增序号、毫秒位置及实际暂停／播放状态。倒退和不连续定位必须重新准备代次；外部循环位置回跳也不能伪装成普通连续样本。当前范围为单次位置上限 24 小时，不是商业许可规则。
- 全部映射区间必须落在宿主过去的允许年龄内，且符合组的误差上界。提供方速率／位置分辨率另有显式预算。错误、过期、未来、重复和错代次观测在推进任何来源前拒绝。
- 媒体帧采样不重新接管属性；Player 的真实步骤激活才产生新接管。接管时刻是宿主接纳该更新的时刻，不把媒体内部历史时间直接拿去排序。显式定位对该位置所有已拥有属性重新接管；组内同刻沿用来源身份稳定排序。
- 媒体渐变从自身计划状态计算，现场覆盖层不会改变其时间线数学结果。场景列表跟踪、属性释放、动态效果与循环折叠均复用原有 Player／Ownership。
- 短暂缺样本保持上一贡献；失联期限按映射区间的最早观测时刻计算，重复读取或坏消息不延长。达到期限报告 `Lost`，来源状态显示保持；新样本不能悄悄恢复，须新代次准备。这里没有机构动作派发，不能据此声称已实现机构重放保护。
- 输入控制权、商业许可、媒体新鲜度和物理输出权保持独立。媒体定位不改宿主单调时间或合成帧序号；提交物理端口仍需现有端口许可。

## 验证与剩余工作

实际工程包含媒体列表、自主动态效果和手动层；双时钟采用不同原点与 100 ppm 速率差的软件前向模型。测试覆盖暂停／恢复首个差值、反向定位、整组成员切换、失联保持／恢复、旧键与坏观测原子拒绝、渐变与现场起点隔离、独立准备线程及晚到结果。完整帧另进入现有 Port＋软件驱动，确认定位不重置序号、外部端口接管仍拒绝旧许可。

TIME-001 已将准备与观测接入原独立宿主的固定容量槽、控制权与回执，见[宿主契约](media-host-ingress.md)。独立进程与桌面入口已通过原生静音软件验收，范围见[后台音频应用契约](background-audio-application.md)；原生音频仍没有声卡呈现时刻校准，蓝牙音箱／实板／多设备启动精度未验收。此媒体组核心契约不改变工程 JSON 或设备执行包。

## 原生音频消费观测

`stagemaster-audio::Transport::performance_observation()` 返回当前正式演出音源的进程内实例、主机播放意图和一致的 `PerformanceSnapshot`。没有正式音源时返回 `None`；输出故障或读取竞争返回错误，不用界面旧缓存代替执行观测。普通试听／临时循环仍未接此接口。

快照中的 `consumption` 在首个完整采样帧消费前为 `None`，之后包含实例、累计完整帧数、采样率与原消费时刻 `std::time::Instant`。素材位置／循环遍数与消费计数配对读取；循环回跳不倒退消费计数。暂停／继续保持实例，重新准备／定位后重建会更换实例。实例只在当前进程内唯一，适配时仍须绑定宿主与时钟身份，不能直接作为远程设备身份。

`requested_playing` 仅表示主机意图；不代表音频回调已经暂停，也不确认音箱实际发声。接续的 [ADR-118 音频适配](resident-native-audio.md) 同时返回完整 `request` 代次，确认时比较实际 `render.applied`，并为普通正式音乐提供无循环计划的同一观测路径；原普通试听入口尚未迁移。控制元数据、重复读取、结束／取消及缓存回退不会刷新消费时间；界面忙时保留原快照并标记待更新。适配器须分别处理播放意图、实际消费与错误状态，不能将暂停时不变的消费计数伪造成新样本。

原生 Rodio Player／虚拟 Mixer 的测试验证真实消费、暂停／继续、停止／重建与忙读取；没有打开物理音频设备。消费发布不新增阻塞锁、分配或 I/O；回调开销和硬件呈现延迟尚未量化。异步准备期间的追赶和有界宿主入口已补；循环回跳按下述 ADR-122 验证，提供方重启重绑定及多编辑进程的音频输出权仍是接续工作。

## 暂停确认与回调健康

`PerformanceControl::request_playback(bool)` 返回 `PlaybackRequest { revision, playing }`，代次不回绕，重复相同意图保持代次。原生音源从下一个完整帧应用最新请求；左右声道之间的新请求不会改变已开始的这一帧。请求不产生观测，`requested_playback()` 也不代表已经执行。

`PerformanceSnapshot::render` 首个完整帧前为 `None`，随后包含音源实例、递增序号、采样率、原回调时刻及该帧实际应用的请求。播放帧同时更新 `consumption`；暂停帧输出零样本，只更新 `render`，素材位置／循环遍数、消费计数和消费时间保持。没有拉取的已准备音源不能宣称健康；请求、读取、循环元数据、结束和缓存不会刷新时间。取消／解码故障在帧边界停止后不再产生健康观测，正在输出的半帧先完整结束。

正式 Transport 的 Player 持续拉取，音源自身执行帧边界暂停；普通试听仍保持原路径。界面 `Position.playing` 与原生 `requested_playing` 表示主机意图；媒体适配须检查快照中的错误、停止和结束状态，再使用 `render.sequence`／`render.at`／`render.applied.playing` 与同一快照素材位置。不能拿暂停时的旧消费时间当健康，也不能为缓存重新盖章。结束须显式协调组结束，不把最后一个播放帧外推为仍在演出。

回调确认只证明原软件音源已经被拉取，不证明声卡／蓝牙音箱的实际呈现或静音时刻；重采样、设备缓冲和传播延迟仍另测。真实后台测试已覆盖暂停超过组失联期限仍保持暂停、继续首个消费差值、停止拉取后缓存拒绝与失联、自主灯光保持运行。独立进程持有正式音源，桌面关闭后继续；旧编辑试听在多进程之间的输出权仍待统一。

## 连续消费与正式循环（ADR-122）

`Sample.progress: Option<MediaProgress>` 是可信原生提供方的配对观测，包含音源实例、采样率、素材 tick、累计消费与累计回跳；普通正式音乐也可提供该观测。激活绑定形态和实例，初始计数为零，替换音源须重新准备。非音乐来源不能使用该路径；未声明循环的音乐不能增加回跳计数。普通线性 Sample 保留原倒退拒绝规则。

任意两份有效观测须满足位置／消费／回跳的整数关系，消费速率仍受实际原时间戳和误差预算限制；暂停不续造消费。LoopPlayback 的累计回跳值跨区段和循环结束保留，seek 才归零。一次更新跨多遍仍只采样一次已准备灯光；新一遍开始在真实宿主时刻重新声明本组编排属性，其他来源和未编排属性不受影响。

具体生命周期、量化定位和验收依据为 [ADR-122](../development/decisions/PRODUCT-ADR-122-background-audio-loops.md)。早期关于所有倒退均须重编译的规则仅适用于未携带合法循环依据的观测；提供方重启与真实物理时钟适配仍未关闭。
