# 多来源共享后台宿主

HOST-004／005 已进一步接入[多来源独立进程应用入口](multi-source-process.md)与桌面后台控制，下面的库边界保持；物理输出仍未迁移。TIME-001 新增[后台媒体准备／观测入口](media-host-ingress.md)，媒体应用入口仍待接入独立进程／桌面。

HOST-003／[ADR-107](../development/decisions/PRODUCT-ADR-107-shared-host-backends.md)。`stagemaster-runtime-host` 保留一个调度实现，`stagemaster-live-host` 将[固定来源组](prepared-source-compositor.md)接入其中。当前为灯光软件后台，不是统一音视频渲染回调；音视频独立时钟与设备回调仍走各自模块。

## 所有权与准备

调用顺序：同一工程准备 `Session` → `LiveBackend::new(session)` → `Host::<Live>::start_backend(backend, configuration)` → 可信应用确认操作者后调用 `connect` → 有租约的 `Client<Live>` 提交操作。

只有未使用、未故障的来源组可以交给新调度宿主，启动身份由来源组保留。组对象转移到唯一 worker 后，调用者只保留来源身份、客户端和只读观察者。目录／灯具语义／载入放在准备阶段，运行中不读取工程或节目文件。

原 `Host::start(Runtime, Configuration)` 和默认 `Client`／快照／回执类型继续有效。默认设备命令仍是场景启动、暂停、继续、下一步、停止，不能将 Runtime 的装载／安装动作塞进队列；文档编译失败用例保护这条类型边界。

## 后端契约

`Profile` 定义进程内命令、状态、回执和帧元数据；不是未经认证客户端协商的任意协议。`Backend` 提供准备检查、单调时间基点、状态、推进、完整帧、取得／续期／释放控制权及提交操作。调用有界且不阻塞，不另起播放线程。快照和帧元数据为固定大小、可复制数据；生产命令克隆不得引入无界工作或 I/O。

HOST-004 将接纳期限扩展为 `impl Into<Deadline>`：原 `Duration` 调用继续有效，也可传入同进程原始 `Instant`，后者原样写入队列信封；过去的时刻拒绝，未来不得超过 5 秒。网络层只传相对请求预算，由可信应用首次接纳时生成 Instant，不能跨机器传该时钟值。

共有机制保持：32 项有界队列、每周期最多 8 条命令、1～100 毫秒调度周期、最多 5 秒的入队操作期限、过期未执行、不等待已丢弃回执、只读观察争用时跳过发布、错过周期不突发补帧、队列外关闭及超时后保留同一宿主句柄。终止／故障撤回有效观察，不返回可继续发送的旧帧。

## 公共控制权

`stagemaster-runtime::authority::Authority<A, S>` 从原设备 Runtime 中抽取，使用同一个租约／重试规则。它不调度节目、不生成输出，不代表商业许可或认证。

1. 后端先推进同一单调时间并处理输入租约到期；失去输入权不停止节目。
2. `check` 验证租约及连续序号。完全相同的重试返回历史回执；同序号不同内容或跳号使当前输入权失效，错误租约不能撤掉正确持有者。
3. 后端检查上下文修订并应用业务操作。有效上下文的业务意图包括拒绝也推进修订；过期上下文拒绝保留当前修订。随后 `complete` 更新接纳序号并缓存包含当时状态的回执。
4. 从检查、应用到完成由同一后端串行调用；载荷／快照克隆必须有界。通用容器自身无堆分配，设备默认类型仍为固定数据；宿主属性批量只克隆已准备的共享只读载荷。

`Request<A = Action>`、`Receipt<A = Action, S = State>` 的默认值保持原设备 API。设备 Runtime 的控制 API 移到独立小文件，装载／维护和输入权不再混在同一个大段实现中。

## 多来源调用与观察

- EXEC-014 的 `Action::Batch { batch: Batch, command: BatchCommand }`：`Batch::new(&[Key])` 接纳前构造 1–64 项唯一不可变 Arc 切片，worker 克隆共享存储。核心 `Session::control_batch` 全组身份／类型预检，沿同一单调时间和原 Player 应用 Pause／Resume／Stop；只支持普通独立节目，一次最终合成。不新分配每帧载荷，不改变媒体、手动或设备默认 Action。单操作权限／修订／序号／期限／重放与内部故障规则不变，整组一个回执；不能把 UI 多次单来源请求称为原子批量。

- `Action::Control { source, command }` 操作某个已准备场景／列表，停止也可清空手动层。
- `Action::Patch { source, patch }` 只操作手动层。`Patch::new` 在入队前准备最多 512 个不重复属性，后端继续检查实际布局；上游灯具语义层负责具体功能值有效性。
- `Action::Level { source, level }` 调整普通亮度电平，不隐式释放位置或其他属性。
- `State` 包含启动身份、工程布局身份、上下文修订、采样时间、输入持有者和最多 64 个来源的状态／步骤／电平。取得控制权回执带实际快照，不依赖下一次观察发布。
- `FrameInfo` 标明工程布局、启动身份、上下文修订、合成版本、实际采样时间和逻辑输出域。合成版本可在同一周期内因命令跳增，不是物理包序号或丢包计数。

属性批量使用有上限的不可变共享载荷；输入端分配，worker 克隆共享所有权。完整来源组、逐属性取高／接管、效果求值和唯一通道编码仍属于 Session，不在后端再实现。暂停／完成保持贡献，停止只归还指定来源；客户端生命周期与播放生命周期分离。

## 验收与后续

实际后台线程测试覆盖：真实工程动态效果在客户端消失／输入权到期后继续、新操作者取得控制权、明确接管、旧租约拒绝、重复回执不重启、同序号冲突收回输入权、上下文拒绝消耗序号、局部停止保留其他来源、排队过期后以原序号重新提交、后台故障撤回观察、正常关闭，以及属性载荷容量。截止时间测试故意阻塞真实适配器；此测试桩不进入产品路径。

原设备 Runtime、默认宿主、独立执行进程与设备通道全部继续回归；共享内核另做 Xtensa 无标准库编译。当前没有改 HOST-002 的 HTTP 命令协议或桌面控制入口，没有连接真实设备。下一步把多来源组接进已认证的本机应用入口，来源目录／请求映射与业务回执需单独验收；输出权与发送完成仍由[输出端口](output-port.md)负责。
