# 设备硬件看门狗

[ADR-138](../development/decisions/PRODUCT-ADR-138-device-watchdog.md)／[OUTPUT-002](../development/tasks/OUTPUT-002-dmx-transmission.md)。这是 S3 板级组装，不改变 Runtime 或设备包语义；代码在 `apps/esp32-player/src/board/watchdog/`，策略、原子进度和硬件适配分别组织。

| 入口 | 归属和约束 |
| --- | --- |
| `WORKER.beat()` | 第二核在实际运行／输出服务成功后调用；不是通信心跳，不从独立保活定时器调用 |
| `WORKER.fail()` | 锁存失败；后续 beat 不得恢复或回绕为健康 |
| `Watchdog::arm(TIMG1)` | 唯一拥有 TIMG1，Stage0 1 秒主系统复位；不抢占调度器的 TIMG0 |
| `supervise(receiver.run(tx))` | 在发送任务自身交错监督与原 Receiver；任务同步阻塞时不能由其他任务代喂，正常退出也终止喂狗 |

启动窗口最多 10 秒等待首次工作器推进，之后每次观察到新的工作器进度将截止时间推进 2 秒；重复读取不续期。到期后才到达的新进度、倒退的计数／时钟、计数耗尽和工作器失败均锁存，不自动恢复。即使软件监督没有再次被调度，TIMG1 仍在最后一次喂狗后独立复位主系统；这不依赖异步定时器能取消 UART 同步轮询。

软件策略判失败或发送任务退出时，原发送 Future 被销毁，复用原 Transmitter／Line 的方向关闭；不禁用硬件看门狗、不原地重建输出端口。同步卡死不能靠析构保证关闭，须等待硬件复位；复位过程的 GPIO 电平和外部下拉仍需独立电气验证。重启使用新启动身份，不自动重新执行旧节目。主时钟／电源故障、深睡和 JTAG 停断点不在本次保证范围。

2 秒进度预算包含维护操作；既有实板单请求约 494 ms 是配置参考，不代表任意最大包都已通过压力测试。正常帧的 40 ms 事务预算／100 ms 新鲜度继续由原输出模块执行，看门狗不是帧时序保障，也不保证失去信号的灯具熄灭。

`runtime-dmx-probe` 按 [ADR-139](../development/decisions/PRODUCT-ADR-139-s3-output-scheduling.md) 将发送任务及 UART 中断绑定第二核，中断执行器与普通工作器分开调度；蓝牙／周期报告留第一核。该镜像采用此监督组装，GPIO21 仍由实验 Line 强制低；旧 `runtime-gatt` 不受影响。独立 `watchdog-probe` 只用于明确选择的同步卡死／任务退出／运行核停顿／主动失败试验，无蓝牙和存储操作，不是商业固件。其 CoreMwdt1、持续恢复及宿主观测延迟必须由实板日志证明；软件策略用例和编译不能替代这些记录。

完整服务实板载入曾触发 32 KiB AppCpu 栈保护；本组装已将第二核任务栈独立配置为 48 KiB 内部 SRAM，正常不输出固件仍为 32 KiB。该静态预留不挤占既有固定堆、不属于堆峰值；调用点采样仍不能声称完整栈高水位。故障与复验记录见工单。
