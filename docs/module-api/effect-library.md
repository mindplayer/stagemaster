# 灯效模板库伪 API · draft-1

依据 [ADR-090](../development/decisions/PRODUCT-ADR-090-reusable-effect-library.md)。这是未来服务的可类型检查设计，**没有运行实现、没有云端入口，也没有改工程格式**。已实现部分仍以 [lighting-effects.md](lighting-effects.md) 为准。

`EffectCatalogApi` 只检索／获取不可变模板。下载资源经已有资源入口验证为本机固定引用后，`EffectBindingApi.review` 在 Rust 侧只读检查；`apply` 用同一不可变审阅票据和预期工程修订创建效果实例，单次可撤销事务。票据不是现场执行授权，应用也不会开始播放。底层复用 ProjectService 与现有编译器，不新建另一效果数据库／播放器。

声明先收敛三类规则：亮度曲线、颜色角色步进、相对双轴；每种规则的能力要求由核心推导，不能信任包内自行声称兼容。颜色步进／模板实例尚待实现，类型存在不表示已有 Player 支持。世界空间模板在确定可携带空间锚点契约后另加类型，不将原工程坐标偷偷复制到新场地。

角色映射分别为有类型的 RGB 值或具体色盘功能键；同一模板可对不同型号采用不同绑定。颜色角色是作者命名的用途，不是字符串颜色名自动识别。连续步进仅混色目标可承接；不同光源的颜色一致性需要额外测量，不承诺屏幕 RGB 等于实灯色度。

每份审阅包含固定模板哈希、工程修订、所选灯具／单元、参数、档案／校准和目标能力依赖；服务保存不可变提案并核验提交，不接受客户端篡改审阅结果。阻断与缺绑定不能得到可应用票据。改变参数、选择、目标或模板须重新审阅；票据失效返回 `STALE_CONTEXT`，重复请求按既有 commandId 处理。草稿预演绑定同一提案，使用当前唯一预演会话和取消协议，具体适配留在实现工单。

首个实现需要单独冻结严格 JSON schema、单位和范围、容量／依赖深度、版本兼容、引用／复制／编辑派生策略、完整字段错误及迁移测试。当前不把本文件作为最终发布包规范，也不向正式界面放置空按钮。类型声明仅展示有限功能，后续节点通过显式 schema 增量扩展，不使用任意脚本或 `any`。

云端最小顺序：本地导入／导出闭环 → 同模板跨档案绑定 → 版本与依赖收集／离线复验 → Fastify 目录、权限与分发。每一步都沿用相同已验证的核心语义。
