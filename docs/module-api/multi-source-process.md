# 多来源独立执行进程

HOST-004／[ADR-108](../development/decisions/PRODUCT-ADR-108-multi-source-process-entry.md)。同一个 `stagemaster-execution-host` 程序增加来源组档位，复用[本机应用服务](local-execution-process.md)和[共享执行宿主](shared-live-host.md)。本接口只有软件采样，未启用真实输出，不能作为音视频统一时钟或商业授权方案。

## 准备与发现

启动参数：`stagemaster-execution-host 工程路径 group 来源清单路径 新运行目录 --software-output`。来源清单最多 64 KiB，严格 JSON，版本必须为 `1`，字段如下：

```json
{
  "version": 1,
  "sources": [
    {
      "id": "66666666-0000-4000-8000-000000000001",
      "priority": 0,
      "selection": { "kind": "scene", "id": "工程中的场景标识" }
    },
    {
      "id": "66666666-0000-4000-8000-000000000002",
      "priority": 0,
      "selection": { "kind": "sequence", "id": "工程中的场景列表标识" }
    },
    {
      "id": "66666666-0000-4000-8000-000000000003",
      "priority": 0,
      "selection": { "kind": "manual" }
    }
  ]
}
```

来源为 1～64 个唯一非零、标准小写 UUID；优先级是有符号 16 位整数，至少有一个场景或列表。节目选择使用工程中的真实 ID，同一节目可作为不同来源准备。未知字段／版本、重复来源、缺失节目、仅有手动层或累计预算超限均拒绝，不发布就绪信息。此清单只是可信本机启动输入，不是工程持久标准、设备包或网络动态安装接口。

所有来源基于同一只读工程快照准备；运行阶段不再读工程和清单。私有运行目录中的发现文件提供 `protocol: 2`、启动身份、实际 URL 和分离的读／控制凭据。组模式路径为 `/v2/{host}/…`；旧单节目路径及 `protocol: 1` 保持。客户端必须按发现档位连接，不凭源 ID 推断同一个执行实例。

`GET /source` 返回工程 ID、内容布局身份、来源名称／选择／优先级／稳定步骤目录、灯具与功能定义，以及 `sourcePlayback`、`sourceLevel`、`semanticManualPatch` 能力。`limits` 明确当前来源数、手动批量、请求字节、请求期限和输出域上限；客户端不能将电脑软件档位当成所有设备的能力。目录不暴露内部 Key、租约、属性数组下标。`GET /state` 返回相同启动与布局身份、修订、采样时间、来源运行状态／当前步骤／亮度电平和不含租约的输入持有者。

## 操作与回执

EXEC-005 增加 `sourceProgress` 能力和普通节目来源的可选 `progress`（协议仍为 2；旧主机可以缺省）。字段：`phase` 为 `idle/delay/fade/wait/hold/finished`；`elapsedMs`、`phaseElapsedMs`、可空 `phaseDurationMs` 是 u64 十进制字符串；可空 `nextStep` 是该目录的稳定步骤身份，`nextWrap` 标记返回首步。Idle／Finished 无下一步，Hold 无总时长，Paused 保留其实际阶段。手动及音频来源没有此投影。已声明能力缺字段、未知步骤、不合法时间或状态组合由共享客户端拒绝。单次状态中的时间、身份与修订保持一致，不混用不同观察或在读取时推进。

创建会话、取得／续期／释放输入权、查询回执及正常关闭复用 v1 规则：8 个操作会话／工作器、8 KiB 请求体、操作截止时间最多 5 秒、连接预算与存活期限、只读凭据不能写入、拒绝 Origin 和重复认证头。请求的 `serial`、`expectedRevision` 和返回的大整数仍是标准十进制字符串。失败映射及等待未知结果继续保留原票据，不能重新发送另一条执行命令。

组模式的 `submit.action` 为：

```json
{
  "kind": "source",
  "source": "66666666-0000-4000-8000-000000000001",
  "action": { "kind": "start", "step": "该来源目录中的步骤标识" }
}
```

内部 `action` 支持 `start { step }`、`pause`、`resume`、`next`、`stop`、`level { value }`（0～65535）及 `patch { changes }`。停止只释放目标来源，电平只缩放普通亮度，零电平不等于释放其他属性。手动层只支持停止清空、电平和属性修改。组模式拒绝旧的无来源操作；旧单节目模式也拒绝组操作。

手动 `changes` 是非空、最多 512 项的原子批量，每项由 `fixtureId`、`attribute`、`value` 构成。整个请求还必须满足 8 KiB，超过时应拆成明确的多次操作，不能悄悄分批声称原子：

- `value: { "kind": "normalized", "value": 32768 }`：连续属性，数值零仍持有属性。
- `value: { "kind": "function", "functionKey": "red", "position": 0 }`：已定义功能，槽位和范围规则由同一个 `FunctionTable` 校验与转换。
- `value: { "kind": "release" }`：归还此属性。

`CompiledOutput::manual_value` 在应用侧将真实灯具／属性与类型值映射为准备快照中的下标及编码值，不改变工程、不生成半帧。所有项目先转换成功，再由 `Patch::new` 拒绝重复下标；任何错误都不提交部分批次。功能通道不能用普通百分比或原始 DMX 数值绕过定义。

格式拒绝不接纳操作序号；已接纳后发现错误来源／步骤／语义，会保存应用拒绝回执，消费应用操作序号但不提交或消费内核控制序号。内核业务拒绝仍消费内核序号，按其历史回执更新绑定。完全相同的重试返回原结果，冲突／跳号不会重放。应用映射及锁等待也消耗原截止时间；应用把首次接纳生成的 `Instant` 原样传入宿主队列，避免换层重新起算相对期限。

## 输出与生命周期

软件帧包含启动身份、布局身份、修订、合成版本、实际采样时间、逻辑域及完整 512 槽。合成版本不是网络包计数，采样不是物理发送完成。内部租约、来源 Key 不序列化；输入权到期或客户端退出不会停止节目，明确接管后旧会话不能控制新持有者的运行。宿主故障／关闭撤回有效观察。

Application 仅定义模式到操作／状态／回执／帧的映射；Service、Registry、命令工作器、HTTP 认证和后台 Host 使用同一份实现。组模式和旧模式都保留真实子进程验收。桌面尚未迁移，后续在此边界接入目录、控制权和回执；物理输出、跨设备远程认证、节目热替换、音视频多时钟和生产商业保护另行实施。
