# Depence R4 对照与专业预演架构补充

日期：2026-09-11。状态：用户要求吸收 Depence R4 的优势，形成专业编排、预演与演出控制的统一系统。本文为公开资料对照与设计建议，无 Depence 实机测试，也不表示 StageMaster 已具备相关能力。MA3／Titan 研究、Rust＋TypeScript 主框架和单机优先方向继续保留。

最新范围：吸收其仿真、监看和演出协作方法；StageMaster 的音视频正式播放、处理、映射与输出由外部系统承担，见[多系统编排与监听／监看](audiovisual-stage-design.md)。下表保留厂商自身的内部媒体功能事实，但不把它们全部转成我们的实现任务。实体控台另外通过[双向硬件控制面](hardware-control-surfaces.md)接入。

## 1. 产品定位

StageMaster 面向“场地准备 → 舞台设计 → 专业编排 → 联合预演 → 方案交付 → 现场执行”的工作流程。MA3／Titan 主要提供专业控台工作方式的参考，Depence R4 加入多设备仿真、舞台场景和方案交付的对照。UE5 是专业渲染后端候选，高斯采集是场地来源候选；二者均不能代替专业设备模型。

Depence 同时有可视化和 Show Control 能力，不能将其归类为只有画面展示的软件。其公开介绍包括时间线、多媒体、Live Panel 与硬件控制。[产品概览](https://www.syncronorm.com/)、[Live Panel 手册](https://help.depence.com/depence-hardware/live-panel)

建议提供三种部署／使用模式，使用相同对象身份和契约：

| 模式 | 输入与输出 | 责任边界 |
| --- | --- | --- |
| 专业控台 | 编辑与控制命令 → 现场节目与信号 | 预演后端可不启动 |
| 独立预演 | 外部控台／播放器信号、场景及档案 → 虚拟舞台与诊断 | 不要求先用 StageMaster 重编节目；默认没有物理输出权限 |
| 编排＋预演一体 | 自身运行／独立盲编上下文 → 专业预演，并按授权控制现场 | 共用节目语义，运行实例、状态与输出权限分开 |

## 3. 要补足的架构边界

### 3.1 节目求值、设备仿真和渲染

节目求值回答“此时要给哪些设备什么值”；设备仿真回答“设备接到这些值后，在模型中怎样响应”；渲染回答“从这个镜头看是什么画面”。例如下达新的 pan／tilt 值、灯头按模型运动、光束投射到墙面，是三项职责。

仿真层按设备族实现窄接口，可位于独立进程或 UE 适配包内部；不要求全部增加为 Rust crate，更不把流体／粒子计算放进灯光输出循环。共享的是输入单位、身份、时间、模型版本及结果含义，复杂 GPU 仿真和渲染可以共用后端资源。

`SimulationModel` 记录支持属性、响应参数、随机种子政策、依赖端口、Seek 能力和质量等级。DMX 映射档案、仿真模型、外观模型和实物校准分别引用，换皮肤不改控制语义，升级仿真不静默改变已保存的预演版本。

### 3.2 仿真状态和时间

仿真实例属于特定 PreviewRef 或现场只读观察会话，有各自的状态和时间映射。连续输入、一次事件及外部反馈分别处理。粒子、运动、喷水等可能依赖历史，不能只把当前值送入渲染器就认定 Seek 正确。

模型声明如何 reset、预滚、检查点恢复或有界重放。恢复较慢时报告 preparing，超预算则拒绝该精度或显式降级；不阻塞现场。固定种子、版本和步进有助回放，但 GPU／第三方模拟的逐像素确定性不能默认保证。

设备依赖图使用有类型的端口与单位，校验悬空引用和环路；环路只在模型明确支持求解时接受。喷水装置的预览默认值等行为由我们自行定义，不自动复制第三方“未连接也按满量模拟”的规则。

### 3.3 外部输入

输入来源显式选择：StageMaster 已求值状态、外部协议数据或已录制数据。协议输入先映射到指定场景和档案；缺通道、不匹配、超时和协议优先级按声明政策处理，不能把未收到的数据默认成现场已归零。

同一仿真对象的来源与仲裁必须明确。独立预演入口不自动转发到真实输出，避免信号回送；接入 MA3／Titan 的具体协议能力、输出授权和场景交换要分别测试。

DMX 录制保存接收时间、来源、采样／丢包信息和档案／配适修订；它是协议状态记录，不能自动恢复原控台的 Cue、Preset、跟踪与效果意图。节目语义录制与 DMX 录制分开标识。

### 3.4 场景动画与视频源

灯具可挂在移动桁架／装置上，局部安装变换、场地静态变换和时间相关姿态分别建模；图纸明确输出静态安装状态或指定时刻姿态。动画不能直接改永久配适或灯具身份。

虚拟摄影机、素材、外部流都通过视频源身份接入；摄影机拍到播放自己画面的屏幕会形成循环依赖。媒体图应拒绝无定义的循环，或明确采用有延迟反馈与深度／资源限制，不无限递归渲染。

投影模型描述位置／方向、镜头范围、遮罩／融合及受光几何；虚拟屏幕与投影面保持区别。真实投影效果仍受设备标定影响，正式映射和输出由外部系统负责。返回图像需标记映射前／后取点，避免将已变形画面再次套用虚拟校正。

### 3.5 图纸、资产与运行权限

图纸／表格从固定工程、场地和现场绑定修订生成；编号、设备数量和配适与同一版本一致，导出时标记版本及视点。图纸不是另一个可独立修改配适的数据库。

资产库保存档案、几何、仿真模型、校准和派生物依赖；缓存／云端更新生成新版本，不覆盖正在使用的模型。高斯采集继续按[混合场景方案](venue-capture-design.md)处理，不假定扫描外观天然可重新布光。

激光、无人机、烟花、机械等仿真模块只能产生模拟结果；未来接入物理执行需要独立适配、能力与授权。图形里可播放一个效果，不构成已经支持真实设备的证明。

## 4. 伪 API 补充方向

以下是内部职责草案，尚未加入 TS 声明或实现；公共错误、权限、JobRef、幂等和资源生命周期沿用[模块 API](module-api/README.md)。

| 类／方法 | 调用含义 | 限制 |
| --- | --- | --- |
| SimulationCatalog.describe(modelRef) | 返回设备模型版本、单位、输入与回放能力 | 不因渲染器名称就宣称全功能支持 |
| SimulationSession.prepare(scene, modelRefs, sourceBinding) | 校验依赖并预备资源，异步返回会话 | 来源绑定为服务端验证的只读授权 |
| SimulationSession.restore(session, targetTime) | 按预滚／检查点规则定位，返回准备任务 | 校验对应同步组代次，拒绝旧位置结果 |
| SimulationSession.observe(session) | 输出派生姿态、光学／特效状态与诊断 | 大数据走受控数据通路，不逐粒子 RPC |
| PreviewRenderer.attach(scene, simulationSource) | 消费可呈现的状态与媒体，建立渲染会话 | 同一模型不能在桥接层和 UE 内重复推进 |
| SimulationSession.close(session) | 结束订阅，释放模型／缓冲 | 幂等回收；不停止现场节目 |
| PlotService.export(revisions, viewSpec) | 后台生成版本固定的图纸／表格／展示文件 | 不读取不断变动的全局编辑状态 |

这里将原 UE 方案的已求值输入进一步展开：简单模型可以直通或在后端内部求响应；复杂模型由仿真模块生成结果。具体数据结构与传输协议在原型前细化，当前 `contracts.ts` 未具备这些能力。

## 5. 验证顺序

1. **专业灯光＋场景**：受控灯具档案、移动／光束／Gobo、雾、视点；验证同一输入、帧关联、模型精度和故障隔离。
2. **联合预演**：一个虚拟屏幕、音频试听、投影基本几何、相机视频源；验证同步组、Seek、来源和循环依赖。
3. **独立预演模式**：一个有文档的外部输入源，验证配适、来源切换、录制／回放、断连恢复；不重复编程。
4. **场地采集与交付**：小场地混合模型、固定修订的灯位图／配适表／效果视频，核对更新前后对象一致性。
5. **专项仿真**：按实际项目选择激光、喷泉或特效之一，定义模型与验收，再扩充其他设备族。

这是设计建议，不是完成期限。预演研究可先用静态／录制输入验证，专业单机编辑与输出闭环按原计划推进；不要求等全部专项仿真完成才可使用控台。

首次验收至少覆盖：渲染负载不改变节目求值；同一场景三种模式身份一致；Seek 后没有旧特效残留；外部输入不自动输出；图纸和工程修订一致；缺模型明确标记。跨设备性能、真实光学精度与硬件输出都需要独立实测。
