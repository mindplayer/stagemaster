# 后续交付路线与验收方案

2026-10-07：本页保留完整 H1–H8 能力与原出口；**当前优先顺序改按[首发完善计划](../first-commercial-release-plan.md) R0–R5**。以下“当前首项”和待实施描述是 10 月 4 日快照，必须先核对最新工单，不重新开发已完成界面。纯灯光首发通过不等于完整音乐／UE 目标通过。

状态：2026-10-04 交接时的实施顺序。关联现有 AUDIT-001，不另立无限扩展的目标。H1–H8 是路线顺序／出口，不是已经存在的工单。每项开工查现状、复用未完成工单；新增编号先查重。

## 交付目标和依赖

近期目标：单机真实编排＋一款 ESP32 播放盒的一路 DMX 可验证交付。高级灯效、视频、多轨、云端、移动端和实体控台有明确位置，不全部成为首次交付前置。

~~~text
当前基线
  → H1 正式循环可用 → H2 必要现场操作
  → H3 指定真实灯型完整适配
  → H4 实物输出／本地执行验收（有条件可提前穿插）
  → H5 代表性任务＋安装包＋稳定性 → 首次受控试用出口
  → H6 专业能力扩展
  → H7 云端／商业安全
  → H8 手机平板／ARM／控制面与实体控台
~~~

硬件缺条件不阻塞 H1／H2 或其他独立软件任务，但必须保持物理交付未完成。发现数据丢失、执行错误或安全边界缺陷时先修具体问题，再回到顺序；不能以持续打磨 UI 规避硬件出口。

## H1 完成已有正式演出循环

当前首项，沿用 [AUDIO-020](../tasks/AUDIO-020-performance-loop-sections.md)；调度、持久格式、有界音源和运行控制已有实现，只补未完成部分。

| 增量 | 修改入口 | 通过条件 |
| --- | --- | --- |
| 区段目录与精确编辑 | UI 独立列表／属性组件、已有 AudioLoopEdit、桌面音频编辑 | 新建、检索、选择、起止精确输入、次数／持续、启停／锁定、取消／错误定位；合法编辑一次历史，同值无历史 |
| 时间线与成组操作 | 既有 AudioWorkspace 局部接线，独立区段轨与草稿协调 | 区段可见；选择／移动／长度调整不与播放头冲突；接近目标才吸附；拖动连续、松手一次提交；成组移动／复制／删除原子拒绝 |
| 正式原生闭环 | 共享 Transport 和循环栏、原生音频与 UE | 固定次数、持续循环、圈末继续／取消退出、暂停恢复、定位／停止正确；名称／锁定不重启声音；保存重开等价 |

至少覆盖：无区段旧工程、相邻区段／空隙、次数 1、非法重叠／越界、隐藏已选项、锁定成员、失败保留草稿、换工程／隐藏后的旧异步回复。实际音乐＋内嵌 UE 共享来源和游标，操作独立工程副本，结束恢复静止；未听音／未实测 UE 不能关闭整个 AUDIO-020。

不增加多音轨、自动鼓点算法、视频剪辑或另一个播放头。已有 WaveSurfer 和 Rust 音源继续复用。成熟经验按既有创作软件研究与循环 ADR 使用，遇到具体未定交互再查官方文档，不重做泛研究。

## H2 补齐必要现场操作

按 [EXEC-007～011 契约](../../module-api/desktop-background-execution.md)接续。先做有界连续属性，再考虑完整专业执行器页。

- 逐灯／选组连续属性：首增量只做共同亮度，复用来源推子的单在途／最新目标与回执机制。区分混合／未持有，冻结灯组／属性／工程／控制者，松手发送最终意图；失焦／取消停止未发请求。已应用值不因取消自动回滚，不写工程撤销。轴、颜色、轮盘分别按语义扩展，不能给功能档位无条件线性插值。
- 后台运行主控与明确释放：先核对已有软件预演总控与后台输出权威的差别。0 电平仍持有；释放才归还；停止与熄灯分别表达。灯光熄灭不是机械急停。以后物理推子也走同一控制权与回执。
- 执行工作面：当前／下一步、人工等待、延时／渐变、筛选和常用排序已有基础；补代表演出需要的批量操作／保护，不立即照搬全部顶级控台页面。

验收两个真实动态节目＋手动层，覆盖拖动、轨道外松手、精确输入、失联／抢占／旧回执、归零再释放、退出编辑器再连接；已准备节目继续且状态能解释。软件快照不当物理反馈，真实输出相关最终通过依赖 H4。

## H3 完成指定真实灯型

沿用 [FIXTURE-006](../tasks/FIXTURE-006-real-fixture-intake.md)，复用 FIXTURE-007／008、POSITION-002／003，不把测试夹具发布为真实灯型。

1. 先完成 30W 的 11 通道模式。用户已确认水平 540°、垂直 270°；粗细、色盘区间、图案、频闪、调光、轴速度、内置程序和复位逐项留证。0–9 等颜色档可自定义；未知颜色／图案不编造。依 2026-10-04 用户要求及 ADR-159，声控／内置自走等脱离编排权威的档位禁止选择、记录和输出，仅保留禁用资料；复位持时与未知混合控制宏不开放普通场景入口，不进入亮度滑块或无意录入的效果。
2. 再完成 18 通道灯。按归档说明书补独立发光单元／联动通道，先定契约和能力版本；目标执行器不支持时编译报告定位并拒绝，不靠删通道凑合导出。
3. 编排使用语义属性，档案负责通道、物理量、定制轮盘与修订；替换先审阅能力／范围和受影响场景。不能转换的部分显式提示，不让相同外壳或型号名称决定映射。

验收非零起址、16 位粗细端点、功能边界、全通道默认状态、定制轮盘顺序、导入导出、错误／撤销／保存、两灯替换报告。实灯结果单列；未知厂家参数可标未知并限制相关功能，不能假装完整光学预演。

## H4 一路 DMX 与设备独立运行

接续 [OUTPUT-002](../tasks/OUTPUT-002-dmx-transmission.md)、[MEMORY-003](../tasks/MEMORY-003-large-package-maintenance.md)。本地输入按实际硬件另建限定工单；历史路线 PLAYER-004 只是规划项，当前没有该编号的独立工单文件，不假定已经实施。软件和逻辑 UART 短测已有证据，不重新证明 ESP32 能运行状态机。

| 出口 | 工作与证据 |
| --- | --- |
| 输出状态真实 | 区分发现、连接、安装、载入、运行、逻辑发送／故障；没有物理反馈不写“灯具正常” |
| 差分线路 | 核实引脚／发送使能、连接器／极性、供电和测试负载；按具体授权测 Break／MAB、槽宽、512 槽、刷新及故障／停止。按官方标准与板卡资料测前定容差，不事后放宽 |
| 自主执行 | 正式工程经原编译／下发／安装／激活运行；电脑退出或 BLE 断开继续，重连不自动重放，重启恢复符合已声明能力 |
| 本地输入 | 先核实实际按键／显示／扩展硬件，用统一语义入口提供选择／执行／停止；不能虚构板载显示或 U 盘主机能力 |
| 资源上限 | 最大合法／畸形包、累计预算、解析／安装期限、完整栈高水位、内部堆／PSRAM 分开及长期稳定性 |
| 故障恢复 | 中断、坏包、掉电、旧／重复命令、忙状态、维护静默；半包不覆盖当前可运行版本 |

首版至少 8 小时工程压力记录，覆盖所选灯型与真实 DMX；这是工程起点，不是寿命认证。没有波形／DMX 测量条件时写明缺项，不用日志、绿灯或主机时间代替差分测量。实灯、刷机、部署按用户已有具体授权处理；范围不明再询问，普通只读检查不重复求许可。

## H5 受控试用版本

H1–H4 达到约定范围后集中验收，不无界加功能。三条必过任务：

1. 无音乐剧本：打开工程、配适／分组、预设／场景、人工等待／定时步骤，到现场暂停继续、手动接管／归还；编辑其他场景不误改输出。
2. 音乐片段：资源定位、灯光片段／渐变／循环、任意定位、内嵌预演及保存重开；素材丢失错误可定位可恢复，不清空工程。
3. 脱机盒子：明确能力、导出／下发、激活／独立运行、断线重连、停止／维护／重启，状态与实际测量一致。

从干净入口用正式 .app 和独立副本执行，覆盖失败重试、取消、撤销重做、搜索／选择保持、键盘焦点和笔记本尺寸。基础编排不依赖 UE；专业三维发行配置须能在无 UE 编辑器的客户环境运行。未过打包门槛仅称内部开发／受控试用，不能宣传完整客户预演已交付。

发布清单包括准确版本、支持灯型／模式／板卡、容量、真实输出状态、安装／恢复、已知问题、回退路径、日志入口和开源／素材许可证。检查干净安装／升级开旧工程、卸载保留用户工程；H7 生产保护未过前不能声称生产授权已完成。

请未参与开发的灯光师实际完成这三条任务并记录卡点；自动化测试不能替代。只在出口完成后上调进度，不以按钮数、提交数或测试条数计算百分比。

## H6 专业能力扩展

首版闭环后按实际收益择序，每项先小范围验证：

- 效果：更多属性模板、复杂路径／录制、速度主控、跟踪和释放渐变；云库前先有稳定的本地导入导出模板。
- 编排：人工／音乐混合段落、多轨贡献与冲突规则、外部时间码。先定时钟所有者、定位是否重放离散动作、迟到／重复规则，再做 UI。
- 场地：异形座区、混合变换、墙洞／高度、模板与性能；不扩成通用 CAD。位置／校准在核心，UE 做交互投影。
- 预演：图案／棱镜／光圈等真实能力、光束遮挡／烟雾、性能预算、GDTF／MVR 有界导入和兼容报告。先用官方格式与合适库，不承诺导入即支持全部灯具。
- 音视频／互动：外部播放监看适配、能力发现、准备／回执、媒体时间映射，先一种真实提供方。电机／激光安全和故障边界独立，不与普通 DMX 渐变混同。

## H7 云端与生产商业保护

沿用 Fastify＋PostgreSQL＋对象存储。先做身份、工程／灯效版本目录、不可变资源、权限审计、断点取得和内容校验；下载进入既有 Delivery→Install→Activate 链。媒体存对象存储，数据库保存索引、关系和版本，大资源不塞 JSON。

独立 ADR 明确设备身份、信任根、密钥轮换／恢复、签名／加密、固件更新、离线交付政策，优先成熟实现。旧 24 小时规则已取消；开发令牌／TLS 测试不是生产方案，不承诺无法逆向。ESP32／ARM 的硬件保护分别验证，不提前烧不可逆熔丝。

云不可达时，本地已准备节目按已选策略执行；U 盘和网络共享内容身份，不形成权限旁路。未定商业规则不阻塞本地编辑与执行，不预建空微服务。

## H8 多端与设备产品化

先选一个真实目标端到端验证，再扩展：

1. ARM：复用无界面宿主，按需组装音频／有线／存储；实测调度、掉电、重启，Mac 结果不能替代。
2. 手机平板：复用命令／业务组件，适配权限、发现、文件、音频、触控。浏览器蓝牙／iOS 能力先实测；原生桥或局域网网关按限制选择，不假设 MAC 地址跨端稳定可得。
3. 控制面：推子／旋钮／按键映射、反馈、软接管／拾取、控制权与断开行为，先验证一个实际设备。
4. 一体控台：按能力组合编辑、执行、渲染与控制面，单独验证启动恢复、热保护和现场故障；主备与多机协作另立协议任务。

## 验证命令和证据

从仓库根执行，保持项目内缓存／日志。按改动选用，不是每次文案修改全部运行；先看锁文件，不为交接升级工具链。

export TMPDIR="$PWD/tmp"

可选 HTTP、纯灯光应用按[开发方法](../README.md)追加特性检查；UE／Xtensa 按原工单可复现命令，不猜参数。固件须交叉构建，主机通过不够。缺依赖单独处理，不删除 locked／offline 来掩盖已有验证状态。

长作业保留同一会话等待，不因无输出重复启动；不要同时在同一目录做会替换正在测试可执行文件的不同特性构建。保留失败日志，查原因后按影响重验。旧音频锁／准备竞争有过偶发记录，重跑通过不等于根因修复，不删测试或降低断言。

提交前检查完整差异、依赖和文件职责，近 300–400 行评估拆分，超过 500 行写理由或拆分，不压缩排版规避。产物只进项目，不批量 git add . 把 output/、日志或用户工程纳入。
