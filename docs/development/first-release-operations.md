## 试用前与三条路径

先备份工程及音乐资料，核对实际候选版本、灯具模式与地址。普通编排不允许声控、自动自走或未知危险宏，不能用原始通道值绕过保护。通用测试灯型与画面不能替代厂家档案或实灯验收。

| 任务 | 最短工作流与观察点 |
| --- | --- |
| 无音乐剧本 | 场景编辑 → 执行步骤 → 工程检查 → 保存重开。音乐可选；场景、延时／渐变与人工推进不依赖音乐或三维。编辑、离线预演和现场执行分开。 |
| 音乐片段 | 音乐时间线 → 导入／恢复原音乐 → 片段和正式循环区段 → 工程检查 → 保存携带素材 → 明确准备与播放。波形显示不是正式时钟；三维只观察已有权威输出。 |
| 脱机盒子 | 工程中选择场景／列表 → 生成播放包 → 单独核验安装权限与结果 → 明确激活／运行。安装成功不表示已播放或 DMX 合格；音乐及卡点不在盒子包内，接线／差分／实灯／长期门槛仍开放。 |

三条任务仍须未参与开发的灯光师在最终版本独立完成，本表不替代验收。内部验证先用软件 DMX；本说明不授权实灯、刷机、部署或更改系统权限。

## 无音乐剧本：编排与软件后台

1. 核对“灯具”的模式和配适地址，在“场景编辑”选灯，可记录灯组、记录预设并按需要保持场景引用。预设改变会影响引用，独立值与引用不要混同。
2. 在“执行步骤 → 步骤编排”选择场景，精确设置延时／渐变和“推进方式”。人工等待须明确执行下一步；定时等待从渐变结束后开始。可填写幕／场、台词或动作提示；非法时间会定位报错，先改正或取消，再应用。
3. 检查工程、保存，关闭重开确认内容。音乐为可选；“未使用音乐”不是失败，不能为了无音乐任务伪造空音乐资源。
4. 软件验收进入“执行视图 → 后台执行”，勾选明确的列表，再“载入所选节目”。这只准备固定版本，不自动播放或抢控制。明确“取得控制权”和“执行所选”后，按当前／下一步骤观察人工等待、定时转场及暂停／继续。
5. “打开手动编程”使用后台固定灯具，精确设置后明确应用。亮度零值仍持有，须“释放所选属性”才归还；页面切换、取消草稿和归还控制权不等于停止。另一个编辑场景的应用不替换运行版本。
6. 软件验收结束先“停止”该列表、释放需要归还的手动属性，再“关闭后台”并确认。实际现场输出另需设备／安全资格，不能用软件回执代替差分或实灯。

## 报表与脱机节目交接

1. 在“工程”导出“配灯表（CSV）”，包括全部灯具的模式／地址、空间／安装位置与灯组；选择列表后导出“节目单（CSV）”，逐步核对幕场、提示、延时／渐变和推进方式。手动等待为空，不能理解为自动立即推进。CSV是人类交接资料，不是可回导工程或设备输入。
2. 在“播放包”明确勾选场景或完整列表；分页、搜索不会自动取消隐藏的已选节目，注意“包含筛选外节目”。“生成播放包”后核对节目清单、输出线路与容量，再“另存播放包”。取消不会导出文件，错误或损坏的已有目标会拒绝，使用新文件名，不随意覆盖工程或唯一原包。
3. 导出包含已应用但未保存的编辑，不能以文件名或保存修订相同认定内容相同。编辑／草稿或选择变化后先重新导出报表、重新生成包；旧回执保留来源，不代表当前内容。交接时一起记录工程身份、来源保存修订和对应摘要。报表摘要使用保存编码，播放包“来源快照”使用有序紧凑编码，因此同一内容的两值不同；不要跨种类直接比摘要。包自身完整性摘要也不同于整文件SHA256，均不是商业签名／安装许可。
4. 包只包含所选灯光节目；音乐、卡点和音乐时间线渐变不随包导出。软件校验通过只代表包可编译，安装仍须设备权限与结果核验，安装／激活／运行／发送完成分开。当前无设备的内部试用只做文件核验，不能宣称真实盒子已安装、已播放或物理DMX合格。

[DESKTOP-010](tasks/DESKTOP-010-native-handoff-exports.md)已在准确内部候选验证上述有限软件交接段：取消、错误目标保护、跨页／筛选上下文、未保存版本及旧结果失效，两快照报表逐字段／字节、原生包与Rust编译一致，并使用现有读包／文件安装／虚拟重放范例对照。列表范例停在首步人工等待，完整剧本推进沿用DESKTOP-008证据；不替代表格应用兼容、实际设备权限／接线／差分／实灯／掉电／8小时或独立灯光师任务。实际产物 `data/DESKTOP-010/`、日志 `logs/desktop-010-*`，原候选和来源工程保持。

## 工程、草稿与保存

打开工程不自动执行，最近工程是路径索引而非备份。未应用的输入框草稿与已应用但未保存的编辑要分开：明确应用或取消，不能把草稿显示当成落盘。工程事务沿用撤销／重做；播放定位、音量和输出总控不因此成为工程历史。

保存音乐工程时，先核验和归档音乐，再写工程 JSON。缺失／内容变化会报错，不能拿原“已保存”标签当成本次保存成功。保留错误和原文件，恢复资源后再保存；不要手改摘要或用同名歌曲替代。

跨机器或备份时携带工程文件与同名目录，例如：

```text
演出.project.json
演出.project.json.assets/
  <音乐内容摘要>.wav
```

`.assets` 附在工程文件全名后，不是另取短名。改工程文件名时，随附目录须对应改名，之后重新检查。音乐原文件还应另有备份，缓存不是唯一档案。

## 音乐丢失：按顺序恢复

1. 进入“工程 → 检查工程”。灯光编译、音乐资源和设备发布分别报告；编译通过不代表音乐可用，也不是音频输出测试。
2. 若“本机使用”找不到音乐，点“前往音乐”，选择“重新定位音乐”。选择原内容 WAV／MP3／FLAC，不只比文件名；同格式但不同内容会拒绝，取消不会替换工程音乐。
3. 成功准备后波形出现，仍是暂停。未明确点“播放音乐”不应发声。开声前调低音量；有双重声音、卡顿或杂音立即停止、保存现场信息，不盲目重复播放。
4. 返回工程“重新检查”。准备音乐不修改工程，先前报告可能仍是旧的检查时结果，必须显式刷新。本机文件完整而随附缺失时，点“保存并补齐”。
5. 保存后旧报告标为“报告已过期”，再“重新检查”；确认两份资源完整后关闭，从最近工程重开，保持暂停，核对片段、循环和工程内容。

[DESKTOP-007](tasks/DESKTOP-007-native-resource-recovery.md)已在正式内部桌面实际执行：缺失另存拒绝且原文件不变、定位取消、错误内容拒绝、原文件暂停恢复、补齐、报告失效／刷新及退出／最近重开。没有播放声音、启动执行后台／三维或操作设备，不能写成听感、崩溃恢复或客户安装通过。

支持单／双声道、8–192 kHz、最长一小时、最大 512 MiB，缓存上限 4 GiB。缓存清理界面未交付，触及上限应保留错误并安排受控整理，不随意删除唯一音乐；详见[音乐契约](../module-api/audio-editing.md)。

## 未保存工程恢复

顶部“恢复”或欢迎页“恢复工程”进入恢复中心。保护已应用的有效编辑，不含未应用草稿、撤销栈、选择或播放进度；音乐身份与编排可保留，外部素材不在检查点内。

仅选择“可以恢复”记录恢复为副本，来源文件不自动覆盖。新副本须另行保存，音乐缺失仍按上节恢复；不自动播放。“窗口使用中”不可抢占，损坏记录不冒作成功。不要随意丢弃唯一副本。保护失败要留错误，原编辑不因检查点失败自动撤销；详见[恢复契约](../module-api/project-recovery.md)。

DESKTOP-007仅核对只读入口；后继[DESKTOP-008](tasks/DESKTOP-008-script-recovery-acceptance.md)对已关闭后台的新独立工程作了一次受控异常退出，实际验证已应用内容恢复、未应用草稿排除、无保存目标副本及新路径保存，原文件保持。不是自然崩溃、运行容灾、其他平台或客户安装资格；未丢弃其他历史记录，也未测试独立永久丢弃。

## 运行异常与反馈

音乐停止、控制权释放、零值与熄灯不是同一动作；退出三维不等于停止演出后台。后台已运行时，先明确停止对应来源，再按现场入口关闭所属后台；不要强制结束未知进程代替应急操作。真实输出应急和差分行为须现场另验。

记录候选／工程版本、问题时间、编辑还是执行、明确点击的操作、错误文字或截图、音乐文件名、设备连接状态及是否已停止。不要发送授权令牌、私钥或未脱敏的工程／后台目录。

当前内部实例运行日志在 `tmp/desktop-desktop-release-qooqnJ/logs/`；音乐资料与无音乐剧本验收日志分别在项目 `logs/desktop-007-*`、`logs/desktop-008-*`，证据分别在 `data/DESKTOP-007/`、`data/DESKTOP-008/`。保留原始失败，不用一次成功覆盖旧记录。工程、素材独立备份，日志不是恢复副本。

剩余：恢复／自然结束人耳确认、历史原生拒绝及音频预留偶发根因、实际灯型未知范围／光学、差分／实灯／完整最坏组合／8小时、客户 Shipping／权限签名／最低系统、全产品许可和独立灯光师任务。内部包复制不替代干净安装／升级／回退，客户环境资格仍未取得。
