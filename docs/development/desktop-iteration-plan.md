# 编排端迭代计划

更新：2026-09-24。依据 [ADR-006](decisions/PRODUCT-ADR-006-visible-desktop-increments.md)、[ADR-007](decisions/PRODUCT-ADR-007-effect-editing-first.md) 与修订后的 [ADR-008](decisions/PRODUCT-ADR-008-ipad-primary-authoring.md)。当前围绕 MacBook 设计、开发和验收；未来 iPad 主力定位只作为架构与交互的适配准备。用户暂无 iPad，移动宿主／触控布局不作为当前前置任务。Rust 工程模块不依赖 Tauri、操作系统或设备。

原则：每轮交付一个真实操作闭环，直接在实际数据和文件上迭代。正式入口不放预置节目、演示状态、教学展板或尚未接通的按钮。设计稿、测试夹具和技术说明留在开发资料中。

| 顺序 | 用户可以做的事 | 完成条件 |
| --- | --- | --- |
| 1：DESKTOP-001 | 新建工程、添加／配适灯具、创建场景并修改属性、撤销重做、保存／重开 | 已实施灯光编辑子集；真实 .app 与文件验收；错误不破坏已保存内容 |
| 2：UX-006 | 确定舞台选灯、效果塑形与时间编排的主工作流 | 按 MacBook 收敛[总体框架与共同指向](../ui-design/workspace-framework.md)，验证整组光束持续跟随目标的操作关系；设计稿不扩展产品业务层 |
| 2a：UX-007 | 定义舞台和观众区如何创建 | [平面布置／三维同步设计](../ui-design/venue-layout-design.md)已形成：尺寸化舞台、区域生成观众、过道联动；未实施产品建模 |
| 2b：FIXTURE-001 | 定义可复用灯具功能、个人灯库与建档交互 | [灯具定义设计](../ui-design/fixture-definition-design.md)已形成，参考 MA3／Titan／GDTF；具体格式扩展和编辑器尚未实施 |
| 2c：UX-008／009 | 检查完整功能的归属、空间及组件交互 | 三张结构图保留参考；[组件工作台](../ui-design/component-workspace-design.md)已验证按需展开、建档往返和上下文保持，收集操作反馈后逐步接入真实能力 |
| 3：编排界面接入（实施前单独建工单） | 在新工作区使用已有真实编辑能力，验证选择与属性联动 | 小范围完整操作；保持保存／撤销；没有假执行或为填满布局而造的功能 |
| 4：PROJECT-001 后续 | 编排场景列表，设置渐变／延时；接入时间线和小范围效果编辑 | 精确领域契约与命令先审查；拖动一次产生一个可撤销修改；保存重开含义不变 |
| 5：PLAYER-001 | 播放／暂停离线预览，定位节目时间，查看实际生成的通道数值 | Rust 权威时钟与执行结果；预览与现场输出有独立控制边界 |
| 6：PLAYER-002–005 | 选择片段、编译、下发，在现有 ESP32 上独立选场景和播放 | 1 路真实 DMX 时序／稳定性、掉电恢复、离线运行及本地操作验收 |

音视频参考、波形卡点和灯组／预设的直接编辑随真实编排流程逐步加入；使用相同工程身份与版本体系。未来进入 iPad 阶段再建立移动宿主、真实文件、触控、生命周期和预览预算的验证工单，当前不前置。云端存储、手机与远程控制通过宿主适配接共享核心，不复制工程语义。授权商业门槛仍按 AUTH-001 执行；播放盒已激活节目不依赖控制端持续在线。

UE 专业预演和空间搭建作为[效果编辑工作区](../ui-design/effect-editor-design.md)的舞台视图扩展。先保留稳定对象和编辑命令边界；待独立工单验证原生进程、运行时交互、加载与性能后再接入。它不替代 Rust 效果计算，也不成为普通编排或 ESP32 播放的前提。

共同指向是三维设计首要验收任务：目标点拖动时整组光束持续跟随，而安装位置不变。实际实现按空间观察／摆位、目标与校准契约、Rust 指向求解逐步接通；先固定目标和手动拖动，再做路径与关键帧。当前设计稿只验证理想指向关系，不构成真实运动学或输出实现。

空间创建按 UX-007 的小闭环另立实施工单：矩形舞台／台高、站席或直排坐席区、过道避让、二维／简化三维一致和真实保存。场地参数、生成规则与版本契约先审查；复杂看台、扫描和 UE 精细渲染后续展开。用户日常无需先进入游戏引擎编辑器搭场地。

灯具建档按 [ADR-009](decisions/PRODUCT-ADR-009-fixture-definition.md) 先审查可复用能力、模式、功能区间及版本契约，再接真实编辑器；从亮度／RGB 建档、保存复用和离线编码核对开始，随后扩展常见摇头灯。复杂灯具与共同指向实施前补齐对应档案能力，不能只在 UI 增加字段后交给当前线性编码器。受控实灯测试等待输出仲裁和停止机制；不把完整 GDTF 导入、云端灯库或预演模型列为基本建档前置条件。

每轮用户反馈围绕实际任务：添加灯具是否顺手、配适错误是否容易修正、场景选择和参数是否清楚、时间线是否跟手、保存状态是否可信。优先修正阻断任务的问题，再扩展下一块。原时间线交互代码和 15 项回归测试保留，正式入口接入前不显示模拟执行。
