# 编排端迭代计划

更新：2026-09-23。依据 [ADR-006](decisions/PRODUCT-ADR-006-visible-desktop-increments.md)、[ADR-007](decisions/PRODUCT-ADR-007-effect-editing-first.md) 与最新 [ADR-008](decisions/PRODUCT-ADR-008-ipad-primary-authoring.md)。iPad 为未来主要编排终端，触控优先设计；macOS 是当前开发及已有验证入口。Rust 工程模块不依赖 Tauri、操作系统或设备。文件路径保留供既有链接使用。

原则：每轮交付一个真实操作闭环，直接在实际数据和文件上迭代。正式入口不放预置节目、演示状态、教学展板或尚未接通的按钮。设计稿、测试夹具和技术说明留在开发资料中。

| 顺序 | 用户可以做的事 | 完成条件 |
| --- | --- | --- |
| 1：DESKTOP-001 | 新建工程、添加／配适灯具、创建场景并修改属性、撤销重做、保存／重开 | 已实施灯光编辑子集；真实 .app 与文件验收；错误不破坏已保存内容 |
| 2：UX-006 | 确定舞台选灯、效果塑形与时间编排的主工作流 | 三张桌面候选作参考；按 iPad 主力定位收敛触控布局，具体设备／视觉待反馈；不扩展业务层 |
| 2a：移动宿主验证（实施前单独建工单） | 用 iPad 完成最小离线工程操作与触控验证 | 同一 Rust 模块、真实保存重开、文件导入导出、生命周期、触控输入与本地预览预算；尽早暴露平台限制 |
| 3：编排界面接入（实施前单独建工单） | 在新工作区使用已有真实编辑能力，验证选择与属性联动 | 小范围完整操作；保持保存／撤销；没有假执行或为填满布局而造的功能 |
| 4：PROJECT-001 后续 | 编排场景列表，设置渐变／延时；接入时间线和小范围效果编辑 | 精确领域契约与命令先审查；拖动一次产生一个可撤销修改；保存重开含义不变 |
| 5：PLAYER-001 | 播放／暂停离线预览，定位节目时间，查看实际生成的通道数值 | Rust 权威时钟与执行结果；预览与现场输出有独立控制边界 |
| 6：PLAYER-002–005 | 选择片段、编译、下发，在现有 ESP32 上独立选场景和播放 | 1 路真实 DMX 时序／稳定性、掉电恢复、离线运行及本地操作验收 |

音视频参考、波形卡点和灯组／预设的直接编辑随真实编排流程逐步加入；使用相同工程身份与版本体系。iPad 提供本地编排能力，云端存储、手机与远程控制通过宿主适配接共享核心，不复制工程语义。授权商业门槛仍按 AUTH-001 执行；播放盒已激活节目不依赖 iPad 保持前台运行。

UE 专业预演和空间搭建作为[效果编辑工作区](../ui-design/effect-editor-design.md)的舞台视图扩展。先保留稳定对象和编辑命令边界；待独立工单验证原生进程、运行时交互、加载与性能后再接入。它不替代 Rust 效果计算，也不成为普通编排或 ESP32 播放的前提。

每轮用户反馈围绕实际任务：添加灯具是否顺手、配适错误是否容易修正、场景选择和参数是否清楚、时间线是否跟手、保存状态是否可信。优先修正阻断任务的问题，再扩展下一块。原时间线交互代码和 15 项回归测试保留，正式入口接入前不显示模拟执行。
