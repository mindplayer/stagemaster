# 桌面端迭代计划

更新：2026-09-23。依据 [ADR-006](decisions/PRODUCT-ADR-006-visible-desktop-increments.md)。当前以 macOS 验收，Rust 工程模块不依赖 Tauri、操作系统或设备。

原则：每轮交付一个真实操作闭环，直接在实际数据和文件上迭代。正式入口不放预置节目、演示状态、教学展板或尚未接通的按钮。设计稿、测试夹具和技术说明留在开发资料中。

| 顺序 | 用户可以做的事 | 完成条件 |
| --- | --- | --- |
| 1：DESKTOP-001 | 新建工程、添加／配适灯具、创建场景并修改属性、撤销重做、保存／重开 | 已实施灯光编辑子集；真实 .app 与文件验收；错误不破坏已保存内容 |
| 2：PROJECT-001 后续 | 编排场景列表，设置渐变／延时；把已认可的时间线操作接入真实工程 | Rust 领域校验与命令先行；拖动一次产生一个可撤销修改；保存重开含义不变 |
| 3：PLAYER-001 | 播放／暂停离线预览，定位节目时间，查看实际生成的通道数值 | Rust 权威时钟与执行结果；模拟预览与现场输出有独立控制边界 |
| 4：PLAYER-002–005 | 选择片段、编译、下发，在现有 ESP32 上独立选场景和播放 | 1 路真实 DMX 时序／稳定性、掉电恢复、离线运行及本地操作验收 |

音视频参考、波形卡点和灯组／预设的直接编辑随真实编排流程逐步加入；使用相同工程身份与版本体系。云端存储、手机／平板与远程控制接宿主适配和共享核心，不复制工程语义。授权商业门槛仍按 AUTH-001 执行。

每轮用户反馈围绕实际任务：添加灯具是否顺手、配适错误是否容易修正、场景选择和参数是否清楚、时间线是否跟手、保存状态是否可信。优先修正阻断任务的问题，再扩展下一块。原时间线交互代码和 15 项回归测试保留，正式入口接入前不显示模拟执行。
