# PRODUCT-ADR-126：执行应用按能力组装音频后端

状态：accepted，本项实现与软件验证通过，整体 FRAMEWORK-001 仍在验收。2026-10-03；基线 `8464d8a`，main。

## 整体验收发现

通用 Runtime／Host／LiveBackend 没有声卡依赖，但 `apps/execution-host/Cargo.toml` 固定依赖 stagemaster-audio 和 Rodio。即使只组装灯光执行应用，仍会带入解码／声卡库。运行时不打开声卡不等于构建时可以去掉模块，尚未落实 ADR-100 的按设备能力组装。

采用 [Cargo 官方可选依赖与 features](https://doc.rust-lang.org/cargo/reference/features.html)；默认能力保留，新增能力是加法，不复制另一个执行程序或播放器。Cargo 会合并依赖特性，因此纯灯光验证必须单独选择此包并禁用默认特性，不能用整个桌面工作区构建证明无音频依赖。

## 决定与兼容

1. 执行应用增加 `audio` 特性，默认启用，维持桌面及现有完整后台行为；纯灯光以 `--no-default-features` 组装，音频／Rodio 为可选依赖，通用时间与多来源语义保持。
2. 共用 CLI、场景／列表准备、来源组、应用会话、控制权、工程投影和软件采样。音频组装职责从通用准备中拆出，音频所有者仅在启用后端时存在。无需增加动态插件框架、第二套协议或工程格式。
3. 纯灯光版本明确拒绝音频来源清单、媒体操作及声音输出范围参数，不忽略音频内容或伪报播放成功；只发布实际支持的能力。未来其他媒体／外部系统按自己的能力接入。
4. 桌面打包显式启用 `audio`，避免前一次纯灯光构建产物被错误复制进桌面。默认验证保留全部音频测试；纯灯光单独运行真实进程、旧来源／控制／观察用例和不支持能力的拒绝用例。
5. 不修改灯光／音频的执行、时间、许可、控制权、包格式或现有 HTTP v1／v2 语义。无物理声卡／DMX、板卡或 UE 操作；不将当前 macOS 构建宣称为 ARM／Windows 已通过。

实际桌面准备脚本同时按生效的 `CARGO_TARGET_DIR` 读取后台构建产物，避免构建在隔离目录、复制却读到默认目录旧文件。默认仍使用项目 target；本轮在项目 tmp 隔离目录实测构建、复制摘要相同，且桌面后台含 CoreAudio。此处属于产物选择修复，不修改产品运行协议。
