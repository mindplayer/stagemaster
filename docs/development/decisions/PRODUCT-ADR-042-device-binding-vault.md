# PRODUCT-ADR-042：设备绑定凭据与持久提交

日期：2026-09-29；状态：接受实现，板级集成待验收；DEVICE-002B，基线 `d8692f3`，主工作区，当前会话单一写入。

## 问题与决定

LE Secure Connections 在本机完成认证和同启动重连，但绑定仅在 RAM，广播身份也随启动变化。正式业务会话须先具备稳定本机身份、持久绑定及明确撤销结果。公开设备描述、主机传入的主体编号和普通加密均不产生安装权限。

新增独立 Rust `stagemaster-device-auth`，先实现有界绑定档案、严格编码和可选持久存储适配；不绑定 UI、trouble-host 或具体 ESP32。最多四个绑定，各自持有随机主体标识、对端身份地址／可选 IRK 和 LESC LTK；只由可信蓝牙适配层在已认证绑定完成后构造。记录本机随机静态地址与 IRK，设备重启不再更换已初始化身份。私密字段禁止派生 Debug／Serialize，缓冲和凭据离开作用域清零；不是生产 Flash 加密或防逆向实现。

借鉴 [trouble-host 0.8.0](https://docs.rs/trouble-host/0.8.0/trouble_host/) 的 BondInformation／add_bond_information，复用栈的配对、身份解析和密钥持有证明，不实现密码协议。对照 [sequential-storage](https://github.com/tweedegolf/sequential-storage) 与 [EKV](https://github.com/embassy-rs/ekv)：前者适合少量普通配置但会忽略损坏项；绑定撤销不能依赖该回退语义。选 EKV 1.0.0 的原子事务及 CRC 错误传播，接受少量记录下额外的空间和页擦除成本。依赖严格锁定，故障注入验证其在本项目中的实际边界，不能只引用上游保证。

## 持久边界

固定格式采用 4 KiB 页、4 字节对齐、32 页数据库、256 字节块、CRC；额外一个 4 KiB 格式页，总长 132 KiB。格式页标识全部影响磁盘格式的编译配置；挂载前核对，禁止不同配置静默打开。库版本和格式变更须单独迁移，不自动格式化旧／损坏分区。板卡最终分区位置另核对，不能使用本文件的尺寸猜测写入地址或覆盖现有节目区。

首次初始化只接受完整擦除的专用区域，由可信宿主显式调用；数据库和初始身份写成后最后写入格式标识。中途失败保持不可用，由明确的本地恢复流程处理，不自动重建身份。撤销以新一代完整档案提交，不能只从蓝牙栈 RAM 删除。

每次变更先撤回内存档案的可用性，完整写事务提交后再读取校验；失败、取消或提交回执丢失均保持待恢复，不能继续用缓存的旧权限。恢复时只认持久结果，回执不确定不等于操作未发生。只在成功回读后报告新增／撤销成功。所有 Flash 操作须位于已有存储执行器及允许的维护窗口，不在无线回调内擦写；取消 UI 等待不取消已开始的实际写任务。

锁定源码审查发现 EKV 挂载时逐页探测元数据，对候选页的底层读错误可能跳过。因此适配器另外锁存物理 I/O 错误，恢复或提交出现任何此类错误均拒绝暴露档案，显式成功恢复后才可再用；不能仅以库返回了某个有效快照认定安全。故障试验已覆盖这一规则。CRC 仅检测损坏，不能证明防恶意整区回放；本模块负责自有 Secret／编码缓冲清零，不承诺清除第三方库的全部内部缓存或编译器临时副本。

## 后续集成和验收

独立测试涵盖非法／未知编码、重复主体／身份、日志脱敏、空白初始化、重开、撤销、提交不确定、逐存储操作断点、部分写／擦、CRC 损坏和配置不符；目标 Xtensa 构建验证资源。随后组合栈绑定导入／移除、物理准入／尝试限制、连接随机业务会话与旧连接撤销，再进行真实重启与认证后的 GATT 安装验收。新模块或软件测试通过不代表这些后续动作已完成；现行用户连接和节目内容保持。
