# PRODUCT-ADR-131：原生设备服务的运行连接

状态：accepted，本增量已实现并验证。2026-10-03；基线 `8d0d093`，main；DEVICE-003 第五增量，当前会话单写者。上一目标回合已实现、验证并提交共享客户端，分类为 progress。

## 问题与决定

现有 Service／Ble 的连接自动准备安装会话，不能靠设备的播放能力把安装连接当成运行连接。复用 ADR-130 的 RuntimeClient、既有 GATT 记录收发及 Service 取消／清理，不另建连接管理器或播放器。

1. 新增显式原生 `connect_runtime`，与原 `Request::Connect` 安装／诊断路径互斥；预期范围必须包含观察权限，连接时不取得控制权、不执行、不进入维护。旧凭据仍只提供身份核对，服务端必须独立授权；不升级旧固件。
2. Transport 增加类型化运行准备、就绪、发送及收取适配，默认拒绝运行。Ble 的运行适配拥有已有 RuntimeClient，复用 GATT 记录与诊断保活；不创建系统蓝牙配对，不按公开描述授予权限。
3. Service 通过原后台任务串行处理运行调用；单个调用槽，业务回复与连接故障分开。心跳在等待回复时继续，30 秒总期限不因排队／保活刷新。取消发送后的调用关闭连接，未发送的排队调用可以撤回；重连没有自动命令重放。
4. 原生运行快照区分当前就绪、待确认意图、最近历史回复。发送前登记意图；断线清除就绪但保留不确定意图与历史回复，供后续桌面如实展示。开始新连接清空前一连接记录，epoch 拒绝旧操作。诊断在线不等于运行就绪或物理输出。
5. 限定 device-host、必要本地依赖、集成测试及文档；不提前接桌面按钮或公告固件能力。测试用同一真实共享客户端、安全会话及原工作器，通过软件承载驱动 Service；实板运行队列／独立调度和真实 DMX 仍为后续出口。

接线复核：旧安装服务在安全确认后主动打开安装工作器并发送 SMAP 就绪，因此不能在同一入口等待后续消息再猜测运行意图。本增量为运行选择独立 GATT 服务 `f889edb0-0100-4e83-968e-799ab99558fa`，写入／通知分别为同族 `edb2`／`edb3`；安装 `eda0`／`eda2`／`eda3` 保持。二者复用同一记录适配和安全分片实现，按服务和特征共同过滤通知；没有运行服务时明确拒绝，绝不退回安装握手。设备发现仍使用原诊断服务；固件未来须显式接入并公告新能力。

## 验证

原安装／诊断回归、运行连接与旧 epoch／互斥、目录到执行、调用取消／超时／业务失败、保活与断线自主运行、重连只读均需证据。原生 BLE 在本轮编译与边界检查，软件承载测试不能代替射频／实板验收。新增文件按职责拆分，不增加第三方依赖或修改工程／设备包／密钥配置格式。

最终 96 项相关 Rust 回归通过，含 8 项原生运行服务集成及 1 项通知路由隔离新增测试；全工作区全部目标严格 Clippy（application）通过。新增文件低于 300 行，原 Ble 的物理连接抽为独立模块。生产仅增加已有 runtime-protocol 的直接依赖，三个本地模块及既有 Tokio net 特性仅用于测试；无第三方升级。详细证据见 [DEVICE-003](../tasks/DEVICE-003-remote-runtime.md#第五增量原生运行连接服务)，调用与 UUID 见[契约](../../module-api/native-device-runtime-service.md)。本增量不修改固件、不启动蓝牙、不接桌面按钮；完整任务仍开放。
