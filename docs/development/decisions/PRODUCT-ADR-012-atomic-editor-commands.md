# PRODUCT-ADR-012：批量编辑与场景复制

日期：2026-09-24。状态：已评估，实施于 DESKTOP-002。基线 `0cce099`。

用户要求以持续目标模式丰满正式工作台，同时吸收成熟软件的小功能和操作细节。现有逐灯逐属性命令无法保证多选编辑、RGB 取色和批量配适的一次撤销与失败回滚。

## 决定

- Rust `EditCommand` 增加 `batch`，包含 1–256 个基础命令，禁止嵌套。先在工程副本顺序应用，再校验最终工程，全部成功才替换当前文档。失败不改变文档、历史或会话代次。不逐项提交，也不隐式拆批。
- `duplicateScene { id, name }` 深复制场景，生成新标识，保留全部属性来源、释放操作与扩展内容；原场景和副本分别可编辑。不复制场景列表引用，不改变播放次序。
- 工程只读灯具视图补 `domainId`，空位建议使用稳定输出域标识，不按可重名的显示名称判断。
- 宿主仍用现有会话代次拒绝陈旧编辑。一个批次是一条历史记录，空操作不产生历史。新能力不更改 JSON 文件版本、执行内核、设备权限或 AI 授权。
- 多选只编辑共同属性，混合值明确显示；滑块／百分比改为绝对值赋给全部选中灯具，不暗示相对比例。RGB 操作只改颜色三个属性，不修改亮度。预设引用只在显式修改该属性时替换。
- 本地输入草稿不直接写工程；合法提交后由 Rust 确认。失败保留草稿与选择；切换目标、工作区或文件前完成草稿验证，取消可还原。拖动期间仅本地反馈，结束一次提交，取消不生成历史。
- 批量配适按灯具模式占用连续地址，同一输出域／线路内找空位，无空间则明确报错，不静默换线路。Rust 最终校验为权威。

## 经验与取舍

参考 [Titan 批量配适](https://manual.avolites.com/docs/patching/changing-the-patch/) 的多选、过滤和成组操作；参考 [Ableton 多片段编辑](https://www.ableton.com/en/manual/clip-view/) 的共同属性与上下文，以及[标准复制快捷键](https://www.ableton.com/en/manual/live-keyboard-shortcuts/)。沿用按需属性组件与可取消草稿，暂不实现相对值编辑、完整灯库、空间建模或时间线播放。

## 验收

覆盖中途失败回滚、最终校验失败回滚、地址交换、嵌套／数量限制、复制身份与引用保留、多灯单次撤销／重做、陈旧代次拒绝。原生界面验证批量添加、选灯、混合参数、颜色、复制、搜索、切换保持、错误恢复与保存重开。
