## 实际缺口与成熟经验

现有 A0 Mixer 是分配树／完整诊断轨迹的参考混合器，权重作用于所有属性，零权重即释放；不能直接当成亮度推子。现行 Player 的完整向量包含未编排属性默认值，也不能直接作为多来源贡献，否则未编排颜色会覆盖其他节目。单列表包没有逐属性所有权，当前不更改持久格式或假装已支持设备多执行器。

官方 [MA 播放与优先级](https://help.malighting.com/grandMA3/2.5/HTML/cue_playback.html)区分播放对象／执行操作柄、属性优先级和 Soft LTP；[Titan 播放选项](https://manual.avolites.com/docs/cues/playback-options/)区分亮度推子、全属性跟随、释放遮罩和释放时间。吸收来源／属性控制、推子与释放分离的机制，先定义本项目明确的默认模式，不完整照搬两家不同的行为。

## 决定

在现有 engine 内增设有界 `LiveMixer`，复用 domain 固定点数值与成熟 HTP／LTP 规则，保留原 A0 API／测试。准备时分配索引、固定来源槽和属性缓冲；周期发布、修改电平、释放和求值不分配、不 I/O。当前面向标准系统宿主；不据此宣称 ESP32 适配或硬实时。

- 布局包含属性默认值、HTP／LTP、已识别亮度属性与离散标记；用编译工程完整快照指纹绑定，避免相同向量长度跨工程／配适／修订误用。
- 每来源使用私有句柄及不回绕代际、业务身份／类别、优先级、电平和命令序号。完全属性快照中的 None 表示未控制／释放，Some(0) 表示明确零值；无来源时才回退默认值。
- HTP 在最高有效优先级内取高，LTP 在最高优先级内取最近明确接管的属性值。连续采样只更新数值，不抢占 LTP；新控制属性或显式重新执行／手动修改才能更新该属性顺序。顺序由核心分配，不接受壁钟排序。
- 亮度电平只缩放已识别的数值亮度，颜色、位置与离散功能不被缩放；零电平保留来源所有权，显式释放才归还。全属性交叉、自动关闭、释放渐变后续另行定义，不能把它们悄悄混入普通推子。
- 离散功能只选择完整合法编译值，不加权穿越功能区间；当前拒绝离散 HTP 或离散亮度定义。手动来源仍须经过可信宿主／灯具语义校验，核心的 u16 并不构成任意通道操作权限。
- 失败批次保持原贡献；错误布局、形状、重复／旧命令和已释放句柄明确拒绝。所有权句柄不能作为网络认证或输出端口许可。

首次实际组合采用同一工程的两个动态保持场景与一个手动来源；场景仍使用既有 Player／效果求值，编译显式拥有的属性与启用效果属性。场景未写入和显式释放不贡献默认值。共享属性合成后只调用既有输出编码器，并作为 OUTPUT-001 的单一 Composite 来源。

这一步解决多来源的基础语义，不把所有现场功能一次前置。多步骤列表的跟踪所有权、延时／释放包络、跳步／循环后属性接管顺序须下一项在既有 Player 时间语义上验证；本项不把整份默认向量临时包装成列表贡献，也不另写第二个时间播放器。桌面、独立进程与设备正式接线后续推进。

实现补充：发布／电平命令保留最后序号用于关闭来源，不能因序号耗尽留下无法释放的贡献。合成编码器也绑定同一完整快照指纹并在准备阶段分配缓冲，来源准入与最终编码都拒绝同形状的异工程误接。
