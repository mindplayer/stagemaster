# PRODUCT-ADR-111：独立时钟映射的有界基础

- 状态：accepted，软件基础增量已实现并验证；基线 `b89b3a4`，main，当前会话单写者。
- 关联 [TIME-001](../tasks/TIME-001-independent-clock-boundaries.md)；继承 ADR-052／097 的完整同步组要求，本增量不视为 TIME-001 完成。

## 判断与参考

现有 Live 来源的接管事件与租约都使用宿主单调时间。把音频素材位置直接代入该时间会在定位／循环时倒退，且改变接管顺序和授权有效期。因此先建立可复用的独立时钟测量边界；播放位置和同步组在后续实际调用中接入，不能通过“改 now 参数”兼容。

延续 [GStreamer 时钟分层](https://gstreamer.freedesktop.org/documentation/application-development/advanced/clocks.html) 与 [RFC 5905 时间戳交换](https://www.rfc-editor.org/rfc/rfc5905.html)。本项目复用四时间戳测量原理，输出保守区间，不假设上下行延迟对称。不是完整 NTP／PTP 实现，也不引入新的媒体栈。现有项目未找到可复用的时钟域／代次与受限区间转换实现；新建无依赖、无分配、no_std 的窄 Rust 模块，供宿主和受限设备共用，不自研协议栈。

## 具体约束

1. `ClockId` 为非零 128 位身份，`Clock` 同时携带启动／更换代次；`Instant` 明确为该时钟域的单调纳秒。不能跨身份或代次直接比较，媒体位置不使用此类型。适配层负责由系统计时器换算并报告精度。
2. 一次交换包含来源发送 s1、目标接收 t2、目标发送 t3、来源接收 s4。每一对必须属于同一时钟及代次，且本域时间不倒退。目标应在收到请求后记录 t2、发送响应前记录 t3；响应必须与原请求身份对应，认证／请求关联在承载适配完成，本模块不把数值合法当作对端可信。
3. 目标时钟相对来源时钟的速率漂移上界为显式能力配置 r（ppm），不能从一次交换推断；测量另带四次时间戳的最大采集误差 e。它们是上界条件，不是软件宣称已测得的硬件指标。无限或未知上界不能返回“精确同步”。
4. 以 s4 为基准，目标时间在保守区间 `[t3−e−推进误差, t2+e+ceil((s4−s1+2e)×(1+r))]` 内。额外推进基于本域非负差值，向外取整；实现采用 u128 中间值并检查最终 u64 范围。接口返回最早／最晚时刻及区间中点／不确定度，调用者不能只使用中点而忽略质量。
5. 配置限定一次往返、最大观测年龄及最大不确定度。重复读取不更新时间基准；过期、过宽、错域、倒序、溢出拒绝。映射不可调整任何系统时钟，不续租、不发控制命令、不重放动作。构造失败不改变旧对象，旧对象仍按原有效期失效。
6. 第一个验证增量覆盖不同原点、上下行不对称、目标处理耗时、漂移、采集误差、纳秒取整、身份更换及长时／大数；再以真实工程编译／Player 证明两个时钟下的独立执行。同步组定位、音频采样适配与统一 Live 合成仍需后续增量，纯数学测试不关闭 TIME-001。

本增量不改工程 JSON、设备包、当前 GATT／HTTP 协议或桌面显示。后续发布同步状态前必须明确实际音频时钟是软件消费还是声卡呈现，并完成组内暂停／定位／失联与来源合成验收。

实现结果：7 项时钟专项及完整工作区回归通过；[ADR-112](PRODUCT-ADR-112-media-following-source-groups.md) 已将该映射接入真实媒体来源组与统一合成，原生音频／后台宿主入口继续由 TIME-001 推进。
