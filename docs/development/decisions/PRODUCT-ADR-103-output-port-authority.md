# PRODUCT-ADR-103：单端口输出权与驱动完成边界

- 状态：accepted，软件增量实现／验证；基线 `e5314d5`，main，当前 Astra 单写者。
- 工单：[OUTPUT-001](../tasks/OUTPUT-001-port-authority.md)，承接 ADR-097／100。上轮 TRANSPORT-001 是已提交的实际进展。

## 依据与范围

现有 `Runtime::render` 与 HOST-001 的 Frame 是软件采样；`DmxSink::send` 尚未区分接纳、发送完成和停止清理。设备维护目前依赖宿主真实关闭输出后确认，ESP32 安装镜像始终禁用输出，并非已实现可切换输出端口。

借鉴 [OLA 的设备／端口／线路分离](https://www.openlighting.org/ola/getting-started/using-ola/)与 [ETC sACN 的来源丢失处理](https://etclabs.github.io/sACNDocs/2.0.2/source_loss_behavior.html)：输入来源、合成、物理输出应分别负责状态。这里只复用职责划分，不照搬协议专属超时，也不把本模块称作 Art-Net／sACN 接收器。现有属性混合内核保留，多个执行器和推子先在属性层合成；不对粗细 DMX 字节随意逐字节取最大值。

新增无堆、no_std 的 `stagemaster-output-port`，一个对象独占一个 Driver。可信宿主选择本地执行、外部帧或合成器来源；该选择不授予账号／商业权限。来源切换先撤销旧许可、清除未发帧并要求驱动排空；收到当前停止票据对应的真实静默回执后才发新许可。启动也不假设驱动已静默。

## 契约

- 输入控制权和输出许可分开。控制客户端断线不直接撤销运行器的输出；输出来源停止更新时按显式新鲜度预算关闭端口，恢复须重新选择来源。
- 每来源只保留最新完整 512 槽待发帧，至多一个驱动在途帧。严格递增帧号允许跳号；重放／旧许可／错误线路／未来或过期采样拒绝，不刷新期限。外部时钟须先映射到宿主单调时间。
- Driver 的提交只代表接纳，单独报告完成或开始前过期丢弃；它必须有界、非阻塞，实际开始发送前再次检查有效期，不暗中无限刷新或积压旧帧。停止必须禁止新发送、清理队列并结束在途操作，才报告静默。回执关联启动、端口与不回绕票据，旧回执不能恢复新来源。
- 主机轮询处理有固定事件预算。帧完成／静默回执都有固定等待期限；驱动故障、时钟倒退或票据耗尽撤销许可并尝试关闭，不伪报静默或自动复活。源超时关闭后可以显式重新取得输出，驱动故障需独立恢复。
- 停止发送、节目 Stop 恢复档案默认值、全场黑场和机构急停是不同动作。端口静默不能推断灯具熄灭，也不把全零帧作为所有设备的安全状态。
- 驱动确认静默且无可发送来源时，宿主可在同步闭包内执行维护确认；不能把旧回执或尚未执行的 Future 当维护许可。

现有桌面、固件及 DmxSink 入口保持。先用软件驱动与真实 Runtime 采样贯通，验证本地到外部的切换和维护边界；不刷机、不发送真实 DMX。物理驱动要分别验证电气时序、队列、看门狗和真实停止，不能靠 trait 文档宣称已达成。

实现细则：两个预算显式为 1～60,000 ms；每次轮询最多 4 回执／1 提交。采样时间在当前许可内也不倒退；最终票据保留给关闭，计数／时间溢出不能继续获权。维护闭包只返回 `()`，不返回 Future。实际状态与调用见[契约](../../module-api/output-port.md)，物理适配的完成／停止与独立看门狗仍须分别验收。
