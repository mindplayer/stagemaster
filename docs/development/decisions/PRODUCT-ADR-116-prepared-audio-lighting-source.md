## 证据与取舍

现行后台 `SourceSpec` 只能选择设备包中的场景／列表；桌面 `AudioPreview` 则按 `AudioTimeline::lighting_at` 选择灯光片段，在片段变化或回退时调用 `Document::compile_audio_segment`。后者已经处理历史渐变、效果偏移、动态交叉和切片。直接把音源放进后台却只运行一个测试列表，会丢失真实产品的编排内容；在调度线程临时编译也不符合既定资源边界。

复用 ADR-111 的 GStreamer 时间职责划分、现有音乐片段编译器、同一 render::step／blend 和统一 LiveMixer。先将实际编排预先编译并接入原媒体组与 Host；音频所有者、应用命令和独立进程入口接续完成，不另起播放器服务。

## 边界

1. 新增宿主内存中的来源选择，区别普通场景／列表与工程音乐灯光轨道；不扩展设备 PackageSelection、工程 JSON 或当前 HTTP 清单。音乐轨道必须属于显式媒体组，不能默认由系统时钟自行播放。
2. 准备阶段编译默认段和全部启用片段／绑定卡点，共用一套输出映射并绑定完整工程快照。单场景使用原 render::step 的有界随机位置采样，交叉复用 SceneCrossfade；位置由调用者提供，不新增时间引擎。完整采样不编译、不克隆计划、不分配和不访问文件。
3. 预算累计所有驻留计划，交叉的两侧均计入目标值、效果通道和关键帧；所有来源合计仍使用现行预算。失败准备不更换运行内容，旧计划依旧在调度外释放。
4. 音乐轨道是独立的完整编排：只拥有其启用内容／交叉来源／历史快照实际涉及的属性集合。该集合内，场景未赋值与空白段保持现有默认值语义；集合外不覆盖其他执行来源。显式 release 在完整场景中仍按现有编译结果取默认值；现场稀疏列表的释放规则不变。历史快照里的明确属性也属于编排内容。
5. 段落切换／明确重新激活产生接管；一次前进跨过完整启用片段落入另一空白时也处理片段结束，同段普通采样与暂停／继续不反复抢回手动层。原媒体组仍负责年龄、代次、时间映射、失联与整体准备交换；素材回跳须重新准备代次，不能绕过原校验。
6. 默认值、离散功能、效果相位、动态交叉及总控只在原有语义与编码层处理。桌面既有编辑预演保留，后台通过真实工程对照验证后再接产品音频入口。

## 验收

真实片段、卡点、空白／停用片段、历史切片、动态交叉、向前跳段／重新定位与终点对照原单段编译；累计预算及快照拒绝。接同一媒体组、手动层、自主动态来源与实际 Host，检查完整通道、暂停、失联与手动接管保持。验证代码与物理设备分开，当前不打开声卡或输出板卡。
