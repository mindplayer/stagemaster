# PRODUCT-ADR-037：独立安装工作任务与过期队列

日期：2026-09-28；状态：接受软件边界，ESP32 并发调度须实测后开放；DEVICE-002C，基线 `31b4df5`，主工作区。

## 决定

新增无具体平台和调度器依赖的 `stagemaster-install-worker`，独占既有 `stagemaster-transfer::Service`，不复制包解析、事务或 NOR 逻辑。所有操作由一个工作任务串行执行，无线适配只重组有界消息／接收回执，不在 GATT 回调中擦 Flash 或全包校验。核心不依赖 ESP32、线程、UI 或云端。

工作请求有宿主分配且不可回绕的非零连接代号，不能从对端字节解码得到。已认证权限由 B 适配提供 `AuthorizedLink`，另发内部 `Open` 命令；普通传输帧不能自行打开权限。共享存活代号作为队列之外的撤销通道，断线／过期／取消认证立即清除。工作任务在开始处理和产生回执前分别核对最新代号，拒绝过期排队请求／旧授权与晚到回执；同一工作任务不接受旧代号重新打开。

开始执行的 Flash 操作不能假装被撤回：断线期间允许当前有界请求完成到既有安全边界，随后撤销会话并丢弃旧回执。已有安装事务与归属保留，由重新认证的连接通过现有 Status／Cancel／Reconcile 查询／取消／对账。取消命令不能跳过前一请求的提交结果，ATT 成功不等于已安装。协议错误导致连接失效并要求新代号，不能在原代号静默重新授权。

ESP32-S3 首个候选以官方 `esp_rtos::start_second_core` 启动单一 Flash 所有者，使用独立静态栈和有界请求／回执队列；所有 `Rc`／驱动／租约在该任务内创建和使用，不跨核搬移。Flash 用官方 `multicore_auto_park`，每个物理写／擦期间安全停放另一核，不能开启 `multicore_ignore`。这是减少同步大请求阻塞的承接方案，不保证单次擦写中断已满足实时性。必须测量最长物理操作、保活往返、任务栈／内存和故障后恢复；若无线仍不能稳定维持，再调整块调度或传输维护协议。

保持现有 NOR 分区地址／容量、包和 SMP 消息格式；板级分区类型兼容调整见下。维护时释放旧播放器预算并确认物理输出静默。当前镜像的 GPIO21 持续禁止输出，未来真正输出适配仍须 Runtime 的静默确认，不能因独占写任务就默认可边播边擦。静态栈大小不是高水位证明。

## 实板发现后的分区类型调整

首个实板镜像在创建 NOR 区域前触发上游 `esp-bootloader-esp-idf 0.6.0::PartitionEntry::partition_type` 的 `unreachable!()`；`raw_type()` 支持读出 0x40，但 `as_flash_region()` 必须转成仅支持 0–3 的类型枚举。不是表校验通过就代表所有 SDK 操作兼容；未开始节目擦写。

接受将开发板 `stmpkgs` 从自定义类型 0x40／子类型 0 改为 `data` (1)／`undefined` (6)。[ESP-IDF 官方分区说明](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-guides/partition-tables.html#subtype) 明确提供未指定用途的数据子类型；锁定 Rust SDK 的 `DataPartitionSubType::Undefined` 也支持该值。继续使用上游 FlashRegion／NorFlashRegion 边界检查，不将节目冒充 NVS 或某种文件系统。

比较了保留 0x40 并增加自有有界 NOR 适配：这能保留分区类型，但会新增底层范围、偏移、标志和错误转换代码。当前尚无正式客户设备／旧节目数据迁移需要，采用已有通用数据类型的成本和误写风险更低。自定义 0x40 本身符合 ESP-IDF 规范，本次是锁定 Rust SDK 的兼容取舍，不认定该类型非法。不得修改 Cargo 缓存源码或伪造分区枚举。

分区标签、0x610000 地址、0x402000 长度、双槽格式 v1 和 flags=0 严格检查继续有效，只接受新类型组合；旧 0x40 表必须在转成 FlashRegion 前明确拒绝。分区表改变需要显式受控刷入，不能由业务安装请求改表；新固件不自动迁移或格式化节目。既有 `flash` 工具后续显式使用同一分区表和 ota_0，避免恢复诊断镜像时重置为占满 Flash 的旧 factory 分区。实板必须重新验证只读启动、首次写入、重启恢复和无线保活。

- B 系统绑定确认尚待用户答复，不因此创建无线写权限。可以在既有硬件测试授权内运行本地受控存储验收；此结果必须标记为工作任务验收，不能替代正式已认证 GATT 与桌面安装闭环。

## 当前实测结论

软件 299 项测试及严格检查通过；实板已通过两个槽的实际小包／舞台场景包安装、持久恢复、同包零擦写和同内核逐帧摘要对照。另记录一轮 BLE 断开，不能认定整个设备安装出口完成。锁定 SDK 的串口日志整次使用临界区，测试改为汇总后两轮 27／28 场景、438 次保活通过，最大往返约 410 ms；分配器峰值约 52 KiB（实际 53,008 B）。这不等于 250 ms 内完成所有应用往返，也不改变既有单次 ATT 期限或 6 秒保活语义。详细样本、失败及限制见 [实板验收](../tasks/DEVICE-002C-worker-acceptance.md)。

仍保持静默维护和有界串行调度决定；不能以本地实验的固定主体、编译时包或一次成功记录开放生产写权限。B 的认证依据、正式 GATT 重组／断线撤销／旧回执排空，以及桌面核验须独立完成。
