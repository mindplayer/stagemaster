# PRODUCT-ADR-139：S3 发送调度与无线隔离

2026-10-04；接受、短期实板联测通过；基线 `80076c0` 加当前 OUTPUT-002 看门狗工作区，当前会话单写者。

原第一核普通 Embassy 任务与 BLE／诊断共用调度。实板已经出现真实 Queue Deadline：break 最大 1,175 µs、单次 write 等待最长 44,261 µs，取消发生于 write，40 ms 总发送期限因此失败。第二核节目帧仍正常推进；不因此下调解析能力，也不延长发送期限掩盖链路失约。

复用锁定 esp-rtos 的 InterruptExecutor，使用尚未占用的 FROM_CPU_INTR2，在第二核以 Priority2 调度发送任务；原工作器仍在同核普通线程执行器，BLE／常规诊断留第一核。只搬板级发送组装，不改 Port、Queue、Transmitter、设备包和 Runtime 语义。第一核最早初始化禁用的方向脚和阻塞 UART；把阻塞所有者提交给第二核发送任务后，在该任务内转换 async，确保 UART 中断也绑定第二核，避免只搬任务但保留原中断归属。

看门狗与 Receiver 继续位于同一发送任务，任何其他任务不能代喂；正常工作器失活由进度策略判断，发送任务同步卡死由硬件计时复位。第一核仍可以读取独立发布的状态。发送阶段不做格式化、堆分配、存储或业务操作；第一核按原诊断周期读取固定原子耗时计数，发送任务仅启动／终止时报告，日志不会延长看门狗。原始 Queue 故障单独锁存，避免 Port 的通用 Driver 错误掩盖根因。

第二核已有的 48 KiB 栈预留同时须容纳中断抢占时的调用链。必须重新实际构建、载入／运行、断线、暂停和停止验证，检查栈保护与帧时序；不能只凭中断优先级宣称达标。GPIO21 仍强制禁用，真实差分波形和最大负载继续独立验收。

严格类型检查拒绝把已经绑定中断的 async UART 通过 SendSpawner 迁移（HAL 刻意标为 !Send）。因此传递 PreparedLine 阻塞所有者，在目标任务体内构造 async UART；没有添加 unsafe Send 或绕过驱动的核亲和约束。原独立 UART／队列实验入口继续复用同一适配。

最终原包 180 秒观察：断线采样 41.549984 秒约 40 Hz，最大工作 944 µs、间隔 29.888 ms、错误为 0；UART 最后完成 6,150 帧、单次 write 最长 5,593 µs，所有取消为 0，无栈保护或运行复位。保持原期限通过；完整证据与未完成的波形／最重负载／长期验收见 OUTPUT-002。此结果支持调度隔离有效，不排除其他负载下的潜在抖动。
