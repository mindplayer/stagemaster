## 问题与参考

执行台已具备目录／搜索、常用排序、固定步骤与单节目控制；多节目暂停／继续／停止只能逐项提交，不具有同刻整组语义。前端循环会暴露部分成功、迟到控制和混合回执，不作为批量实现。

参考 [Titan Playback Groups](https://manual.avolites.com/docs/running-the-show/playback-controls/#playback-groups) 的明确成员与选择展示、[grandMA3 Pause](https://help2.malighting.com/Page/grandMA3/keyword_pause/en/1.9) 的暂停与关闭分离。只借鉴选择／组控制机制，不复制互斥自动关闭、宏语言或私有实现；不推断厂商实现具有本项目的原子保证。

## 决定与兼容

- Rust 新增 `Session::control_batch(keys, BatchCommand, now_ms)`，命令只含 Pause／Resume／Stop，1–64 个唯一普通场景／列表来源。全组身份、类型和数量预检后推进同一权威时间，在唯一 worker 内逐项调用原 Player，再一次最终合成。预检拒绝不部分应用；内部求值／编码失败沿原语义锁存整组故障、撤回有效帧，不承诺故障时状态回滚或发布部分成功。
- 暂停只影响运行中，继续只影响已暂停，待执行不启动；沿原播放器 no-op 语义。停止归还所选普通来源贡献，其他普通节目、手动层／音乐、总亮度／熄灯与控制权保持。批量启动、跳步、电平和媒体同步组不在范围。
- 原宿主新增有界不可变 `Batch`（接纳前 Arc 分配，worker 克隆共享载荷）与 `Action::Batch`，仍走原队列、租约、修订、序号、期限和单一回执。不增播放器、线程、时钟或热路径分配。
- v2 宣告可选 `sourceBatch`；`submit.action={kind:"batch",sources:[UUID...],action:{kind:"pause|resume|stop"}}`，1–64 唯一 ID，仍受 8 KiB 请求限制。v1 拒绝。客户端／正式桌面暴露一个 batch 请求，未声明能力明确不可用；不逐条 fallback、不自动重发。工程／设备包／媒体格式及依赖不变。
- 界面有序选择在同一后台／布局内跨搜索保留，“全选当前结果”只增加可见普通节目，显示筛选外选项且整组选项纳入审阅。音乐／手动层无批量勾选。选择只属于 UI，不改变运行、优先级、工程历史或保存。
- 每次操作先冻结目标、命令、后台／布局／会话／修订与审阅时状态；确认列出完整名称及停止影响。隐藏／失焦／Escape、选择／筛选、身份／控制／修订变化取消旧审阅；取消不发命令、不回滚已有操作。确定后一次提交冻结修订；旧回执、待确认、读取失败、只读、连续手势互斥，不把“请求成功”当全部生效。

## 验证与不扩大范围

核心测试：同一时间暂停／恢复、混合状态 no-op、停止局部释放、其他动态来源和手动值／总控保持、重复／空／超量／外来／手动／媒体全组拒绝、倒退时间和故障帧撤回。宿主／真实进程：一次修订／回执、重放、旧版本、失权、过期和大小／类型拒绝，原来源操作保持。

UI：64 项搜索多选、隐藏项完整审阅、冻结取消与旧确认、只读／待确认／拒绝、草稿和上下文保持、键盘与窄栏；实际 React＋正式 `.app` 两个动态节目／手动层及退出重开只读验证。来源工程字节不变，不把软件帧当实灯反馈。实际结果在工单保存；听音／物理差分／长期／客户 UE 包仍独立门槛。
