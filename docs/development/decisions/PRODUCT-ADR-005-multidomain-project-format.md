# PRODUCT-ADR-005：声光电与互动机构的工程格式草案

- 日期：2026-09-23；基线：`fc14472`；负责人：当前 Astra 会话
- 状态：accepted（设计边界）；字段格式为 `0.1.0-draft.1`，尚不承诺持久兼容
- 工单：[PROJECT-001A](../tasks/PROJECT-001A-format-design.md)，属于 PROJECT-001 的格式设计增量

用户要求基于既有讨论设计完整 JSON 格式，覆盖未来音乐、视频与密室电机。交付为工程正文、现场绑定、设备部署清单的 Schema、示例和开发期校验；不在本轮实现保存服务、媒体系统、运动驱动或安全控制器。

## 分层决定

1. 工程正文维护逻辑对象、灯光／媒体／机构定义、场景与时间线、条件联动、监看和操作面布局。现场连接绑定另有文档，机器地址、密钥、短期会话和授权不混入正文。
2. 沿用外部音视频正式播放／处理、StageMaster 统一控制及参考预览／监听的既定边界。媒体时基显式，节目时刻、媒体位置与运行单调时间分别表达。
3. 电机运动由独立控制器执行；工程保存有单位的目标、速度、反馈要求和控制器能力需求。保护性限位、急停、人员保护、逃生释放和运动闭环不由节目 JSON、网络或授权状态代替。节目中的联动条件只是业务门槛，不能视为经认证的安全链。
4. 持久对象使用规范字符串 UUID，显示编号和地址独立；所有引用按对象种类校验。时间使用精确整数刻度字符串及显式时基，物理量用规范十进制字符串和单位，不将所有设备压缩成 DMX 数值。
5. 状态赋值与离散动作分开；定位时间线不重放电机／继电器等动作。动作声明重试、反馈、截止时间和重放规则，不能承诺跨设备恰好一次或原子执行。
6. 发布目标依赖显式能力及闭合引用。ESP32 单路灯光包不自动携带媒体或机构能力；不可执行的必需行为拒绝发布。预览上下文不取得真实控制权。
7. 格式主体采用严格字段与带类型分支；扩展通过命名空间、版本、必需性和引用清单登记。未知必需语义拒绝编译，未知可选内容不能被简化端静默删除。

## 成熟依据

- [OpenTimelineIO](https://opentimelineio.readthedocs.io/en/latest/tutorials/otio-file-format-specification.html)：借鉴明确类型、版本、媒体引用与时间线结构，不照搬其对象树以替代灯光共享预设引用。
- [GDTF](https://www.gdtf.eu/gdtf/)／[MVR](https://github.com/mvrdevelopment/spec/blob/main/mvr-spec.md)：借鉴灯具模式、逻辑配适、稳定身份和场景资源；保留交换适配，不宣称此格式实现了二者的导入器。
- [OSC 1.0](https://opensoundcontrol.stanford.edu/spec-1_0.html)：借鉴类型化控制和时间标记；实际发送仍经适配器，协议支持不证明目标能精确调度。
- [OPC UA Robotics](https://reference.opcfoundation.org/specs/OPC-40010-1/full)：借鉴机构、轴、运行状态与保护状态的分离，不将普通状态观察当安全功能实现。
- [ANSI E1.64-2024 概要](https://webstore.ansi.org/standards/esta/ansie1642024)：舞台机械控制涉及操作面到机器的完整控制链。本轮只阅读公开概要，未核验标准全文、不声称符合标准。

## 范围和验证

Schema 是持久格式的结构契约来源；Node 工具只作设计期严格 JSON／结构和示例一致性检查，不成为第二套运行内核。领域校验和执行权威后续由 Rust 实现，Schema 通过不能作为运行授权。测试覆盖有效样例与关键非法变体，不写会操作真实设备的样例脚本。

PROJECT-001 的读写／迁移／恢复与 PLAYER／AUTH 的执行、授权、可信时间任务仍待实施。该草案完整表达当前需求的主要模块，不声称预知所有未来功能，也不将示例里“已声明”解释为“已支持”。
