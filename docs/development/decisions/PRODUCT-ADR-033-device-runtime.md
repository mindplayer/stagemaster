# ADR-033：设备运行、控制回执与安装维护

2026-09-28；接受并实施。PLAYER-003E，基线 `4b3ffe9`。不修改工程／包／安装传输的持久格式。

## 成熟依据及复用边界

[Pharos 触发器](https://dl.pharoscontrols.com/software_help/designer2/content/help/reference/trigger/overview.htm)将面板、协议、时钟等输入归一到播放动作，[动作目录](https://dl.pharoscontrols.com/software_help/designer2/content/help/reference/trigger/actions.htm)区分启动、暂停、释放等操作。借鉴输入适配与播放引擎分工，继续复用已有 Player；本轮不引入脚本、天文时钟或多组混合。

[AWS 幂等请求设计](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)区分明确请求身份、相同意图重试与同号不同内容。设备采用有界的单控制者／一个在途请求／最后回执机制，匹配现有安装协议经验；只保证本次启动的控制租约内至多执行一次，不声称跨断电的恰好一次。控制连接不是物理输出所有权，延续现有伪 API 与 ADR-004 授权边界。

## 数据和生命周期

新增独立 `stagemaster-runtime`（no_std＋alloc），依赖已验证包、Installed 只读源和 Player；不依赖文件、NOR、GATT、UI、UART。`Runtime<R, P>` 持有可选 `Installed<R>`、待选键、最多一个已载入节目、控制租约与回执；P 为可信宿主提供的播放许可策略。存储的最新安装候选属于 Installer，不因 Runtime 保留旧包就改变。

节目键为 `(kind, UUID)`，包身份来自 Commit／Archive；不能跨包复用下标。待选项与已载入项分开：播放中可选择下一节目，载入和执行分别显式请求。状态同时给出绑定包、待选／载入节目、运行实例、当前步骤和模式；回执明确是某次请求完成时的历史快照，实时状态另查。

- **选择**：校验已绑定目录，失败保留原选择和播放；不读节目块、不开始运行。
- **载入**：只允许当前播放器 Idle（或未载入），Finished 仍保持末帧，须先停止。先核对目录／预算，拒绝时保留旧计划；随后释放旧计划，再解码新计划并用可失败的缓冲分配构造 Player。此后的读取／完整性／分配失败保持同一待选项、无载入计划、无新输出帧，明确要求重试，不能谎称已回滚旧计划。同节目已 Idle 载入可直接成功。拒绝双计划峰值是当前 128 KiB 堆的主动取舍。
- **执行**：必须待选与载入相同，使用稳定步骤 ID；创建新的单调实例 ID，执行／重执行都属于新实例。相同请求重试不创建新实例。
- **暂停／继续／下一步**：只作用于已存在实例；继续必须 Paused，下一步必须 Running 且确有后续步骤。暂停不改变待选项。许可策略分别看到新启动、继续原实例、推进原实例。
- **停止**：不受播放许可过期阻止，调用原 Player 恢复档案默认值，清除实例；不笼统将全部通道清零。即使待选已变仍停止实际载入项。
- **时钟**：只接可信宿主单调毫秒，网络不提供时间。每次操作先正常推进；倒退在任何状态变更前拒绝。连接失效仅撤销控制，当前播放器继续。tick／输出不分配，也不访问包读源。

## 控制权与幂等

可信宿主验证本地输入或远程控制权限后调用 `acquire`；核心生成带启动 ID 和递增代次的租约，附主体、来源和有界到期时间（最长 60 秒）。默认无控制者。已有未到期控制权时需显式 takeover，不自动抢占；renew 不能复活已过期租约。撤销／到期／接管不停止播放；同一启动中租约代次不重用。启动 ID 必须由宿主生成、不可使用持久固定值。

请求包含租约、从 1 连续递增的序号、期望运行修订号与类型化动作。精确重复最后请求返回原回执；同号不同内容／跳号／旧序号撤销该控制者。错误租约不得撤销另一个合法控制者。合法序号的业务失败也记录回执并消费序号；修复后必须是新请求。新请求修订号不匹配不执行，避免旧选择或旧计划被继续使用。接管、维护确认／结束和进入业务处理的动作（包括失败）更新修订；tick 不更新业务修订，但状态时间持续变化。

只缓存最后一个请求／结果，宿主按一个在途操作管理。重连必须新取得租约、读取状态；不能把旧请求改成新租约自动重放。停止也经相同控制入口；本地面板可由可信宿主显式接管后停止。没有网络可直接触发的免鉴权紧急按钮。

## 安装维护与输出交接

模式为 Operation／Quiescing／Maintenance。初始 Quiescing，要求宿主先确认输出静默再绑定包，冷启动不自动执行。

普通控制 `BeginMaintenance` 只允许无实例且播放器 Idle，生成带启动 ID／新修订的静默请求；尚不授予安装资格，保留读源／计划。此时不生成帧。输出适配器实际完成关闭／待发送帧清理后，可信宿主用该请求调用 `confirm_quiescent`；精确匹配后释放全部计划、目录和读源租约，进入 Maintenance 并返回不透明凭据。逻辑停止不是物理静默确认，网络不能自行确认。

安装写操作通过 `with_maintenance(凭据, 闭包)`，仅在当前 Maintenance 允许闭包运行；核心自身不创建或交出可写存储对象。未来宿主将持有的安装服务每次请求放在此门内；存储仍不绑定 Runtime，可信宿主不能绕过门直接使用底层写接口。闭包返回值由宿主管理，不是永久写许可；可信宿主必须让每次实际写操作都经过当前状态检查。并发异步适配须保持同一串行所有者，不能绕过该入口。

`finish_maintenance(凭据, 装载只读安装快照的闭包)` 在无旧目录／计划的状态调用；失败停留 Maintenance，可重试，显式返回 None 可退出到空设备。成功绑定包但不选中／载入／播放，凭据失效。Quiescing 可由 `CancelMaintenance` 撤回并保留原内容，新修订使迟到的静默确认失效；初始没有旧内容也可取消为空设备。Maintenance 不能通过该取消绕过包恢复；安装事务的取消仍由 Installer 处理。

这是一项可信宿主契约，不是密码学授权。帧元数据提供启动身份、业务修订和采样单调时间；物理驱动必须按模式和这些上下文丢弃旧帧，确认等级与错误上报在输出适配任务实现；本轮没有实际输出或刷机。

## 资源、许可与验收

运行核心显式接收装载预算（≤既有 64 KiB 包准入）；按目录 loader_peak_bytes 在释放旧计划前检查。绑定快照的完整验证依然要在宿主预留既有 Archive 校验预算，不能用较小节目预算倒推快照验证也只需这么多内存。预算声明不是内存实际预留；所有新 Player 缓冲使用 try_reserve，失败返回可恢复状态。读取源只在载入时使用；运行单计划，不按帧分配。

许可 P 在新执行、继续和手动推进的应用边界接收包／节目、实例、操作类型和宿主单调时间。默认没有隐式“允许全部”；开发测试显式提供策略。停止／维护不受许可阻止。此次接口不是 24 小时授权实现：签名、可信现实时间、跨断电防回退以及自动到期有限收尾仍由 AUTH-001 实现；单调时间不能冒充现实授权期限。

验收包含真实导出包全节目逐帧比较，面板／远程共用命令、重复／冲突／过期回执、租约接管与无连接播放，选择与载入失败，维护关闭确认／迟到确认／取消／写门，预算与读源释放、目标板完整代码生成链接及资源核对。模型与主机不替代实板；状态文档逐项区分证据。
