# ADR-090：可复用灯效与云端灯库的分层

2026-10-02，方向接受，接口为设计稿，未上线云端服务。基线 `7befdf7`；主工作区、当前会话单写者。延续 ADR-009、ADR-021／022／058／084，补充用户要求的跨型号灯效复用，不替换现有工程／播放器。

## 参考与取舍

- [MA3 2.4 配方](https://help.malighting.com/grandMA3/2.4/HTML/recipes.html)将灯具选择、预设和时间／相位等规则组合后生成值。采纳规则与灯具绑定分离、显式重新生成；不照搬多重隐式覆盖关系。
- [Titan 19 预设](https://manual.avolites.com/docs/palettes/creating-palettes/)区分通用、同型号共享和逐灯值，效果预设可只包含效果参数。采纳分层复用及属性范围；当前不采用自动最近色匹配，因为本项目色块仅是显示注释，不是经过测量的色度。
- [GDTF 通道定义](https://gdtf-share.com/help/users/gdtf_builder/dmx/index.html)区分通道、逻辑属性及功能区间。用独立导入适配器吸收其描述能力；灯具档案不是动态灯效模板，不能以导入成功代替本核心支持执行。

## 数据归属

| 层 | 保存什么 | 不保存什么 |
| --- | --- | --- |
| 标准能力注册表（Rust） | 类型、单位、连续／离散／动作语义、作用单元、合法组合及版本 | 厂商名推断的能力、未注册任意键 |
| 灯具档案／私有变体 | 硬件和固件版本、模式、通道及条件、粗细精度、功能键、固定档位／连续区间、物理模型、资料及实测来源 | 工程地址、云账号、运行连接 |
| 灯效模板库 | 不可变版本、规则、参数约束、灯序／空间选择规则、需要的能力、属性占用、基础值处理方式、资源依赖 | 某台灯 UUID、配适地址、现场校准、原始 DMX 帧、可执行脚本 |
| 工程效果实例 | 固定模板及依赖快照、参数、有序灯具／单元绑定、颜色角色对应、世界目标、应用修订与来源 | 自动追随的云端 latest、现场控制租约 |
| 编译／执行产物 | 精确工程与档案／校准版本、目标预算、已解析且可确定执行的数据 | 云灯库检索、现场猜色或自动换型号 |

工程是离线权威：更新模板／灯具库只产生新版本；下载、应用到工程、编译、激活分别确认。工程保存可独立使用的依赖快照，云删除／离线不能改写已保存内容；实际使用权限仍遵循既有授权契约。私有现场校准不回灌公共灯具档案。

## 复用与兼容性

1. 亮度波浪可绑定具有有效调光能力的灯；无独立调光时，只有已明确实现、声明作用范围的虚拟调光适配器才能承接，不能默认压低所有通道。
2. 颜色追逐保存颜色角色及节奏。混色灯、色盘灯各自绑定角色：前者使用支持的混色模型，后者明确固定功能键。连续渐变不能悄悄变为跳色；允许转换时生成单独、可审阅方案。通光、白色滤片、半色、未知色片保持区别。FIXTURE-007 的 RGB 色块不参与物理颜色自动匹配。
3. 摇头轨迹区分相对轴角度与共同世界目标；依赖轴模型、安装／校准，检查整条行程及精度。540°／270°总行程不等于零位已经确认。固定射灯不得接受运动模板。
4. 多光源、多灯珠、矩阵、多个盘均有独立单元／属性身份，不能全压成灯具级单个 red 或 color-wheel。模板的灯序与单元序分别绑定；更改组成员时须重新预检和应用。
5. 星空灯的内置程序、图案盘、激光图形索引、媒体播放、电机动作不是同一种“效果编号”。内置宏记录具体档案限定的功能语义，不能伪装成跨型号通用效果。激光扫描／图形流、运动机构与离散复位需要独立能力、控制策略和目标验证，不通过通用连续曲线开放。
6. 预检逐灯／单元返回可直接使用、需要绑定、明确转换、阻断及原因。未识别能力、缺资料、未知必要默认值、依赖缺失和预算超限不能以 0 填充后继续。默认整批原子失败；主动排除不兼容灯具必须展示新选择范围并重新预检。
7. 预检绑定工程／模板／档案／目标修订与所有参数；提交时再次核验。取消不修改工程，应用形成一次历史；旧播放计划不被模板更新原地修改。

## 模块和接口

界面复用“编排 → 效果资源 → 选择模板 → 指定灯具与对应关系 → 预演 → 应用”，灯具档案仍在灯具库。预演使用唯一 Rust 编译／播放与三维来源，不另开云端效果求值器。

设计接口见 [effect-library.md](../../module-api/effect-library.md) 和独立可类型检查的声明。核心解析／绑定／编译由 Rust 实现并生成客户端类型；TS 负责目录、界面和 Fastify 云业务。PostgreSQL 保存归属、标签、权限及不可变版本索引，对象存储保存模板包与媒体，哈希校验及依赖限制在导入侧执行；标签、预览图和检索结果不是执行语义。

当前先为已有亮度、RGB、相对轴和世界直线效果建立边界，保持现有工程不迁移。后续先做本地模板导入导出及 Rust 绑定闭环，再接云目录。ESP32 接收目标支持且预算内的编译节目，ARM 可提供更高能力档位，均不要求下载完整库。

## 实施门槛和本次验证

本次为架构准备：核对当前 `lighting-effects.md`、档案映射与 FIXTURE-008 编译测试，新增伪 API 的正反例类型检查；**没有宣称跨型号颜色追逐、云端库、多单元、激光或新灯型已实现**。

后续实现必须验证：同模板换两种地址布局输出意图一致；异构色盘绑定不同功能键；连续颜色要求对色盘拒绝；缺轴／越行程定位到灯；重复单元／多属性竞争拒绝；离线重开固定版本；云更新及过期预检不改已应用工程；超预算失败；取消／一次撤销恢复全部绑定。新增说明书先归档来源和模式差异，未确认区间作为缺口，不猜测物理颜色或通道安全值。
