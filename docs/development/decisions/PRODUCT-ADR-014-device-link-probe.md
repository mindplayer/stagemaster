# PRODUCT-ADR-014：设备连接边界与首轮蓝牙验证

日期：2026-09-26。状态：诊断增量已实施并实板验证；PLAYER-002A，基线 `6fce3db`。

用户授权在已连接的 ESP32 上测试一轮，并要求抽象连接层，优先 BLE GATT 直连与保活。此次改变先 USB 业务下发的顺序：GATT 优先验证设备发现、连接、握手、心跳和断线恢复；USB 继续承担开发、诊断和恢复。执行包、持久安装、控制及身份授权仍按各自契约推进。

## 分层决定

- `stagemaster-playback` 改为 `no_std + alloc`，不改执行语义、计划上限或公开方法；分配器由宿主提供。电脑与设备共享同一份实现。
- 独立 `stagemaster-device-link` 拥有版本检查、会话、序号和应用保活，不依赖 GATT、USB、桌面或播放内核。链路失效本身不能停止或启动节目。
- 固件置于 `apps/esp32-player/`，独立 workspace、锁文件与项目内 Xtensa 工具链；板卡引脚和 BLE 驱动不进入共享核心。
- GATT 适配将特征写入转换为有界消息，将回复提供给读取／通知。ATT 写成功只代表传输接受；必须核对应用回复的会话、序号和状态，不能当作执行成功。
- 主机连接适配后续承接系统蓝牙 API；界面只消费连接状态和业务结果。不以 Web Bluetooth 覆盖 macOS／iPad 所有宿主；共享协议，平台分别适配。

## 本轮探针边界

仅验证握手、心跳、共享播放内核的板内自检。探针不接受节目控制、执行文件或真实输出命令，不是正式商业服务。RS485 方向 GPIO21 保持接收，禁止使能发送；板上测试数据不进入用户工程或默认界面。

应用心跳候选周期 2 秒，6 秒没有新的有效消息即过期；单调时钟由宿主注入。重复／乱序、错误会话和无效包不能延长租期；重连产生新的会话，过期连接须重新建立。设备重启也必须产生新的会话标识。通知不可靠时可读取回复；不把 GATT 连接／通知确认当成应用存活证明。

BLE 监督超时属于链路层，应用保活属于会话层；手机后台、系统休眠及射频丢失不能承诺永久在线。设备独立播放以后不依赖这些心跳；重新连接先核对身份、版本、活动节目和状态，再允许显式控制，禁止自动重放旧指令。

本轮 20 字节消息适应最小 ATT MTU；大文件以后独立定义分块、偏移、总长、摘要、流控、恢复和原子安装，不逐帧传输 DMX，也不把整个工程塞入特征。临时探针版本与 UUID 不承诺产品长期兼容。BLE 配对／绑定不替代设备身份及文件播放授权；真实控制前必须补所有权与认证。

## 参考与验证

复用 [Espressif Rust 工具链](https://docs.espressif.com/projects/rust/book/getting-started/toolchain.html)、[esp-hal](https://github.com/esp-rs/esp-hal) 与 [TrouBLE](https://github.com/embassy-rs/trouble) 的控制器／主机栈分离和现成 GATT，不自研蓝牙协议栈。版本、交叉编译、资源与实板证据在工单记录；开源组件可运行不等于整机蓝牙认证。

BLE 探针采用常规 Flash 镜像，使用用户本轮测试授权进行受限诊断固件刷写，记录地址与版本，不写 eFuse、不开启安全启动或更改永久保护。已识别原分区；用户明确“原有固件不用保存”，已停止原镜像读取并删除本轮读取文件，不做备份。完整 DMX 接口及时序／灯具、长时间运行均不以本轮通过代替。
