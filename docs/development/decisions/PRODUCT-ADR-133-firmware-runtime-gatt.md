# PRODUCT-ADR-133：固件运行入口与独立调度

状态：accepted，软件实施与交叉构建验收完成，实板仍待验证。2026-10-03；基线 `5688d6a`，main；DEVICE-003 第七增量，当前会话单写者。中途进度查询只核对状态，分类 no progress；接续回合重新验证同一工作区并完成本增量，不重启已终止构建。

## 决定

沿用 ADR-131／132 已验证的独立运行服务、共享安全记录和原工作器，不再另写播放器。现有安装镜像不宣称播放；新增显式 `runtime-gatt` 构建组合，把运行服务接入原第二核工作器。此阶段保留 OutputDisabled，只有软件节目执行／采样，绝不公告 DMX_OUTPUT 或自动刷入。

1. 固件安装与运行共享一套握手、分片、加密记录和保活适配；单个物理连接在第一次应用写入时选择入口，之后不能切换。运行服务使用原生端已约定的 edb0／edb2／edb3，安装 eda0／eda2／eda3 保持。不触发系统配对。
2. 可信本地开发配置新增 SMDV v2 的显式范围，仍为 160 字节：第 52 字节为非零权限位（安装 1、观察 2、控制 4），53～55 及152～159保持零。v1继续只允许安装，禁止把保留字节当新权限。仅设备角色可以产生许可；原 permit() 仍仅给安装范围，新的运行许可必须来自显式观察范围，保留控制／安装位供受控维护。不是网络凭据，也不是商业授权方案。
3. 第二核始终推进同一个 ManagedWorker；运行命令／回执各一格，与现有安装队列分开。Live 全值通过临界区同步，取消／失败／Drop 清空。完成通知拥塞不能阻塞 tick；旧代次结果丢弃，未确认结果不伪造成功。调度保持固定 25 毫秒节拍，并处理当前模式的命令。
4. 运行镜像启动后只绑定已安装目录，不自动选择或执行。显式进入维护后，板级适配基于整个启动期间真实保留的 OutputDisabled 确认静默，再允许安装；普通观察／重连不进入维护。软件播放采用明确开发策略，生产节目许可继续独立。
5. 通用协议适配以真实固件源码做主机测试，复用原安全会话、工作器与包；旧安装和新运行分别验证。实际 Xtensa 严格检查／构建核对产物容量，内存数值为静态与链接证据，不能冒充实板峰值或时序测量。源码按握手、业务路由、记录、同步槽与调度拆分。

## 本轮边界

涉及设备开发配置解析／生成工具、固件 GATT 和调度、必要主机保护测试与文档。构建验收使用项目内独立测试配置，不修改现有实板密钥或控制端凭据，不连接／刷机／发灯。实际板卡运行、桌面操作、UART DMX与现场时序是接续出口，完整 DEVICE-003／AUDIT-001 保持开放。

## 审查结论

现有 Noise／有界记录、Embassy 的 Ticker／单格 Channel／临界区 Mutex 和原 ManagedWorker 继续复用，没有新增第三方实现或另写播放器；选择依据沿用 ADR-131／132 和现有工具链，不重复控台研究。两类应用入口直接共享固件协议源码，7 项主机用例通过；214 项相关回归加最后新增 3 项共 217 项，不重复计数、不作为全工作区测试。严格工作区 Clippy、旧安装与新运行 Xtensa Clippy、最终固件完整构建通过。

镜像 808,704／3,145,728 字节（25.71%），保留原裸机 RWX 告警；单格运行请求／完成／有效性分别 120／1,344／128 字节，工作器静态任务槽 7,792 字节，主任务槽 14,112 字节。均为最终 ELF 静态证据，不能证明实板峰值或准时发送；[固件契约](../../module-api/firmware-runtime-gatt.md)说明限制和维护顺序。实现按既有实例分层、队列背压下推进、出错撤销和旧配置兼容满足本增量出口。完整物理／界面出口不在此关闭。
