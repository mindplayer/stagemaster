# PRODUCT-ADR-035：设备标识与能力声明

日期：2026-09-28；状态：接受，DEVICE-002A 已实施并通过只读实板验收。

## 决定

新增独立 `stagemaster-device-info`，no_std、无堆／I/O／认证／安装依赖，负责版本化设备描述编解码。诊断 20 字节握手保持兼容；同服务新增只读特征 `f889ed64-0100-4e83-968e-799ab99558fa`。GATT 仅承载描述，未来其他连接适配复用相同值对象。

区分三种标识：稳定设备标识用于选择与匹配；每次启动重新产生的 16 字节标识用于识别状态重置；诊断连接的 64 位会话标识用于防止跨连接缓存串用。它们均不是认证。ESP32 首个稳定标识以类型命名空间加芯片只读出厂 MAC 构造，不把随机广播地址或 macOS 外设 UUID 当设备身份；不写 eFuse。以后其他板卡使用自己的命名空间来源。

描述声明设备型号、固件版本、可实现功能和硬上限；当前空闲量、安装状态、配对结果、控制权及授权到期另属业务会话。功能位只表示已接入的能力：仅诊断固件不能因为存在构建检查代码就声称支持安装、播放或 DMX。包／传输版本、消息／分块／节目／包预算必须与声明对应；禁用的安装／运行能力不得带看似可用的非零预算。

首版固定 96 字节，小端整数：`SMDC`、主版本 1、保留字节、总长，随后设备标识／启动标识／诊断会话，型号、三段固件版本、能力位、包／传输版本、包／节目／线路／消息／分块／槽容量／装载内存／帧间隔、认证机制编号与保留区。精确偏移由模块文档和独立字节用例记录。读取时长受主机期限限制；多次底层长读期间的描述须保持不变。

主版本／长度／保留区／零标识或相互矛盾的能力严格拒绝。未知扩展功能位保留以提示版本差异，不自动开放本地未知操作；未知型号保留编号，不能误认另一种板卡。认证机制字段为声明，任何值都不产生授权。没有新特征的旧设备明确保留“仅连接诊断”兼容能力；存在但损坏的描述不能静默降级成可信安装目标。

主机仅在有效诊断握手后读取描述并核对连接会话；断开、取消或失效清除当前描述。UI 接收 Rust 已解释结果，显示设备标识／固件／支持范围，不在前端判断安装权限。真实下发入口需后续业务会话和安装适配完成后才出现。

## 成熟机制与边界

- 复用 [ADR-014](PRODUCT-ADR-014-device-link-probe.md) 和 DEVICE-001 的诊断握手／保活，保留旧设备兼容；不再增加另一种无意义心跳。
- [Espressif Protocomm](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/provisioning/protocomm.html) 将传输与安全会话分开，提供持有证明及成熟加密方案；采用这种职责划分。当前工程采用 Rust esp-hal，不能把 ESP-IDF 的 C 组件直接视为现有可用模块。
- 已核对本地锁定的 `trouble-host 0.8.0` 官方源码：安全模块区分未加密、加密未认证、加密已认证，以及绑定信息和重连事件。后续比较原生安全连接与配对机制，不把 Just Works 等同于抗中间人认证；本 ADR 不提前冻结认证方案。
- 复用 PLAYER-003C 的受限 SMP 封包／重组／安装回执；能力声明不再复制其事务状态机。

本决定只冻结 A 的只读描述边界，不授予无线写入，也不替代 AUTH-001 的生产设备身份、商业许可、可信时间或加密节目包。B 的认证方式和 C 的 Flash／无线调度必须先独立审查。

## 验证

精确格式与调用见[模块接口](../../module-api/device-description.md)。独立黄金字节／坏包／未知字段／会话关联、主机旧固件／读取故障／取消／失效／重连和 UI 故障清除均通过。实板 0.2.0 在两次启动、六条连接中通过描述读取与 48 次保活；设备标识不变，重启产生新启动标识，重连产生新会话。原生 Rust 宿主亦通过实际读取、五次保活和断开清除。具体日志／资源／边界见 DEVICE-002 工单。

该验收只证明只读描述和诊断兼容；业务认证、真实安装、播放和 DMX 仍未接入，不能因为 A 完成而关闭 DEVICE-002。
