# PRODUCT-ADR-141：UART 写入使用有界就绪查询

2026-10-04；接受、代表性负载及停止后持续观察通过；MEMORY-002／OUTPUT-002，基线 `9f3fcb4`。仅调整板级 Line 适配，不改包、状态机、队列、输出权或期限。

最终压力复测中，四类控制与断线返回成功，约 16 秒后 UART 写入等待到达单帧期限并触发发送退出／硬件复位。严格串口报告拒绝此轮；工作器此前最大间隔 35.647 ms、无时钟错误，写入操作最长 24.061 ms 且在取消路径结束。不能把控制命令通过当发送通过，也尚不能断言已定位 HAL 中断的上游根因。

复用锁定 esp-hal 1.2.2 的 `UartTx::write_ready` 与 `write`：官方 API 保证就绪时 `write` 不阻塞，返回实际写入数量。板级适配是唯一 UART 写入者，两次调用之间不挂起，硬件只会继续排空 FIFO，不会有另一写入者把它填满。未就绪时通过原 Embassy Timer 等待 1 ms 再查，不忙循环，也不直接改 UART 寄存器。保留 async 类型用于原 Break／排空，发送队列与真实排空确认不变。

上层原单帧 40 ms 期限仍包围整个等待和写入，取消仍关闭使能，独立硬件看门狗继续监督同一发送任务。没有超时重发、放宽期限或另起任务伪造进度；就绪持续不成立必须按原规则失败。权衡是有限的周期唤醒开销，实际节拍与资源必须通过同板测试判定，不能仅靠源码推断更稳定。

参考为项目锁定的 [HAL 源码](https://github.com/esp-rs/esp-hal/blob/915465df59aee91b627fe538f0b442e56c7f4fc9/esp-hal/src/uart/mod.rs)（`write_ready`／`write`／`write_async`）与原单帧／队列契约。先验证相同压力语料、暂停／断线／停止后持续发送，再恢复原包；必须保留先前失败，不缩短采集窗口来规避它。GPIO21 继续禁用，真实差分波形与 8 小时长期验收仍独立。

最终四类容量包完整 360 秒采集通过；断线同实例连续 41.574907 秒约 40 Hz，最大采样间隔 44.017 ms、最大计算／采样 3.525 ms，UART 完成 13,753 帧且无故障或取消。停止后的连续出帧观察为 228.774984 秒，新增独立报告门槛要求至少 180 秒；既有单启动、帧率、暂停和 50 ms 判据保持。最大写入 2.749 ms／排空 5.924 ms，内部堆峰值 80,616 字节。证据见 [MEMORY-002](../tasks/MEMORY-002-device-capacity-acceptance.md)。这支持当前适配修正，不是上游根因定论或长期实时保证。
