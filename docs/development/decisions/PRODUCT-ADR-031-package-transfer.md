# ADR-031：播放包传输与连接／事务分离

2026-09-28；接受并实施。PLAYER-003C，基线 `4e09820`。

## 参考与取舍

复用 [Zephyr SMP 封包](https://docs.zephyrproject.org/latest/services/device_mgmt/smp_protocol.html) 的 8 字节大端包头、命令组与请求／响应，以及 [SMP BLE 传输](https://docs.zephyrproject.org/latest/services/device_mgmt/smp_transport.html) 的按长度重组；[镜像上传](https://docs.zephyrproject.org/latest/services/device_mgmt/smp_groups/smp_group_1.html) 提供按摘要识别内容、按已收偏移续传的参考。节目采用自己的应用命令组，不使用固件镜像上传／重启命令，不宣称与通用固件升级工具直接互通。

现有 Rust no_std 路径复用已锁定 minicbor 和 SHA-256；不为少量安装命令引入完整 Zephyr 管理系统、文件路径远程写入或 Shell。SMP 的 8 位序号仅做包头关联，应用正文再带 64 位完整序号和 16 字节连接身份，以防序号回绕和旧连接回执误认。工程 JSON、包格式和诊断 20 字节协议保持原职责。

## 决定

- 独立 `stagemaster-transfer`，no_std；固定消息缓冲，不能按网络长度分配。使用 SMP v2、私有应用组 `0x5354`，正文 CBOR，应用版本 1；软件参考阶段尚未分配正式 GATT 特征。
- 包读源补充 `ReadAt for &T` 的透明借用转发，供上传器持有已有不可变读源；不改变包格式、校验或所有权要求，避免为切片另复制整个包。
- 封闭命令为查询、开始、分块、校验、提交、取消、对账。请求带连接身份和从 1 严格递增的 u64 请求序号；变更携带安装器的启动身份／事务计数。响应带同一连接／序号／命令和权威安装状态；错误分为封包错误、业务拒绝和提交待确认。
- 连接生命周期、安装事务、播放授权彼此独立。服务默认没有可用连接，可信宿主显式注入已经授权的主体及新随机连接身份；这里不实现密码学认证，不允许 GATT 诊断握手直接调用此授予入口。未完成事务保留主体归属，其他主体不能续写或取消；断开只撤销连接，不丢弃安装或操作播放器。
- 同一连接只允许一个请求在途，服务缓存最后一个请求摘要及完整回执；完全相同的重传返回原回执，不重复写存储，不重新执行提交。相同序号不同内容、跳号／过期、连接错误视为协议失步，终止该连接后重新授权并查询。不同连接重试由安装事务／摘要和权威状态对账，不复用旧连接的序号。
- GATT 保证一条连接内按序交付；消息只按协商的有效载荷切片，不另造逐片协议。重组边界错误、片段超时或发送途中结果不明时丢弃整条连接及半包，重连查询已确认前缀；不能把整包重发拼进未清空的半包。已完成消息的回执丢失可直接重复同一请求。
- 主机协调拥有稳定包读源与显式安装意图，只按设备报告的进度继续；完整校验成功后再提交。丢失回执不能推断失败；待确认先对账。取消等待当前请求结果或重连后查询，若提交已成功明确返回已安装，不能显示已取消。另一未完成包、其他主体占用和存储失败不自动清除。
- 已完成或已取消的上传意图保持终态，重新连接不会重新安装旧包；需要再安装时创建新的显式意图。最后一个 u64 请求的成功结果先被确认，序号耗尽只阻止下一请求，不能遮蔽已经提交的成功。
- 状态消息中的槽、代数和已接收字节不构成物理输出确认；安装服务不暴露场景执行、任意文件、eFuse、复位或原始 DMX 命令。

## 验证与适配边界

用 20／较大载荷分段的内存链路贯通真实文件存储，测试两端编码、请求回绕、重放、断连续传、设备重启、取消和提交不确定。逐帧比较安装包与源包；统计字节／消息数量。此值是协议开销，不是射频吞吐。

以后接 CoreBluetooth 时按 [maximumWriteValueLength](https://developer.apple.com/documentation/corebluetooth/cbperipheral/maximumwritevaluelength(for:)) 取真实写入上限，通知方向按其实际载荷限制单独分片；不得硬编码把默认 20 字节当作所有设备性能。是否采用带响应写入、队列深度、后台行为和心跳调度在 GATT 实板任务验证。文件校验／Flash 操作必须离开蓝牙回调和实时输出线程，不能因本轮同步参考调用而阻塞现场执行。
