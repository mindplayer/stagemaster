# PRODUCT-ADR-117：受控媒体提供方命令

- 状态：accepted，受控提供方软件增量已实现并验证；TIME-001，基线 `f4aeb04`，main，当前会话单写者。完整后台音频产品接线仍未完成。
- 上一回合为 progress：真实音乐编排预备来源已提交。完整 TIME-001 与持续目标未完成。

## 问题与依据

现行 LiveBackend 只对灯光激活／停止校验控制权；MediaPort 只能准备和提供观测。应用请求解析在 Authority 校验之前发生，不能在此调用音频播放。让音频工作线程取得操作者租约则会夺走人的输入权。正式后台音频必须先有一个经过原控制权校验、容量固定、可查询实际完成情况的提供方入口。

沿用 ADR-111 的时钟／媒体职责、ADR-114 的调度外准备及原有请求回执，继续复用实际 Rodio 音源。借鉴现有异步准备机制，将请求接纳和消费回调执行确认分开；本项没有新的跨设备原子性承诺。

## 决定

1. 在原 LiveBackend 注册可选的受控媒体组；固定媒体位置上限和作业期限，在启动之前确定。普通媒体观测组保持原接口，未注册组不能凭空发送提供方命令。
2. 播放、暂停、停止和定位仍通过原 Client／Authority／修订／重复请求回执校验。接纳后产生不可伪造的请求票据，媒体组观察分别包含请求及完成结果；请求回执成功不代表已发声、已暂停或已定位。
3. 每组一个命令状态槽及一个完成槽，最新明确请求替代旧意图；串号不回绕。提供方只读取已接纳意图，准备／解码和音频设备操作仍在调度线程外。重复回执不重新投递命令；控制者退出不取消已经接纳的演出意图。
4. 提供方准备结果携带请求票据，仍使用原准备槽及回收方式。原调度者在票据仍有效、未过期、组代次正确时激活；旧准备留下错误结果供原提供方在调度外回收。受控组不能经旧的直接激活／停止入口绕过音源协调。
5. 提供方须在真实音源操作及媒体观测接纳后报告完成。停止确认后由宿主释放该组贡献；失败或超时保持可辨认的失败结果，不能伪装为成功或回滚已发生的声音。取消音源和音源失败后的收尾是提供方的责任，其他自主灯光仍继续。
6. 控制槽和准备槽使用 try_lock；主调度不等待音频设备、锁、文件、网络或作业结束。后台销毁后拒绝新提供方操作，允许回收已驻留计划；不引入音频／界面依赖到通用宿主。
7. 本次先贯通受控命令、准备激活与真实音源的代表性调用。独立进程的音频所有者、桌面入口、普通试听统一、提供方重启、循环回跳和自然结束仍须继续完成；不把接口与测试提供方当作完整产品所有者。

## 验收

原 Host 中验证控制权、旧修订／旧代次、重复回执、后续意图替代、过期、准备失败／回收和关闭。使用真实 WAV／原生音源验证请求接纳不产生回调确认，音源执行后才完成；暂停期间健康观测继续、自主灯光继续。全部软件验证不打开物理声卡或灯具输出，不修改工程／设备包／HTTP／GATT 格式。
