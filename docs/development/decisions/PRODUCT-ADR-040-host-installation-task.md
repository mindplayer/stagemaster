# PRODUCT-ADR-040：主机安装任务与工程编辑分离

日期：2026-09-28；状态：接受；DEVICE-002D，基线 `59224fd`，主工作区，当前会话单一写入。

## 决定

新增独立 Rust 主机安装任务层，复用 `stagemaster-transfer::Upload` 管理事务，不在界面重建协议状态机。任务拥有已验证的不可变包和明确选择的稳定设备，借用应用级连接服务；工程编辑、缓存重新生成、关闭面板均不能改变进行中的包。传输适配仍只搬运一条消息，Flash／设备维护／授权继续在原模块。

`Prepared` 在有界包校验完成后保存包摘要、来源、节目数量与预算。开始前再核对目标设备／连接代次／认证和容量；没有可信会话时不创建假任务、不发送安装消息。一个应用只允许一个未解决任务，完成后可以开始下一项。每项操作带任务标识，旧页面不得取消新任务。

暂停恢复仅为网络故障后的任务状态，不修改 goal 状态。断线保留原包及取消意图；恢复须由用户显式选择同一稳定设备的新认证会话。设备重启通过已有 Upload 状态查询／新事务规则恢复。已知远端业务错误可在原会话显式重试；传输不确定或协议错误须重新连接，不重发半包。

进度只用完整应用回执确认的字节。校验、提交和取消单独显示，不能用传完字节数冒充已安装；安装成功须获得与包身份一致的持久提交。取消只设置意图，等待正在进行的消息结束，再由 Upload 查询／取消事务。若提交已经发生，取消后仍报告已安装。断线中的取消保留为待确认，不伪造取消成功。

联调发现连续新建 Upload 会重置同一业务会话的请求序号。序号属于会话，不能随安装任务清零。增加 `Upload::connect_at` 和仅在已确认边界可读的下一请求序号；任务服务独占安装消息入口并在任务之间保存当前会话游标。未完成请求或传输不确定时游标失效，即使明确移除本机任务也不能在原会话从 1 重来。设备协议、严格递增校验及幂等规则保持不变。

安装任务独立于工程代次。桌面从既有生成缓存按代次／随机标识取得不可变字节，开始时按播放包操作门→工程操作门顺序检查缓存标识和当前已应用工程，防止与导出反向加锁或准入期间缓存改变；任务开始之后编辑和重新生成可以继续。界面按单调任务修订拒绝迟到状态，不将私有认证会话或原始协议帧暴露到 IPC。

退出应用会停止主机通信，不宣称远端事务已取消。首个任务层不实现后台自动重连或跨进程任务日志；桌面接入必须对未解决任务的退出／移除作明确提示。故障中允许用户明确移除本机任务，但该动作不发远端取消，不把不确定结果改成“已取消”；设备未完成事务仍由后续状态核对处理。

## 复用与验收

复用 Upload、Archive、Tokio 任务／取消通知和单连接消息层；同一包只读共享，避免每个片段复制整份文件。不增加第三种业务语言、不依赖界面、文件选择器或具体 GATT。

验证真实导出包的任务进度／成功／取消／丢提交回执恢复；新任务互斥、旧任务标识、缺认证／超容量、错误设备恢复、原包不变、业务失败重试、后台任务退出与故障移除边界。产品原生仍无已认证安装权限；软件夹具只能用于测试，不能写进正式界面冒充设备成功。完整 DEVICE-002 仍以正式 GATT、实板和桌面闭环为出口。
