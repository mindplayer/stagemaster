# ADR-091：本地亮度灯效模板的第一个执行闭环

2026-10-02 接受；基线 `7de8cb9`，承接 ADR-090 的 MA 配方／Titan 属性范围／GDTF 语义映射研究。当前会话主工作区单写者。

先实现可验证的通用调光模板，其他类型以后按能力增量接入。模板类型、文件解码、工程绑定分别为独立模块，不建立第二个求值器或云服务。文件格式 `stagemaster-effect-template`、版本 1，只支持 `intensity-wave`：平滑／三角／脉冲、归一化 low/high、周期、整体相位、灯序展开与反向。low/high 使用现有核心的 0..65535 归一化精度，**不是 DMX 通道值**；此为实际 v1 契约，与 ADR-090 draft-1 的十进制伪接口区分。文件不得携带灯具、地址、工程／场景标识、基础 RGB、脚本或任意扩展。最多 16 KiB，严格拒绝重复键、未知字段、未知类型与版本。

模板自有 UUID／修订 UUID；SHA256 对解析后固定排序紧凑 JSON 的完整模板 envelope（不含摘要）计算，空白变化不影响摘要。摘要只保证内容一致性，不表示作者可信或云授权。原模板以完整、严格验证的快照保存在场景效果的 `templateSource`，声明 `lighting.effects.template-source@1`。这是来源快照，当前效果仍保存完整参数并独立编辑；不是远程引用，也不是自动同步。重复使用同一模板身份不会触发工程对象 ID 重复。修改本地效果不改来源快照，再次导出当前效果生成独立模板身份和修订。

绑定由 Rust 以明确的场景、有序灯具与完整模板完成。首版需要独立连续 dimmer，复用既有编辑校验、属性竞争、编译和桌面预算，不推断虚拟调光。所有目标有序、唯一、1..512；未知／无调光、同属性竞争、容量或编译错误整批拒绝。绑定检查产生不透明 Rust 审阅对象，内部冻结完整工程内容和候选；应用前核对完整内容（不能只看尚未保存时不变的 revisionId）。取消丢弃审阅对象，应用是一次正常工程历史，不启动播放器。首版检查目标明确为现有桌面播放器；硬件能力与云票据另接适配器，不假装下发检查已完成。

实现先完成核心文件／来源／绑定验证，再接文件存储与桌面导入、审阅、导出界面；核心出口不等于用户工作流完成。未来云目录提供同一不可变文件的检索与下载即可复用此核心，但权限、签名、目录冲突处理尚未实现。颜色角色、多发光单元、相对轴模板、激光程序等不混入 v1 后门字段。

验收：同模板不同档案通道／地址输出意图相同；静态颜色与轴不变；取消无改动；属性冲突／不兼容／重复目标原子拒绝；未保存编辑使旧审阅失效；离线保存重开来源完整；本地编辑不回写来源；篡改来源摘要、未知字段／类型、重复键／超容量拒绝；复制效果／场景保留来源但更新工程身份；普通旧效果兼容。

同一工程内若出现相同 templateId／revision 而摘要不同的来源，拒绝整个导入或打开；不同内容必须使用新修订。允许多处重复引用同一完整快照，也允许同一模板的不同修订并存。
