# PRODUCT-ADR-124：音频输出占用与编辑／后台交接

状态：accepted，本增量实现与软件验收通过。2026-10-03；TIME-001；基线 `983001c`，main，当前会话单写者。

## 问题与参考

现有跨进程管理锁只覆盖播放请求与后台准备过程，请求返回后音乐仍可持续；另一编辑进程已经播放时，新后台也不能只靠停止当前窗口完成交接。

参考 [QLab 试听路由](https://reference.qlab.app/docs/v5/tools/auditioning-cues/)区分试听和正式输出的机制，输出占用归属于明确路由，不能等同操作者控制权。当前只有应用数据实例内的共同声音路由，先验证其独占生命周期；未来耳机／多声卡可配置独立路由，不提前实现路由矩阵。旧版进程没有持有新占用，升级时须先退出旧版；此机制不宣称可以排斥旧二进制。

跨进程协调复用 Rust [File::try_lock](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock) 的非阻塞排他锁及句柄关闭释放机制，不新增服务、轮询心跳或租约续期。此为同一应用实例内合作进程的协调，不是系统声卡独占，也不是抵御本机恶意用户的安全机制。

## 决定

- 音频适配层提供显式 OutputScope 与不透明 OutputLease。范围由应用组装传入，不来自工程文件；共享私有目录中的固定锁文件不删除、不截断、不克隆句柄。相对目录、非私有目录及异常文件拒绝；当前只验收 Unix 宿主。
- 编辑音源首次挂载输出时取得占用，准备元数据／静态定位不占用。暂停、自然结束及输出故障保留占用，直到明确停止、清空工程或关闭音源；避免另一窗口在暂停间隙接管。已配置范围的 Transport 停止时先回收音源和设备，再释放占用；输出绑定与范围配置保留供后续明确播放。
- 正式后台在准备时取得同一范围的占用，贯穿就绪、暂停、停止和提供方恢复；只有关闭媒体所有者／进程结束才归还。不按客户端退出、HTTP 无响应或心跳过期推断释放，不自动中断另一窗口的音源。
- 原管理锁继续覆盖慢准备及启动交接。当前编辑音源先停止并使旧请求失效；后台准备在该锁内检查占用，子进程自行取得生命周期锁。占用检查至子进程启动期间，合作编辑入口不能穿插启动；若其他独立进程竞争，实际占用失败即拒绝，不发布虚假的就绪。
- 后台命令行增加可选 `--audio-scope 绝对目录`，桌面始终传入自己的范围。系统音频必须显式配置范围；独立静音软件测试可省略。范围不写入可携带工程／包，恢复音源不能丢失后台占用。
- 物理声卡已排队的声音、蓝牙延迟与采样级无缝切换不在此锁的保证范围。默认输出、静音软件输出在当前桌面共用一路占用；未来独立监听通过明确路由配置扩展。

## 验证

验证真实 Transport 在普通／正式播放、暂停、定位、循环、停止、清空和销毁期间的互斥；准备失败不遗留占用、旧准备不能在停止后重启。验证真实后台跨进程占用、编辑请求返回后仍排他、后台恢复保留、正常关闭／进程被杀后释放；全部使用实际 PCM 的软件输出，不操作物理声卡或灯具。验收结果记录到 TIME-001。

原生验收发现操作错误会被自动状态读取清除；界面现区分操作失败与读取失败，前者保留到下一次明确成功操作（含手动刷新），后者在读取恢复后清除。手动刷新与其他明确操作等待已在途的读取，不被自动轮询吞掉。浏览器真实组件及重新打包后的原生桌面均已验证；未改变 UI 协议。
