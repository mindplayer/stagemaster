## 用户最新要求与结论

用户明确“现在不考虑限时”，要求软件和硬件具备商业化所需的授权与加密保护，采用成熟物联网领域的做法；具体方法以后再讨论。

当前不实施或固定 24 小时期限、临时／正式许可分型、离线委派签发、计时起点、到期收尾、续期及永久授权政策。旧资料中的相应规则保留历史含义，不再作为当前工单验收门槛；这也不表示已决定永久免费、永久离线或免授权。后续确认商业模式与产品条件后再形成方案。

软件／硬件商业安全继续是产品要求，当前只确定模块边界；不因为暂不讨论期限而移除身份、访问控制或内容校验，也不因预留接口就宣称已达到生产保护水平。

## 现在保留的职责

| 职责 | 边界 |
| --- | --- |
| 身份与归属 | 软件实例、设备、账号／组织的身份和关系分别管理；连接地址不代替可信身份 |
| 商业权益与许可 | 决定特定主体可以使用哪些产品／模块／内容；规则独立于工程、播放算法和界面，具体授权范围与形式待定 |
| 内容与通信保护 | 内容来源、完整性、保密需求与连接会话分别验证；云端和 U 盘进入相同受控导入路径，传输加密不自动授予商业权限 |
| 凭据与产品生命周期 | 凭据配置、持有、更新、失效以及设备更换／转移保留独立服务边界；具体密钥设施、证书体系和流程后续选定 |
| 执行与部署 | 可信应用层验证后向核心提供明确许可结果；内核不请求云服务，硬件适配报告实际保护能力；界面不能自行宣布已获授权 |

后续优先采用成熟标准、维护良好的密码实现与适合目标硬件的现有能力，不自创密码算法；选型以保护目标、跨端兼容、资源预算、运维恢复及实测为依据，不以流行程度代替验证。当前不选算法、供应商、芯片、安全元件或量产配置，不提前冻结密钥／许可文件格式。

云端与 U 盘并行交付、本地完整准备后执行的方向保持。商业策略不能由交付途径或 UI 布局隐式决定；具体离线权利与失效处置在后续策略中说明，不把持续联网写成播放核心的依赖。

## 与现有实现的关系

已有开发 GATT 安全会话、安装准入、显式 PlaybackPolicy 和相关测试保持。它们是开发／模块验证证据，不等同生产身份、商业许可和量产密钥管理已完成。本次没有修改协议、持久格式、密钥、固件或运行行为。

控制权租约、开发连接凭据期限、请求截止时间、保活超时和节目时间上限有各自的通信／运行作用；本次后移的是商业使用限时规则，不能据此删除这些既有保护或延长开发凭据。商业授权、现场控制权与物理输出权继续分开。

AUTH-001 调整为商业身份／授权／保护方案的后续设计与验收项，当前不实现限时策略。HOST-002 继续实际工程准备与独立执行进程的软件验证，显式软件执行策略不能冒充生产许可，也无需等待商业授权服务上线。
