# PRODUCT-ADR-045：正式安装 GATT 与连接级会话回执

日期：2026-09-29；DEVICE-002B/C/D；基线 `a5f0df9`，主工作区，当前会话实施。状态：接受实施，实板出口待验。

后续用户明确要求不依赖系统配对记录、云端保存设备归属。产品方向改按 [ADR-046](PRODUCT-ADR-046-cloud-owned-direct-gatt.md)；本决定为 LESC 实验安装候选，不能当作最终架构。首次 GATT 实际传输中断，详见[检查点](../tasks/DEVICE-002-installation-gatt-checkpoint.md)。

## 决定

复用已验证的 LESC 持久绑定、Authority、Endpoint、ManagedWorker、NOR 双槽和主机 Upload 任务，不另写安装协议或密码算法。新增 `installation-gatt` 固件特性，继承绑定与存储准备，只有实际档案／维护存储已就绪才声明安装能力；GPIO21 保持低，不提供播放或输出能力。它与本地固定授权探针互斥。节目分区进入现有可安装句柄，所有写操作仍受维护许可和当前连接代次约束。

独立服务 `f889ed80-0100-4e83-968e-799ab99558fa`：`...81...` 认证只读会话回执、`...82...` 认证有响应写片段、`...83...` 认证通知片段。只有 Authority 当前 Grant 才能创建 Endpoint；存储工作器确认打开后才发布非零会话回执。回执关联稳定设备、启动、诊断随机号、128 位业务随机号、认证方式 1、协议 1、片段／消息预算和 6 秒租约。它不携带主体或密钥，不可反向解码成设备端 Grant。

80 字节小端回执：0..4 `SMAS`，4 版本 1，5 权限位 1（安装），6..8 长度 80；8..24 设备，24..40 启动，40..48 诊断会话，48..64 业务会话；64..66 认证方式，66..68 传输版本，68..70 数据片段上限，70..72 消息上限；72..76 租约毫秒，76..80 保留零。全零仅表示尚未准备，不是成功；其他未知／矛盾字段拒绝。线缆编解码放在无 I/O 的 `stagemaster-device-link::management`，与 Authority 分离。

片段包前置独立方向的 32 位连续序号，第一包为 1、不回绕；后接既有 SMP/CBOR 的原始片段。每连接数据上限为 `min(244, ATT_MTU - 3) - 4`，最低 MTU 23 时为 16，通常为 240。Endpoint 和 Upload 只见原始数据，4 字节封装属于 GATT 适配。这样可以检测缺片／重复／乱序；尾片全部丢失由既有固定期限发现。没有另写业务重组器或自动重试写操作。

此封装源于核对锁定 `btleplug 0.13.2`：macOS／Windows 上游通知广播容量为 16，公开 Stream 会过滤 Lagged 错误；仅在外层加队列不能声称检测了底层全部丢片。序号加端点固定期限确保丢片失败关闭，而不是拼成另一条完整回执。主机另设有界接收队列，溢出立即撤回安装权限；同一连接任务继续穿插 2 秒保活。ESP32 每轮最多发送一个片段，检查实际订阅，250 ms 底层发送期限，持续处理保活及工作完成；不能等待整个包时阻塞无线事件。

认证依赖原生系统维护的 BLE 绑定和设备端实际安全栈。CoreBluetooth/btleplug 不向应用公开可移植的 LESC 等级查询；桌面读取的是设备在认证链路上发出的授权回执，不能将字节解码本身宣传为独立密码证明或设备固件远程证明。设备端始终重新检查实际加密等级／绑定、存活代次和维护许可，客户端声明无法获得写权限。物理设备首次信任和实体准入／撤销管理继续依 ADR-043/044；当前已明确授权的 Mac 绑定用于首个闭环。生产商业许可及文件加密另行实施。

## 集成及验证

原诊断固件保持兼容；声明安装但缺特征、坏回执、无认证／订阅、旧启动／会话、缺片和队列溢出均拒绝，不降级为安装成功。主机 BLE 适配拆分发现、认证／安装和通知接收模块，避免扩大原单文件。

先做公共回执／分片序号和故障测试，再编译双方；实际已绑定板卡完成真实工程包下发、原子提交／摘要核验、重复安装、取消、断线恢复及旧完成清理。正式桌面任务必须复用同一 API 完成可见进度与结果；软件夹具和内部固定授权不计实板完成。保持原用户工程与三维进程，全部产物留在项目。

## 实板发现后的兼容断点

旧绑定设备升级后，macOS 全量发现仅返回原诊断／证明服务。明确新服务 UUID 曾返回全部安装特征，但后续同样查询又出现空特征；增加 btleplug 原生筛选接口后仍复现。板端 ATT 日志显示设备实际有安装句柄 22／24／26，而失败连接只收到旧范围／Included Service 的查询，没有安装特征的重新发现。因此不能宣称显式查询修复缓存，也不保留无效的依赖分叉：最终仍使用锁定的官方 btleplug 0.13.2。

参考 [Apple 服务变更回调](https://developer.apple.com/documentation/corebluetooth/cbperipheraldelegate/peripheral%28_%3Adidmodifyservices%3A%29)、[Bluetooth GATT 缓存与 Service Changed](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/Core-60/out/en/host/generic-attribute-profile--gatt-.html)。锁定 Trouble SDK 默认仅空 GATT 服务，没有 Service Changed／Database Hash。此前实验固件未预置这些能力；当前旧 Mac 绑定需一次明确的系统忽略／重新绑定后再验证新服务。未经确认不删除系统绑定。

这是待验的迁移处理，不是通用固件升级机制。正式硬件发布前必须单独完成标准数据库变更、客户端订阅持久化、跨升级验证；在此之前不得承诺新增 GATT 特征能对已有客户无感升级。固定的管理消息协议允许后续业务在同一特征内扩展，但不替代该机制。
