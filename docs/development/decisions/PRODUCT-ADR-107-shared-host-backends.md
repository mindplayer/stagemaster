# PRODUCT-ADR-107：共享宿主与控制权后端

- accepted，实施前审查及软件增量验证完成；2026-10-03，基线 `b6b8fee`，main，当前会话单写者。
- 工单：[HOST-003](../tasks/HOST-003-shared-live-host.md)，接续 MIX-003，上一轮为已提交进展。

现有 Host 的线程、队列、超时、观察和关闭机制可复用，但其命令、快照和回执直接绑定单节目 Runtime。Runtime 的租约／严格序号／重复回执也与设备装载实现混合，若直接另写多来源宿主就会出现两个控制系统。

决定：抽取 Runtime 中无标准库、无分配的通用输入控制权容器；保留原公共类型默认参数和设备行为。宿主通过明确后端契约接收不同命令／快照／回执／帧元数据，默认 API 仍为已载入设备播放器，默认操作仍只允许播放控制，不能借泛型放入读取／安装操作。只有一个原有 worker 调度实现、队列和关闭机制。

新增多来源适配器持有 MIX-003 的 Session，复用同一个控制权容器，使用有限容量的属性批量载荷和固定快照；组命令、回执上下文、单一单调时间与帧错误均从该后端进入同一 Host。来源选择和启动身份绑定，掉线／租约结束只结束输入权，不停止来源。商业授权、认证网络和物理输出许可保持独立；不把控制租约当商业限时或认证证据。

验证必须同时覆盖旧设备路径和真实多来源后台线程：客户端消失后动态效果继续、明确接管、旧租约／重复冲突／过期上下文／过期排队命令拒绝、重复成功回执不重放、停止只释放目标来源、故障撤回有效观察与明确关闭。共享的无标准库变更做 Xtensa 编译保护。此次不操作用户工程、窗口或硬件；HTTP／桌面协议迁移仍需后续独立入口验收。

实施结果：上述机制复用原 worker 和抽取后的 Authority，未引入第二条控制循环。6 项新适配测试、842 项全工作区测试、2 个文档示例、严格 Clippy／fmt 与 Xtensa 编译通过，审查接受此库级增量；结果和限制见工单。HOST-002 的现行单节目 HTTP 协议继续有效，多来源应用协议尚未实现，不能把当前验收扩展解释为完整桌面或物理输出交付。
