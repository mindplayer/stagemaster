# ADR-024：灯具模式与配适工作流

2026-09-27，接受。FIXTURE-002，基线 a92e5cb。当前会话审查后实施。

现有场地、编排与 UE 已可联动，但正式 UI 只能添加两种通用模式，是接入实际灯具的直接障碍。本轮优先补项目内灯库和换灯／配适，不扩张未经实现的摇头灯语义。

参考 [Titan 配适](https://manual.avolites.com/docs/quick-start/patching-fixtures/)与[换灯](https://manual.avolites.com/docs/patching/changing-the-patch/)：按厂家／型号／模式选择，查看地址占用，明确换灯，工程锁定档案副本。参考 [GDTF 通道定义](https://www.gdtf.eu/gdtf/file-spec/dmx-mode-collect/)：逻辑属性与物理通道分离，粗／细通道按有效位序定义，不要求相邻。只复用机制，不宣称 GDTF 导入或复杂通道兼容。

- 持久化继续复用现有 Profile，新增独立 Rust fixture 模块及 `op: fixture` 命令域。UI 的通道号从 1 起，核心转换为 offsets 从 0 起；16 位仍为 u16-be，offsets 顺序为粗／细。细通道可在粗通道之前，不需新增小端编码。
- 首次编辑器支持物理调光、完整 RGB、调光＋RGB；默认值 0–65535。空余通道明确输出 0，不提供频闪／复位／电机的伪线性属性，也不伪造 RGB 虚拟调光。以后非线性功能与位置能力沿 ADR-009 独立扩展。
- 模式包含名称／厂家／型号／模式／完整占用宽度／属性映射。新增与复制均生成新 id 和 revision；仅未使用的模式可原位编辑。使用中必须另存并显式替换，旧模式不自动改变任何工程灯。
- 显式批量换模式仅允许相同受支持属性集合，保留灯具 id、名称、域、场景／预设／效果／组／灯位和挂接。可保留地址或明确按顺序重新配适；占用扩大产生冲突时整批拒绝，不删记录、不自动占用其他线路、不自动停放灯具。
- 配适 UI 提供线路占用图、地址范围、搜索多选、批量连续改址和可用空间建议。Rust 进行最终边界／冲突／引用校验；错误包含灯名与地址。
- ProjectView 增加 profileId 与完整模式只读投影。现有文件格式、能力声明、播放时钟不变。RGB-only 档案加入已有三维颜色投影（无物理调光时强度为 1，黑色不发光），不改变 UE 帧协议。
- 所有变更经过 Session 原子历史、错误保留、取消、保存重开。模式面板使用正式工作区，草稿参与保存／导航检查。无真实 DMX 操作、固件或新依赖。

审查：线性档案格式已可表达本轮范围，无需另造文件；使用中不可变＋显式换灯避免修改灯库意外改节目。严格同属性换灯避免 silent loss；更广泛属性映射、跨工程个人灯库/GDTF 导入、轮盘/快门/关节和实灯测试仍后续。实际验证记录在工单。
