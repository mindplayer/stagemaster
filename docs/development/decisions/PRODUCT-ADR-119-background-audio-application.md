# PRODUCT-ADR-119：独立应用中的音频所有者

- 状态：accepted，独立应用增量已实现并通过软件验收；TIME-001，基线 `8de06bf`，main，当前会话单写者。
- 上一回合为 progress，原生静音挂载与固定输出绑定已验证；完整目标保持 active。

## 决定与边界

复用 ADR-117／118、原执行进程、原控制会话和 Rodio 音源，实际组装后台媒体所有者。它持有固定工程、运行目录内校验过的资源、Transport、准备器和原媒体端口；不取得操作者租约，不在 HTTP 参数解析或灯光主调度中执行音频操作。

1. 来源清单增加显式版本 2：一个 `audioTimeline` 来源绑定工程音乐，音频输出必须明确选择 `systemDefault` 或 `software`。软件输出实际拉取 Rodio Mixer 的 PCM，并按本机时间推进，不能标为声卡／音箱呈现。旧版本 1 保持；首个应用增量支持普通音乐，已启用的演出循环明确拒绝，继续后续迁移，绝不静默忽略循环。
2. 准备阶段校验并复制随附资源到私有运行目录，后台运行不再依赖原工程／随附目录。编译、音源准备、输出操作和回收在媒体工作线程；灯光仍由原 Host 唯一调度。
3. 媒体请求走同一受保护应用入口、控制权、修订和去重回执，携带观察到的组播放代次；状态包含请求接纳和实际完成。成功提交投影为 accepted，不能用 applied 表示音源已执行。新意图替代旧准备，过时请求不得启动音源。
4. 先静音挂载，取真实健康帧准备／激活该组，确认激活后才播放；暂停／定位等实际回调确认后报告完成。常驻提供方不随控制客户端退出或租约到期停止。组失联或音源失效须停止该音源并报告故障，不默默继续声光错位。
5. 增加可信提供方结束入口，固定一个待处理终态槽，按当前播放代次释放该组并记录自然结束／故障原因；请求保存完整组键，已完成回执在所属组中只保存代次和结果以限制快照体积；主线程只 try_lock。旧代次终态不能影响新播放，来源所有权不因自然结束而泄漏。该入口不用于操作者绕过控制权。
6. 输出设备、请求／准备、观测和错误分别管理；忙观测不能替换为新时间戳，停止状态不能伪造实际消费。自然结束、停止和提供方故障分别可识别。关闭后台时先通知媒体退出／取消，再关闭原 Host，回收音源、编译计划与线程。
7. 本机应用 API 的新媒体能力先用真实独立进程验收，再迁移桌面。标准 GUI／旧客户端不会因这项提交自动获得音频控制；演出循环、提供方自动重启和跨设备同步仍须继续完成。具体商业加密授权仍后议，不增加限时规则。

具体清单与状态契约见[独立应用后台音频](../../module-api/background-audio-application.md)。本增量定位末尾明确拒绝并通过 `seekIncludesEnd: false` 声明，完整末尾定位继续后续，不截断为其他位置。

## 验收

真实子进程与实际 WAV／Rodio 软件输出验证：原受保护会话播放、暂停、定位、停止、自然结束，控制端离开后继续；原工程和素材移走仍可执行；旧代次、越界、缺失／损坏资源拒绝；后台正常关闭释放线程和运行发现记录。独立灯光来源继续，命令接纳与实际输出观测分开。只选择显式软件输出，不自动开启物理声卡或灯具。

验收结果：220 项相关 Rust 回归、最终 8 项进程专项、全工作区严格 Clippy／fmt 通过；过程问题、日志与剩余出口见 TIME-001。终态回执缩减身份冗余，主调度未增加动态分配。客户端／桌面迁移、循环／末尾定位／重启与云端交付仍未完成，不能据此关闭完整工单。
