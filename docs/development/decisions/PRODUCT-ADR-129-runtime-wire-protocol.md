# PRODUCT-ADR-129：有界设备运行消息

状态：accepted，协议与工作器适配增量已实现并验证。2026-10-03；基线 `61047e8`，main；DEVICE-003 第三增量，当前会话单写者。

## 依据与取舍

ADR-128 已证明原工作器的运行调用语义。完整内部 Reply 同时包含状态与最多两段 512 字节文本，不能直接冻结为安全记录。复用当前传输层的 minicbor（已有精确版本）、固定数组／严格解码、已认证会话关联和有界单记录机制；不另造加密、无线分片或序列化库。SMAP v1 的安装就绪仍按原维护工作器确认，不将其权限提升为运行。

## 决定

1. 新增 no_std 的 `stagemaster-runtime-protocol`，只依赖原 runtime／install／package 与既有 minicbor；没有认证、工作器、UI、驱动或分配器调用。共享操作数据从 install-worker 搬至该模块，旧 operations 路径重导出保持调用兼容；Connection、权限检查、执行和缓存仍属于工作器。
2. 采用独立 SMRT 消息族、固定 8 字节前缀和定长 CBOR 数组。协商请求、就绪、运行请求、回复分类型；严格拒绝未知版本／类型／保留字段、数组长度、尾随内容、无界数组、错误枚举和超限文本。所有消息最多 1,280 字节，沿原安全 Message 承载，不混用安装消息。
3. 协商在已确认安全通道内完成，客户端提供版本范围和消息预算；设备就绪回执关联 device／boot／连接代次／安全 session／主体／许可修订，声明实际允许范围与剩余开发许可。解码和相关性检查不构成授权；准入和逐次撤销仍由真实 Session 提供。安装凭据不默认获得运行权，也不公告物理输出就绪。
4. 请求复用同一应用序号、业务修订及类型化动作。回复回显完整请求和观测时点。状态／操作回复保留完整软件状态与成功／业务错误；目录／步骤回复只带版本化观测、数量与单条内容，避免复制完整状态超限。客户端必须先关联本次请求，不把历史观测当实时或物理回执。
5. 固定文本完整保留，步骤名称与编号均按现行最大 512 字节设计；最大字段实测证明满足记录上限。协议模型不输出核心私有令牌或接受远端静默确认。
6. 此增量验证编解码、协商关联和加密消息往返调用原工作器；正式 Channel 的运行握手、无线队列、固件调度、客户端状态与 UI 后续接通。不得仅凭序列化单元测试宣称远程运行完成。

## 出口

协议对照字节、所有动作／状态／错误、最大文本和数值、截断／尾随／未知与旧安装消息拒绝；真实加密会话中的请求→原工作器→回复、重复执行保护、断线自主运行及观察权限隔离。保留已有 58 项工作器回归。宿主与 Xtensa 编译、严格检查通过后集成；不刷机，不操作真实灯具。

## 实施结果

13 项协议专项、3 项加密工作器专项与原有相关测试共 74 项通过，0 失败／忽略。最大步骤页包含两段 512 字节文本和最大索引／计数，实测 1,142 字节；逐位变异中可接受的消息能再次完整编码，不接受坏 UTF-8、无界数组或超长文本。加密重试没有新建运行实例，断线后自主执行保持，完整软件灯值与独立 Player 一致。

全工作区全部目标严格 Clippy（application）、Xtensa application-gatt 严格检查通过，未刷机。依赖只加入本地协议 crate；宿主与固件锁文件没有第三方版本变化，minicbor 复用原精确版本。实现／测试文件均低于 300 行。正式 Channel 运行握手／无线队列／固件调度／桌面与真实输出仍待接线，见[工单](../tasks/DEVICE-003-remote-runtime.md)及[字节契约](../../module-api/device-runtime-wire.md)。
