# PRODUCT-ADR-151：后台手动编程器边界

2026-10-04，接受；EXEC-007，基线 `cd48397`。

参考 [grandMA3 编程器](https://help.malighting.com/grandMA3/2.5/HTML/operate_programmer.html)：选灯、持有属性与释放独立，逐属性移出和清空编程器有区别。本项目使用显式中文动作，不照搬多次 Clear 的隐式阶段。复用已有 semanticManualPatch／FunctionTable／来源混合与控制回执。

后台目录是固定运行工程的权威来源。客户端接收原 fixtures 和 limits，手动输入按后台灯具能力交集；轮盘只有完整功能定义一致才能批量同选。编辑工程或选中场景改变不会替换后台对象。功能通道明确 functionKey／区间位置，不能用任意 DMX 或百分比绕过类型。

只读扩展 `manualOwnership` 能力，手动来源状态新增 `held` 目标数组（fixtureId／attribute），普通来源不携带。原 live SourceInfo 增加可空 512 位持有掩码，从原稀疏贡献读取；零值仍持有，未拥有则无位。固定大小、无逐帧堆分配，原 Copy 状态和单一调度保持。应用在观察投影层按准备时的映射转换成语义目标，不向外暴露内部属性下标。不引入另一份可写影子状态，也不将最终混合输出称为手动持有值。

界面先提供选择灯具、选择共同属性、明确待设置值、原子应用、所选属性释放、整层释放确认。持有目标来自实际快照；待设置输入不宣称当前实际值。搜索不丢隐藏选择，改变目标／属性需先处理草稿。按原请求字节上限与条数上限完整预检，超出拒绝，不静默分批冒充原子。过期身份／修订继续由 Rust 拒绝。成功回执只能清除对应提交的草稿，新的输入与失败保留；隐藏禁用控制并取消整层确认。手动改变运行状态不写工程、不进入编辑撤销；取消尚未应用输入无副作用。

兼容：协议仍为 2，可选能力只读扩展；旧宿主可继续节目播放，无完整目录／持有能力时不提供新的手动编辑。新声明能力必须有完整有效的持有状态，否则客户端拒绝观察。跨机、物理输出、生产安全不因本增量宣布完成。
