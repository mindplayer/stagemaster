## 触发与成熟经验

用户提出将 ESP32、未来 ARM 盒子和带推子／旋钮的一体化控台视作同类设备：当前软件形成共享基座，未来按硬件放入不同业务与展示模块。采纳“共享平台、组合产品”的方向；设备属于同一管理体系，但是否能编辑、计算节目、独立播放或只转换输出，需要分别声明。

用户随后明确未来云端与 U 盘共存，以兼顾商业化和稳定性；采纳两种交付入口并行，统一内容验证、安装与授权边界。

官方资料核对（2026-10-02）：

- [grandMA3 2.4：网络与 DMX 输出](https://help2.malighting.com/grandMA3/2.4/HTML/qsg_output_dmx.html)明确 onPC 的计算主机是电脑，控台方案由控台担当计算主机；物理端口与网络 DMX 节点负责相应输出。可借鉴计算、操作和端口的分工；不能据此认为所有 Node 都能装入完整工程自主播放，也不照搬其商业解锁规则。
- [Avolites Titan 17：T1／T2](https://manual.avolites.com/docs/17.0/about-the-consoles/t1-and-t2/)说明 USB 接口配合电脑上的 Titan Go 工作；其功能与控台软件一致，界面用虚拟推子／按键适配操作方式。借鉴同一业务能力配不同操作面，不能把 USB 接口误作完整节目播放器。
- [Avolites：跨电脑／控台搬运工程](https://cont.avolites.com/faq/how-can-i-move-my-show-files-to-another-computer-or-console/)说明可经 U 盘转移兼容版本的工程。U 盘是内容载体，载入后的执行仍由相应主机承担；USB 存储、USB 外设连接和 DMX 输出不是同一种职责。

上述为公开功能证据，不推断厂商内部线程、模块源码或性能。下面的产品组装是本项目决策。

## 架构决定

StageMaster 形成可持续交付的共享软件平台，当前桌面版是平台的一种产品组装，也承担开发验证入口。它的工程语义、执行核心、应用接口及可复用组件进入各产品共同依赖；新硬件不复制整个桌面工程后另行维护。

采用职责组合，避免一个包含全部方法的通用 Device 大类。硬件身份、连接端点、可运行服务、能力预算和当前角色分别管理：一块主板可运行多个服务，一台控台也可包含计算主板、输出控制器与面板控制器。设备具备某项功能，不等于当前已激活该角色或拥有输出权。

| 产品形态 | 按需求组装的模块 | 执行归属与限制 |
| --- | --- | --- |
| 电脑工作站 | 工程编辑、编译、现场控制、执行宿主；可选音视频、预演与输出适配 | 可本机计算并连接输出节点，也可编排后部署到独立盒子 |
| ESP32 播放盒 | 受限执行器、安装／本地存储、DMX 输出、设备管理；可选本地按键 | 执行能力预算内的目标包；不携带完整编辑器、媒体或 UE |
| ARM 播放盒 | 执行宿主、存储和设备管理；按能力增加媒体、输出和简化界面 | 可独立播放；ARM 架构名称不保证媒体性能或 DMX 接口能力 |
| 纯输出节点 | 接收帧、端口调度、协议／电气驱动、状态管理 | 上游负责节目求值；没有播放器就不能因断网自动继续完整节目 |
| 推子／旋钮扩展面 | 输入驱动、映射、接管与权威反馈 | 连接本机或远端执行服务；只有控制面并不代表拥有执行器 |
| 一体化专业控台 | 编辑／现场界面、硬件控制面、执行宿主、存储、输出；可选媒体与预演 | 可把多个角色组装在一个机箱内；重渲染和界面不成为实时输出依赖 |
| 平板／手机 | 共享客户端与适配交互；按实测能力增加本地编辑、编译或执行 | 可遥控，也可承载本地服务；后台运行与输出能力须按操作系统验证 |
| 专业预演工作站 | 场地／资源、仿真、渲染与只读状态接入 | 可观察本地或外部执行源，不因具备渲染能力获得物理输出权 |

表内均为部署方案；未验证组合不标为产品已支持。不要求同一二进制、相同操作系统或相同进程拓扑。可复用的 Rust 核心与受限执行子集遵循共同语义与一致性用例，目标适配分别构建。TypeScript 界面只进入需要它的产品，UE／媒体／云端依赖按需部署。现阶段采用显式依赖和构建组装，不前置动态插件加载器或通用模块市场。

## 必须分开的运行路径

1. **主机现场执行：** 电脑／控台加载工程并准备计划 → 主机执行器求值 → 输出节点发送 DMX。输出节点不必理解完整工程；失联后依声明策略处理，不能声称自己继续推进节目。
2. **设备自主执行：** 编排端按目标编译 → 经有线、无线或存储介质搬运 → 设备校验、安装、准备 → 本地执行器推进并输出。控制端退出不等于停止；断线后能继续多久还受已验证内容、时间来源和许可约束。
3. **同机组合：** 一体化控台把编辑、控制面、执行与输出组合在本机，仍沿同一应用边界调用；不为实体按键另写一套播放语义。

一个设备可以具备前两种能力，但同一物理端口在同一时刻必须有明确的输出权威。模式切换是显式准备／接管，需使旧来源失效；未来多执行器混合先在拥有输出权的合成层完成，不能让网络帧和本地播放器竞相写端口。自动故障接管另行验证，不能把保活等同于无缝接管。

传输、内容和时间独立：BLE／以太网／USB 是连接选项；工程、执行包与媒体是不同内容；逐帧流、控制命令、安装数据有不同预算。无线低带宽不限制已安装节目的本地刷新，但逐帧无线模式需要额外的带宽／抖动证据。现有 BLE 安装通过不证明该模式可用。

## 能力、文件与商业边界

- 设备描述至少区分稳定身份、连接代次、服务／契约版本、编译档位、内存／存储／并发／端口预算及已验证组合。UI 可据此展示能力，但编译／安装／准备入口必须再次验证，不能相信 UI 隐藏了按钮。
- 工程保留统一可编辑意图；发布过程按目标生成明确版本和依赖的执行包／资源。完整工程能在兼容编辑端流转，不代表 ESP32 可以直接解析或执行任意工程。U 盘与云端下载都须经过同一内容校验和激活边界。
- 硬件能力、已部署模块、商业许可及当前控制／输出权分别校验。云端管理资产、发布和许可，设备报告实际运行事实；用能力不足的设备购买许可，也不能获得不存在的算力或接口。
- 推子／旋钮和触屏共享语义命令与权威反馈，保留拾取／接管机制；机构互锁、急停和实际设备保护依既有专项边界，不能并入普通灯光默认值。

## 云端与 U 盘并行交付

云端承担账户、版本、资源分发、许可签发与交付记录；U 盘承担本地工程／发布内容及适用授权凭据的搬运。两者进入同一导入／部署流程：识别内容与目标 → 校验完整性、版本、资源和许可 → 安装到本地 → 准备 → 显式激活。内容身份按发布版本／摘要确定，不依赖下载 URL 或磁盘路径；同一版本经两种入口重复到达，不能成为两份不同节目或重复激活依据。

现场正式播放默认使用本地完成准备的内容，避免依赖云端持续在线或 U 盘持续插着。若未来提供直接从外置介质播放大型媒体，它必须是另一个显式能力，单独验证拔盘／读取故障，不能把导入成功当作素材已留在本机。运行版本与待更新版本分开；中断下载、导入失败或资源不齐不能替换当前可用内容。云端不可用时已有授权与完整本地内容仍按许可规则运行，后续再同步实际交付状态。

两种入口不改变授权期限。沿用用户已明确的“当前文件临时离线 24 小时、提前提示、允许本次节目结束、随后禁止新播放”语义；复制文件、换 U 盘、重新导入或修改本机时钟都不能成为重新授时或续期依据。许可应绑定既定内容身份和许可作用域，设备端独立验证；永久离线销售、生产签名／密钥、可信计时、断电防回退及循环节目收尾仍需 AUTH-001 决定并实测，不把介质可读视为播放获准。当前没有因这项决定新增永久离线授权。

U 盘接入也是目标能力：电脑／合适的 ARM 或控台可提供导入服务；现有 ESP32 不因有 USB 插座就视作已具备 U 盘主机、文件系统和供电能力。初期可由电脑读取 U 盘，再经既有安装链给 ESP32 下发执行包，不强制所有盒子直接插盘。网络、U 盘、蓝牙均不能绕过同一受验的安装与激活边界。

## 当前实现与接续

当前已存在受限工程编译、执行包、设备安装／运行核心及独立调度宿主库；完整可组合设备平台尚未完成。HOST-001 是一种有操作系统的宿主实现，不能要求 ESP32 运行 std 线程、Tokio 或桌面网络栈。

HOST-002 继续验证实际工程 → 独立执行进程 → 控制客户端断开／重连，是电脑／ARM 类宿主边界的首个证明；本机 HTTP 仅为一个适配器，不作为所有设备必须采用的协议。再以第二种软件承载检验既有设备契约，随后推进端口控制权和多执行器边界。将来依据实测补独立播放、纯输出、控制面组合验收；不因本决定批量开发所有硬件版本。

验收需分别证明：客户端退出后自主执行继续；纯输出节点失联不会伪报独立播放；切换输出来源后拒绝旧指令；相同受支持节目在不同执行档位结果一致；超出能力明确拒绝；禁用预演／媒体模块不影响纯灯光链。分发阶段再验证云端／U 盘导入同版内容的一致性、重复／中断／缺资源保护、本地完整准备后断网拔盘继续，以及复制／重导入不能重置许可。真实硬件和物理输出继续按具体工单与授权验收。
