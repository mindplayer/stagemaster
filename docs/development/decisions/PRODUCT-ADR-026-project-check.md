# ADR-026：工程检查与问题导航

2026-09-28；接受。CHECK-001，基线 `3c322e6`，干净 main，当前会话实施。

沿用 PLAYER-001 的工程／执行计划／设备安装边界。参考 [Unreal Map Check](https://dev.epicgames.com/documentation/unreal-engine/map-check-errors-in-unreal-engine) 的集中错误与警告、对象关联机制，复用本项目真实 Rust 编译器、播放容量常量、编辑队列与历史，不另建界面编译器。

- `Document::check` 是独立、只读工程服务；接收已经通过格式和引用校验的 Document，检查全工程配适条件，逐项编译场景和列表。一个节目失败不终止其他节目；共同配适错误使节目显示“受配适阻断”，不堆叠相同错误。空工程不算通过。
- 报告含稳定问题代码、中文信息、级别、对象位置、每节目结果与真实计划统计。容量上限来自执行器；数值缓冲和效果数据字节分别标明范围，不当作设备文件体积或整体内存测量。不保留编译出的所有计划。
- 桌面宿主按 generation 抓取 Document 副本，释放会话锁后执行检查。独立并发门限制同时一份报告；检查不更改历史、播放快照、工程和文件。报告附宿主 generation；编辑、撤销、保存或重开后，旧报告一律不能代表当前状态。过期报告可读，定位禁用，复查重新捕获快照。
- UI 独立工程检查组件位于“工程”；检查与定位先处理草稿，校验失败保留输入并定位原字段。异步检查期间可以编辑；完成后按当前版本判断是否过期。取消仅放弃本次结果，不冒充终止已经运行的编译。问题与节目可搜索／筛选／定位；导航复用工作区选择，不自动播放。
- 电脑通过仅表示现有单域单线路编译成立；灯具缺少舞台位置是预演警告，不阻断电脑播放。设备执行包／安装尚未实现，由宿主明确声明不可发布，不由纯工程核心推断板卡能力。不得显示“可下发”、虚假硬件容量或可点击的空导出入口。

工程持久格式、控制权、时间语义和真实设备权限均不改变。当前检查不涵盖真实灯具接线、光学校准、现场负载和设备安装；后续目标适配器追加独立验证，而不复用一个含糊的“全部通过”。
