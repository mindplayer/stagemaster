# PRODUCT-ADR-007：先确立效果编辑体验，再扩展业务能力

日期：2026-09-23。状态：执行顺序与职责已采纳；具体视觉候选待用户反馈。负责人：当前 Astra 会话。

## 背景

DESKTOP-001 已完成真实灯光编辑与保存，但默认界面按配适／场景／工程数据分类，偏离用户此前认可的舞台画布与剪映式编排。用户最新明确要求重新定义好用的界面，尤其重视效果编辑，暂不急于扩展业务层。

## 决定

1. 当前下一项调整为 UX-006：定义编排界面、选择／修改范围、时间操作和效果塑形，并提供静态视觉候选。场景列表／时间线领域实现不抢在这一轮设计前推进。
2. 默认工作流围绕舞台选灯、效果调整、时间安排和预览。配适／工程管理作为辅助入口；已有真实功能保留，不因重做布局推翻 Rust 工程／存储模块。
3. 效果编辑同时表达时间变化和灯具顺序。编辑上下文、预览状态、运行状态分开；视图切换不产生隐含运行副作用。
4. 用户希望功能逐步丰满，因而只定义足以稳定后续演进的交互原则。暂不实现全套效果引擎、节点系统、任意工作区框架或全部端的布局。
5. 设计稿与正式产品分开。正式入口仍遵循 ADR-006 的真实能力原则：无虚构设备状态、预置展示节目、教学展板或空壳按钮。
6. 按用户本轮补充，将 UE 专业预演与空间搭建纳入舞台视图的扩展目标，复用既有独立渲染后端方向。UE 中的选择／变换通过稳定 ID 和编辑命令返回工程；不接管效果时钟或现场输出。不在本轮安装或接入引擎。

## 影响与审查结论

本次改变任务优先级和界面组织，不改变首版软硬件交付目标、技术栈、工程 Schema、公共 API 或播放语义。界面设计中关于复制、相位、裁切、关键帧及合成的意图，不自动成为领域契约；进入实施前按原流程形成精确说明和保护验收。

无需等待新的业务模块才能研究和选择布局；需要真实灯光求值时必须回到 Rust 核心，不以界面动画补成另一套引擎。已有 43 项 Rust 与 15 项 UI 回归保护继续有效，本轮仅设计资料不重复运行。
