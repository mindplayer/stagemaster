# PRODUCT-ADR-052：设备分层内存与宿主音频同步

日期：2026-09-29；PLAN-002；基线 `5e7f204`；主工作区，当前 Astra 单一负责人。
状态：接受方向；本轮仅设计审查，未启用 PSRAM、修改固件或实现媒体播放／跨端同步。实施顺序和验收见 [PLAN-002](../tasks/PLAN-002-memory-audio-boundary.md)。

## 需求与范围变化

用户要求充分利用板载内存，近期由电脑／手机经有线音频或系统蓝牙音频向音箱播放，ESP32 执行更丰富的灯光节目，达到经过测量的近似同步；以后可把音频文件放入有较大存储的 ARM 播放盒，在盒子本地放音。用户提到 K11，但具体厂商／型号、架构、SDK 与音频能力尚未核验，不将名称当能力证据。本决定对旧“正式音频全部由外部软件播放”的边界增加**可选独立基础播放适配**：素材解码、播放和音频输出由实际执行端负责；不把 DSP、专业混音或视频合成并入灯光核心，外部 QLab／媒体服务器路线继续有效。

当前 ESP32 产品档位不接收音频流、不充当音箱网关；这不是宣称所有 ESP32 都无法存音频，而是本项目按存储、解码、音频硬件、实时性和交付成本选定的职责。音箱连接走电脑／手机的系统音频路由；ESP32 的免系统配对 GATT 控制连接与它是两条独立通路，不能把盒子的免配对要求套到音箱。系统音频组件与成熟库优先，Rust 权威调度、TypeScript 界面的职责不变；具体跨端播放库另行验证后选定。

## 执行端与资源部署

| 部署方式 | 音频文件／播放归属 | 灯光执行归属 | 时钟与操作端 |
| --- | --- | --- | --- |
| 当前 ESP32 组合 | 电脑／手机本地文件、系统音频路由 | ESP32 本地节目与 DMX | 音乐组参考放音端，跨端测量映射；编辑端同时是放音端 |
| 未来一体播放盒 | 有明确解码／音频输出能力的 ARM 等盒子本地持久存储和放音 | 同盒可用 DMX 适配，或独立输出节点 | 同盒仍需映射音频时钟与灯光时钟；手机／电脑可仅作编辑及遥控 |
| 混合现场 | 独立音频执行端或外部播放器 | 一个或多个独立灯光节点 | 同步组指定一个参考时钟；不能因设备联网就宣称已同步 |

工程的音频资源与灯光编排不写死 CPU、端口或本机绝对路径。部署绑定另选 `audioExecutor`／`lightingExecutor`（仅职责名，非现行字段），目标声明支持的编解码格式、音频输出／路由、预加载／定位／循环／定时能力、时钟反馈和可用存储／内存。即使是 ARM 或磁盘很大，缺少音频硬件／驱动／可用接口也不能成为放音端。

音频资源清单使用稳定资源身份、摘要、字节数、格式／时长及必要版本；各执行端独立报告缺失、传输、校验与准备状态。云端下载地址／访问凭据不写死在节目中，文件数据传输与播放控制分开。资源必须先在实际执行端持久保存和验证，完整的“灯光包已安装”不代表“音频也就绪”。盒子按容量可流式解码／有界预读，不把整首解码 PCM 常驻 RAM；8 MB PSRAM 也不能替代断电保存文件的 Flash／SD／eMMC。

手机／电脑遥控断开后，已经在音频盒和灯光端完整部署、准备并授权的节目可按既定政策自主运行；若手机本身正在放音，关机或音频停止就不能声称盒子会自动接管声音。音频执行端转移必须显式重新部署、准备、对齐位置和移交控制，防止双端重叠放音。本轮不实现迁移或无缝热备。

## 内存归属与容量

1. 板级内存模块负责探测、初始化、能力分类、分配与诊断；工程、编译器和播放器不引用 PSRAM 地址或具体 ESP32 驱动。
2. 内部 SRAM 优先承载输出时序、ISR／驱动必需数据、关键任务栈、通信控制和当前帧；关键路径不逐帧动态分配。内部总量还包含代码／静态数据等占用，不能将 512 KB 全部划为堆。
3. PSRAM 用于有预算的节目目录、可提前准备的计划／效果数据和缓存；在时间关键路径使用的数据须实测最坏访问成本。缓存关闭期间可能访问的栈、缓冲和状态不得盲目迁入 PSRAM。Flash 擦写继续遵循现有维护互斥，不因有 PSRAM 放开演出中安装。
4. 当前 128 KiB 堆、单节目 32 KiB 和装载峰值 64 KiB 是现有参考档位，不是最终硬件上限。先实测 PSRAM，再定义新目标档位；修改上限必须连同编译器、设备能力、解码校验与预算报告一起版本化，不给旧设备静默发送超限包。
5. 启动报告标称／探测／可用容量；运行报告按内存区域分开的当前和峰值占用、最大连续可分配块及栈高水位。预算包含装载临时副本、目录、分配开销、通信和节目切换峰值，保留余量；不把旧堆峰值与新增容量直接相加当安全证明。
6. PSRAM 缺失或自检失败时明确报告能力降低，只接纳仍满足内部预算的节目；不得让既有大包静默降级后尝试运行。支持可恢复分配失败，不以大容量掩盖泄漏或无界队列。

信息量主要随属性数、场景／曲线、节目长度和运行重叠增长，不能只用灯具台数估计。一条线路按每帧 512 B、40 帧／秒、10 分钟保存逐帧通道快照，需要 12,288,000 B（约 11.72 MiB，尚不含索引），已经超过 8 MiB。因此优先保存可重放的曲线／关键帧和必要事件，按窗口预加载，而不是预存全程 DMX 帧。预计算的节拍／标记可参与灯光编译，波形和音频正文留在宿主。

## 音频、灯光与时间

- 工程保存音频资源身份／摘要、裁切与时间线位置、循环范围、同步组及灯光关联；波形可重建。资源部署到实际播放音频的执行端。ESP32 灯光包只包含它能执行的灯光数据、时间标记及必要关联，不带完整灯库说明、3D 模型或音频文件；未来音频盒接独立资源清单和素材部署，不强塞进当前 ESP32 包格式。此处为字段职责，尚未修改 JSON 或包格式。
- 音乐驱动的同步组，以音频输出位置映射到宿主单调时钟；独立灯光模式使用设备单调时钟。一个组只有一个明确时钟负责人，不能由两个 UI 或手机／电脑同时发出互相覆盖的播放控制。
- 主机与设备交换带发送／接收时间的观测，估计偏差、漂移、往返延迟和不确定度；不能假定两台设备的时间戳直接可比，也不能把 RTT 除二当精确单向延迟。重启、休眠、重连和时钟代次变化使旧映射失效。
- 先完成音频预加载和灯光计划准备，再下发带节目摘要、播放代次、目标位置、设备开始时刻和截止时间的有界调度。设备报告已准备与实际执行状态；迟到命令不偷换为立即播放，准备失败不启动剩余目标。提交后部分失败仍须报告，不能假设无线跨端具有原子启动保证。
- 校准分别记录输出路由、系统延迟估计、人工／测量修正、依据与新鲜度。约定“正延迟表示输出比提交晚”：若声音晚 150 ms、灯光输出晚 20 ms，则为了同一感知时刻，应让音频提交比灯光提前 130 ms；这是解释符号的假设例子，不是本项目测量。计划预滚提供提前量，不能让已错过的声音倒流。
- 同时考虑长时间漂移、音频缓冲停顿和灯具响应差异。仅在允许范围内平滑修正灯光时间映射，不能为追音乐倒退设备单调时钟或重发离散动作；大幅跳时、暂停、定位、循环都产生新的播放代次并明确重算起点。机械动作／激光触发不因定位自动重放。
- 蓝牙音箱作为近似同步路线；有线／USB 音频作为首个测量基线。不给固定“蓝牙延迟值”或未测毫秒保证。音箱路由变化、来电、后台／锁屏及宿主休眠触发明确状态，旧延迟校准失效；Tauri／浏览器定时器不承担音频或 DMX 关键时序。
- 断连策略归节目：独立灯光可按已验证规则继续；音频跟随模式在有限失联窗口内续跑后，按明确配置保持或渐退，并报告同步失效。尚未测出失联窗口前不提供默认无限“仍同步”；重连先对账位置与代次，不从头重复执行。控制保活、时间同步与 24 小时文件授权保持独立，均不能互相续期。

## 模块与调用边界（设计草案）

| 模块 | 调用职责 | 状态归属 |
| --- | --- | --- |
| BoardMemory | probe／allocateByCapability／snapshot | 板级内存区、分配预算；无音频语义 |
| AudioOutputAdapter | inspectOutputs／prepare／schedule／pause／seek／stop／observe | 所选音频执行端的资源、输出路由代次、播放位置与时钟观测；电脑／手机／盒子适配不同 |
| ResourceDeployment | planForTarget／transfer／verify／inspect | 执行端独立资源清单与已验证素材；复用资源／传输层，音频就绪与灯光安装分开 |
| ClockMapping | observe／estimate／invalidate | 两个单调时钟域的偏差、漂移、不确定度与有效期 |
| TransportCoordinator | prepareGroup／scheduleGroup／reconcile | 组内计划、播放代次、准备与部分失败状态；复用现有 TransportCursor 设计 |
| DeviceRuntime | prepareProgram／scheduleStart／observe | 设备本地计划与实际运行；未来通过版本化命令接入，不改变现有未支持命令的含义 |

名称用于实施拆分，不表示已存在这些公开方法，也不预先新增空壳服务。复用现有 `ClockInstant`／`MediaTime`／`TransportCursor` 的时钟域和代次思想；设计草案与现有 GATT 协议分别演进。

界面落在现有编排时间线（音频轨／波形／标记）、设备面板（内存／能力）和播放输出组件（音箱选择／延迟校准／同步状态）。先交付真实音频与灯光闭环，再开放对应操作，不加入假波形、假输出或常亮的“已同步”。

审查结论：接受“充分利用内存＋近期宿主放音＋未来大存储盒子放音”的需求；采用按能力部署、分层预算和可测同步，避免大堆、整包常驻、CPU 名称绑定或同时发开始命令带来的返工。DEVICE-002 已完成的安装出口不变，本决定不代表 PSRAM、音频或实际 DMX 输出已实现。
