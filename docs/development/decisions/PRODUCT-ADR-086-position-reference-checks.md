# ADR-086：摇头灯参考点检查

2026-10-02；接受；POSITION-003，基线 `028362d`。承接 ADR-085，当前会话直接实施。

## 依据与边界

借鉴 [MA 位置校准](https://help2.malighting.com/grandMA3/2.4/HTML/patch_position_fixtures.html) 的已知世界点、逐灯对准及记录轴角流程。先建立可保存、可复查的输入和误差，再接拟合；本轮不是四点自动定位。用已有 glam 和同一 Rust 正向模型，不增加通用矩阵库或 UI 求解。

本轮的“记录参考点”保存的是操作者选择的世界坐标与当前场景轴设定，来源明确为 `sceneSetpoint`，没有实灯反馈或自动到位证明。现场应先用轴调整对准实际参考物再记录；离线录入可验证模型但不等于测量校准。场景效果控制的位置不能采样，拒绝旧运行帧／列表继承为依据。

## 持久数据与归属

- Fixture 新增可选 `positionReference`，版本能力 `lighting.position-reference@1` 必须声明。对象 `{profileId,profileRevision,points}`；每灯最多 16 点、整工程最多 1024 点，沿用工程 8 MiB 上限。点 `{id,name,targetMeters,panValue,tiltValue,source:"sceneSetpoint"}`；轴值来自 Rust 按真实 8／16 位读取，不能由前端伪造。世界米制坐标独立于场景，原场景以后改变／删除不改记录。名称非空且有界、点身份在工程内唯一，禁止未知字段和无效坐标。
- 记录属于具体灯具实例，删除灯具时随实例消失；未来复制灯具不得无提示复制测量记录。引用的档案身份／修订是历史标识，不要求历史档案继续存在。换灯／修改档案后保留点，但标记模式不匹配且禁止继续往旧记录采样；清除旧参考记录后才重新开始，单次撤销可恢复。
- 安装姿态／手工零偏变化后，用**当前**物理模型重新计算旧点的偏差；这用于检查调整前后变化，不改已记录设定。模式不匹配／无安装／无两轴模型时只显示保留的数据和明确原因，不伪造有效结果。
- 不改变场景、默认值、零偏、灯位、DMX 或三维；校验记录不进入执行包。旧工程字段缺省无迁移，旧读者依能力拒绝。

## 核心与接口

`IntersectingHead::check_reference(installation, angles, target)` 返回沿光束有符号距离、到**正向射线**最近点的米制误差、角误差与最近世界点。目标在后方不能因共线得到零误差；目标等于轴心拒绝。复用已有 ray，范围／有限性先检查。

`PositionEdit` 增加 `captureReference {sceneId,fixtureId,name,targetMeters}`、`removeReference {fixtureId,pointId}`、`clearReferences {fixtureId}`。前者在写入前校验静态场景来源、安装／模型、档案快照匹配、容量和唯一名称；只记录当前实际量化设定，零偏不写两遍。删除和清空也走工程原子历史。

FixtureView 可选 `positionReference` 包含原记录与 Rust 派生的检查结果／不可检查原因；无记录时省略。UI 保留单一工程快照权威，不读写原始 JSON，不算几何。界面放单灯位置的“参考点检查”，支持场地点选、精确 XYZ、命名、记录、逐点删除／全部清除、取消、撤销与重开。录入只是草稿，必须明确记录；切换上下文不会自动把未确认的参考点当成测量。

## 后续拟合约束

下一阶段才引入模型匹配的姿态／零偏拟合、样本分布、留出点和残差评估。安装旋转与轴零偏存在可互相解释的自由度，不能同时无约束拟合；先固定一种参数化与已知量，再选成熟数值实现。不得仅凭四个任意点或训练点误差小就报告校准合格。
