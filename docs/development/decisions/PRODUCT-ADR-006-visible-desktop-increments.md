# PRODUCT-ADR-006：以真实桌面工作流推进交付

- 日期：2026-09-23；基线：603f40f；状态：accepted
- 用户要求：桌面优先、可见反馈、持续迭代；按真实交付标准实现，不增加样例入口、演示数据或教学说明页。

## 决定

Tauri 2 薄宿主复用唯一 React 界面；TypeScript 负责显示和输入，Rust 负责工程语义、编辑命令、校验、修订与保存。平台 API 只在 ApplicationHost 适配器出现，工程模块不依赖 Tauri。原时间线交互原型及保护测试保留供后续接入，但不成为正式桌面入口，也不把模拟保存／执行暴露为产品能力。

DESKTOP-001 调整为真实最小灯光工程编辑闭环：空白新建、原生打开、命名、灯具配适、场景属性编辑、撤销重做、保存／另存为及重开。无预置节目，无假设备在线状态，无尚未接通的播放按钮。视觉沿用现有深色工作台；只显示用户执行任务所需的状态和错误。

新增独立 crates/stagemaster-project：严格 JSON 解码 → 嵌入既有 Schema 的结构校验 → 已实现灯光子集的领域校验 → 私有 Document；模块包含编辑命令与视图投影。当前支持归一化灯具档案、灯具、配适、灯组、预设和场景。场景列表、时间线、外部媒体、机构和扩展暂不接收；打开时明确拒绝，不丢弃未知内容后重存。工程格式仍为 0.1.0-draft.1，不改变既有时间和控制权语义。

新增存储适配模块负责限量读取、同目录临时写入、同步和替换提交；文件由原生选择器授权，不开放任意路径给前端。加载时保留磁盘基线，保存前比较，检测外部变更时拒绝覆盖。保存成功才更新基线和修订；编辑中的草稿与已保存修订分离。正常关闭、新建、打开都经过未保存保护；崩溃恢复与多进程协同写入另行实现，不宣称已具备。

宿主串行执行文档操作，命令带会话代次防止陈旧界面写入。撤销由 Rust 管理；UI 仅保留尚未提交的输入草稿。保存前先提交当前输入，避免失焦与快捷键竞争。JSON Schema 是结构约束单一来源；不另建 TS 文件解释器。

## 交付顺序

1. 本轮：真实工程和灯光编辑工作台；保存重开、错误恢复、未保存保护及本机 .app 验收。
2. PROJECT-001 后续：场景列表、渐变／延时、时间线编辑接入同一工程，补齐其领域校验与持久化；保留成熟拖动交互。
3. PLAYER-001：Rust 播放、离线预览和通道监视，继续区分编辑、预览和现场输出。
4. PLAYER-002–005：单路 DMX、编译下发和 ESP32 独立播放；授权按 AUTH-001 商业门槛另验收。

每轮交付能用的完整小功能；不为等待全部模块齐备而铺设空壳页面。

## 实施审查：空白工程与可执行工程

新建／保存测试发现格式草案把 entryPoints 的最小数量设为 1，导致用户还没有编排任何节目时无法保存。这混淆了可编辑工程与可执行交付包。调整未发布草案：可编辑工程允许 entryPoints=[]，Schema 的 minItems 由 1 改为 0；其他字段与版本不变，已有样例仍有效。部署清单与后续编译仍须指定存在、已校验且受支持的节目入口，空白工程不能发布或执行。增加独立的空白工程结构和保存重开验收，不削弱执行入口检查。
