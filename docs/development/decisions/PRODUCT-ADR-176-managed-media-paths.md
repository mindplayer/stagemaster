# PRODUCT-ADR-176：受管理音乐副本的普通路径边界

状态：当前实施会话接受限定方案，2026-10-06；实施 AUDIO-024。依据既有资源身份／归档机制与首版数据保护标准，不重开声音、播放器或存储选型。

## 事实与风险

`Resources.resolve`／资源检查使用会跟随符号链接的文件判断；`archive` 对已存在副本先验证摘要，`import` 在指定根目录创建临时文件并发布。若受管理缓存、`.assets` 目录或摘要文件被链接替代，现有实现可能把外部内容当作随附副本，或向链接指向的目录发布文件。先用项目内独立夹具实际复现，保留红灯，不从阅读代码直接宣称所有情况已验证。

## 决定

- 受管理命名空间仍为现有缓存根与 `<工程文件全名>.assets/<摘要>.<扩展名>`；目录祖先须为普通目录，摘要条目须为普通文件。显式拒绝符号链接（包括悬空链接）、目录型条目及其他非普通路径，不按目标内容摘要正确就接受链接。
- Resolve、只读检查、导入发布与归档共用一个小型私有路径校验。缺失仍是缺失；路径损坏在检查中为原 `invalid`，缓存优先与损坏缓存不静默切换来源保持；相同路径只校验／读摘要一次。
- 目录创建前后、目标复用／发布前重新核对，异常保留原工程、源文件和链接指向的目录／文件，不自动拆链接、删除或改权限。有效普通副本继续复用，损坏普通副本仍可由已校验原内容按原原子替换修复。
- 用户通过原生选择明确导入的源文件是读取来源，不等于受管理缓存。允许原有合法源文件链接经原有内容／大小／取消验证复制成普通托管文件；不一律禁用文件选择或改变资源身份。硬链接按普通文件处理，替换只替换受管理名称，不原地改写其余名称。
- 本增量是发现静态不安全路径并减少发布窗口，不声称抵御并行恶意进程在校验与文件调用间替换任意祖先。宿主私有目录、原子发布与现有单准备任务保持；完整 dirfd／平台安全存储及跨进程总预算另行评估，不虚构已经实现。

Rust 为最终判断；UI 沿既有资源检查／错误展示，不新增持久字段、接口、时钟、所有者或依赖。以前可用但靠链接提供的受管理副本现在须明确拒绝，可由用户选择安全位置或复制普通原文件处理；不自动迁移或覆盖。无音乐工程不受影响。

## 验证与边界

覆盖目录／祖先／条目／悬空链接、只读错误、发布原子保护、正常副本与普通损坏修复、源文件链接导入、取消、无资源与大小限制。原测试不弱化；相关 Rust／严格检查实际执行。正式内部桌面验证带音乐身份但不播放的检查与保存拒绝／安全路径恢复，真实声音、GPU、实物与客户资格仍独立。
