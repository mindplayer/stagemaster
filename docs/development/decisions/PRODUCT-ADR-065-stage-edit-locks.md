# ADR-065：场地对象编辑锁

状态：接受，已实施并验收；STAGE-002，基线 `c32eeb0`。

参考 [SketchUp Outliner](https://help.sketchup.com/en/sketchup/working-hierarchies-outliner) 的目录组织／锁定可见状态及 [Locking Objects](https://blog.sketchup.com/youtube-all-videos/locking-objects-square-one) 的防误改机制。沿用既有空间不是坐标父级、挂接桁架存在联动的契约，不照搬通用建模层级。

工程可选 `stage.editLocks: [{kind: space|construction|placement,targetId: UUID}]`，最多 1600 个唯一有效对象引用；非空须 `stage.edit-locks@1`。引用字段不用 id，避免与对象身份定义混淆。旧工程不补字段，清空锁时移除字段／能力。锁属于编辑规则，可撤销／保存，不是授权或保密措施，不影响编译／播放／灯光参数。所有者可明确解锁。

`StageEdit::SetEditLocks {targets,locked}` 单次接受 1–1600 个唯一有效引用，允许多灯一起锁／解锁；使用既有事务，一次撤销。读取和选择仍允许，复制锁住的空间／构件产生新身份且副本未锁；删除和参数更新被拒绝。空间锁定仅保护空间本身；空间成员可移动。支撑体锁定保护支撑体参数，但可挂接未锁的灯。灯位锁定保护位置／朝向／空间归属及挂接关系，桁架联动或空间删除会间接改它时整批拒绝，明确提示受影响对象。围护锁定还保护其依赖的空间几何，不能通过改房间轮廓绕过。

Rust 在每个编辑子操作前捕获已锁对象的受保护投影，操作后比较，失败由 Document 原子回滚；Batch 按子操作依次检查，显式解锁→修改→重锁可放同一事务，不能用“修改后再解锁”绕过。工程验证拒绝未知／重复／悬空引用以及缺能力数据；Schema、JS 审核同步。历史恢复由既有完整文档快照完成。

UI：目录标记锁定；右属性区提供当前单对象／选中灯具的锁定状态与显式锁／解锁；锁定对象可选择与检查，属性修改和拖动禁用。多选包含锁定灯时整体移动拒绝，不偷偷排除一部分。三维编辑仍经同一 Rust 事务，UI 同步禁用所选锁灯的移动授权。独立灯光编程不受影响。显示隐藏与本机相机仍是临时界面状态，不混入锁数据。

模块拆分：本次新保护／变更模块独立，超过 500 行的 StageWorkspace 抽出对象创建／复制／删除动作及相应对话框，保留工作区草稿和选择协调。既有 StageCanvas 约 470 行按相关手势提取锁定判断，不继续增长为综合编辑器。

未包含：任意复合对象、座区参数化、全三维组变换、图层权限继承。验收后继续补必要场地能力，不把锁定当作完整场地管理。
