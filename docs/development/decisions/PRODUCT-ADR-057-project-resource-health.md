# ADR-057：工程检查中的音频资源健康

状态：接受并实施；2026-10-01；UX-028，基线 `396de3b`。

## 问题与取舍

CHECK-001 的 `desktopReady` 仅证明灯光节目可编译。音乐在工程外，当前本机缓存能播放并不保证同名 `.assets` 文件夹可随工程交付。不能通过准备／播放音频来探测健康，否则可能重载并打断唯一音频会话。

借鉴既有内容寻址资产、保存时随附复制、内容摘要校验；资源检查复用 `stagemaster-audio` 的键校验、512 MiB 上限、16 KiB 流式 SHA-256，不重写解析器或引入资源数据库。可移植资源与本机运行资源分开报告；此次只覆盖已有音乐，不提前声称视频、云端或完整开演检查。

## 契约与归属

- 音频适配库新增只读 `Resources.inspect(digest, extension, project, cancelled)`，返回 `local`、`companion` 状态及本机来源；不会创建目录、复制、修复、解码、装载音频或修改资源。明确 `valid`／`missing`／`invalid`／`notSaved`，取消返回失败而非伪造资源损坏。
- 本机资源遵循现有播放相同的缓存优先解析规则；若缓存损坏而随附文件完好，仍如实显示本机损坏，不擅自更换播放来源。随附资源独立检查，未保存为 `notSaved`。
- 桌面 `check_request` 在同一 Session 锁内捕获 Document 与工程路径，然后锁外编译并检查资产。响应新增 `audioResource`（无音乐为 null），由宿主附加；不改变 `Document.check()`／`desktopReady`、工程 JSON、播放器或设备包。
- UI 将“电脑预览”明确成“灯光编译”，增设音乐文件与随附副本报告和前往音乐修复入口。采用同一 generation／草稿新鲜度保护；文件外部变化不会改变 generation，因此报告明确为检查时结果，需重新检查。
- 定位到既有音乐页后沿用该页准备与重新定位流程，检查本身不装载音频；完整性通过不代表声卡、听感或声光同步已验收。

验收含正常／缓存独有／随附独有／双缺失／损坏／无保存位置／取消／非法键；检查前后文件内容与音频运行不变；原生检查定位、修复后重查及过期报告保护。
