# ADR-053：本机音频卡点编辑

2026-09-29；已接受，由当前 Astra 审查实施；基线 `79b584d`。

用户澄清需求为剪映式音频卡点。首个可用增量提供单音乐轨、真实波形、播放／暂停／定位、缩放、时间标记及绑定场景、精确编辑、撤销和保存重开。音乐留在电脑，不下发 ESP32，不把电脑听感预览称为硬件声光精确同步。多轨混音、自动节拍检测及物理输出延迟校准后续独立实现。

## 数据和时间

现有 `timelines` 是通用动作／同步组草案，尚未实现，不能将单轨编辑伪装成完整调度器。以能力 `media.audio-editing` v1 增加可选 `media.audioEditing`：音频内容摘要／原始名称／格式／时长、源文件裁切起止、相对裁切起点的毫秒标记。标记可引用灯光场景，按时间排序、同一时刻最多一个标记；切换场景为隔离硬切，动态效果从该点重新计时。未绑定的标记仅作节奏参考。旧版本因能力不支持而拒绝，不静默丢音频。媒体外部系统／动作／监看保持原契约，当前读取仍拒绝未实现的部分。

Rust 工程模块拥有验证、引用完整性和编辑语义；波形与解码数据不进工程 JSON。宿主通过流式解码得到有界峰值缓存（20 ms 一格，最长 1 小时），不把整段 PCM 放进内存。单次导入有容量、时长和声道限制，取消不编辑工程。

音频源通过 SHA-256 命名的不可变资源缓存保存，保存工程时先归档到工程同名 `.assets` 目录，再提交 JSON；移动／发送工程必须携带该目录。恢复点使用本机缓存；缺失资源明确重定位且校验摘要，不偷偷替换音乐。导入／解码在后台、同时只允许一个准备任务；工程代次变更拒绝迟到结果。缓存与外部文件路径不进入公开工程格式。

## 执行与界面

复用 rodio 的流式 Decoder／Player、系统音频设备，默认设备打开失败不自动改选其他设备。Rust 宿主持有单一播放状态，界面仅发送操作／显示位置；试听位置驱动已有 Rust 灯光核心的场景／效果采样和 UE 预演。定位重建目标状态，不逐帧追赶历史。正常场景列表与音频试听互斥，换工程／关闭／改变音频会停止旧声源；编辑标记可保留当前听音。输出设备真实 DAC 时间与蓝牙音箱延迟尚未校准，不能作为远端提前调度的时钟证据。

界面使用独立音频卡点工作区组件、Canvas 有界波形、指针捕获／取消及键盘精确操作。音频导入不自动发声；只有用户点击播放才输出。

## 成熟经验及边界

- 剪映／主流非线性编辑器：波形定位、播放头、音乐打点与片段裁切；吸收交互，不引入混音／视频处理引擎。
- [QLab 时间线音频](https://qlab.app/docs/v5/audio/audio-cues/)：媒体源范围与执行时长分开，外部媒体路径不等于媒体内容身份。
- [rodio 0.22.2](https://docs.rs/rodio/0.22.2/rodio/)：复用成熟解码和设备适配，独立文件峰值处理。`Player::get_pos` 为软件消费位置，不声称等于扬声器到达时间。
- OpenTimelineIO 的媒体引用／源范围分工沿用 ADR-003；当前不宣称 OTIO 互操作。

验收须覆盖真实声音、波形／定位、标记增删拖动／取消／精确输入、灯光场景切换、撤销保存重开、资源缺失和错误输入；未通过项如实列出。
