# ADR-096：可保存演出循环与本圈结束后继续

状态：调度核心语义采纳；工程／音频适配待实施验证；AUDIO-020；2026-10-02；基线 `c8df526`，当前会话单写者。

AUDIT-001 U06 尚缺正式区段循环。AUDIO-005 的临时试听不保存、只能无限重复一个短区间，不能代替演出编排。本任务完整出口为可命名／保存／重开／撤销的区段、固定播放次数或持续循环、运行圈数、本圈结束后继续、音频和灯光共用真实原生游标。支持沿同一时间线顺序经过多个不重叠循环区段，不通过不断重启播放器或 UI 定时器回跳实现。

参考 [QLab 5 Audio Cues](https://qlab.app/docs/v5/audio/audio-cues/) 的区段和总播放次数，以及 [Devamp](https://qlab.app/docs/v5/other-cues/devamp-cues/) 的当前圈边界退出。参考 [grandMA3 2.4 Timecode Settings](https://help2.malighting.com/grandMA3/2.4/HTML/timecode_settings.html) 的时间源／循环／停止行为分别配置。采用本项目的原生音频时钟，不照搬英文操作名、外部时码控制或自动触发后续未知动作。

## 先确定的调度规则

- 区段为半开区间 `[start,end)`；开始处属于区段，结束处属于后段。按原时间线排序，允许相邻，不允许重叠／嵌套；最多 128 段。区段以外继续原时间线。
- 固定次数指总播放次数，1 表示经过一次。持续循环必须显式表示，不能用零次／负数／特殊字符串混充。完成固定次数后自然进入后段。
- 「本圈结束后继续」只针对当前运行区段；重复请求幂等，允许在到达边界前取消。请求绑定区段与播放实例，迟到请求不能影响下一段。在本圈末尾继续，不在点击瞬间跳走。
- 暂停保存位置、圈数与已申请的边界退出；停止归零并清除运行历史；显式定位是一次新的局部进入，当前位置所属区段从第 1 次计，之前区段不重放。编辑中的草稿和播放中的编排快照独立，不能暗中改变已运行循环。
- 灯光按音频实际消费的原时间线位置确定性重算；回环时回到该处的已编排效果进度。循环不隐式重放电机／烟火等一次性外部动作；本轮不扩充这些动作权限。

在 `stagemaster-playback` 增加独立 `LoopSchedule`／`LoopPlayback`，单位为调用方一致的整数刻度（音频适配用样本帧），不依赖 JSON、音频库、UI、UE 或设备。核心不读取时钟；`advance(delta)` 使用整数商／余数跨过重复次数，不逐圈追赶，不分配。非法时间／圈数溢出不改变原游标。音频适配必须复用此状态机和唯一消费游标，不能再写一套近似毫秒循环算法。

## 后续接入必须验证

工程将保存独立身份、名称、范围、总次数／持续方式、锁定／启用；能力声明、严格 schema、命令原子性、复制／批量、音乐裁切与资源替换都需显式检查。区段本身不复制音乐、场景或通道值。临时试听与正式循环必须明确互斥，不能叠加两个回环控制器。

持久字段为 `audioEditing.loopRegions`（省略等价空数组），元素 `{id,name,startMs,endMs,plays,enabled,locked}`；`plays` 显式为 `{kind:"count",count:1..4294967295}` 或 `{kind:"untilExit"}`。非空区段要求 `media.audio-loop-regions@1`；删除最后一段保留能力，移除音乐清除能力。全部区段（含停用段）都必须有序、互不重叠并在裁切后的音乐范围内，核心只将启用段编入运行快照；精度为整数毫秒，换算样本帧时端点使用同一整数时基，不能量化为零长度。

命令入口为 `AudioEdit::LoopRegions {command}`：`add` 由核心分配身份；`put` 更新已有未锁区段，不能顺带修改锁定／启用；`edit {ids,action}` 支持整组移动／复制（目标为最早所选起点）、删除、启停、锁定和播放次数。全部使用已有工程克隆校验与一次历史；复制保留相对间隔、播放方式和启停，生成独立身份并解锁。锁定批次可显式解锁，复制可读取锁定对象，其余修改包含锁定对象则整组拒绝。裁切保持与现有卡点一致的局部坐标，导致任一区段越界则拒绝，不静默删除或压缩；音乐替换沿用先移除再导入。编辑／运行快照失效和音频准备另由宿主处理，支持保存不能被当作已经支持播放。

原生播放需先完成有界准备：循环 PCM 总预算、线性前后段、失败保持旧可用状态、取消／过时准备拒绝；不得缓存整场一小时 PCM 或在每次回环时分配、读文件／定位解码器。连续过界、大步定位、暂停恢复、最后一圈、无限区段退出及多个区段都按样本顺序验证。具体解码组织在适配代码实施前审查，不把此文档当作已接通。

UI 提供时间线区段与独立编辑组件，常用范围输入、取播放头／所选片段、圈数／持续、锁定、取消、错误焦点、一次撤销、保存重开。运行区显示当前区段／第几次／已申请退出；不伪造含人工等待时的全场剩余时间。设备包、授权收尾和真实输出按各自契约后续适配，未支持目标必须明确拒绝，不能丢掉循环语义导出。

## 音频接入实施前检查点

现有 `Transport::pause` 通过记录毫秒位置再销毁 Player 完成，无法直接保留正式循环的圈数和退出意图。rodio 0.22.2 已有 `Player::pause/play/is_paused`；后续正式播放应利用保留音源的暂停路径，并调整 playing 判定，不将“队列非空”当作正在播放。源消费位置只表示软件消费，不能称为已校准扬声器时间。

循环区段缓存与线性前后段分开：缓存按所有启用段合计预算检查，线性段不能因演出很长而全量常驻内存；解码准备、失败／取消和过时结果须在工程互斥锁外完成。源样本选择和对外位置必须复用同一个 LoopPlayback，不能在音频源和界面各算一次余数。音频准备的具体队列、缓存大小和欠载策略尚待实现前最终确定，不能把这段检查点当作已经实现。
