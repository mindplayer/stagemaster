# PRODUCT-ADR-112：媒体跟随组与自主来源共用合成

- 状态：accepted，软件来源组增量已实现并验证；接续 TIME-001／ADR-111，当前会话单写者。
- 范围：先验证宿主内真实编译、播放器、属性合成及完整帧；不更改工程／设备包／网络协议，不声称音频硬件同步或完整 TIME-001 已交付。

## 取舍

沿用 GStreamer 的单调时钟、运行时间与素材位置分层（参考链接见 [ADR-111](PRODUCT-ADR-111-independent-clock-mapping.md)）。媒体组由外部已确认的消费游标推进，宿主自主来源继续由宿主单调时间推进。两者使用既有 Player 与 LiveMixer，不另建播放器、不把素材位置放进租约／请求期限。

本增量不推算声卡呈现时间，不根据未校准的游标盲目外推。短暂缺少观测保持最后贡献；达到明确失联上限后锁定为失联，需要准备新的播放代次恢复。设备适配以后可增加经验证的调度策略，不能默默改变本次语义。

## 运行契约

1. 准备时固定媒体组身份、提供方时钟、成员来源与观测预算。同一来源只属于一组；手动层不作为媒体组成员。原有 `Session::prepare` 继续创建自主来源。媒体组仍在同一 Session 的累计计划预算内。
2. 每组有执行实例绑定的键与播放代次。先取出不引用运行 Session 的不可变准备器，开始／定位再由独立工作线程编译同一不可变工程，使用既有 Player 从起点求得目标位置，得到不可伪造的准备结果；激活校验工程、组、旧代次、截止时间和首个观测。任何准备或输入检查失败均保留现行执行。
3. 成员一起切换到新代次，外部仍须分别报告音频／视频设备实际执行情况；这只保证本机组的一次完整合成，不承诺多设备原子开始。激活借用准备对象并把旧播放器交换回其中，成功或失败均由调用者在调度外释放，避免错误返回自动析构大计划。调用端还须限制准备／回收任务数量。
4. 观测包含严格递增的序号、提供方单调时间戳、毫秒素材位置和实际播放／暂停状态。提供方到宿主的 Mapping 必须匹配双方身份／代次，整个时间区间须在允许年龄内且不位于未来；另检查误差预算、时间顺序和有界位置推进。倒退或不连续定位必须重新准备播放代次，重复／迟到观测不得续命或重放。
5. 媒体计划的渐变从计划自身状态计算，不能因现场其他层当前值不同而改变同一素材位置的结果。复用现有 Ownership 的属性跟踪和 Player 的延时／效果／循环折叠，只跳过现场起点注入。暂停保持当前位置；恢复后只推进该组。媒体成员拒绝单独接收自主播放命令，避免混用时钟。
6. 自主来源按实际宿主时刻排序；媒体观测是当下接纳的状态更新，其新属性接管统一标记为接纳的宿主时刻。时间戳映射用于判定质量与新鲜度，不把媒体内部历史时刻伪装成精确现场动作时刻。普通值采样与暂停／恢复不重新接管；显式定位对目标位置已拥有的属性重新接管。
7. 所有来源仍通过唯一 LiveMixer 和完整 512 通道编码；媒体组停止只释放该组。失联可观察，保持值不等于媒体仍在正常播放；恢复必须更换代次。纯灯光求值不会派发外部机构／音视频动作，未来不可逆动作必须另设执行确认及去重契约。
8. 原生音频适配、独立宿主命令队列与远程协议留作后续增量，须把这些可运行边界接入实际入口后才能关闭 TIME-001。当前软件调用不包装成已测量的声光同步精度。

## 验证出口

同一真实工程准备媒体跟随列表与自主动态来源；不同单调原点及有漂移的时间戳，经统一编码核对实际帧。验证暂停／反向定位／失联保持／重新准备恢复不打断自主来源，旧代次／过期准备／错工程／旧序号／错域／未来或过宽观测原子拒绝；手动接管不会被普通媒体采样抢回，显式定位才重新接管。现有自主来源排序、资源预算与宿主租约回归继续有效。
