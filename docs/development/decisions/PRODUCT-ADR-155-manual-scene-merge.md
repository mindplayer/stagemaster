# ADR-155：现场手动值合并到既有场景

状态：accepted；2026-10-04；EXEC-011，基线 2fc2c96。不改变持久工程格式、后台运行快照或物理输出。

参考：MA3 [Store Settings](https://help.malighting.com/grandMA3/2.5/HTML/cue_store_settings_preferences.html) 的 Programmer／选择范围与 Merge，以及 Avolites [Editing Cues](https://manual.avolites.com/docs/cues/editing-cues/) 的保留未修改内容、明确更新场景或预设。本项目沿用已有电平前权威手动捕获、Rust 工程事务与历史，不另建输出录制器；不声称实现完整跟踪更新。

决定：在采集前显式选择“新场景”或“合并到原场景”和目标。Rust 在当前工程上建立不可变合并计划，逐项报告新增／替换／相同、旧值／预设引用和仍保留的已启用效果。仅同一灯具同一属性替换，其他属性、效果、场景身份名称及引用位置保持。被触及的预设引用变成独立值，不修改预设；动态效果仍可能控制这些属性，必须展示。共享场景使用位置在同代工程中可查看，后台固定工程不会热替换。

采集结果由现有单个五分钟随机票据托管；票据绑定动作种类、工程代次和精确目标场景。确认不接受客户端拼装灯值或新的目标。目标、定义或代次变化拒绝；失败保留票据可重试，成功消费；取消／切页／换工程丢弃。核心检查目标基线，宿主再做代次保护，整个修改一次历史，相同内容不增历史。超容量、无目标、过期或不同动作无副作用。

实现与验证按 EXEC-011：独立小文件；软件后台与原生编辑、取消／历史／保存重开，设备／UE／音乐不启用。实际验证结果与未完成项记工单，不把设计作为交付。
