# PRODUCT-ADR-121：后台音乐的末尾定位与终态

- 状态：accepted，末尾定位与实际回执草稿增量通过软件及原生静音验收；证据见 TIME-001。
- 基线：`e0e2487`，main，当前会话单写者；上一轮仅报告进度，为 no progress，本轮继续实际实现。

## 问题与决定

原后台拒绝等于音乐时长的定位，避免把没有后续采样的音源送入“等待播放回调确认”的流程。仅放宽界面上限会造成等待超时。沿用 ADR-117 的已授权请求／实际完成分离，以及既有原生 Transport 的结束位置语义，不新增播放器或界面时钟。

1. 新后台声明 `seekIncludesEnd: true`。客户端同时识别旧后台的 false 和新后台的 true，并按实际能力校验范围；超出时长仍拒绝。工程、设备包和请求结构不变。
2. 等于时长的定位是显式终态操作，无论 playing 是否为 true：原生音源在调度外准备并实际应用末尾位置，确认 ended、未请求播放且无故障；不挂载虚假播放回调、不编译末尾灯光计划。
3. 提供方通过原请求完成槽报告实际完成。原 Host 核对未超时、当前票据、未激活替换计划及原组代次，再用同一 stop_media 释放该组贡献；其他来源继续。不得同时发送自然结束通知造成双重释放。错误提交的末尾替换计划在激活前拒绝，仍由提供方回收，不能先影响灯光再报错。
4. 等待 Host 完成时保留原活动组身份；失败仍可收尾，成功后清除跟随。原生音频显示“已结束”、位置保持时长；媒体组沿用 Stopped，表示不再贡献灯光。自然结束继续原终态通知，显式末尾定位由原控制回执证明完成。
5. 从末尾再次播放重新准备零位；向前定位可保持暂停，停止返回零位。重复请求、旧代次、被新意图替代及迟到完成不能影响新节目。

## 参考与范围

复用项目已有成熟媒体时钟／结束状态研究（TIME-001、ADR-111、ADR-119）及原生音源、LoopPlayback 的既有结束状态；在应用边界接通，不再设计通用多媒体引擎。自动验证使用真实 WAV 解码与软件 PCM 输出，不能据此证明声卡物理延迟或真实 DMX。

验收覆盖：未开始／播放中／暂停时末尾定位；灯光归还；位置与结束状态稳定；再次播放与回退定位；越界、旧请求、超时、失败及重复回执；旧后台能力兼容；共享客户端和桌面实际入口。循环回跳、提供方重启与云端／U 盘交付仍属于持续目标，当前决定不宣称它们完成。

## 原生验收发现的草稿回执问题

实际桌面定位到 300 秒后，音源已结束，旧组件却因 HTTP 首次结果仍待确认而保留输入草稿；随后重新播放时音源已到 13.986 秒，滑条仍显示草稿 300 秒。修复只在组件与既有回执投影：保存本次宿主／会话／序号，再从接纳回执中的媒体请求号关联实际完成。接纳、旧观察或别的请求不能清空草稿；原请求完成仅清除提交的同一份草稿，不覆盖用户后续输入或取消。Rust 回执本来已携带 state，本次 TypeScript 补齐已有字段，不增加传输协议或领域状态。
