# ADR-027：独立工程恢复检查点

2026-09-28；接受。RECOVERY-001，基线 `cd7e0e9`，main，当前会话直接实施。

参考 [Blender 自动保存／恢复](https://docs.blender.org/manual/en/latest/troubleshooting/recover.html) 将恢复副本与手动保存分开；复用既有 tempfile 同目录原子替换、Rust Document 严格校验和 [std::fs::File 文件锁](https://doc.rust-lang.org/std/fs/struct.File.html)。不使用 PID 或时间戳猜测进程存活，不引入数据库或另一种语言。

- 存储模块新增独立 RecoveryStore／RecoverySession。检查点封装格式仅供本地恢复，带版本、会话 UUID、检查点 UUID、时间、来源说明和原始 JSON 文档；不改变 show 工程格式。Document 仍是唯一内容验证器，嵌入 RawValue 保留原始 JSON，避免解析时吞掉重复键。
- 每个应用会话持有稳定的独立租约文件锁；索引锁协调创建、发现、恢复与删除，租约锁保护活跃窗口和恢复认领。列表用内容摘要作为操作令牌；恢复／丢弃重新检查令牌及占用状态，不允许过期选择删除新检查点。损坏／不兼容项保留并显示原因。
- 临时文件写入、文件同步、原子替换、目录同步沿用现有保存机制；写入失败保留上一检查点，并明确显示“恢复保护未更新”。正常编辑继续有效，不能把备份失败误报为编辑失败。每会话只保留最新检查点，总数限制 64；容量满时提示清理，绝不静默淘汰未保存工作。
- 超过 30 天仅标记“较早”，仍允许恢复；时钟倒退或异常不用于认定活动会话失效。清理由用户明确丢弃触发，取消保留原记录。仅处理本模块的 UUID 文件及对应临时文件，拒绝符号链接及非普通文件，未知文件不递归删除。
- 桌面编排操作串行协调：抓取已应用的有效 Document 后释放 Session 锁，再写检查点；普通检查点磁盘 I/O 不占住预览锁。保存／退出／切换工程处理旧恢复记录后再完成生命周期。恢复先认领原记录，加载为未保存副本（file=None），清空播放与历史；新检查点成功落盘后才清除原恢复记录，失败时原记录继续保留。
- 本轮保护已经通过核心校验并应用的编辑；尚未应用的输入框草稿不序列化成有效工程，界面明确这一范围。恢复状态、来源与日期可见，持久化失败不能藏在日志里。
- 存储路径由宿主注入：当前开发构建统一放在项目 `data/recovery/`；库不依赖项目目录或 Tauri。正式安装环境使用宿主用户数据路径适配，不把开发绝对路径写入工程内容。

审查门槛：异常终止后仍能恢复、活跃双实例互斥、损坏／旧记录处理、过期令牌拒绝、明确丢弃与取消、恢复后另存为且原文件字节不变、保存清理／失败保留、原子写入失败保护、原生窗口流程。不得以正常退出重开替代异常中断测试；原用户未保存进程不能用于破坏性验收。

实现审查补充：列表可清理无持有者且无记录的孤立租约及对应临时文件；恢复后的来源仍仅作说明并在后续检查点延续。原生保存已提交但后续打开／清理失败时，界面重新读会话代数再报告原错误。接口和实现边界见[工程恢复接口](../../module-api/project-recovery.md)。
