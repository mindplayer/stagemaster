# ADR-095：双动态场景交叉的确定性求值

状态：采纳并实施；核心、工程、宿主及原生界面验收通过；2026-10-02；AUDIO-019；基线 `ad500e7`，当前会话直接审查。

依据 AUDIT-001 U06，现有进入渐变仅冻结前一场景在边界的值，不能表达旧效果继续运行期间逐渐交给新效果。本任务完成条件包含核心、工程持久化、编译／宿主调度、时间线编辑与取消／历史／保存重开的完整工作流；仅核心通过不结项。

参考 [OpenTimelineIO 转场与时间线结构](https://opentimelineio.readthedocs.io/en/latest/tutorials/otio-timeline-structure.html)：转场独立于两个片段的源时间，不改变时间线总长，邻接转场不能互相重叠。参考 [grandMA3 时间规则](https://help.malighting.com/grandMA3/2.3/HTML/cue_timing.html)：连续属性渐变与图案等离散属性直接切换须区别；不将视频透明度或音频等功率混音直接套给灯光。此处采用本项目既有整数线性混合与进入即切换规则，不声称复刻 MA 的全部时间优先级。

第一实施边界：在 `stagemaster-playback` 增加独立 `SceneCrossfade` 与 `CrossfadeTiming`。输入为两个已有、各自已验证的无延时单步骤保持计划；计划默认值、效果、历史进入渐变与各自偏移仍由原求值器解释。调用方须将两个计划编译到同一灯具／语义属性有序绑定；核心再次要求属性数量和离散掩码一致。不能按 DMX 地址直接混合不同灯具模式。

`CrossfadeTiming {duration_ms, offset_ms, source_elapsed_ms, target_elapsed_ms}`：两个 elapsed 是当前可见段落起点对应的各源局部时间；offset 是原交叉已进行时间。采样 t 时分别求值旧／新计划于 source+t 和 target+t，再按 min(offset+t,duration)/duration 混合连续值；离散值始终来自新计划。持续效果各自继续运行，任何内部进入渐变照常求值。向后定位、重复采样和从中间开始应与顺序播放完全一致。源时间由调用方给定，不增设时钟、音频源或 UI 求值。

为避免另造一套算法，从原 Player 抽出私有步骤求值和整数混合职责；Player 行为由原有执行／效果／离散属性／偏移测试保护。新求值器只持有两个不可变计划与两个固定输出缓冲（最多每个 512 个 u16），构造时有界分配，正常采样不分配、不追帧、不依赖设备。每个源偏移／交叉偏移加采样时间必须处于核心 24 小时上限，全部检查通过才更新输出，非法调用保留上次结果。

当前不改变 `Plan` 的设备编码、主工程字段、旧进入渐变或现有播放行为。复合双场景求值类型不是普通设备 Plan，后续宿主不得误导出为旧播放包。工程接入必须单独确定稳定转场身份、相邻关系、源句柄范围、禁用／锁定、分割／内部截取、历史渐变重叠、引用删除与预算规则，并补 schema／独立格式检查；不能用“冻结旧效果”的退化来冒充持续动态交叉，也不静默改变旧工程输出。

第一阶段验证：双效果不同时期／相位／曲线、两个源各自历史渐变、离散切换、随机顺序定位、交叉中切片后的逐采样一致、512 属性及时间极值、无效尺寸／计划／离散映射拒绝。完成后继续工程与界面接入，不能把基础求值完成写成多轨或商业演出已完成。

## 工程与宿主接入决定（本轮采纳）

新增可选 `fadeMode: snapshot | dynamic`，省略等同旧 snapshot；能力 `media.audio-clip-crossfade@1`。普通 dynamic 片段进入时使用相邻且启用的前段继续运行，无相邻来源则使用灯具默认值。持续时长仍为 fadeMs，不改变片段范围；零渐变直接切换。改模式／场景／渐变时长或显式重新计算时清除历史，移动与复制保留已有历史。

分割或完整内部截取保存 `entryCrossfade {durationMs, offsetMs, source: {sceneId, effectOffsetMs, elapsedMs, entryFade?}}`。sceneId 可为 null（灯具默认值），其余均显式毫秒；source 内可保存普通进入渐变的语义快照，不可再嵌套 entryCrossfade。目标源时间沿用片段 effectOffsetMs。每次左裁切推进交叉 offset 与 source elapsed，右裁切只改变可见长度；允许按源零点恢复。entryFade 与 entryCrossfade 互斥，后者仅用于 dynamic；fadeMs 必须等于剩余交叉时长与片段长度的较小值。源场景为稳定引用，改其效果会更新历史来源；删除被引用场景必须阻断并给出片段定位。历史起始值合计沿用 32768 项预算，单次 512；所有源范围不超过音乐一小时预算。

新动态过渡不能以尚未完成的另一双动态过渡作为来源（否则产生三源）。分割后具有同一历史的相邻片段不构成新过渡，允许无损恢复；普通静态渐变仍可取上一动态过渡的实际结束值。编译不递归走前驱：普通前段进入渐变必已完成，只有显式历史需要至多两源求值。来源与目标的灯具身份、属性键、位置索引和离散标记必须逐项相等。

新增 `compile_audio_segment` 输出独立的宿主采样器与映射。旧 `compile_audio_lighting` 对动态片段明确拒绝，避免误传设备单 Plan；旧静态片段仍兼容，包括从上一双动态片段取边界值。宿主只接已有原生音频游标，不引入第二时钟。格式、引用预检、编辑事务和宿主测试通过后再开放正式界面入口；工单在原生操作验收前保持实施中。
