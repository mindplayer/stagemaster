# ADR-028：有界播放包与单节目装载

2026-09-28；接受并进入实现验证。PLAYER-003A，基线 bdbf3f1。当前会话直接开发。

## 参考与选用

延续 ADR-002 的主机编译／自包含／传输分离。参考 [CBOR RFC 8949](https://www.rfc-editor.org/rfc/rfc8949.html) 的明确类型、定长容器和确定性编码，以及 [minicbor Decoder](https://docs.rs/minicbor/latest/minicbor/decode/struct.Decoder.html) 的无分配逐字段读取。比较 [Postcard 稳定格式](https://postcard.jamesmunns.com/wire-format)：适合共享 Rust 类型，但派生 Vec 解码前仍需额外限额控制；本轮选 minicbor 手动限定字段与长度，避免实现通用序列化器。只复用标准编码，不接受任意 CBOR 对象、标签、浮点、无限长容器或跳过未知字段。

ZIP／整份 JSON 对首个执行包没有必要，且会增加解压内存与通用工程解析依赖；固定私有字段二进制容易逐次扩展失配。本轮采用小型定长文件头＋CBOR 目录＋独立 CBOR 节目块，SHA-256 校验完整文件和各块；不引入压缩或另一种产品语言。

## 模块与边界

新增 `stagemaster-package`：`no_std + alloc`，依赖共享播放内核、minicbor 与已有 SHA-256。只认识计划、通道映射和元数据，不认识 Tauri、工程 JSON、文件系统、蓝牙、授权或板卡 GPIO。`ReadAt` 注入有长度的随机读取；目录与单个节目分开装载，不要求整包在 MCU RAM 中。

工程层独立 package 编译适配器复用现有场景／列表编译；核心播放 `Plan` 只补只读 repeat／effects 查询。输出映射降为每个 u16 属性对应的粗／细槽地址，复用现有高字节／低字节语义；独立输出编码器须逐帧与桌面 `CompiledOutput` 对照。不把粗细通道各自渐变。

每包可选多个具名场景／完整列表，节目内含全部目标值、默认值、时间、循环、效果、步骤标识／名称和输出映射。预设引用和共同对焦已由工程编译解析；空间模型不进入设备包。保持当前编译器的整条线路默认值／映射，避免切换／释放遗留通道；不在本任务悄悄改变其依赖范围。时间区间裁切、媒体、电机动作和未实现能力不出现在可导出入口，不把未来格式字段静默忽略。

同一快照、选择和编译版本输出相同字节；包含来源工程／保存修订及当前完整快照 SHA-256，未保存编辑不能仅用旧 revisionId 标识。来源快照以 serde_json 当前有序对象映射的紧凑 UTF-8、无末尾换行流式计算摘要，不调用排版保存路径，避免只读编译因排版膨胀误拒绝合法工程。无随机包 ID／当前时间。选择顺序规范化，重复选择拒绝。包完整性摘要不是签名／授权；当前仅开发参考包，不伪装为可安装商用授权包。

## 首个软件参考档位

`reference-single-line-v1`：一条线路，最多 64 个节目、包 2 MiB、目录 16 KiB、单节目块 32 KiB；内核属性最多 512、每节目步骤最多 128、单步效果通道最多 128。每个字符串最多 512 UTF-8 字节。编码后的实际大小与实际解码资源共同判断；总计目标值／效果／关键帧仍受内核上限约束。

装载峰值参考预算 64 KiB，必须计入目录常驻结构、单块输入缓冲、计划目标／默认值、播放器当前／起点值、容器头、映射／标签及分配对齐余量和 8 KiB 扫描栈／散列工作区参考余量；装载前扫描拒绝超限，不能先按不可信长度分配再检查。使用有界 try_reserve_exact；校验无效数据不能 panic／无限循环。报告采用保守的 64 位容器布局以避免低估主机／32 位差异，并另列实际载荷；真实板卡分配器、栈、无线栈、同时保留新旧计划等另行测量。

该预算由 PLAYER-002A 配置 128 KiB 堆、蓝牙期间约剩 90 KiB 的实测留出余量推导，不是板卡额定可播放容量。单活动节目装载有独立验收；无缝跨节目切换、Flash 分区／安装与双槽回退必须在 PLAYER 后续以板级证据确定，不能据本包上限直接冻结。

## 格式与验证

文件头固定 64 字节，小端长度／版本／目标档位；其余目录和节目字段均由 CBOR 编码，容器确切长度、整数范围、布尔值、UTF-8、唯一标识、槽位占用、长度总和／尾部及保留位严格验证。偏移相对节目区、必须连续不重叠，拒绝截断／多余尾部。先验证包摘要，再逐块校验与预算扫描；装载时重新核对块摘要，避免存储变化后使用旧目录。未来存储适配必须保证读取的是固定提交版本。

验证包括确定性、依赖闭合、静态／渐变／效果／关键帧／16 位／摇头静态对焦的同内核重放和 DMX 字节一致性；随机损坏、恶意长度／枚举／重复、超限、旧版本／能力拒绝、只装一个节目、错误不启动播放器。桌面“播放包”位于工程工作区，选择／搜索／批量、检查与问题定位、结果过期、取消、原子另存与源文件保护作为正式流程，设备安装状态保持未开放。

## 桌面提交边界

主机只缓存最后一个经过验证的编译结果，使用会话版本＋一次结果标识防止旧结果导出；生成可在编辑继续时完成，过期结果停用。导出对话框及原子写入进入既有工程操作队列，播放轮询不持有文件 I/O 锁。编译失败不返回部分包；取消不写文件也不改变工程历史／保存修订。

文件后缀 `.smpkg`。存储模块抽取既有锁／基线比较／临时文件＋同步＋重命名提交原语，工程保存继续使用相同原语；包导出独立类型只接受完整验证的字节，禁止当前工程路径、符号链接和覆盖非播放包文件。已有有效包可通过系统另存对话框确认后更新。摘要只负责完整性，未来授权封装独立增加。
