# PRODUCT-ADR-055：工作台唯一三维视窗

2026-09-30；PREVIS-002；基线 `a690cea`。用户反馈加入音频卡点后预演异常，要求只保留一处；当前会话审查接受。

代码证据：AudioWorkspace 的 show3d 不受 visible 限制，WorkspaceSurface 只移走 DOM 而不卸载 React。后台音频页的 PrevisPanel／WebRTC 仍在运行；舞台或编排可再创建另一视窗，违反既有信令 maxSubscribers=1，且各视窗分别发送选灯／查看输入。不能通过增加订阅者额度掩盖所有权问题。

统一为工作台公共区域的一个 SharedPrevis，移除页面内各自的视窗与开关。切换工作区保留同一 React／Pixel Streaming 实例和 UE 相机；收起时卸载视频连接，停止预演才关闭渲染器。复用 Epic 官方传输库及现有 Rust 预演、草稿队列，不增加第二时钟、播放器或场景模型。参考沿用 ADR-019 与 UX-015 已验证的机制，修正其在音频接入后被破坏的单视窗约束。

灯光来源仍由 Rust 返回；切页不发送来源命令或开始播放。「当前场景」只在编排页按显式选择跟随，离开编排取消该自动跟随；音频播放／定位仍按现有契约切到播放源。公共组件轮询仅观察状态，外部切换来源后停止旧场景跟随。

公共视窗在舞台页允许安装位置编辑，在编排页允许选灯，在其他页只查看。舞台选择通过显式组件句柄和通知适配；相机导航不触发草稿提交。上下文／权限变化取消移动模式，过期的异步进入移动和位置提案拒绝，避免离开舞台后遗留可编辑状态。位置仍走既有版本校验／原子历史。

不修改工程 JSON、GATT、Rust 时间与输出语义或预演线协议。本次新增小组件／权限模块，抽走 Workbench 的重复视窗编排，保留其他无关大型编辑逻辑，避免在故障修复中全面重写工作台。

用户随后补充缺少进度控制：公共预演增加音乐播放／暂停／停止、时间与可拖动进度，复用工作台唯一 useAudio 会话；音频编辑页使用同一个会话。拖动预览本地位置，松手提交一次原生定位，键盘按 10 ms 步长定位；不按每个像素排队重建音频输出。打开三维本身不加载音乐或接管已有场景播放器，只有进入音频编辑或明确播放音乐才准备资源。

同时修复切回音频页重复准备音乐的问题：同一工程／资源／裁切范围先检查原生声音是否仍已准备，保持播放位置；若其他预览释放了音频所有权，则重新准备。显示状态与原生音频时间仍分离。当前进度条对应有限长度的音乐工程，不给等待手动推进的场景列表伪造全局时间轴。
