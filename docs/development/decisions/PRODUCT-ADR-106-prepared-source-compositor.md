# PRODUCT-ADR-106：固定来源组与按生效时间合成

- accepted，软件实现与本轮验证完成；2026-10-03，基线 `bc831a6`，main，当前 Astra 单写者。
- 工单：[MIX-003](../tasks/MIX-003-prepared-source-compositor.md)。上一轮 MIX-002 已提交，属于进展。

## 核对结果与取舍

现有独立宿主直接持有单个设备 Runtime，其租约／回执和后台线程已经验证；不能把多个 Runtime 线程堆在一起接同一端口，也不复制控制租约。接线前还缺少一个实际持有所有来源、统一推进和合成的对象，以及多个自动步骤之间的时间排序。

复核 [MA 播放／优先级](https://help.malighting.com/grandMA3/2.5/HTML/cue_playback.html)（页面 2.4）和 [Titan 19 播放选项](https://manual.avolites.com/docs/cues/playback-options/)：播放对象与执行控制面分开，来源优先级与属性取得顺序分开。本项目的同毫秒自动激活顺序是自定确定性规则，不宣称复制厂商私有算法。

## 决定

1. 新增标准宿主软件组合模块 `stagemaster-live`，准备时编译固定数量的场景／列表并注册手动层，绑定完整工程快照和唯一输出编码器。运行中仅操作来源身份；来源与 mixer 句柄绑定在内部，不向客户端暴露可混用句柄。
2. 同一个外部单调毫秒推进所有来源；Player 在真实激活边界提供该时钟域内的生效时刻，跳过整圈时提供最后一个完整圈的起点。适配器保留每属性最新声明时刻，不能用采样时刻替代真实激活时刻。
3. 一轮先计算最终贡献，再按生效时刻排序声明；同毫秒自动事件按稳定来源身份排序。普通人工命令先统一推进至该时刻，再应用命令，因此同刻明确操作在已处理自动边界之后。既有优先级、HTP／LTP、推子与释放语义仍由同一个 LiveMixer 处理。
4. 完整合成前不公开中间帧。计算／混合内部失败锁存故障并撤掉有效帧；不能将半完成结果或旧帧重新标成新采样。参数／身份／倒退时钟错误明确拒绝。当前固定来源组生命周期由宿主负责，控制连接消失不等于停止来源。
5. 所有运行缓冲及排序空间在准备时按已有属性／来源预算分配，正常周期不增加容量；整圈仍折叠，不突发补发旧帧。来源关键帧／效果继续由 Player 求值，渐变起点取调用前完整合成快照，未声称长时间停顿后的历史物理状态精确重建。
6. 这是统一宿主的实际软件执行后端，先以真实工程、多个列表／场景、手动层和软件输出验证；当前不改 HOST-002 的网络入口或复制一套线程／租约。随后抽取现有宿主的执行后端接口，复用原后台控制与故障收敛边界。

手动层是可信语义适配后的属性入口，参数形状／范围／重复项必须检查；不把它当任意网络端点或设备授权。商业许可、物理输出、独立音视频时钟同步、热替换以及完整专业总控后续独立推进。工程／设备包格式保持；新模块不作为 ESP32 内存与实时性承诺。

## 验证

反转来源准备顺序不改变不同生效时间下的胜出者；同刻顺序稳定，人工命令在自动边界之后；跨多圈仍按每属性最后声明排序，发布之间连续采样不抢占。准备拒绝重复／未知／超量来源，参数错误原子拒绝，停止只释放目标来源；动态场景与多个列表输出同一编码器，来源控制权与界面生命周期分离。复用原播放器、MIX-001／002 与工作区回归，检查无新增生产第三方依赖和小文件边界。

实施审查：使用独立小文件分别承载准备、来源命令、排序合成与诊断；累计目标值／效果／关键帧预算在准备时限制，手动属性的业务有效性由既有语义适配器负责。内部两阶段发布只在私有 mixer 中进行，任何失败撤回整帧，外部无法观察中间状态。旧 Observer 接口与单来源播放器保持兼容；未新增第三方依赖，未修改持久格式。契约见[固定来源组](../../module-api/prepared-source-compositor.md)。

实施后审查通过：836 项工作区测试、最终 9 项来源组专项、27 个 crate 文档测试运行（含 1 示例）、严格全工作区 Clippy／fmt、Xtensa runtime-check 通过。当前只确认软件边界；独立宿主／桌面／真实输出接线另行验收。
