# PRODUCT-ADR-013：场景列表与独立离线预览

日期：2026-09-26。状态：已实施并验收（DESKTOP-003 / PLAYER-001A）。基线 `af3e83f`，工作区为项目主目录。

用户要求深入 goal 模式完善可用产品，并再次强调模块开发、功能解耦和扩展性。本轮实现 DESKTOP-003 / PLAYER-001A，不把规划中的设备播放器或完整时间线认定为完成。

## 模块与接口

- `stagemaster-project` 拥有工程、引用、顺序、时间字段校验与原子编辑。独立 `sequence` 模块负责列表命令，`compilation` 负责已校验工程到不可变执行计划的转换；编译不改工程。
- 新增 `stagemaster-playback`：纯 Rust、无 Tauri、JSON、文件、网络、线程或设备依赖。输入有界的归一化属性数组、完整目标状态与整数毫秒，接收外部单调时间；只计算状态和值。编译后不依赖工程树，未来可接其他编译源与设备宿主。
- 复用 `stagemaster-dmx::Patch` 编码及现有归一化值；暂不修改 A0 多来源混合器。单列表独占离线预览，释放回档案默认值；不把此规则当成未来多播放源混合规则。
- `apps/desktop/src/preview.rs` 独立承接单调时钟、计划装载、控制代次和预览 DTO。工程会话只有协调职责。预览不进入编辑撤销栈、不标脏、不保存运行状态。
- TS 的列表编辑、属性表单、预览面板是独立组件，通过宿主接口提交命令；不解释 JSON 或计算灯光渐变。刷新数值有节流且不积压请求。

## 编辑／格式

沿用草案中已有 `lighting.sequences`，不改文件格式版本。列表至少有一步；步骤使用稳定标识，数组决定顺序，显示编号精确规范化检查唯一（1 与 1.0 相同）。重排不改编号或标识，复制步骤生成新标识及空闲编号，复制列表保持场景引用。场景被引用时拒绝删除并定位列表。

新增具名列表命令创建／更新／复制／删除，步骤插入／更新／移动／复制／删除；全部复用原子编辑／撤销。当前支持继承／独立模式、单次／循环、手动／完成后自动推进。无外部动作；非空 actionIds 明确拒绝。

工程时间仍是整数刻度字符串和时基；本执行子集只接受可精确表示的毫秒，每字段 0–86400000 毫秒；不截断精度或溢出。编辑命令使用整数毫秒，界面输入秒（最多三位小数）。其他时基若精确等价可读取，超出子集明确拒绝。

## 运行语义

- 延时先保持进入时的值，再线性渐变；自动等待从渐变完成算起。手动步骤完成渐变后保持，直到执行下一步。自动最终步骤完成等待后结束并保持最后值，显式停止才回档案默认值。单次列表末步没有“下一步”，该操作不截断尚未结束的渐变；末步手动模式保持，直到停止或重新执行。
- 继承模式在编译时按顺序求每步完整目标；省略继承，释放恢复默认。独立模式每步从默认构造目标。跳转的目标不依赖上次播放路径；渐变起点为跳转瞬间当前值。每次循环第一步采用同样的独立入口目标，避免残留累积。
- 选择不执行。执行所选／下一步才改变预览。暂停冻结延时、渐变、自动等待；继续不计暂停期间时间。暂停时执行所选开始新的运行步骤。
- 内核时间必须非递减；同刻自动边界先求值，再处理收到的控制命令。大跨度推进跳过完整自动循环，不按丢失帧补跑；零时长全自动循环拒绝，含手动等待可合法为零。
- 执行计划最多 1024 步、512 个属性、262144 个目标值。内核预分配当前／起点缓冲，推进工作有界；编译／DMX 预览 DTO 分配在非实时层。这里不是经过 ESP32 测量的容量承诺，也不是持久播放包 ABI。
- 装载生成新的预览代次；命令携带代次和递增请求序号，重复／乱序不执行。编辑后旧预览计划继续独立，界面提示需要重新载入；陈旧计划禁止新的执行／继续，但允许暂停／停止。新建／打开成功清除预览，取消打开不清除。保存不使计划过期。
- 初次预览由用户选择列表并显式载入，失败保留已有计划。当前只编译同一输出域／线路上全部配适完整的灯具，512 通道数值是真实编码结果；没有任何物理输出适配器。
