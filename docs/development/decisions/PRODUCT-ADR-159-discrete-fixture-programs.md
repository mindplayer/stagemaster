# PRODUCT-ADR-159：内置程序使用独立离散控制选择

状态：接受，当前实施会话评估；FIXTURE-010，基线 main `f9a8ef5`。先记录本决定再实施，不改变时钟／控制权／物理输出权限。

## 依据与取舍

H3／FIXTURE-006 的 30W 第 10 通道已确认 0–59 外部其他通道作用，60–159 四种自动模式、160–255 四种声控模式。第 11 通道 250–255 持时复位是另一种命令，不能混入同一选择。[GDTF 1.2 属性表](https://gdtf-share.com/help/developers/gdtf_1_2/annex/index.html)分开 PositionEffect、ColorEffects 与 FixtureGlobalReset；借鉴内置选择与连续属性／复位分离，不把本项目属性声称为 GDTF 导入或一个统一物理程序引擎。

复用 FIXTURE-003B 的功能身份、原生区间／代表值、LTP、延时后的直接切换、稀疏预设和语义 2 有界包。百分比或线性渐变会经过其他自动／声控档，不能使用；另造播放器则重复权威时间。本增量只支持说明书确认的保持式程序选择，不支持锁存宏或持时复位。

## 决定与兼容性

- 新属性 `fixture-program`，中文“内置程序”，独立归入控制。只接受固定档位，8／16 位粗细均可；所有选择 position=0，没有连续程序速度。保留名称与真实原生区间／代表值；未知范围不填，不按名字推断动作。
- 功能身份保留一个 `external`（外部通道控制），其余为 `auto.<稳定标识>`／`sound.<稳定标识>`。默认必须为 external／0，禁止把自走／声控放入工程默认以免普通载入误触发。新草稿外部区间与代表值留空，须按资料确认。分类在 key 中显式承载，不增加模糊中文名称判断或额外格式字段；复制保留身份，独立导入生成模式身份。
- 工程新增 `lighting.fixture-programs@1`，同时要求原 `lighting.fixture-functions@1`；缺少／未知版本原子拒绝。旧读取器因未知能力或属性拒绝，不静默丢程序。结构不改，独立模式 envelope 仍 v1，旧建档验证拒绝新属性。编译仍为既有直接切换值／语义 2，旧语义 1 目标必须拒绝；不改已验证 ESP32 受限播放器职责或包版本。
- 场景只用明确的功能选择，不接收普通数值，不允许动态函数叠加，不穿越中间档。UI 没有程序百分比滑块；自动／声控分类明确，默认外部控制可清楚恢复。普通亮度／位置预设不含程序，单独“仅内置程序”可显式记录／调用；已有“全部”仍为用户显式整场记录，不暗中扩大局部范围。
- 零值、清除／释放、停止和归还控制权保持原规则；不把“释放当前场景属性”说成复位或强制终止灯内程序，实际输出回到默认／下层。总亮度／熄灯不更改程序选择，软件熄灯不能承诺覆盖灯具内置程序的真实行为或机械急停。
- 实际程序可能忽略其他通道或自主管理运动／颜色／频闪，软件输出监看仍只报告编码值；UI 明确内置动作与覆盖范围未模拟／未实测。UE 不另执行这些程序，不伪造轨迹。混合控制宏、18CH 独立单元和持时复位留后继。
