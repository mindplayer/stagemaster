# PRODUCT-ADR-125：云端／本地介质共用节目包导入

状态：accepted，本增量实现与软件验收完成。2026-10-03；DELIVERY-001；基线 `7ef847e`，main，当前会话单写者。

## 问题与成熟机制

设备上传已有不可变字节和独立全包验证，安装器已有两槽提交／固定快照，运行层另验播放许可。但尚无可复用的文件／网络导入入口；复制两套安装器或把下载成功当成激活都会破坏这些边界。

参考 [TUF 规范的目标获取流程](https://theupdateframework.github.io/specification/latest/#fetch-target)：内容长度和摘要与下载地址分开，在交付给应用前完整核对。仅借鉴这项机制，本次不实现 TUF 元数据、签名、可信根或版本防回退，不把裸摘要当来源认证。商业策略仍按 ADR-101 后议。

HTTP／TLS 复用既有版本 [reqwest 0.13.5](https://docs.rs/reqwest/0.13.5/reqwest/struct.ClientBuilder.html)，通过可选 `http` 特性启用成熟 TLS 后端；不自行实现 HTTP 或 TLS。明确超时、长度上限、禁止自动重定向及取消，避免无限下载或把签名地址转发至另一目标。

## 决定

- 新增主机模块 `stagemaster-delivery`：有界收集 → 完整包验证 → 不可变读源。文件和 HTTPS 同用此入口；不依赖 Tauri、设备连接、运行器或云端账号。仅当前 `smpkg` 受限灯光档位，2 MiB 上限属于此档位，不是未来多媒体平台上限。
- 内容身份复用 `stagemaster-install::Identity` 的字节长度与 Archive 摘要；路径／URL 不进入身份。Archive 摘要不是整个文件直接 SHA-256，HTTP ETag 也不能替代它。HTTPS 调用必须传预期身份，文件可先独立检查后审阅；预期身份须由调用应用的可信发布／选择流程提供，包内自称或网络响应字段不授予权限。
- 下载只接受 HTTPS、成功的完整响应和原始内容编码，不自动跟随重定向、不携带通用账号凭据。对声明长度和实际接收长度双重限制，短包／额外字节／错误摘要／超时／取消均不产生可用内容。不将可能含凭据的 URL 写入错误消息。具体云端目录、账号认证及已签发布描述接入另验。
- 文件导入冻结完整内容，拒绝非普通文件；有界读取中取消／拔盘／错误不产生结果。导入成功后不依赖原文件或网络继续可用。不新建永久下载缓存、第二套安装状态机或自动激活流程。
- 现有设备上传的 `Prepared` 改为复用该已验证读源，保持现有构造与信息接口兼容，并提供从已验证结果构造的入口。目标能力与安装权限仍由原上传服务检查；安装和激活继续交给原 Installer／Runtime。
- 软件代表性验收走真实文件、HTTP/TLS、本地两槽安装与 Runtime：相同版本两种入口身份／输出一致；重复导入不重复提交；更新不替换正在运行快照；来源消失后已有内容可用；许可拒绝对两入口一致。取消／损坏／缺字节不能改变当前安装。额外覆盖受限设备能力拒绝。

## 范围与预算

主机导入持有最多一个包的收集缓冲及不可变快照转换峰值（约 4 MiB 加包校验、网络／TLS 和运行时已有预算，并非全进程上界）；验证在非实时工作队列进行，ESP32 不链接 HTTP／TLS／主机导入模块。大型音视频资源须后续按流式本地对象存储和依赖闭合实现，不塞入此 2 MiB 灯光包。

本增量不新增桌面云按钮／占位服务器、不连真实云服务或 U 盘、不操作板卡／物理输出、不改变包格式。通过代表性链路后才继续正式宿主入口与整体审查；不能宣称完整云商业化已经交付。
