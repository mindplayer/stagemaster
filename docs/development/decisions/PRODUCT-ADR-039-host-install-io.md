# PRODUCT-ADR-039：同一主机连接协调保活与安装消息

日期：2026-09-28；状态：接受，主机调度已实现并验收，原生认证与正式 GATT 仍须另验收。DEVICE-002C／D，规划基线 `9c183f4`，实施基线 `fd92ca1`，主工作区，当前会话单一写入。

## 决定与复用

现有 `Service::operate` 在连接期间独占 `Transport`，适合单一诊断通道，但不能让新的上传组件另开连接或等待该锁。继续保留单一连接任务，增加容量为 1 的内部安装请求入口，连接任务在消息片段之间优先处理保活。复用 Tokio 有界通道／oneshot／计时器，以及已有 SMP `Assembler`、`Request`、`Response`，不自建线程池或另一套上传状态机。

上传器继续独立维护不可变包、进度、取消意图和恢复对账；连接任务只负责一条消息的分片传输及匹配回执。公开原生 Rust 方法接受连接代次和已编码消息，不接受用户自报授权；没有对应 IPC 或自动接通的 UI 按钮。后续桌面组件通过安装协调层调用，不直接生成协议帧。

## 权限和生命周期

`Transport` 可返回已验证的安装连接事实，含稳定设备、启动、业务会话、认证机制和真实片段／消息上限。该结构不提供网络反序列化，只能由可信平台认证适配生成；服务将其与当前诊断描述的设备／启动／声明及协议版本核对。描述只能拒绝不兼容组合，永远不能创建权限。当前原生 `Ble` 没有完成 B，必须继续返回无安装权限，不能用名称、公开随机数或诊断握手填入。

一次只接受一个应用请求，包括已排队与执行中；第二个请求明确返回忙，不能偷偷排到另一包后面。新的物理连接创建新队列；断开／取消／过期清除权限并丢弃旧队列、半包和迟到回执。调用者丢弃等待 Future 时，尚未开始的请求可以直接丢弃；已经开始传输则断开，避免原对象继续拼半包。

消息成功必须收到匹配的业务会话／完整序号／命令和启动身份的完整响应。ATT 写成功不是安装成功，远端业务错误仍作为真实响应交给 `Upload`。错序、额外通知、无效片段、失败／不确定发送和超时都关闭当前连接，由重新认证后查询权威状态恢复；不在连接层自动重发半包或取消事务。

## 时序

保活仍每约 2 秒执行，4.5 秒陈旧判断和设备 6 秒规则不变。若有安装工作且距离上次有效回执已达 1.5 秒，先保活再开始下一片；一片写入最多等待 0.5 秒，不并发操作同一 Transport。保活等待还须受剩余陈旧期限约束，不能在过期后重新发布在线。

请求整帧发送最多 5 秒；最后一片写完后等待工作器及完整回执最多 30 秒，第一片回执到达后整份响应另受 5 秒限制。消息阶段期限不因保活或更多片段延长。通知读取采用非阻塞、取消安全的有界队列接口；等待响应时仍能保活和取消，不将 30 秒等待变成独占阻塞。

## 验收与范围

既有诊断生命周期保护测试必须继续通过；新增真实包通过服务、既有上传器、软件协议端点与 FileStore 的安装／重连核验，并覆盖慢片段期间保活、并发请求拒绝、缺认证／声明不匹配、发送／半包超时、错误回执、调用 Future 取消和断线资源清除。软件适配中的测试授权仅是明确夹具，不能导入原生产品。原生主机另对当前只读 ESP32 运行诊断回归，保护舞台窗口。

这一步不冻结 B 的密钥持久化／配对格式，不宣称正式无线安装已可用。正式平台适配必须验证认证、订阅、通知队列上限／溢出、协商 MTU、断开清理及实板故障；D 的中文进度／取消／恢复和完整交付仍待接入。
