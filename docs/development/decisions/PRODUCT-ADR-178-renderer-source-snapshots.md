# PRODUCT-ADR-178：三维组装接续自动构建来源

状态：接受限定来源接线，2026-10-06，DESKTOP-014。基线 main `a60bf83`；不是签名／权限或客户发行授权。

## 问题与决定

DESKTOP-013 新构建自动捕获完整限定输入 `sourceEvidence` 版本1，三维组装入口却只接受历史封套的20份手工摘要。不得为了让新包通过而制造旧封套、忽略新快照或把旧音乐／GPU资格转移到新源码。

- 既有 `--internal-release-record` 可直接读取准确归档目录中的新版原始 build-record；仍接受历史20摘要封套，旧记录不改写、不晋级。新版快照只表示构建来源，不携带原生／客户资格。
- 原 task／成功退出／release＋audio／隔离能力、计划／归档位置、实际身份／后台／复制清单和目录保护保持。快照存在时必须验证版本1、规范结构、准确包内唯一来源原字节与当前全部限定输入；不能退回20文件子集绕过，未知版本拒绝。
- 原编译Git基线、dirty与差异保留；同一字节输入的后继文档提交或将原未提交输入纳入版本，不重标原包为新提交／纯提交。SHA-1与SHA-256基线按对应Git对象格式核对。来源摘要不是完整供应链或签名认证。
- 快照比较复用既有 captureSourceEvidence。其目录检查从组装门面抽到纯叶模块，保留旧导出，不让来源捕获与组装来源验证产生依赖环；不改目录检查行为。
- 红灯发现捕获结果的scope数组直接引用全局扫描表，修改本次元数据会漏后继工具来源或误删必要Schema。返回数组改为独立副本，静态扫描表只读；范围／字段／版本不变，消费者修改自身资料不得影响后继生产扫描。
- 来源核对只读，不建立runtime。已有准确实例目录不能重新组装。实际组装的ad-hoc重签及目录映射按用户明确授权单独执行；未获允许不调用组装器。原Game／Node／旧包保持，不构建UE或修改系统权限／证书。

公共工程／播放包／运行API、时钟、控制权与DMX语义不变。先用真实Git／文件夹具复现现代原记录被旧封套要求拒绝，再验证兼容、完整输入变化、结构／资源／身份／版本和失败前不写入；当前来源的真实构建与只读预资格单列。组合音乐／GPU若受授权限制保持未通过，不缩减首版H1–H5。
