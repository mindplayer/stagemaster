## 需求与结论

用户希望完整工程保留在手机、平板、电脑，利用这些设备完成复杂解析与计算；选取若干片段后，通过蓝牙装入标称 16 MB 闪存的 ESP32，再由盒子独立播放。

采用“完整工程 → 选择范围并解析依赖 → 目标编译 → 自包含播放包 → 设备校验安装 → 本地执行”。一个播放包可以收录多个有名称的片段。手机／平板／电脑复用 Rust 编译规则，设备复用受限执行算法；不另写三套工程解释器。现有原型尚未实现这些服务。

用户进一步要求独立判断，不能将提出的实现设想直接当成要求。我们的决定是保留“主机编译、设备自主播放”的分工；不预设只能导出短片段，不预设蓝牙是唯一或首选文件通道，也不把这块开发板的 16 MB 作为未来所有产品的固定上限。

研究的是厂商工程内容和分层方法。当前编译输入是我们自己的版本化工程；MA／老虎专有文件的直接导入属于独立兼容任务，不能因理解业务内容就声称已能解析其文件。

## 独立比较与选用理由

| 路线 | 收益 | 代价与本项目判断 |
| --- | --- | --- |
| 盒子直接运行完整工程 | 与编辑对象高度一致 | 需要复杂依赖、类型、脚本与运行环境，增加内存和验证负担；本次不采用 |
| 手机／电脑持续计算并无线发送每一帧 | 盒子简单，现场编辑响应直接 | 手机后台、失联和无线抖动进入播放链路，不满足自主播放；以后若有在线调光需求，作为有独立失联策略的模式 |
| 完全预计算输出快照 | 盒子逻辑简单，可逐帧对照主机结果 | 存储随时长增长，改变地址或灯具模式需重新编译；适合短片段验证和有界采样轨道，不能默认长节目都能压小 |
| 受限播放计划，必要时附采样轨道 | 静态、渐变、循环紧凑；复杂关系由主机解析 | 要定义有限指令和一致性测试；推荐，但首轮仅实现已有静态／线性渐变子集，不在设备端重建通用效果引擎 |

先按真实代表性节目测生成包大小、运行峰值和物理输出，再扩展指令或存储。编译后整场节目在预算内就可以整场下发；只有超限、业务需要独立触发或选择局部内容时才分片。不能为了“切片”增加拼接和进入状态错误。

以后若业务确实需要更长的复杂采样节目，比较扩大闪存、外部存储和更高档设备的整机成本，避免长期维护昂贵且脆弱的极端压缩。当前无需因此换掉已有样机。

## 提取片段需要完成的工作

“选择场景”与“截取时间范围”都可以是入口；对同一工程修订、指定播放上下文和目标能力，编译结果应可重现。

1. **确定范围和依赖。** 解析所选灯具、预设、编组、继承值、效果和被引用对象。MA 手册明确提示复制序列后仍可能引用原数据池里的预设，说明复制表面对象并不保证独立。
2. **补齐片段起点。** 从整段节目的第 30 秒开始，需要知道该时刻已生效的灯光值、正在进行的渐变和效果相位，不能假定全部从零开始。外部输入、随机效果和多路叠加必须有明确上下文；无法确定时拒绝独立导出或要求选择可审阅的固定版本。
3. **降为受支持的执行数据。** 主机完成依赖解析、效果展开、目标裁剪、数值转换和复杂计算；设备保留有界计时、简单插值、循环及发送。为降低闪存和传输量，不把“主机计算”解释为“必须保存每一个输出帧”。
4. **定义进入和结束。** 片段进入时从当前输出渐变，或从精确起始状态播放；二者要显式区分。结束、释放、循环回接和跳转有确定行为，不能遗留上一片段的无关通道。改变灯具模式或地址后要重新编译／验证绑定，不能继续盲播旧包。
5. **检查真实资源。** 编码后给出文件实际字节数；校验解码大小、运行内存、每周期运算量、峰值事件数和通道上限。压缩文件小不代表能实时执行。

首个受限档位继续从 RGB／调光灯具、静态场景、线性渐变、延时与顺序循环验证。任意脚本、依赖实时音视频输入的效果和未支持动作不能静默删去后显示“导出成功”。独立播放模式不依赖手机持续在前台运行。

## 数据表示和容量

优先用“初始状态＋变化事件／关键点＋时长和循环参数”。恒定部分只保存一次，循环可复用同一段；需要时对复杂曲线离线采样，但必须规定误差、边界和容量。离散功能通道不能随意插值；16 位属性的粗细字节不能独立渐变；总亮度和熄灯需要属性／通道类型信息，不能把所有 DMX 字节一起缩放。

以下只是容量算例，**不是实际包测量**。假设 1 路、512 个数据槽、每秒保存 40 个完整输出快照，不计时间戳、索引、包头和校验：

| 内容 | 原始数据量 |
| --- | --- |
| 1 个完整通道快照 | 512 字节 |
| 100 个完整通道快照 | 51,200 字节，50 KiB |
| 连续逐帧保存 1 分钟 | 1,228,800 字节，约 1.23 MB |
| 连续逐帧保存 10 分钟 | 12,288,000 字节，约 12.29 MB |
| 连续逐帧保存 1 小时 | 73,728,000 字节，约 73.73 MB |

表中 MB 按 1,000,000 字节，KiB 按 1,024 字节。100 个快照不等于完整的 100 个动态场景，时间与必要元数据另计。40 Hz 是算例和候选工程目标，不是强制协议帧率；不能预设压缩比例或承诺可保存多少分钟。

例如固定一组灯在两秒内线性变亮，主机可提供起止值、时长、曲线和通道信息，由设备插值，免去保存 80 个整路快照。复杂效果可能需要更多关键点或采样数据，空间取决于变化复杂度，不仅取决于节目时长。

16 MB 是标称总闪存，不是节目净空间，更不是可用运行内存。还需容纳固件、设置、分区信息；若支持固件回滚、节目暂存与旧版回退，也需相应空间。实际分区在固件构建和设备核对后确定；首版不固定拍脑袋的分区大小。[Espressif 分区说明](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-guides/partition-tables.html)

节目配额至少区分当前已安装容量、上传暂存预算、最大单包、解压／装载内存和可回收空间。不能为装入新包提前删除唯一可运行旧包；资源不足就明确拒绝安装。运行状态不逐帧写闪存。

## 传输选型与跨端边界

| 通道 | 推荐角色 | 需要承担的成本 |
| --- | --- | --- |
| USB | 首次开发、时序验证、恢复与有线传输 | 需要线缆，移动设备的接口／权限需分别适配 |
| 无线局域网 | 产品批量上传播放包、状态读取及网页／应用接入的优先路线 | 需要配网；现场没有路由器时可用设备热点；必须验证手机局域网权限、发现、鉴权及传输期间的资源干扰 |
| 低功耗蓝牙 | 就近发现、配网、短控制命令；按实测决定小包传输范围 | 分块和流控、有效速率及系统差异；浏览器支持不统一，不适合作为全部跨端功能的唯一基础 |

这是工程取舍，不是已经测得无线速度差异。S3 支持连接路由器及自建热点，因此无线局域网不等于必须接入互联网；设备热点和手机切网体验仍需实测。[Espressif 无线网络模式](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/network/esp_wifi.html)、[苹果局域网访问说明](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)

ESP32-S3 支持低功耗蓝牙，不支持经典蓝牙串口方式。若实施蓝牙上传，用自定义服务承载设备能力、分块上传、校验／提交、控制命令与状态，不把它当作天然的文件系统。[Espressif 蓝牙说明](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-guides/ble/overview.html)

- **同包多通道：** USB、局域网、蓝牙与未来云端入口复用设备包、安装服务和播放控制契约；不同传输的分块大小和重试由各自适配器处理。
- **可靠传输：** 有总长度、包摘要、上传身份、偏移和分块确认；协商设备缓存限额并流控。断线后核对设备已持久确认的进度再续传，重连不重放执行命令。
- **可靠安装：** 区分接收到、完整校验、持久保存、可激活与正在播放。节目和索引提交具备掉电恢复规则；新包失败不损坏旧包。首版安装／擦写在明确维护状态执行，未验证前不承诺演出中无缝安装。
- **本地运行：** 包完整安装后，手机只需发送选择、执行、停止／释放等短命令。手机锁屏、应用退出或蓝牙失联时，盒子仍依自身时钟运行既有本地节目；外部音视频同步依赖另行声明。
- **控制权：** 上传和控制仅开放给已绑定的入口，同一时刻有明确的控制者；多个手机不能靠最后到达的无线包争抢输出。具体配对／绑定、授权与会话代次在协议任务定义。
- **跨端实现：** 共享界面、编译模块和应用契约，各系统适配蓝牙权限与传输。苹果平台有原生蓝牙框架；浏览器蓝牙并非各主流浏览器通用，不能假定一张网页就能在所有手机直接连接。[苹果蓝牙框架](https://developer.apple.com/documentation/corebluetooth)、[浏览器蓝牙兼容边界](https://developer.mozilla.org/en-US/docs/Web/API/Web_Bluetooth_API)

下载耗时由实际包大小和实测有效传输率决定，不能拿无线物理速率直接换算。USB 首先用于板级验证，然后优先验证局域网安装；蓝牙进入配网／控制适配候选，不为首个有线闭环同时堆上两套无线功能。网页访问本地设备还需处理浏览器的安全上下文、来源和局域网权限，不能由“支持无线局域网”推导为任何网页都能直连。本决定不等于立即完成全平台移动应用或开放演出期间的无线更新。

## 已连接设备的只读检查

2026-09-21 系统设备树发现厂商 `Espressif`、产品 `USB JTAG_serial debug unit`，标识 `303A:1001`；存在 `/dev/cu.usbmodem2101`。这证明系统已枚举到乐鑫 USB 调试接口，尚不能单凭它确认具体板卡修订、16 MB 实际容量、分区内容或蓝牙运行状态。

本轮仅读取系统设备树和串口路径，没有打开串口、复位、读取闪存、刷机或发送 DMX。板卡电气接口的待办仍见[硬件基线](../../hardware/waveshare-esp32-s3-rs485-can.md)。

## 实施与验收调整

PLAYER-001 的契约增加片段入口状态、时间范围、依赖闭合、资源报告与确定性样例。PLAYER-003 的包和安装协议与传输解耦，先用 USB 调通，再优先验证局域网分块／续传／命令去重。无线协议和固件框架须一起验证 UART、存储及调度干扰；不能仅凭语言偏好冻结框架。移动宿主编译与无线适配单独验证，保持“盒子自主执行”的边界。

新增验收：截取渐变中途仍正确；引用外部预设仍可独立执行；片段中断／循环／切换与主机参考一致；不兼容／超限在发送前明确拒绝；传输中断保留旧包；重复命令不重复执行；手机退出后本地灯光持续；蓝牙压力不破坏物理发送。原有时序、掉电恢复和本地操作要求保留。
