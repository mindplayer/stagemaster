# PRODUCT-ADR-168：后台三维读取的繁忙分类

状态：2026-10-05 已有限实施，红绿／桌面／严格检查通过，完整软件及原生复验中。关联 [PREVIS-008](../tasks/PREVIS-008-native-audio-loop-observation.md)、[PREVIS-009](../tasks/PREVIS-009-background-frame-busy.md)、[后台只读三维](../../module-api/background-previsualization.md)。

## 实际证据

PREVIS-008 正式内部桌面复用现有音乐消费者与独立 Game，固定／持续循环、暂停十秒处80灯量化投影、运行中三维重开与后台隔离已有证据。额外帧观察首轮遇到409；原检查器未保存该次响应正文，不能追溯其确切原因。随后一组明确的并发只读帧请求实际返回200／409，后者正文为“后台观察正在读取”，没有控制命令或故障注入。

`Background::lights` 的 Reader `try_lock`拒绝和上游样本拒绝都以字符串返回；桌面 `frame` 将所有错误映射409。明确的局部读争用因此被当成来源／版本冲突，UE既有503暂时保持机制不能正确区分。仅将请求串行或放宽检查不能修复该分类。

## 有限决定

1. 在桌面后台适配内部引入小型类型化读取失败，区分 Busy与拒绝；核心公开 `Reader` API、桥协议2、工程格式和字段不变。不增加队列、时钟、播放器或缓存有效期。
2. 局部 Reader锁争用直接标为 Busy；核心现有字符串出口中，只识别准确的“后台请求未成功（503），请核对连接与原回执”。其他错误及近似文本均保留拒绝，不能凭字符串包含“繁忙”或任何非200响应扩大重试资格。公共类型化客户端错误迁移可后续单列，不在本修复中改变公开API。
3. Busy返回既有503语义并保留具体中文原因；身份／绑定／版本、鉴权、失效、故障和未知错误仍按原有拒绝处理。保留桥问题提示和失败日志，不将拒绝记成有效帧。
4. UE沿用原503处理：仅已有有效画面可短暂保持，不更新最后有效时间，满2秒仍失效；首次帧、场地、移动和其他错误不享有保持。没有新增重发控制、延长期限、合成回执或安全豁免。
5. 先保护分类红灯／真实争用，再相关Rust、当前全量、严格检查和正式桌面构建。按ADR-167复用原Game／Node生成新的独立内部副本，原PREVIS-007／008包与证据保持；再验收真实200／503争用、音乐回执及只读GPU，008完整出口只在实际复验后收敛。

采用现有 Rust非阻塞锁、HTTP暂时繁忙和EFFECT-004保持机制，不自建观测服务或第二渲染入口。修复是实现对既有繁忙边界的对齐，不授予控制／编辑／硬件资格，也不把首轮未知409根因写成已证明或已修复。现场听音、厂家光学、客户发行和物理／长期门槛不因此关闭。
