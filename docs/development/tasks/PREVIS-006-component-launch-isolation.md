# PREVIS-006：组件启动完整性与实例目录隔离

状态：**ready，本轮实施**。基线 main `842e697eb65b4e27cf3bdb7fe8c95a76477c7dfe`，主工作区单写者，未跟踪 output/ 保持。属于 H5 已发布客户预演组件准备，非客户整包／GPU出口。

## 问题与限定范围

实际源码有两个隐患：resource_dir/previs 只检查三个文件，缺组件会在 debug 桌面静默改用 UE 编辑器；完整组件使用 app_local_data_dir，绕过现有项目内开发／验收实例目录。当前正式本机打包使用 debug，不能靠 release 分支排除前者。

按 [ADR-166](../decisions/PRODUCT-ADR-166-component-launch-isolation.md)实施一个内聚增量：

- 独立模块核对已安装组件的入口、清单、依赖上下文及 Mac Game 基础资源；目录缺席才能使用原有开发编辑器分支。部分、无效或指向组件外的路径明确拒绝，不使用系统 Node／编辑器补齐。不在宿主重写 npm 解析、签名／Mach-O完整资格或每次散列整包。
- 提取已有宿主数据目录选择，恢复／执行／音频／导航的现行路径及格式保持。组件使用同一验收实例所有者下专用 user／cache、项目内 tmp／logs；客户 release 保持本地应用目录，不写项目开发日志到用户默认区。不授予工程／导航目录权限。
- 创建预演目录前校验现有祖先及目标为普通目录、无链接；错误在启动组件前返回，不修改系统权限、不关沙盒。开发编辑器的现有目录和缓存行为保持。
- 拆出路径／完整性／测试职责，Rust拥有进程、原桥认证、时钟、控制权、UE／UI协议及项目格式不改。无新播放器／服务／依赖，无 Xcode／UAT／烘焙、刷机、设备或音乐操作。

## 实际验收要求

1. 新文件系统／实例／组件保护先复现旧失败，再实现；保留原预演路径、恢复与进程保护。真实完整组件目录可只读定位，不能称其已获得客户运行资格。
2. 实际执行相关桌面 Rust 回归、fmt、全目标严格 Clippy；阶段跨宿主目录入口的变更执行当前工作区全量。保留失败；不改弱现有断言。
3. 正式桌面包实际构建，用项目内验收副本的部分组件确认中文拒绝且不启动编辑器／信令／Game，工程与宿主状态保持。使用实际组件／正式桌面，不把纯路径测试当端到端客户包验收。既有 Editor 分支不重新宣称 GPU通过。
4. 保存实际命令／日志／版本证据，核对受保护工程、最近目录、原 Game／签名及历史证据，更新 STATE／工单并提交。Xcode临时例外、客户签名／最低系统／许可、GPU／听音／物理／长期保持未通过；接续整包组装，不扩 H6。

成熟机制：沿用本机 Tauri 2.11.6 的 PathResolver（resource_dir／app_local_data_dir）和现有恢复实例选择；复用 PREVIS-005 锁定 Node／官方信令上下文，而非自写依赖管理器。具体权限仍依据 [ADR-165](../decisions/PRODUCT-ADR-165-packaged-renderer-file-access.md)，本任务不把已验证的本机绝对资格装入正式应用。
