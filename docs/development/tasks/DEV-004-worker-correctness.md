## 固定修复契约

### 1. 原子取消与终态发布

- 接受取消与发布 `candidate_ready` 必须通过同一套带锁的状态转换仲裁，不能先读取状态再无条件覆盖。
- 在模型调用前、调用期间、候选构建中及最终发布前接受的取消，均不得产生可接纳的新候选；原始响应可留存为诊断证据。
- 如果发布已先完成，cancel 返回该终态并明确没有新接受取消，不能把终态退回 `cancel_requested`。
- 任务状态、attempt manifest、候选接纳资格与全局后端状态必须一致。后端已返回不能被晚到的 cancel 永久写成 still_running；确实无法确认的活动保持 unknown。
- 检查 run/repair/cancel/recover 的相关转换。在获取生成锁后重新核对任务状态、attempt 和剩余预算，避免陈旧读绕过次数上限或取消结果。锁只覆盖必要的状态操作，不让 cancel 为等待推理结束而无法被接收。

### 2. 所有已创建任务有真实收尾

- 上下文超限、请求准备失败等可预期错误，要么在创建 running 任务之前拒绝，要么落入明确的 failed 记录；不得遗留假 running 和活动 owner。
- 准备阶段没有发出 HTTP 请求时，不能谎报有未知后端推理。原有其他任务的 unknown 状态不能被此路径清除。
- 已创建任务的失败记录包含分类错误、attempt、实际耗时和已保存产物位置。对进程真正崩溃仍保留显式恢复，不自动重放。
- 前置拒绝若不创建 job，应返回可识别错误且不阻塞下一个合法任务；修复阶段拒绝应准确记录其失败并保留历史候选证据，不冒称已发起推理。

### 3. 单次与剩余预算覆盖完整请求

- 用单调时钟建立整个 HTTP 请求的 deadline，覆盖连接、响应头、成功／错误响应体读取；可持续收到少量字节不能延长 deadline。
- 请求上限为单次配置与任务剩余预算两者较小值。截止后不发布迟到候选，记录实际耗时；无法证明后端结束时标 unknown 并阻止下一次生成，沿用显式恢复流程。
- 不以杀死共享模型服务落实超时；如实现使用辅助线程或进程，须有有界退出／清理证据，不产生无主 HTTP 工作。具体实现由 Sol 决定。

### 4. 先保存传输证据，再解析内容

- 成功收到的原始响应在 JSON 及提案解析失败时也必须保存；非法 JSON、非对象 JSON、无效编码都有明确分类。
- 所有已发出的请求，不论解析成功或失败，都扣除真实耗时，不能依赖某个异常恰好附带 elapsed 字段。
- 对不完整／超长响应只保存约定上限内的字节并标记 incomplete，不伪装成完整响应；字节超限后的连接关闭不等于证明后端推理结束。
- usage 能解析时保存原值，不能取得时写 null；不补造模型用量。只把必要错误摘要返回终端，完整响应保存在产物目录。
