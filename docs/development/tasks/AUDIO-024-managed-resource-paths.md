## 实施范围

- 先用实际 `Resources` API 复现受管理目录／文件链接的错误接纳、归档写入链接目标或资源健康误报；只操作项目 `tmp/` 内新夹具，不触碰既有缓存、历史包或用户目录，不把推测当修复证据。
- Rust 小型私有路径校验模块；资源查找／导入／归档与只读健康检查接线，保持原 API／健康枚举、摘要和大小／缓存预算、原子发布／修复普通副本、取消。源文件明确选择的链接读取与托管路径分开；不引入依赖或新存储平台。
- 不安全目录、祖先或条目明确拒绝，失败原子保护源／工程／链接目标；只读检查不写入或创建目录。缓存优先继续，损坏缓存不静默改走另一个副本。缺失、安全普通副本、同路径检查、普通损坏修复仍可用。按 ADR 说明并行路径替换的未覆盖边界，不冒称无 TOCTOU。
- 第一独立原生包实际拒绝链接目录并保护原 JSON／链接目标后，发现既有随附检查提示仍笼统承诺“保存可补齐”。仅扩 `CheckAudioResources` 的 invalid 提示：普通副本与异常路径分开，后者明确安全位置另存与重查。原保存／定位按钮与结构化接口保持，不靠匹配错误字符串决定权限；该新事实先补范围，再修改 UI，并执行相应全套、类型、格式及新独立桌面验证。
- 每项缺陷先红后绿；相关 Rust 全目标测试、fmt、严格 Clippy实际执行，边界影响较广时做当前全量。UI／格式若无源码变更不冒计重跑。正式独立内部桌面带音乐身份但不播放，验证检查显示、保存拒绝／安全路径恢复及原 JSON／工程编辑状态保持；构建或纯文件测试不能代替原生出口。
