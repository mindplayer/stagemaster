# UX-004：时间线连续拖动

基线：`92089f6`；主工作区，开始时干净。负责人：当前会话；状态：done。结果版本为本次 `fix(ui): make timeline gestures continuous` 提交。

用户反馈时间线拖动不流畅。已在当前浏览器复现：时间尺从 x=290 拖到 x=450 后仍停留在起点 6.8 秒；代码只有 pointerdown 定位，没有连续拖动。片段移动每次强制量化为 0.5 秒，关闭吸附后仍按 0.1 秒跳动。

本任务仅修改 `apps/ui-prototype/` 的 UI 手势、针对性测试和相关说明。补齐时间尺／播放头拖动，片段改为连续定位与邻近吸附，合并每帧更新，保留一次手势一次撤销。验证拖出区域、取消、缩放与末次位置，并保留保存／现场模拟隔离。

这是内存演示适配器的输入精度修正，不修改 Rust、公共 API、持久化或执行时间语义。时间数值采用毫秒精度，不代表调度或输出精度保证。

## 实现

- `useTimelineGesture.ts` 集中管理指针捕获、每帧合并、末次位置提交、取消和放大后边缘自动滚动；手势中只改预览草稿，松手才产生一条撤销记录。
- 时间尺连续拖动；播放头标签可直接拖动，保留按下位置的偏移，避免按住标签时跳位。拖动暂停离线预览，不操作现场 GO；Esc／指针取消／窗口失焦会取消当前手势。
- `timeline-interaction.ts` 计算连续位移与裁切；磁吸范围固定为 6 CSS px，目标为其他片段边缘、播放头、Cue 边界和可见的大刻度，不再全程量化到半秒。Shift 临时绕过磁吸，并显示对齐参考线。
- 移除舞台亮度反馈的 100 ms 过渡拖尾；播放头在起止点保持完整显示，不撑大轨道滚动范围。窄屏也保留吸附开关。

## 验证与审查

`npm run check`、`npm test`（15 项）和 `npm run build` 全部通过。新增 5 项保护回归覆盖微小位移保留、磁吸像素阈值与缩放、双端裁切、边界、滚动后的坐标，以及提交后一次撤销与现场快照隔离。Rust 未改，未重跑其测试。

浏览器实际核验：

- 同一段时间尺从 x=290 拖到 x=450，修复前停在 6.8 秒，修复后到 13.4 秒；按住播放头移动时实时到 16.3 秒，拖出轨道后约束到 20 秒。
- 487 px 宽的 20 秒轨道上，片段移动 3 px 反映为 4→4.123 秒；松手位移 7 px 提交 4.287 秒。一次撤销回到 4 秒，未保存或改变现场模拟 Cue。
- 播放头标签偏离中心按下时保持 20 秒，拖动 96 px 后释放为 18 秒；鼠标释放前尚未绘制的最终位置也能提交。
- 拖片段后 Esc 从 6.053 秒恢复 4 秒，没有新增撤销条目；裁切 10→9.231 秒后一次撤销恢复 10 秒。
- 3× 时间线边缘自动滚动生效，取消手势恢复原片段；缩回 1× 后滚动宽度等于可视宽度，无播放头造成的额外溢出。
- 在 1200×800 桌面及当前 652×897 窗口检查；窄屏吸附入口、时间线、GO 可见。完整重载后的新增 error／warn 为零；日志里曾保留上一轮 AudioReference 热更新改变 effect 依赖项数量的旧告警，本轮未将其当作新运行故障或隐去。

审查结论：本次已修复已复现的交互原因，未改内核与真实输出。未做大量轨道、长音频或多设备性能压测，也未据此承诺固定帧率。[验收补记](../../../design-qa.md)与使用说明已更新；页面保持本地可体验。
