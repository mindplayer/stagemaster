## 问题与限定范围

`usePreviewController.act` 在草稿处理、工程／预演快照的异步等待后，列表载入及普通控制缺少目标／可见工作区再核对。单场景原 `startScenePreview` 有部分保护，但仅检查当前场景 ID，往返同一 ID 可能复活旧意图。先以实际 React `PreviewPanel`、受控等待复现；不能把代码推测写成已发现产品现象。

- 冻结本次操作的宿主、场景／列表和显示绑定；隐藏、目标切换、A→B→A、卸载后，旧尚未发送载入／控制不得继续，旧回复／错误不得污染当前界面。已提交原宿主的动作不声称取消或回滚，不自动重发；既有单操作互斥、轮询及错误分类保持。
- 每个异步边界后、实际发送前核对绑定。仍使用草稿处理后的 Rust 工程 generation、同一播放器 epoch 和宿主返回的下一 serial；不改播放器、时间、持久格式、公共请求或依赖。当前可见面板对共享已载入内容的暂停／停止仍可用，不用“目标不相同”禁用故障停演入口。
- 独立小型操作协调函数、hook 接线和测试；复用 `startScenePreview`，不复制场景载入／执行语义。取消／草稿失败不发送，当前宿主错误保留，串行／陈旧纪元保护不削弱；跨编辑版本的合法草稿应用仍能载入。
- 测试覆盖草稿和快照等待时切换／隐藏／往返、旧动作／错误、载入后不自动执行、当前 generation／epoch／serial、场景原保护、传输动作不应用无关草稿、不重发。真实组件留红绿 DOM／PNG；独立正式内部桌面验证无音乐载入、人工／定时推进、暂停切页／继续／停止、编辑状态保持。组件／构建不能替代原生出口。
