# TIME-001：独立时间域与同步组边界

实施中。准备基线 `3826db5`，时钟／媒体组增量 `b89b3a4` → `773ca5f`，原生消费观测 `773ca5f` → `e30fca2`，原宿主入口增量基线 `e30fca2`，main 主工作区，当前会话单写者。已按 [ADR-111](../decisions/PRODUCT-ADR-111-independent-clock-mapping.md)／[ADR-112](../decisions/PRODUCT-ADR-112-media-following-source-groups.md) 实现时钟区间映射、独立媒体准备器与真实来源合成，并按 [ADR-113](../decisions/PRODUCT-ADR-113-audio-consumption-observation.md) 补正式音频原生消费观测；[运行契约](../../module-api/media-source-groups.md)。本回合分类为 progress，持续 goal active。原独立宿主线程入口已补，独立进程／桌面正式音频仍未接通，本工单未完成；不以当前库级出口替代完整跨边界验收。

## 实施前代码证据

- `stagemaster-runtime-host::Backend`／worker 的 `now_ms` 同时承担输入租约、请求截止与实际调度时刻，必须保持单调；不能拿会倒退的音乐定位位置替换它。
- `stagemaster-live::Session` 目前在同一个单调时间推进所有来源，并以实际时刻决定属性接管。独立同步组需要区分媒体求值位置与接管事件时刻；不能简单为每个来源传不同的 `now_ms`，否则会破坏合成先后次序。
- `stagemaster-audio::Transport::position` 当前明确是软件消费位置，普通播放没有完整的时钟身份／代次；正式演出 Voice 有实例与循环遍数，但仍不是经过校准的声卡呈现时刻。保留这个真实限制，不能包装成“已声光同步”。
- `stagemaster-project::audio_segment` 已接受外部音频游标并在回退时重建采样；`stagemaster-playback` 已有 RateClock 和循环调度，可复用其求值与定位机制，不能另写一套场景播放器。
- `docs/module-api/shared-contracts.ts` 的 ClockInstant／MediaTime／TransportCursor 是早期草案，可复用职责划分，但尚不是运行接口。

## 成熟机制与取舍

参考 [GStreamer 时钟与同步](https://gstreamer.freedesktop.org/documentation/application-development/advanced/clocks.html)：区分单调时钟、运行时间、素材位置，音频设备时钟速率并不必然等于系统时钟；暂停／定位通过基准和片段映射表达。复用其分层思想，当前不为增加时钟边界而整体替换已用 Rodio／CPAL。

参考 [RFC 5905](https://www.rfc-editor.org/rfc/rfc5905.html)：多时间戳交换用于估计偏差、往返延迟及质量。只借鉴可核验的测量机制，不把两台设备时间戳直接相减、不把往返除二称为精确单向延迟，也不在本项实现完整 NTP／PTP 服务。

## 本项要证明的结果

1. 明确时钟身份／重启代次、整数单位、素材位置及播放代次；局部定位不能倒退宿主调度时钟或延长控制租约。映射有误差、有效期和能力依据，未知值不能冒充零误差。
2. 在边界外完成资源／计划准备，再以明确组和代次接纳开始／暂停／定位；迟到旧观测、旧操作和错误时间域被拒绝。准备失败、部分执行、失联与恢复保持可核对状态，不能声称跨设备原子启动。
3. 两个独立时间域的代表性用例使用真实既有工程编译／播放／输出代码，至少一组媒体跟随、一组自主运行。验证组内定位／暂停不影响另一组，漂移与有界失联不重放离散动作，所有来源仍经过单一属性合成与输出仲裁。
4. 为音频观测、独立盒子时钟和未来外部视频留下窄适配口，核心不依赖 Tauri／UE／蓝牙。当前软件验证不宣称声卡／蓝牙音箱或实板同步精度；真实路由校准仍单列验收。

## 实施约束

先形成具体 ADR 与运行契约，核对当前 RateClock／音频段落求值后确定最小代码切入。按时间类型与映射、组内运行状态、播放器接入、宿主适配和测试分文件；不预注册空 crate，不同时重构全部音频／实时输出。允许分可验证增量，但不能以独立数学工具测试替代第 3 项跨边界出口。

验证重点：时钟原点不同、精度／速率差异、单位换算与溢出、样本乱序／过期／身份切换、暂停后恢复、向前／向后定位、来源独立性、迟到命令、准备失败及有限失联。具体生产阈值由目标与测量确定；本轮测试数值不是性能承诺。先做相关软件验证，物理设备仍按既有授权和实测安排。

## 本增量实现与审查

- `stagemaster-time` 无依赖、无分配、no_std；四时间戳以不对称延迟、相对漂移及采集误差得到保守区间。身份／代次、年龄、不确定度、倒序和整数范围均显式检查。
- `stagemaster-live::media` 以固定组、不可伪造的准备器／准备结果和播放代次接入原 Session。准备器可单独移入工作线程，不借用正在运行的 Session；激活借用准备对象，旧计划及失败对象都留给调用者在调度外回收。
- `LiveSequencePlayer::apply_timeline` 复用同一个 Player 与 Ownership，媒体渐变使用计划自身起点，现场来源仍保留原合成基线。中间需要人工推进的列表拒绝作为媒体跟随组，不悄悄卡在第一处等待。
- 来源自主时钟、媒体位置与组失联期限分开。短时缺样本保持，超时锁定失联，恢复要重新准备；旧观测／过期准备不会推进其他来源或刷新有效帧。自主来源继续运行，所有贡献仍由唯一 LiveMixer 合成。
- 新增生产文件最大 123 行，按映射、类型、准备、接纳、控制拆分；未改工程／设备包／HTTP／GATT 格式或第三方版本。未操作设备、固件、原生窗口、用户工程及 `output/`。

## 尚未关闭的出口

1. 正式原生音源现已提供实例、完整帧计数、位置与原采样时间；普通试听／临时循环尚未接入，播放意图与实际消费仍须由后台适配协调。软件消费位置不能称为声卡呈现时刻。
2. 媒体观测、准备激活及回收已接入既有独立宿主线程，沿用有界入口／原控制权与回执，见下方 ADR-114 增量。独立进程应用层与桌面完整音频生命周期尚未接通；可信应用还需限制准备作业和音源资源总量。
3. 提供方重启后的显式时钟重绑定、外部循环回跳／混合人工段落、设备部分启动／失败回执及失联恢复需在实际适配中继续验证。当前提供方固定于组准备；错代次拒绝已测，不能宣称自动重绑定已完成。
4. 当前没有外部机构动作派发，不能将“不会发动作”当成已验收动作去重；真实声卡／蓝牙音箱／板卡同步精度、远程媒体协议及物理输出另验收。TIME-001 与整体 goal 均保持未完成。

接续代码核对：`audio::Transport::revision` 用于准备作业失效，暂停／播放也会改变它，不能直接充当媒体播放代次；普通 `Position` 尚无提供方身份及消费采样序号。正式演出 `Voice::snapshot` 在读取冲突时会返回上次快照并标记 `snapshot_pending`，后续适配绝不能给这份缓存重新打时间戳来续命。`live-host::Action` 和 `State` 目前只有自主来源控制／状态，新入口应复用原宿主并分别管理受控的准备激活与连续媒体观测，而不是让控制客户端保活决定后台音频生命周期。

## 原生音频消费观测增量

基线 `773ca5f`，结果为本次 `feat(audio): publish native consumption observations` 提交。复用实际 PerformanceSource／LoopPlayback 和原 seqlock；完整采样帧才增加消费计数并记录原发布时间，首帧前没有消费观测。控制元数据、结束／取消、重复读取与缓存回退不刷新时间；时间／计数／循环位置在同一快照内，实例与 Voice 统一且不回绕。

`Transport::performance_observation` 提供原生窄接口，竞争／输出故障返回错误，没有正式音源返回 None。`requested_playing` 只表示主机意图；暂停在音频回调生效有延迟，不能拿这个布尔值证明硬件已停止发声。界面可保留明确待更新的旧快照，执行观测不以旧缓存替代。新回调发布不引入分配、文件／网络或阻塞锁，开销尚未量化。

审查结论：原生消费观测增量通过，完整 TIME-001 仍未完成。接续真实后台有界入口／原回执、准备与激活期间音源推进的协调、循环回跳和提供方重启重绑定；普通试听／临时循环的统一适配与实际声卡呈现延迟不得遗漏，不以新观测类型存在代替这些出口。

## 原宿主媒体入口增量

基线 `e30fca2`，main 主工作区，当前会话单写者；依据 [ADR-114](../decisions/PRODUCT-ADR-114-bounded-media-host-ingress.md)／[宿主契约](../../module-api/media-host-ingress.md)。上一回合为 progress，本次继续实际运行边界，不回到局部界面细化。

- 原 LiveBackend 增加固定组的准备槽／最新观测槽；新 Activation 是不可伪造的轻量票据，原 Client／Authority／命令队列处理激活和停止。回执不持有播放器；每组未回收前不能覆盖准备。
- 原 Session 继续唯一合成与编码，原后台 worker 继续独立推进；可信媒体观测不借用操作者租约，真实音频消费在输入权释放、客户端退出后仍推进媒体组。
- 调度只 try_lock，不等待准备端；计划驻留槽内并被交换，成功和失败都由调用端取回释放。端口丢失时保留的资源有上界，后端销毁后拒绝新消息，剩余准备可由仍存在的端口回收。
- Prepared::advance_to 在调度外追赶到新的实际消费位置，失败对象不能进入调度，回退重新准备。Host::clock 与实际调度共享原点，LocalClock 只映射同进程原采样 Instant；不是远程同步或声卡呈现精度。
- 宿主仍是整数毫秒入口，样本映射在其逻辑时刻未来时拒绝；测试等待真实宿主时刻覆盖采样，再提交原时间，不改时间戳迁就验收。
