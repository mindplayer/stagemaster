# UX-023：预演短时状态竞争

状态：完成；结果为本次 `fix(previs): tolerate bounded session contention` 提交；基线 `5eb04f0`；当前会话／主工作区。接续 AUDIT-001 U04 与 UX-020 实测问题。

## 独立判断与实施

原生正常音乐和三维轮询偶发显示“工程正在处理其他操作”。代码审查确认桌面预演命令对 Session 只尝试一次互斥锁，正常快照／编辑的短时竞争也被当成错误。界面保持真实错误可见，不以清空提示掩盖问题。

沿用已有互斥保护与 Tokio 定时让出机制：仅 UI 预演命令在 250 ms 内每 5 ms 尝试获取锁，不占用异步线程，不跨 await 持锁；超时退出且不遗留排队写入，毒化与短时忙区分。取得后只调用一次业务操作，继续在操作内检查工程代次。渲染器逐帧 HTTP 仍采用已有有界工作池和快速拒绝，不在输出循环累积等待。

这是内部获取策略修复，不改 JSON、协议、播放时间或控制权语义，也不引入新缓存。新增辅助和故障注入测试各自独立文件；后续若工程操作长期持锁则仍给出真实忙提示，不能把本改动称为完全消除共享锁瓶颈。

## 验收

单线程异步运行时在竞争期间仍推进定时器；释放后仅一次执行；超时无迟到写入；业务错误不重试；毒化单独报告。Rust 完整测试、fmt、严格 Clippy 和桌面构建。原生真实工程播放／编辑／保存及三维跟随状态检查，设备保持断开。
