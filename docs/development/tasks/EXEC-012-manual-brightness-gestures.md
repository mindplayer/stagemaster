# EXEC-012：所选灯组共同亮度连续控制

状态：本增量完成；2026-10-04，基线 main `9951b33`，结果为本次 `feat(execution): adjust selected fixture brightness continuously` 提交，项目主工作区单写者；开始仅用户未跟踪 `output/`。上一 goal 轮提交并原生验证 AUDIO-020 迟到连接，分类 progress。依 [H2](../sol-handoff/roadmap.md#h2-补齐必要现场操作)、[后台执行契约](../../module-api/desktop-background-execution.md)接续。

目标：在已有后台手动编程器中为所选灯组提供共同亮度推子，真实原子 Patch／权威实际值与精确输入共存。共同亮度仅指无功能档位的 `dimmer`；颜色、轴、轮盘和复位不线性插值。明确一致／不同／部分或全部未持有；不把未持有当零。搜索外所选灯仍在整组目标内。

复用 EXEC-007～011 和 ADR-154 的成熟机制：一个后台只有一个连续请求调度器，来源电平与属性手势互斥；保留一个最新目标和一个在途请求、至少 50 ms 控制间隔、当前修订与自己的新序号／applied 回执、5 秒确认期限。此次只抽取该调度器的目标读取／动作策略，不复制播放器、协议或定时器。固定后台／布局／工程／会话／来源、灯组和属性；隐藏／失焦／取消／换目标／抢占丢弃未发目标，已应用值不回滚，旧在途不操作新对象。

范围：UI 内部目标策略、原单飞控制器与生命周期／range Hook、独立共同亮度组件及 ManualControls 接线，纯规则／控制器与真实组件／正式原生验收。沿原 `ExecutionAction::Patch` 与 manualValues；不改 ApplicationHost 公共接口、Rust 语义、工程／设备格式、控制租约和时钟，因此无需新领域 ADR。有数值草稿先应用或取消；手势中选灯／属性、来源电平、录入及其他控制互斥。归零仍持有，明确释放后原节目接管，不写工程历史。

验收：不同／未持有不触摸无动作，整组容量超限原子拒绝、冻结选择与定义、迟到回执／控制权／工程／布局保护，延迟合并与最终零值、轨道外松手／键盘／Esc、精确草稿／搜索／隐藏保持；真实后台两个动态节目持续运行，设定与零值／释放、退出编辑器再只读连接，独立工程哈希不变。相关 UI／类型／格式、原 Rust 手动回归、正式打包及实际组件／原生验证；不用 mock 或编译代替真实后台，不启用音乐／UE／硬件。产物 `data/EXEC-012/`，日志 `logs/exec-012-*`，缓存／临时文件项目内 `tmp/`。

## 实现和自审

原 LevelGestureController 通过独立目标策略复用所有串行／修订／回执保护。共同亮度策略冻结全部灯具和原子预算，以整组实际持有值确认，不接受仅部分目标已到位。两个来源的电平推子和共同亮度共享唯一调度器，不增加灯光时间所有者、播放器或传输命令。Mixed／未持有初始中点仅供交互；新增 changed 标记保证未移动的按下／松手不隐式写值。

共同亮度组件与策略分别 124／87 行，调度器 286 行；ManualControls 311 行已评估，本次独立连续控制职责抽出，原文件仅继续协调已有选择／精确输入／录入，不进一步机械拆碎。测试 260 行／夹具 134 行，无新增手写文件超过 500 行；没有第三方依赖或锁文件改变。
