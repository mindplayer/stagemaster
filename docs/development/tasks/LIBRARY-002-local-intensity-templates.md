# LIBRARY-002：本地可复用亮度灯效模板

状态：完成；核心基线 `7de8cb9`、结果 `029b60d`，桌面以此接续，main，当前会话单写者，用户的 `output/` 保留。依据 [ADR-091](../decisions/PRODUCT-ADR-091-local-intensity-templates.md) 与 ADR-090。以下保留分阶段验证记录，最终出口见文末。

目标：把已有亮度效果导出为不携带工程灯具／地址的独立模板，Rust 负责文件验证、明确灯具绑定、来源快照和过期保护。随后接桌面导入／审阅／导出，使用户可以跨工程复用。首版只支持现有连续 dimmer 的基本曲线；不宣称云服务、其他灯型或设备执行已完成。

模块：project/effect_template 的类型／codec／绑定／来源验证分别组织，effects 仅接来源字段，Schema 与离线校验同步；不改求值器、设备协议或实时线程。Rust 核心单元与集成保护先验证，再用独立工程验证正式 UI 取消／历史／保存重开。

2026-10-02 核心实现：模板类型、严格 codec、绑定审阅、来源验证各自独立；共用嵌入 Schema 的解析抽到 schema.rs，避免文件和工程对同一来源作不同判断。SceneEffect 只增加可选来源快照，普通 Put 保留历史来源，原输出求值器和设备编码不变。实际 DTO 另置 effect-template-types.ts，未来云端伪 API 保持独立。

专项验证：5 项初步核心用例通过，随后补充场景容量拒绝用例纳入全量。初次编译修正私有重导出可见性、测试 ProjectView 不暴露 revision 的读取路径；测试档案初版只有红色而缺绿色／蓝色，被现有完整 RGB 限制正确拒绝，已补齐测试灯定义。没有放宽产品校验。135 格式、285 UI 与类型检查通过，全量 Rust／严格检查进行中。

桌面衔接方案：动态效果区增加独立模板文件工具，导出已应用的单个亮度效果；导入选文件后冻结当前场景及灯序，展示 Rust 生成的参数／目标／容量，在显式应用前不编辑工程。沿用原生文件对话框、DiskFile 原子保存、工程 generation 和统一事务队列；单项有界审阅缓存、随机 token、有限存活时间，取消只释放对应 token。切页／选择／工程变化拒绝迟到结果。应用接原历史与恢复文件流程，旧预演计划只标记过期，不自动载入／启动。未支持的其他类型明确说明，界面不放空的云端按钮。
