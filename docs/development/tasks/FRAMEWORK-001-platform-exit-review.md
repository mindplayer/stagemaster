# FRAMEWORK-001：平台框架整体验收

状态：实施中。2026-10-03；基线 `8464d8a`，main，当前 Astra 会话单写者。上一目标回合 DELIVERY-001 已验证并集成，分类为 progress。依据 ADR-097／100／101 和 PLAN-003；完整持续目标保持 active。

## 范围与方法

核对本轮实际代码与跨模块证据，不按完成任务数量或文件数量推断架构完成。逐项审查工程／资源、执行／控制权、媒体时间域、预演、设备／端口及交付／许可；区分可运行实现、只完成契约、仍待接入和真实设备未验收。保留用户关于框架优先、不过度细化功能的要求，也不把原 AUDIT-001 尚未完成的产品目标缩小为文档完成。

先记录当前基线的依赖和全工作区回归；核对代表性测试确实经过正式工程、播放器、安装或独立进程；已有原生证据按其提交和实际范围引用，不无关重开用户窗口。发现明显模块边界或主路径缺陷时，在本工单中限定修复范围后实施；公开语义变更另立 ADR。源码／测试／文档按职责组织，用户 output/ 不操作。

## 验收出口

1. 六组职责的现行状态归属、代码依赖、实际调用和失败路径有可追溯证据；发现未接线模块不能称完整产品链路。
2. 当前完整 Rust 工作区回归、可选交付 HTTP 回归、UI 逻辑／类型和模块伪 API 类型检查；不因既有通过记录跳过跨轮集成检查，也不把这些软件验证当作物理输出证明。
3. 独立执行、慢观察／失联、单一合成、音频组定位／暂停／恢复及只读预演的关键不变量已由代码和有针对性的实际用例验证。
4. 设备能力、承载、端口输出权、安装、激活、运行许可与云入口分别核对；未来主机／ARM／ESP32 组合不暗含 UI、TLS 或媒体依赖。
5. TIME-001 等本轮工单按原要求逐条审查，修正当前入口中过期的“下一步”，只关闭已经满足的出口；真实同步、硬件输出、生产授权及移动端不能被软件证据替代。
6. 形成当前实现／限制／优先缺口的整体审查结论，更新 STATE、执行计划和必要的架构入口；保留 AUDIT-001 未解决工作，不提前完成整个持续 goal。
