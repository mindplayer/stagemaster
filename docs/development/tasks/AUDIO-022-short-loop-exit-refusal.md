## 一个问题

优化桌面E0F5rq正式静音后台，四循环原副本中最后`19.875–20.875秒`持续循环运行时，点“本遍结束后退出循环”真实拒绝“请求格式、参数或长度不正确”；权威音源仍region3／exitRequested=false，最新音乐请求10 Applied，没有退出或自然结束。实际记录`data/PREVIS-012/native-final-exit-refused.json`／`native-final-exit-refused-ax.txt`；原写入载荷及HTTP正文未保存，根因未知。

服务`apps/execution-host/src/media/wire.rs`明确核对instance／region／pass与当前权威观察相同，这是保护陈旧命令的现行语义，**不是已经证明该次错误的根因**。之后新暂停11／稳定目标退出12／继续13 Applied及自然结束成功，不能掩盖运行中拒绝，亦不能写成修复历史循环rejected。

1. 记录实际HEAD、只读来源和隔离测试目录；仅读当前相关控制／UI刷新与[performance-loops](../../module-api/performance-loops.md)、[background-audio-application](../../module-api/background-audio-application.md)。保护PREVIS-012所有原始失败及005／007／008／009旧记录，不回写；不重复成功loop编辑或技术选型。
2. 用原宿主／控制客户端和真实请求接缝确定性区分：合法当前目标、跨遍后陈旧目标、音源实例／区段／代次变化，以及真正格式错误。捕获准确非敏感命令目标、原HTTP code／message、是否接纳、原回执、音源／组状态；不记录控制密钥、不搭新播放器／时钟／常驻观测服务，不为复现操作设备。
3. 若确定是合法陈旧目标拒绝，保持严格目标保护，有限完善分类与中文定位／重新明确操作入口；若是实错则先红灯测试再修复。不能接受任意当前遍、替换用户原目标、自动重发控制、重复接纳、重置音乐或延长既有期限。公共API／失败分类或控制语义需要变化时，当前会话先记录独立ADR再实现；普通局部问题自主处理，不空等Astra。
4. 做相关Rust／UI／类型／格式／静态检查，产品代码变动后执行适用当前全量，失败留日志。重新构建与资格必须绑定新真实来源，不冒用旧优化包／旧hash通过；若新来源需要既有工具接线，先限定范围与ADR，不扩大到客户Shipping／签名或UE重建。
5. 正式桌面在同样短区段和长区段验证准确当前退出／取消与陈旧拒绝，request Applied和后续自然结束分别核对，保持后台／音源／唯一公共三维、保存重开与收尾。若旧原生错误根因仍无证据，明确保留未知，不称“同源修复”。收敛后补PREVIS-012新版本复验记录，不修改原检查点false。
