# HOST-003：复用独立宿主承载多来源执行

软件增量完成；结果为本次 `feat(runtime): share execution host across prepared source groups` 提交；基线 `b6b8fee`，main，当前会话单写者；上一轮 MIX-003 已提交，分类为进展。

依据 [ADR-107](../decisions/PRODUCT-ADR-107-shared-host-backends.md)，抽取现有 Runtime 控制权容器，泛化原独立宿主执行后端，接入真实固定来源组。必须保留旧设备控制行为和默认受限命令入口，不复制调度线程／租约，不把库级接线当作 HTTP、桌面或物理输出迁移完成。修改涉及公共内存契约，持久工程／设备包和现有网络帧保持。

范围：`stagemaster-runtime`、`stagemaster-runtime-host`、`stagemaster-live` 的准备状态查询、新的宿主适配模块及测试／契约。按职责拆分已有 Runtime 大文件。用户 `output/`、工程、窗口与设备保持。

## 实现与审查

- 从 Runtime 抽出无标准库的输入控制权容器，原设备路径和新来源组共用租约、连续序号与历史回执；失去输入权不停止节目。修订及业务结果仍由执行后端负责。
- 原 Host 通过类型化后端接收已准备执行对象，仍只有一个后台线程／队列／截止时间／观察与关闭实现；原默认调用兼容，默认命令仍不能装载／安装。
- 新 `stagemaster-live-host` 接入实际 Session；固定来源状态、完整帧元数据、最多 512 个属性的只读批量载荷。输入端准备载荷，后台只克隆共享所有权；没有第二套播放器或合成器。
- 本项复用项目已有 HOST-001／002 的成熟宿主机制和 MIX-003 的来源语义，适用边界仍是灯光软件后台。音视频回调、认证及商业许可不合并进入调度线程；无新第三方依赖、持久格式或网络帧变更。接口与调用顺序见[模块契约](../../module-api/shared-live-host.md)。

## 限制与接续

本项完成共享宿主库的真实线程接线，尚未迁移 HOST-002 的受保护 HTTP 入口或桌面，也未连接物理端口。下一项在现有独立执行程序上补可信来源目录、请求映射和多来源回执，以进程级验收证明客户端退出后继续；随后迁移桌面。多时钟同步、UE 观察隔离、云端／U 盘统一交付及生产商业保护按框架顺序继续。本项为进展，持续 goal 保持 active。
