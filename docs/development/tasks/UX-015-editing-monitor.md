# UX-015：编排与三维同屏

状态：done。2026-09-28，基线 `62ba6f1`，main，工作区 `/Users/sunqi/projects/stagemaster`。用户要求持续改进，当前 Goal 继续；无委派。结果为本次 `feat(ui): integrate scene monitoring and persistent workspace surfaces` 提交。

## 判断与范围

POSITION-001 的实际操作暴露两个必要缺口：调位置／颜色时必须切到舞台查看，工作区反复切换后原生辅助树偶发缺少内容。优先改善完整操作链，暂不扩大运动模型或现场输出。

复用已收敛的[组件化工作区](../../ui-design/component-workspace-design.md)及[总体框架](../../ui-design/workspace-framework.md)：创作软件的画面监看与当前属性同屏、详细资源按任务展开；MA 的预演验证机制适用，但不复制多层窗口布局。保留现有深色组件，不另做示意页面。

## 界面与状态边界

- 编排中央区可开关三维监看，右侧继续编辑当前灯具的位置／光色，下方选灯、效果、预设及播放可独立滚动。
- 监看可跟随当前场景静态值；动态效果明确选择播放预览，沿用已有载入／播放／暂停／停止，切换场景不自动播放。
- 预演仍是同一宿主管理的 UE 进程与 Rust 投影。任意时刻只挂载一个可交互视频视窗；切页重连视频，不重启引擎，相机由 UE 保留。舞台可移动灯位，编排只选灯／查看，避免把指向编辑误作安装移动。
- UI 草稿进入原队列，错误阻止导航并定位；选择／搜索／工作区上下文不因隐藏丢失。监看开关／来源与查看不进工程历史，不改变工程格式、核心时间或输出权限。
- 原生辅助树问题先验证隐藏语义是否冗余；不得通过重建整个 Workbench、丢弃草稿或取消键盘访问来掩盖。

## 验收计划

同屏编辑四台摇头灯目标与颜色；一次历史／撤销、保存重开；三维选灯及无效草稿保护；当前场景跟随／显式播放来源；隐藏／切页后仅一个连接与 UE 进程、相机保持；反复切换原生辅助树、搜索与选择上下文；MacBook 宽度布局／键盘可达。类型、UI 回归、桌面构建；核心未变时不重复无关全量测试。所有原生操作用项目内独立实例，保留原用户未保存窗口。

## 显示容器专项

第一轮原生实测：删除冗余 `aria-hidden` 后仍在“舞台 → 列表”复现，整个工作区与底栏都未返回辅助树；点击可见搜索框未恢复，画面正常。不能把该方案认定有效。

随后采用独立 WorkspaceSurface：以 React 原生 createPortal 和固定目标容器保留组件树、DOM 值与镜头状态，离开工作区只将自有容器从页面卸下，返回时挂回；React 仍维护全部子内容。依据 [React 官方接口](https://react.dev/reference/react-dom/createPortal) 的固定目标与事件／上下文语义；不换 portal 目标、不建立第二个 React root，不把工作区内核状态复制到缓存。此为针对本机现象的适配，是否有效以原生复测为准，不把其他 WebKit bug 当成同一根因的证据。

- 66 项 UI 回归、类型检查、桌面正式构建与独立工程格式检查通过。此次不改 Rust／UE 核心或桥协议，沿用 POSITION-001 已通过的核心验收，不重复无关全量检查。
- 四灯同屏对焦 `(5,2,1.8)` 米，实际桥帧射线在该高度的交点均与目标相差小于 2 毫米（仅本例的量化验证，不代表真实机械精度）；RGB 改为 `#FF6600`，四灯实际帧一致。保存退出重开后两轴读数与颜色保留。
- 初轮对焦一次撤销恢复原场景。输入水平 300° 后切页／三维清空选择均被阻止，草稿与选灯保留、字段聚焦；Esc 恢复已保存状态。三维点选灯体可选中摇头灯 4 并联动单灯属性，未修改安装位置。
- 原生先做 12 次、开启三维并经历错误后再做 8 次工作区切换，内容树均完整。场景与四灯选择、搜索文本及隐藏选择计数保留。三维切页复用同一 UE 子进程（该轮 PID 61366），俯视／剖视状态保持；舞台显示移动灯位，编排隐藏且拒绝移动提案，连接后主动回到查看工具。
- 当前场景切换后实际来源 ID 随之变化，未自动播放。显式载入／播放动态效果后点击“三维监看”，仍在编排页且实际来源为 playback，颜色连续变化、位置不变；暂停后收起／重新打开仍暂停，停止按既有语义回默认输出。
- 原生 1440 像素宽与约 1112 像素宽窗口检查通过；监看与右侧属性固定，下方选灯／效果独立滚动。修复窄侧栏场景摘要溢出，位置按钮继续自动换行。
