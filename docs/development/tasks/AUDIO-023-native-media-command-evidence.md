# AUDIO-023：原生媒体显式请求与原回执的有限留证

状态：ready，2026-10-05。由当前实施会话按已有H1／H5拆分，接续[AUDIO-022](AUDIO-022-short-loop-exit-refusal.md)已交付的分类显示，产品基线main `ec5a825`；后继文档提交不回退。执行前核对实际HEAD、工作区及所属进程，保护用户output/和原始失败。

## 一个问题

AUDIO-022新优化桌面的一秒循环退出已实际显示目标变化拒绝，原音源保持且不虚假显示完成；但是原写入准确目标和HTTP正文未采集。现行API仅保留最新网络回执，随后自动维护的renewed使外部只读审计不能再关联被拒绝的原指令。另一次长循环继续交互只有短暂“核对原回执”，音乐request8不变，原指令是否发出与结果未知；后继明确继续request9成功不能解释它。

现行共享客户端已经把最后显式operation_record与维护record分开；复用该边界，**只补最后一条显式媒体操作的有界非敏感诊断**，不扩大服务历史窗口、重发控制或另建观测平台。历史PREVIS-012原write缺失不能追回，本项不许宣称解释所有旧偶发。

## 范围与顺序

1. 按需读原客户端media_control／control／http、桌面execution入口、executionCommands／useExecution与现行媒体契约；先记录现状、接口、所有者、容量、失败行为与验收。若需要新增View／应用诊断字段，当前会话先记录独立ADR和契约再实施，不改变协议版本、格式、时间或控制权语义。
2. 原客户端在显式操作进入原发送路径时，保留原网络serial、预期revision、group／generation、准确动作及instance／region／pass等合法目标；同原请求对应HTTP接纳／拒绝、原complete outcome、媒体request／Applied关系分开。未进入发送路径不能虚构已经POST，网络不确定不等于服务已接纳。只保留最后一项、有限固定大小；错误／超时／读观察繁忙不隐式重发，自动维护不覆盖显式证据。
3. 优先复用现行operation_record／MediaRequestIdentity及内部验收诊断出口；领域留证、宿主投影、UI说明与测试按职责分文件。只白名单非敏感字段，不记录token、Authorization、环境、完整工程、音源内容或任意请求正文；不搭新后台／定时器／历史日志服务，不增加占位UI。
4. 先红灯证明当前目标／回执证据缺失，再覆盖合法退出／取消、格式错误、陈旧目标拒绝、未发送／结果未知、同请求查询、自动维护不覆盖、容量与敏感字段排除。原控制绑定、序号、期限／音源／PCM和完整帧保护保持；独立验收不削弱。
5. 按改动执行相关与适用当前全量、类型、格式、严格检查和真实组件；新优化包绑定实际提交。原生短／长区段明确一次操作，原目标／原结果留证，即使自动维护之后仍可解释；不得为了得到预期结果盲目点击，拒绝只保留并通过不同明确稳定目标继续。保存重开、唯一三维、同后台与所属进程收尾实际验证，原失败／旧false不回写。

## 出口及排除

一个有限留证增量交付，记录基线／源码／构建版本、红灯、实际测试和正式桌面结果，更新STATE及本工单。原生POST是否发出、接纳、播放完成分别表达；无法知道仍写未知，不把消息或下一次成功当原失败根因。再回PREVIS-012限定复验，不重做已完成循环编辑、拆播放器或无限完善页面。
