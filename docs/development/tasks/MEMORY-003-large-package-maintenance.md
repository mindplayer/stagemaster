## 第一增量：顺序擦除

原 store 中的暂存／写入／封尾职责抽入独立 payload 模块，只增加一个擦除游标，保留既有物理读回和中毒状态。最大 2 MiB 原始存储模型分别覆盖 4/4096 与 256/256 编程／擦除几何，准备阶段不擦任何载荷，顺序写完每个载荷扇区恰擦一次；边界缓冲、封尾和未写扇区保护通过。新后续扇区故障矩阵覆盖驱动之前／部分／之后报错及静默损坏，原每驱动边界完整包恢复矩阵保持。

首版故障语料使用一个有效尾字节＋三个 0xff，模型的半字静默写入实际上仍写完了所有有效数据，因此错误期待拒绝；改为三个有效尾字节，让半写真正损坏载荷后重验通过，没有修改或削弱验证器。初次失败日志 memory-003-nor-incremental.log 保留。相关 142 项 Rust 测试、工作区全部目标严格 Clippy、实际 S3 严格检查及完整链接通过；日志 memory-003-{regression,workspace-clippy,xtensa-check,xtensa-build}.log。镜像 864,992 字节（27.50%），既存 RWX LOAD 告警保留。

实板开始前经原生只读检查原摘要／28 节目、无控制者／实例；串口无占用。真实配置与原分区受控刷写，仅本次实验镜像，GPIO21 禁用；正在对照原 799,587 字节／64 节目包的安装操作峰值及完整恢复。
