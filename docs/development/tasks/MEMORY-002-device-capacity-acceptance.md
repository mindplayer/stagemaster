## 设备角色与依据

继续采用成熟的“主机编译／目标设备准入／本地执行”分工，复用已有 package、Runtime、Player 和安装事务；不为本板另写灯效语义或复制完整工程编辑器。ESP32-S3 可执行当前受支持、通过联合资源检查的灯效文件和状态机；大工程、多执行器合成、音视频与专业渲染仍由主机／ARM 承担。完整 JSON 工程与目标执行包是两个层次，不能把“设备不直接解析全部工程”解释为“没有本地效果执行能力”。

原厂 [ESP32-S3 规格](https://www.espressif.com/sites/default/files/documentation/esp32-s3_datasheet_en.pdf)列出双核 LX7／最高 240 MHz 和 512 KB 内部 SRAM；[微雪板卡说明](https://www.waveshare.com/wiki/ESP32-S3-RS485-CAN)给出本板配置。实板自检检测 8 MiB PSRAM，原分区采用 16 MiB Flash。固定 128 KiB 内部堆只是当前组装给分配器的预算，不是整颗芯片 RAM；还需给栈、静态状态、无线与驱动留空间。PSRAM 不能据容量直接当作相同延迟的内部 SRAM。

保留纯输出网桥作为可选角色，但必须单独验证上游传输速率、抖动、失联和端口所有权。把本地计算换成 BLE 逐帧推送会增加持续连接依赖，不能未经测量就判断更可靠。超出本板预算的内容应在部署前明确拒绝，交给主机／ARM 执行；不静默丢弃效果，不以扩大预算掩盖不足。

## 恢复时发现的维护退出问题

原 28 节目安装到 A 槽 generation 21，原安装例程及重复回执通过，但不重启的 `leave-maintenance` 返回节目读取／校验失败；同启动重试仍失败。`logs/memory-002-restore-operation{,-retry}.log` 保留。重启后绑定正常，而再次进入／退出维护仍失败，不能靠重启掩盖。

临时诊断逐层定位：ManagedWorker 得到 Storage 错误，NorStore 的快照读取安装记录判为 State，具体是元数据 `b[12..32] != [0;20]` 判断为真；同时摘要、标记、尾部填充值通过，捕获的 20 字节实际全零。板级同循环直接快照又通过。证据为 `logs/memory-002-snapshot-{debug,inner,nor,meta,reserved}-{board,leave}.log`，最后一组记录 `SNAPSHOT META 202` 与 `SNAPSHOT RESERVED [0, 0, 0, 0, 0]`。这支持当前 S3 目标路径的固定数组比较／代码生成问题判断，尚未定位上游编译器根因，不能推广为所有 Rust／ESP32 的问题。

仅把零保留区和 0xff 填充区改为显式逐字节谓词；标记、摘要、版本、容量、提交封印等规则不变，无字节格式或协议修改。独立测试逐个篡改两槽的 728 个保留／填充字节，其中头部篡改重新计算正确摘要，仍必须拒绝；合法两槽可快照。没有通过跳过校验、增加重试或扩大资源预算解决。临时诊断和计数器全部移除后，最终 S3 严格检查／链接及实板原包进入／退出维护／目录观察通过；`logs/memory-002-padding-final-{xtensa-check,xtensa-build,flash,enter,leave,observe}.log`。最终镜像 865,872 字节，占分区 27.53%。

扩展相关回归为 189 项 Rust，0 失败／忽略；最后测试助手按严格 Clippy 改为借用迭代器后，2 项新保护测试复跑及工作区严格检查通过。日志 `memory-002-padding-final-regression.log`、`memory-002-padding-final-tests.log`、`memory-002-padding-workspace-clippy-final.log`。安装不同测试内容后不重启激活已通过；后续完整输出复测另发现以下故障。

## 最终镜像复测发现 UART 写入期限故障

零填充校验修正后，测试包安装 B 槽 generation 22、同启动退出维护与目录读取成功；四类控制、暂停和断线也返回通过。但控制结束后约 16 秒继续采集时，实际 UART 写入等待触发 Deadline，发送任务退出，独立看门狗复位。因此 `data/MEMORY-002/capacity-final-report.json` 正确失败，不能将该轮整体判为通过。原始 `logs/memory-002-final-play-{board,gatt}.log` 保留；最大写入操作 24.061 ms、取消计数 1，此前最大运行间隔 35.647 ms、堆峰值 80,616。原 28 节目随后恢复 A 槽 generation 23，退出维护／目录成功，无控制者和实例，再进行修正复测。
