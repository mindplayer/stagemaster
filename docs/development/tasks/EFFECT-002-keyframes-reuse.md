## 实施与审查

独立 `KeyframeEditor` 与 `keyframe-tools` 负责选帧、输入、重排和命令数据；`EffectReuseDialog` 从真实工程场景搜索并复制，保留灯具或替换为当前选择，默认停用。编辑组件复用现有事务、取消和错误提示，不在 UI 求值灯光输出。原三种效果可显式转为关键帧，半速／倍速只修改编辑草稿。

Rust 工程模块强制形状、通道、帧时间和 capability 校验；纯内核新增有界关键帧曲线，按 Q16 相位采样并沿用统一时钟、进入渐变及释放。持久模型不混入原两端值，原格式静态／基本效果兼容；编译逐步核算累计点数，在展开下一步骤前拒绝关键帧超限。见[运行契约](../../module-api/lighting-effects.md)。无新语言、运行库或物理输出路径。

审查通过：支持每效果 2–32 个同步属性关键帧，保持／线性／平滑过渡及闭环，不扩称为全部专业层和现场主控。代码、契约和实际结果边界一致。

## 实际验证

- Rust workspace **145 项**通过：比基线增加 3 项内核、5 项工程测试，覆盖关键帧端点／末帧闭环、三种过渡、相位／延时／渐变／暂停／迟到帧、点预算／内存报告、保存／复制独立、模式和帧序拒绝、歧义字段与未知过渡拒绝、33% 脉冲转换前后 2018 个采样一致、编译超限提前拒绝。
- UI **46 项**通过：新增全部 65536 个 u16 的百分比往返精度、原效果转换、帧重排与显式均分、错误字段识别、深复制和替换灯具兼容性；工程格式 **68 项**通过。类型检查、rustfmt、严格 Clippy、桌面构建和差异检查通过。日志为 `logs/EFFECT-002-*.log`。
- 原生首次布局检查发现多帧全部展开过长，已收敛为选帧条＋单帧属性。实测第二帧改为 90% 后，提交自动切到错序的第三帧并聚焦时间；草稿保持，均分后可继续编辑／提交。倍速 6→3 秒、添加第四帧、保持过渡、重排内容且时间槽不变、360 度灯间展开均通过。
- 原生一次撤销整个新增效果回到原三项／“已保存”，重做恢复四帧；暂停停在 6.598 秒，编辑另一场景期间保持。跨场景搜索“多色”，用当前单灯复用原四灯效果，副本默认停用；副本半速到 6 秒、删一帧、明确点亮并启用后保存。重开仍为原场景四灯／四帧／3 秒，第二场景单灯／三帧／6 秒，文件复核身份与数据独立。
- 应用内 UE 跟随保存后的关键帧播放，四灯光束和落点在两次观察中颜色变化。`data/EFFECT-002/keyframe-editor.png`、`keyframe-previs.png` 及独立验收工程保留。未修改 UE 源码，未重复无关引擎构建／测试。
- 隔离验收实例已经退出；正式用户窗口原有未保存内容保持不变，更新后的应用需用户保存后重开。初版关键帧草稿 Esc 取消未写入工程；未宣称每种手势、移动端和读屏均已验收。
