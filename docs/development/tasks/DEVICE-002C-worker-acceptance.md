# DEVICE-002C：独立工作任务实板验收

日期：2026-09-28；工作区 `/Users/sunqi/projects/stagemaster`，本轮基线 `9998b50`，结果为本次 `feat(device): validate isolated install worker on ESP32` 提交。C 独立工作器增量已完成，正式认证 GATT 与桌面安装闭环仍未完成。

## 实现与判定边界

新增 `stagemaster-install-worker` 串行持有安装服务，内部连接代次、独立撤销通道、过期请求／完成保护和恢复对账。ESP32 第二核承接官方 FlashRegion／NOR 驱动，使用官方多核停放；32 KiB 栈和容量各为 1 的队列。`worker-readiness` 只读，`worker-write-test` 才启用编译时指定真实包的本地试验；两者均不提供无线安装授权，不驱动 DMX。

测试板微雪 ESP32-S3-RS485-CAN，16 MiB Flash，出厂 MAC `28:84:85:56:97:74`，USB `/dev/cu.usbmodem2101`。每次受控刷写显式使用新分区表与 ota_0，专用节目分区外的擦写由刷机工具完成；节目安装器只访问 `stmpkgs`。GPIO21 全程低电平，无 eFuse、系统配对或真实灯具操作。展示窗口及原用户工程／UE 保留。

## 发现并处理的问题

1. 自定义类型 0x40 在官方 SDK `as_flash_region()` 的类型转换中 panic。按 [ADR-037](../decisions/PRODUCT-ADR-037-installation-worker.md) 改为 SDK 支持的 `data/undefined`，地址、容量、双槽格式不变；严格拒绝旧类型，未修改依赖缓存。官方分区表往返与两项布局保护测试通过。
2. 首轮三节目重放全部帧摘要一致，但测试用共享堆瞬时差值断言失败：另一核无线临时分配 32 B，后续占用回到基线。去掉无效的跨核瞬时相等推断，保留结束时基线核验，并启用 `esp-alloc/internal-heap-stats` 记录分配器真实历史峰值。保留原失败日志。
3. 27 场景替换轮出现诊断 BLE 断开。初次失败记录在主机结束串口后截断，不能推断设备同时复位或存储失败。后续启动已读到 A 槽第 3 代完整提交，B 槽第 2 代仍有效，说明持久安装完成；这不将失败的无线并发测试变为通过。增加 ATT 回应／通知期限与通知错误日志，以及失败后 10 秒串口观察，继续定位。
4. 增加诊断后的重复擦写未复现断开，但最大往返达到 1,189.881 ms。检查锁定的 `esp-println 0.18.0::println!`／`with` 实现确认整次格式化与 USB flush 在临界区内；本地探针原先每 1 KiB 都打印完整事务及摘要，干扰被测无线线程。改为只打印协议阶段，按 32 请求汇总、结束时完整汇总实际计数与最大耗时，不改物理擦写策略或 250 ms ATT／6 秒保活期限。日志是已确认的测量干扰来源，是否是那一次断开的唯一根因仍未证明。
