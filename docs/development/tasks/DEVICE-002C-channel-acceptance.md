# DEVICE-002C：分片到工作器的通道验收

日期：2026-09-28；基线 `05cfeee`，主工作区，当前会话单一写入；结果为本次 `feat(device): bridge fragmented installs to isolated worker` 提交。依据 [ADR-038](../decisions/PRODUCT-ADR-038-installation-byte-channel.md)，接口见 [Endpoint](../../module-api/installation-byte-channel.md)。B 的系统绑定确认仍待答复，不进行系统配对、不开放未认证的无线安装入口。

## 本轮实现

在现有工作器 crate 增加无平台／I/O／堆分配的端点，复用既有 SMP 重组和编解码。覆盖打开回执前拒绝业务、一次一个完整请求、分片大小、会话核对、发送成功后移动游标、固定阶段期限、旧代次完成丢弃，以及错误／超时后关闭连接。事务、原子提交、幂等和上传器状态不复制到端点。

ESP32 本地探针通过同一端点向真实第二核队列提交：20 字节状态查询和 244 字节安装片段；等待完成期间每 100 ms 检查期限，队列满时关闭并立即撤销存活代次，旧完成持续消费。它依旧是编译时显式本地试验，固定主体不进入无线接口；诊断 BLE 只负责独立保活观测，不能称为节目已通过蓝牙下发。

## 软件验证

7 组新增保护测试、既有 4 组工作器测试通过，全工作区 306 Rust、严格 Clippy／fmt 通过。真实导出包在 1／20／244／1280 字节分片下经端点、工作器、FileStore 安装并重开；另检查未打开／背压／错误会话、坏片段、时钟倒退／溢出、打开／接收／工作／发送固定期限、同代次错误回执和旧代次丢弃。

“持久提交已完成但只收到第一片回执，重连后用户请求取消”用例仍得到权威 `Installed`，不误报取消。发送未取片段不得确认；重复读取当前片段不移动游标；半包失效后不能重置对象继续拼接。软件故障注入不等同实板拔电或真实 GATT 通知丢失。

日志：`logs/device-002c-channel-{tests,clippy}.log`、`logs/device-002c-byte-workspace-{tests,clippy}.log`。实际 Xtensa 只读／写测试 release 链接和严格 Clippy 通过；保持已知 RWX 段链接警告。

## 实板证据

在微雪 ESP32-S3-RS485-CAN（16 MiB，MAC `28:84:85:56:97:74`）上受控刷写；GPIO21 全程低电平，无系统配对、eFuse 或 DMX。原工程／UE 及舞台展示窗口保留。

第一轮 `data/DEVICE-002/byte-channel-write.json`：106,825 B／27 场景写至 A 第 7 代，B 第 6 代保留；108 次物理写、28 次擦。20 字节查询为 3 个请求片段／6 个回执片段；244 字节通道为 109 个应用请求、526 个请求片段、109 个回执片段。目标 `Endpoint` 2,632 B，堆历史峰值 52,884 B，结束回到 41,080 B；调用前栈采样 13,917 B，仍不是完整高水位。安装加重放 5.901 秒，27×400 帧与电脑一致，219 次诊断保活通过，最大往返 678.695 ms、P99 138.629 ms。日志 `logs/device-002c-byte-channel-write.log`。

第一轮之后补齐探针的每 100 ms 期限轮询和队列立即拒绝。最终适配路径复测 `data/DEVICE-002/byte-channel-poll.json`：110,772 B／28 场景写至 B 第 8 代，A 第 7 代保留；111 写／29 擦。244 字节通道处理 113 个请求、546 个请求片段和 113 个回执片段；20 字节查询仍为 3／6 片。28×400 帧一致，219 次保活通过，最大往返 559.339 ms、P99 138.789 ms；安装加重放 6.057 秒，堆峰值 53,008 B、结束 41,080 B，调用前栈采样 13,917 B，最大单请求 422.153 ms。日志 `logs/device-002c-byte-channel-poll.log`。

实板覆盖正常分片、双核等待、实际擦写／恢复和重放路径；超时、满队列的拒绝规则及失联竞态仍以软件注入／代码审查为据，没有在这一轮用实板故障注入证明所有失败分支。也未把本轮未复现失联解释为长期无线稳定性已通过。

最终已恢复 550,128 B 的只读 `worker-readiness`，`byte-channel-readonly.json` 及 `logs/device-002c-byte-channel-readonly.log` 验证最新 B 第 8 代摘要匹配、A 第 7 代保留、0 写／0 擦、20 字节查询 3／6 片、165 次保活通过，最大往返 140.029 ms。堆结束 41,080 B，设备描述仍仅诊断能力 1／认证 0。复原刷写日志 `logs/device-002c-byte-readonly-flash.log`；未进行实际拔电。

## 审查范围

本轮不改变工程／包／SMP 持久或线缆格式，无 UI 修改；未重复无关 UI 检查。正式 B 认证、GATT 特征／订阅／断开联动、静默维护与运行层衔接、D 桌面下发及完整设备链验收仍未完成。目标保持完整范围，不能以本地分片和诊断保活成功替代端到端安装。

阶段自审：接受字节通道模块和上述受控目标验证，不接受 DEVICE-002 整体出口；核心仍不绑定 UI、蓝牙、具体存储或云端。没有创建代理、另开用户会话或改变生产许可规则。

接续时须先处理主机的单连接 I/O 所有权：当前 `stagemaster-device-host::Service::operate` 在连接期间独占 Transport，循环执行诊断保活。不能让新上传模块另开连接或直接竞争该锁；应由同一连接任务协调保活与安装片段，上传状态和工程快照仍独立持有。B 的认证等待必须早于正常 HELLO 保活，且设备声明本身不能授予安装权限。
