# DEV-001：建立版本和验证基线

状态：ready。负责人：Sol。依赖：无。属于开发基础工作，不实现产品新功能。

## 目标与范围

让两个会话能引用同一份精确代码状态，并使后续任务可在独立工作区验证。
在执行时重新确认项目是否已有 Git；已有则沿用，不重复初始化。

允许：本地 Git 初始化／现状基线提交、必要的忽略规则、开发方法与状态记录、一个验证用 worktree。
不包含远程仓库创建、push、发布、下载新模型或大规模格式化／修复现有业务代码。

## 实施步骤

1. 阅读根 AGENTS.md，检查项目现状、用户改动、已有 Git 配置和忽略规则。避免纳入模型、运行日志、缓存、构建产物、凭据；不用展示凭据内容。
2. 若无 Git，初始化本地仓库，使用已有合法提交身份建立现状基线；不要编造用户姓名或邮箱。确实缺少身份时把这项依赖说明清楚。
3. 执行并保存 `cargo fmt --all -- --check`、`cargo test --workspace --locked --offline`、`cargo clippy --workspace --all-targets --locked --offline -- -D warnings` 的真实结果。基线失败单独记录，不能标成通过或修改验收规则掩盖。
4. 验证从基线创建独立 worktree、进行局部测试、输出 diff 的路径；构建缓存按本机 AI／infra 规则安置，不把可写任务状态混在多个 worktree 中。
5. 更新 STATE.md 的真实基线提交，提交交付记录，清理本任务自行创建且无待交付改动的临时工作区。

## 验收

- 可读取一个真实、可复现的现状提交；没有远程发布。
- 验证日志对应指定提交与工具版本；已知产品缺陷仍明确保留为待修项。
- worktree 中的修改不会直接出现在另一 checkout，接收方可以通过指定提交读取变更。
- 根目录原有业务内容没有被无意覆盖或“顺手修正”。
- 按[交付模板](../templates/delivery.md)记录结果，DEV-002 的依赖状态准确。

本工单是建立基线的例外：开始前没有 base commit 时允许填 `bootstrap`；完成时必须替换为真实提交。
