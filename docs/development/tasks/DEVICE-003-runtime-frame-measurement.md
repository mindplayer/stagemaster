## 问题与限定范围

正式原生运行命令已实板通过，但断线后 elapsed 推进与旧诊断 LIVE 负载计数不足以证明实际节目持续生成帧。原 dispatch 确实调用原 ManagedWorker.render，尚无独立计数／间隔证据。此次在现有第二核工作器中采样实际 tick＋render，使用原 FrameInfo／State，不新增播放器、不改工程／包／GATT 公共字节或控制权语义。

帧尝试、成功、实际运行及无连接运行分别计数；无帧和错误不能冒充成功，旧缓冲不计算指纹。记录相邻调度尝试的最短／最长间隔、超过 30／50 ms 的次数、tick／render／帧指纹耗时、完成队列背压及命令数量。指纹仅供诊断比较，不作为内容身份或校验授权。所有计数固定大小、饱和增长；不分配堆或逐帧串口输出。

跨核发布采用既有 embassy-sync CriticalSectionRawMutex 的完整值拷贝，每秒最多发布一次，失败立即发布；第一核按现有约 5 秒诊断周期读取后在锁外输出。运行构建的安装／运行操作统计不再从第二核直接 println；原安装专用构建保持原行为。参考为项目内官方 Embassy Ticker 及同步原语、现有 Runtime 只读 FrameInfo；适用边界是诊断采样，不是物理 DMX 帧完成或硬实时保证。

## 首轮结果及诊断修正

首轮真实配置镜像 812,480 字节，约 3 分钟单次启动记录：同实例连续断线采样 41.400001 秒，实际生成 39.999999 Hz；暂停继续出帧且进度保持，错误为零，最长计算 621 微秒，堆分配历史峰值 53,140 字节。但最长尝试间隔 50,136 微秒，超过本轮 50 ms 门槛，因此报告失败，不以平均帧率掩盖。原始证据 `logs/device-003-runtime-frames-{board,gatt}.log`，严格分析结果 `data/DEVICE-003/runtime-frames-first-report.json`。

用户本轮要求必须确认 ESP32-S3 能否承担状态机／文件解析，若不合适退为播放器网桥。已经成立的是有界编译包解析、状态转移及断线自主帧生成；未证明完整 JSON 工程、多路／任意大效果、硬实时与真实 DMX 输出。用当前设备和当前真实包测量，不能把 MCU 名称或 PSRAM 容量直接当产品能力承诺。

诊断源码核对发现 esp-println 0.18.0 的普通 println 宏在整个格式化／输出期间持有屏蔽本核中断的锁；底层满 FIFO 又会等待。数据中超 30 ms 间隔多随约 5 秒报告增长，先作单变量对照：格式化在锁外，按最多 32 字节调用原官方 Printer，每段释放锁让定时中断执行；保留全部统计、原 25 ms Ticker、BLE、负载和判据，不更换播放引擎或提高优先级。不禁用串口锁，不引入 unsafe／新依赖。周期报告只由第一核输出，错误／启动日志保持；跨线程诊断不是生产日志协议。实际源码包含测试验证长中文／数值输出逐字节保持且每次写入有界。因果结论须等第二轮实板结果。

## ESP32-S3 的职责判断

保持 [ADR-002](../decisions/PRODUCT-ADR-002-compiled-playback-and-transfer.md)、[ADR-033](../decisions/PRODUCT-ADR-033-device-runtime.md) 和 [ADR-100](../decisions/PRODUCT-ADR-100-composable-device-family.md)：本板适合继续作为**能力有上限的独立灯光播放器**。状态机、受限设备包解析及已有执行子集已有实板正向证据，目前没有因算力或内存不足而整体退回纯网桥的依据。

- 电脑／手机／平板承担完整 JSON 工程、灯具语义、复杂效果依赖与目标编译；设备只接受通过版本、内容和资源预算检查的设备包。这是职责选择，不宣称 ESP32 无法解析任何 JSON。
- ESP32 执行单计划、单路当前受支持语义，承担本地计时、渐变／离散功能和状态转移；运行不按帧分配或读取整个包。当前 2 MiB 包／64 节目／64 KiB 装载是产品预算，不是 16 MB Flash 或 8 MB PSRAM 的全部物理容量。
- 纯输出网桥仍保留为独立设备角色，必须验证逐帧传输带宽、抖动、端口所有权和失联策略。退为 BLE 逐帧网桥会引入对上游持续在线的依赖，不能自动视为更稳定；本轮没有实现或认证该模式。
- 若代表性最重节目、目标温度／无线压力或持续输出测量超过预算，先判定是诊断／调度／输出驱动还是内容算力瓶颈。对超限内容明确拒绝独立部署，交给主机／ARM 执行；不改工程格式、不复制业务内核、不默认静默丢灯效。

完成的是当前真实包和执行子集的可行性确认。尚未验证最大允许节目形状、长期泄漏／栈峰值、8 小时运行、真正 UART Break／MAB／512 槽时序、线路故障与实灯；GPIO21 始终禁用。因此可以保留独立播放器架构，但不能宣布硬件达到商业交付或硬实时。先接并验证独立物理输出节拍及快照交接，再做代表性负载与长期验收；音视频和三维不进入本板此档位。
