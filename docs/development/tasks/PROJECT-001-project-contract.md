## 目标和范围

形成最小工程格式草案、可审查样例和 Rust 读取／校验／保存链路。工程能创建、保存、重开并保留同等的可编辑含义，作为 PLAYER-001 的稳定输入。

先覆盖代表性 RGB／调光灯具、固定档案与逻辑配适、编组、预设引用、场景及列表；明确渐变／延时的存储表达与 PLAYER-001 行为契约之间的关系。时间线、复杂效果等未实现内容声明能力状态，不默默删除或假装可执行。

不要求先完成全部专业对象、多端同步、大型资源容器、增量自动保存或持久撤销历史；真实 UI 保存／重开接入继续由 PLAYER-004 完成。

## 实施次序与接口

1. 对照 ADR 的 OTIO、GDTF／MVR 经验，固定身份、修订、属性／值、时间表达、引用、能力与版本规则；形成精确文档及小型样例。核对原型数值身份、通用归一化值、按显示编号排序等行为的适用范围，不直接承诺其布局兼容。
2. 采用严格 JSON 正文和 JSON Schema 结构规范，实现独立编码转换及 Rust 领域校验；确认契约维护来源及生成／一致性检查方案。读取结果为经过校验的快照或明确诊断，编译器不遍历任意 JSON。
3. 实现完整快照的保存与重开，定义实际提交点和失败恢复行为。文件对应指定修订，读取不会自动激活现场输出。

JSON 编解码与具体文件 I/O 分离，给后续加密工程容器保留接入边界；当前仅实施明文读写，不引入加密库或密钥管理。格式识别不只依赖后缀，未知容器明确拒绝。工程结构和容器版本分开，详见 ADR 的后续加密边界。

[PRODUCT-ADR-004](../decisions/PRODUCT-ADR-004-relayed-device-authorization.md) 的正式／24 小时临时许可属于发布授权层，绑定设备及执行内容；不在可编辑工程正文放入可自行修改的到期字段来充当授权。当前工单仍聚焦工程读写，商业授权另由 AUTH-001 实施。

实施前记录精确源码路径、公共类型、转换错误及新增依赖；不新增一套 TypeScript 工程解释器。按需读取 `crates/stagemaster-domain/`、`crates/stagemaster-show/`、`crates/stagemaster-dmx/` 和模块伪 API；存储适配模块的具体拆分先评审。后续 Rust 实施按此范围另行细化；PROJECT-001A 的开发期检查不替代产品领域校验。

## 独立验收

- 保存重开后身份、顺序、预设引用、值、时间、固定档案和配适含义一致；不以 JSON 排版相同代替语义验收。
- 重复键／身份、断裂／错误类型引用、越界值／配适、缺失资源、不支持能力均明确报错，定位具体对象；失败不留下半个已加载工程。
- 场景改名／重编号不破坏引用；引用保持引用，不转成固定值；未理解内容的重存规则可验证。
- 结构与执行语义兼容分别验证；迁移用受控样例，未知必需版本／能力拒绝；没有真实旧版用户工程时不得声称已验证真实历史迁移。
- 保存失败、中断写入、旧修订保存保护最后完整工程；未通过实际提交点不报告已保存。平台支持按实测声明。
- 明确读取体积、嵌套和精确数值边界；若以后引入压缩或目录提取，另补对应限制测试。
- PLAYER-001 接入读取所得快照后，比较保存前后的编译播放结果。

Rust 实施执行项目规定的格式化、离线工作区测试与严格 Clippy，保留已有保护验收。可复现样例／测试纳入 Git；运行资料按需放在项目 `data/development/PROJECT-001/`、`logs/PROJECT-001/`，临时文件用 `tmp/`。
