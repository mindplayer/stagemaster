# FIXTURE-002：主动工作流审查与后续顺序

2026-09-27，基线 a92e5cb。只检查现行正式代码和能力总表，未重启技术选型。用户要求自主识别必要能力；本轮不是按控台菜单数量堆功能。

| 当前断点 | 判断／模块归属 | 本轮或后续验收 |
| --- | --- | --- |
| 正式 UI 只能选择两种通用灯具 | 阻碍真实工程接入，优先最高；独立工程 fixture 模块 | 本轮补项目灯库、粗细映射、模式替换、批量配适、占用和保护；确认真实编码与三维同一语义 |
| 两轴求解器已存在，尚无完整运动档案和 UE 动态关节 | 下一软件核心能力，应串通物理行程、反向、零位、安装校准、共同目标、越界反馈 | 独立能力／类型和动作定义；不能把 pan/tilt 填进线性亮度编辑器就宣称完成 |
| 色盘／图案盘／快门是分段和离散语义 | 真实摇头灯必需，依赖下一层档案模型 | 每段命名和范围、保持／跳变规则、条件互斥；复位／电机专门权限与执行语义 |
| 编排已有场景和循环效果，现场编程器／速度主控仍缺 | 高价值，但涉及控制权、记录掩码、释放和时间合成 | 后续用一次完整编程器事务补预览、记录、更新／取消，再做现场主控，不在 TS 新造播放引擎 |
| 有房间、平台和挂架，缺隐藏／锁定／空间隔离、门洞与观众区 | 真实多房间工作的下一场地增量 | 可见性和编辑锁归视图状态，不误改节目输出；几何仍一份数据进入内嵌 UE |
| 工程可保存但缺崩溃恢复、问题导航与设备交付检查 | 商业交付必要性高，不能长期只增强视觉 | 核验恢复草稿、外部冲突、坏引用定位；打包前显示设备预算及不支持能力 |
| 软件到独立播放盒未形成 DMX 闭环 | 首次软硬件交付的硬出口，优先于云库／授权花哨界面 | 后续按 PLAYER 工单做片段编译／有界包／原子安装、断连不打断和实际 DMX 波形；真实输出按既有明确授权范围处理 |

本轮选择灯库＋配适是因为它同时打通编排、硬件编码和预演，且能复用已验证格式与核心。没有因此把完整个人库、摇头灯、现场输出或商业安装包标记完成。后续任务在上述顺序和首版交付主线之间取最小闭环；每轮必须说明参考机制、状态归属、用户可见入口和失败恢复验收。
