# PREVIS-002：统一三维视窗与音乐进度

完成；基线 `a690cea`，主工作区，当前 Astra 单一负责人。结果为本次 `fix(previs): unify viewer and music transport` 提交。依据 [ADR-055](../decisions/PRODUCT-ADR-055-single-previs-workspace.md)，用户已有未跟踪 `output/` 保留不动。

## 实现与审查

- 工作台公共 `SharedPrevis` 唯一持有 `PrevisPanel`／Pixel Streaming；删除舞台、编排、音频页的重复视窗。切页保持连接、镜头和当前来源，收起断开观看但保留渲染器，停止预演才关闭渲染端。保留信令单订阅者限制。
- 音频会话由工作台持有，编辑页和三维音乐控制共用原生声音、波形、快照。切回音频页先查询声音是否仍准备，避免 `Transport.load` 把正在播放的音乐归零；其他预览释放声音后重新准备。仅打开三维不加载声音或抢占场景播放。
- 公共音乐控制支持播放／暂停／停止、时间显示、拖动松手单次定位、10 ms 键盘微调、Esc／失焦／指针取消；取消后继续按住拖动不会误提交。资源／范围／工程变化清空旧显示和加载状态，迟到准备结果失效，排队命令绑定发起时工程代次。
- 舞台选灯通过句柄／选择通知适配；只有舞台允许安装位置移动。上下文变化主动退出移动模式，代次令牌拒绝延迟进入移动及旧位置提案。普通相机操作不提交草稿。
- 外部音乐播放接管来源后解除旧“当前场景”自动跟随；切换工作区不发送新的来源命令。工程 JSON、GATT、Rust 时间／输出和预演线协议均不变。公共契约见 [预演](../../module-api/previsualization.md) 与 [音频](../../module-api/audio-editing.md)。

复用 Epic 官方传输组件和既有原生音频／波形能力，没有引入额外依赖或第二个播放器。审查结论：满足单视窗与有限音乐进度出口。当前进度对应音乐范围，不给等待手动推进的场景列表伪造总时长。
