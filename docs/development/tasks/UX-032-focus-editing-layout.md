# UX-032：专注编排布局

状态：完成；结果为本次 `feat(ui): add persistent focused editing layouts` 提交；基线 `0781e16`；主工作区唯一写入；不操作实板及用户 `output/`。

接续 AUDIT-001 U09。参考 [Premiere 面板展开与恢复](https://helpx.adobe.com/ie/premiere/desktop/get-started/tour-the-workspace/display-any-panel-full-screen.html) 的临时聚焦和恢复机制；本项目保留编排的资源与上下文属性，而不是照搬全屏面板和特定键盘布局的快捷键。

在场景／执行步骤／音乐页提供明确“专注编排／显示舞台”切换：编辑区取代中央画布，侧栏保持，音乐公共控制仍可操作，原三维 DOM／连接停放而不重建。每种任务记住本机查看偏好；管理及执行视图不受影响，返回恢复。隐藏编辑上下文前走现有草稿校验，恢复布局可回到完整画布。纯 UI 偏好不改工程或播放状态。

为防止新布局挤压步骤区，需在实际窗口检查步骤表／预览区域及音乐波形的宽高，不只检查 CSS 开关。验证原有分隔尺寸恢复、错误草稿、跨页／执行视图／重启、音乐与唯一三维保持、窄窗口／键盘，以及工程哈希未变。无新增持久工程或宿主命令，记录于本工单即可。


实际实现：独立 LayoutActions 与 focused-layout，按场景／步骤／音乐保存 focusedTasks；旧本机偏好向后兼容并严格过滤未知／重复任务，尺寸与折叠不重置。ViewportRevealContext 仅通知布局展示，不传播放语义；音乐控件留在公共区域，UE 原节点停放。PerformanceLayout 219 行，入口无改动。

验证结果：176 UI、类型检查（含两种布局验收入口）、最终正式桌面构建和 diff 通过；纯 UI 变更未重跑 Rust。`logs/UX-032/` 保存记录，新增验收宿主类型不完整的编译失败保留，已改用正式浏览器宿主并拒绝在桌面运行隔离入口。

- 1280 宽浏览器编排区从 319.9→666.5 像素；按任务记忆，音乐控制可见、唯一 video 节点不重建，显式查看可恢复；无效字段阻止切换并聚焦，重载保持，恢复布局回原尺寸，无控制台错误。
- 新增真实 SequenceWorkspace 窄屏入口，在 1100×800 发现标题竖排与工具栏溢出（270 宽、337 内容宽）。按实际容器宽度将预览移到底部、标题分行；修后标题／工具栏／步骤均 550 宽且无横向溢出，步骤区 385 高，批量区 430 高。浏览器尺寸已恢复，临时页关闭。
- 原生真实 17 步列表专注时可同时显示更多步骤；执行视图往返保留编排偏好。载入列表后“三维监看”自动退出专注并连接真实 UE；音乐在专注模式正常播放／暂停，恢复舞台仍保持 4.685 秒且三维已连接。不是模拟播放验收。
- 原生错误渐变草稿阻止恢复舞台，取消后已保存且专注状态未丢。最终构建重启、最近工程打开后，步骤仍记住专注；资源区收起／展开保持，运行未载入、UE 关闭、设备断开。
- 继续使用 UX-031 独立工程，源文件与副本哈希全未变；无工程历史、实板或用户 output 改动。截图 `data/UX-032/01-专注步骤.jpg`、`02-1100窄屏批量.jpg`、`03-专注音乐.jpg`、`04-最终重开步骤.jpg`。
