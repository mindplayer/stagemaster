# PREVIS-013：预演验证的所属崩溃报告进程收尾

状态：实施中，2026-10-06。基线 main `2b5f10b`，主工作区单写者，tracked 干净；用户 output/ 未读未动。对应首版 H5 的失败留证／稳定性，不扩大为进程管理平台。范围先纳入版本，按 [ADR-180](../decisions/PRODUCT-ADR-180-owned-crash-reporter-cleanup.md) 实施。

## 事实与限定范围

发现三个已脱离父进程的 UE CrashReportClientEditor，分别来自本项目旧预演测试 PID5032、61801 与 PREVIS-004 的 `previs-package-Kd2QO0` 烘焙 PID89041；现场各约100% CPU，持续数日／超过一天。已有项目日志、实际命令行和加载的可执行文件互相核对。UE5.8 的 MacPlatformMisc.cpp 使用 `POSIX_SPAWN_SETPGROUP` 另建报告进程组，原构建组取消不覆盖；不据此推断历史音频／GATT 故障原因。

先保存上述三个准确进程的身份与来源证据，仅在再次核实 PID、启动时间、UID、完整命令和实际可执行文件均相同后终止；保留原报告和日志，不删除、不读取无关报告或改全局设置。历史全局报告路径只作本次已证明所属对象的维护，不成为产品自动扫描／清理范围。

实现只覆盖 `tools/previs/` 已有独立 UE 验证执行器：以唯一项目内实例的 CoreFoundation 用户目录和固定 StageMasterPreview 报告命名确定所属范围，校验真实目录／链接、报告参数与引擎可执行文件、同用户及新进程身份；命令结束或取消后，有限终止该次新产生的 unattended 报告助手并记录结果。既有日志 wx、环境去污染、组取消、原失败和 JSON／GPU／权限验收不变。静态工具、Node、codesign 等无 UE 收尾声明的命令不扫描／清理。识别、超限或终止失败必须明确失败，不能留合格标记。

不自动清理主桌面 Renderer 的报告助手，不声称修复 UE 报告程序内部死循环；相应产品生命周期范围后续另核对。不得按进程名称广泛 kill、误杀并行实例、清空报告、关闭崩溃记录／沙盒、改 SDK、签名或执行新 UE 构建。

## 验收

先红后绿：范围、命名、空格／中文、身份／UID／路径／链接、PID复用、超限、探测失败、失败保持、成功／取消与无关实例保护。实际受控子进程验证脱离原组后仍可准确收尾，错误身份不发送信号；不启动新的 UE 或真正触发系统崩溃。原工具全量、语法／相关格式、文档引用／JSON／diff 实际执行；Rust／UI 未改不重复其全量。

证据 `data/PREVIS-013/`、日志 `logs/previs-013-*`、临时目录项目 tmp/。记录原失败与收尾结果，更新 STATE 后提交。当前音乐／三维组合重签授权、真实灯型／差分／完整资源／8小时和客户发行／独立操作者出口继续开放，完整 Goal active。
