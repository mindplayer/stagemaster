# DEV-002：把临时试验变成可复用的本地工作器

状态：planned。负责人：Sol。依赖：DEV-001。执行前填写基线提交及具体修改范围。

## 目标

Sol 能给本地 Qwen 派发一项有边界的任务，得到候选改动、实际验证结果和可靠状态。
工作器属于开发工具，部署在本机 AI 管理目录，不成为 StageMaster 应用运行依赖。

先审查研究中的轻量候选和现有试验，再选择复用或加固；不要同时安装多个代理框架。
本工单的接口、验收与下面的执行边界固定，适配器实现可以替换。

参考：`/Users/sunqi/ai/tmp/stagemaster-qwen-trial-20260911/run_trial.py`。
该脚本只允许写一个文件、同步请求、有限重试；中断会使任务记录不完整，尚无通用队列和跨文件保护，不能直接宣称为成品。

## 模型与接口

- 保留 `http://127.0.0.1:18100/v1` 和 `default_model`，不修改 Astra／Sol 的 provider 或登录。
- 用已验证的 Chat Completions 工具调用路径驱动 Qwen；直接 Codex 本地 provider 兼容性属于独立试验。
- 先提供薄命令行接口，再按需要提供 MCP。以下是目标接口，不是已安装命令：

```text
submit(task) -> { job_id, state }
status(job_id) -> { state, attempt, progress, updated_at }
cancel(job_id) -> { state }
result(job_id) -> { base, patch, checks, usage, unresolved }
```

传输层不承担工单规则和补丁校验；核心任务逻辑应可直接测试。

## 工单最小字段

`schema_version`、`task_id`、`contract_revision`、`workspace_root`、`base_commit`、
`read_paths`、`write_paths`、`protected_paths`、`acceptance`、`validation_commands`、
`max_attempts`、`request_timeout_seconds`、`total_timeout_seconds`、`model_profile`。

模型接触的上下文只包括任务所需资料，不包含整个 Codex 会话、账号凭据或无关个人文件。
工单与受信任配置确定命令和权限；不把模型返回的 shell 文本当成执行指令。
本地模型本身不获得发布、Git 集成、安装依赖或操作灯具的能力。

## 需要实现的行为

1. 工单与基线校验后才能排队；初期只运行一个 Qwen 请求。ID 重复提交应返回已有状态，避免因超时重试生成第二份任务。
2. 每任务使用独立工作区。校验读取／写入范围、符号链接、路径穿越及受保护文件；保护必须由执行器落实，不能只写在提示词里。
3. 提案保存基线文件哈希和补丁哈希；应用前拒绝过期来源。补丁操作失败不得留下半个修改，更不能恢复覆盖其他会话后来写入的内容。
4. 验证命令由宿主以参数数组调用；先自动格式化任务文件，再运行编译与测试。验收文件由主控提供并保护，模型可另加自己的测试。
5. 初始值为最多三次模型请求、单次 360 秒、任务总计 900 秒；按工单合理缩放。上下文或输出超限明确报告，不能静默截断再覆盖源码。
6. 状态、原始响应、补丁、实际命令结果和错误分类持久化到任务目录。重启后识别未完成任务，不假称成功，不盲目重放写入。
7. 取消传播到请求／执行层，并区分 `cancelling` 与 `cancelled`。关闭 HTTP 客户端不保证后端停止推理；要验证当前 MLX 的行为，不能默认杀掉其他任务共用的模型服务。
8. 工作区隔离不等于 OS 沙箱。构建、测试以及生成的测试代码都可能执行代码；采用可用的实际执行权限边界并验证，任何未实现限制都要在交付中明确标记。
9. 输出短结果供 Sol 审查，完整日志留盘。缺失 token 用量记为 unavailable，不猜测费用，不把本地 token 等同于 Codex 额度。
10. 接纳或合并由 Sol 在授权任务范围内完成；工作器不自行合并。MCP 只包装相同的 submit/status/cancel/result 行为。

若采用第三方实现，固定版本／提交、保留许可证要求，验证上述差异；候选文档里的限制不能自动成为要求用户反复确认的工作流。

## 验收场景

- 一个单文件任务、一个两文件任务能产出并通过独立测试。
- 故意越界路径、符号链接目标、测试篡改、过期基线和畸形补丁被拒绝，原工作区不受损。
- 可修复编译错误按限定轮次修复；只有格式差异时不再次请求模型。
- 超时、取消、进程重启、重复提交和两任务同时进入时状态正确；每次只有一个本地生成任务。
- API 断开或模型输出截断时有可复查失败记录，源文件保持完整。
- 工作器未触及的目录、依赖、模型设置和业务接口保持原状；记录实际执行限制。

模拟／合成响应测试应优先覆盖失败路径，减少本地和云端生成消耗。
合成测试通过后只做必要的实际模型端到端测试；不能用 mock 通过冒充真实接入完成。
