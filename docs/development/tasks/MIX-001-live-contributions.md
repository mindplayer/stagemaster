# MIX-001：现场属性贡献

软件增量完成；基线 `e0d705e`，结果为本次 `feat(engine): compose bounded live scene contributions` 提交，main，当前 Astra 单写者。依据 [ADR-104](../decisions/PRODUCT-ADR-104-live-attribute-contributions.md)，接续 OUTPUT-001 的框架主线。旧 A0 已有明确局限，保留其 API 和保护测试；不回到界面全面丰满。

范围：engine 内有界索引混合器、project 内实际场景贡献编译／Player 适配、软件输出组合与相关契约／状态。项目／播放包格式、桌面和固件保持，用户 `output/`、窗口与设备不操作。

验收：真实工程两动态来源＋手动来源；HTP／LTP、来源优先级、部分属性释放、未编排默认值不遮挡、亮度不改变位置／颜色／功能、连续采样不抢占、明确重新执行接管、旧句柄／布局／批次拒绝、合成后整体 16 位编码进入软件端口。准备后周期不增加容量／分配；批量失效保护，来源槽预算与序号耗尽检查。按职责拆小文件；多步骤／多端接线为后续独立增量，不假称本项已具备完整现场控台。

## 实现与审查

在现有 engine 内新增 `live` 模块，准备固定来源槽／属性缓冲，发布、推子、关闭和合成均不扩容。复用 domain 的固定点缩放，保留原 A0 Mixer 与历史测试，并以满电平连续属性子集作独立对照；不将原“全属性加权、零即释放”直接作为新普通推子语义。来源身份／代际、属性接管顺序、命令序号、业务优先级与物理输出许可分开。

Project 的 `LiveScenePlayer` 复用实际场景编译器、Player、物理位置效果与灯具编码，持有准备好的稀疏属性所有权和发布缓冲。未编排／释放属性不提交默认值；明确写入的默认值仍是有效赋值。`LiveOutput` 在同一完整工程指纹下合成后编码，最终作为 OUTPUT-001 的单一 Composite 来源；新建场景原有显式默认赋值和工程格式不变。

代码按类型、来源命令、求值、场景准备、发布与输出拆分。新增生产手写文件最大 110 行，含测试最大 290 行；入口只注册模块，没有堆入原大文件。未增生产依赖或第三方升级；仅为实际组合验收增加项目测试到 output-port 的依赖。

## 验收覆盖

- 核心：最高优先级内 HTP／LTP、低于非零默认值／明确零、亮度单独衰减、位置／功能保持、逐属性接管和归还、普通采样不抢占。
- 失败：布局／形状／声明／旧序号原子拒绝、句柄跨启动与槽复用、重复身份／来源预算、取得顺序耗尽，以及最后命令序号保留关闭路径。
- 一万次更新下预留容量／属性缓冲地址与接管顺序保持；结合生产路径审查证明正常周期无分配。未做全进程分配器或 MCU 内存测量。
- 448 组连续属性／满电平组合与原参考 Mixer 逐值对照；原优先级和默认值回退保护保持。
- 真实工程：同一盏含调光、完整 RGB、色盘和 16 位水平与 8 位垂直轴模式的灯具，两个动态保持场景与手动来源；使用既有物理运动效果，不绕过灯具／效果能力校验。覆盖释放后回到继续运行的下层值、停用效果不占位、暂停／恢复不接管、明确重执行及失败重试。
- 未保存修改即使 revision 相同也不能混用；相同属性数但配适改变时，旧准备编码器拒绝且保留输出缓冲；正确的新编码器输出对应新地址。
- 实际合成值经既有完整帧编码和软件 Port 驱动；非相邻 16 位粗细通道保持成对、色盘仍为精确档位，接纳与完成分别报告。无真实灯具操作。

首次工程夹具使用了现行模式不支持的残缺 RGB／单轴、空赋值场景及普通波形位置通道，严格校验如期拒绝；改为完整模式、保留有意义赋值和已有物理运动效果后验证。没有放宽生产校验或删除验收断言。

日志：`logs/mix-001-workspace.log`、`logs/mix-001-workspace-clippy.log`、`logs/mix-001-fmt.log`、`logs/mix-001-document-check.json`。此前专项试验／失败及修正记录保留于项目日志，没有用调整验证命令掩盖失败。
