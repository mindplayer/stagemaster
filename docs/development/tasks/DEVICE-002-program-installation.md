# DEVICE-002：软件到设备的节目安装闭环

状态：in progress；基线 `0a0b7e7`，主工作区干净开工，当前 Astra 单一写入负责人。

用户要求持续完成工程。沿用已授权的 ESP32 开发与受控测试，原固件不保留；不操作真实灯具，不启用 RS485／DMX，不烧写 eFuse。原用户工程／UE 保留；测试只操作独立 QA 窗口和项目内产物。

## 目标与增量

1. DEVICE-002A：稳定设备标识、启动身份、诊断连接关联、版本化真实能力。共享 no_std 编解码、固件读取端、主机适配和中文设备详情；旧诊断固件继续可用，未知或矛盾能力不放行安装。
2. DEVICE-002B：受限业务会话与明确的配对／授权依据。不能将名称、地址、声明的主体或诊断握手转换成安装权限；采用成熟机制，方案先形成独立决定，再实施。开发设备准入与生产许可分开。
3. DEVICE-002C：复用 `stagemaster-transfer`／`stagemaster-install`／`stagemaster-nor-store`，GATT 分片和回执、串行安装工作、双槽持久提交。不能直接在无线事件回调中进行长时间整槽擦除；维护状态、内存峰值、任务栈和心跳时序必须实际检查。
4. DEVICE-002D：正式桌面生成包→选择已识别设备→下发→进度／取消／失败恢复→核验安装摘要。独立上传组件和主机协调，不把传输状态放进工程或 TS 播放逻辑。

当前先实施 A，契约依据 [ADR-035](../decisions/PRODUCT-ADR-035-device-capabilities.md)。整个目标到实际安装闭环才完成，不以阶段 A 或纯软件验证结项。

## 范围与验收

- 项目内源码、协议／固件、桌面宿主与组件、锁文件、测试、工具和文档。工程 JSON 与播放计划语义不因通信接入而改变。

- 安装主体可信来源、断开撤销、重连重新授权，旧回执／半包不混入新会话。

- ESP32 资源、Flash／无线时序与故障边界实测；超出预算明确拒绝。实际断电测试若无可控装置则如实区分重启、故障模型和物理断电。
- Rust／UI 相关检查、实际目标构建与原生交互；更新 STATE／接口／出口审查并提交。
