完整目标：多个可保存区段、固定次数／持续循环、精确编辑／锁定／启用、运行圈数、本圈结束后继续与取消退出、暂停定位停止、音频灯光共同游标、一次历史／保存重开。核心阶段不算本任务交付，不以单个临时循环替代正式编排。

实施次序：独立整数调度核心及逐刻度参考验证；工程格式／命令／预算；有界原生音频适配与会话版本；组件编辑／时间线显示／运行控制；完整回归、实际音乐／UE、取消历史与保存重开。与本任务无关的真实设备、刷机、网络部署不操作。

验收要点：半开端点、相邻和空隙、次数 1、多段有限与无限混合、边界退出／取消／旧区段请求拒绝、暂停后续接、定位重置圈数、超大增量不逐圈循环、非法输入原子、容量与数值极限；后续宿主样本输出和位置一致，内存有界，失败不覆盖当前可用状态。

## 原生音源增量（基线 abb4f38）

主工作区当前会话单写者。新增 `stagemaster-audio::PerformanceAudio`／`PerformanceSource`／`PerformanceControl`，复用 rodio 0.22.2 和现有 LoopPlayback，无新增第三方库；Cargo.lock 仅增加已有工作区 playback 依赖边。缓存准备、帧读取、流式解码、消费游标发布、运行意图和样本输出分别组织，手写单文件均小于 300 行。

只有重复段落申请 PCM，全部合计不超过 64 MiB；普通段和次数 1 的区段用 128 × 1024 帧有界预读。源头数帧和相同端点量化避免两个解码器定位偏帧；解码线程最多两条，准备有取消和两分钟限时，文件遵守原 512 MiB 预算。单独缓存的总量不是全应用峰值：替换期的新旧缓存、队列、声卡和解码器工作空间仍须计入宿主预算。

音频消费与圈数共用一个 LoopPlayback；预读不推进，完整立体声帧才推进。运行位置通过有序原子字段发布，控制意图只用短 try_lock；迟到的退出同时校验区段和遍数，不误退出下一段或同段下一圈。`check_ready()` 让宿主在原子替换前再拒绝已知后台故障或取消。欠载／解码失败结束源并报告真实消费位置，不补静音伪造正常播放。

新增 13 项独立验证：多段有限次数、相邻／间隙、次数 1 流式、持续退出／取消、立体声半帧、旧段及旧遍数拒绝、44.1 kHz 裁切与 397 帧端点、定位重置、64 MiB 总预算、取消／准备限时、线程预算／释放、短文件／缺失／不支持声道、固定队列／欠载／顺序异常、预热后解码故障与并发游标一致性。最终全工作区 728 项通过、0 失败、既有 1 项忽略，23 个 crate 文档测试通过；全工作区严格 Clippy、fmt 和 diff 检查通过。日志 `logs/audio-020-native-*.log`。

验证过程曾发现 Clippy 的时长单位／类型复杂度／浮点精确比较提示，以及测试缺少 Debug 派生；已分别修正，PCM 精确传递用位模式断言，未放宽保护或关闭 lint。审查另补同一区段跨圈的迟到控制检查，再执行最终全工作区回归。无工作区依赖版本升级。
