# 第一版商业交付完善计划

先交付一套**小型固定场地可独立使用的灯光编排和播放系统**：Mac 编排、经过验证的灯具档案、一路 DMX 播放盒、离线节目选择与执行、可靠保存和安装恢复。专业三维、音视频同步、云端和其他终端按独立产品增量交付。

2026-10-07，PLAN-006，基线 main `c31e382`。依据[进度评估](commercial-readiness-2026-10-07.md)。首批客户尚未确认，本计划按“小型固定场地、Mac 配置＋ESP32 脱机播放”估算；这是当前推荐实施顺序，不是客户订单或已具备销售资格的声明。

## 首发产品范围

| 项目 | 首发承诺和完成标准 |
| --- | --- |
| 软件 | 先支持一种经过实测的 Apple Silicon Mac 环境；系统最低版本按实际依赖与真机验证公布，不照抄配置中的 12.0。无需终端、Rust、Node 或 UE 编辑器即可安装使用 |
| 编排 | 灯具配适、编组、调光／颜色／位置、已支持动态效果、预设、场景、场景列表、人工／定时推进、撤销重做、保存恢复 |
| 灯型 | 首先完成用户 30W 11 通道实灯档案，再按首个场地需要验证一款染色灯／帕灯。18 通道复杂多单元灯保留适配，但仅在首单需要时前置。每个交付档案保留全部通道占用、已测默认值和禁用区间 |
| 容量 | 一路、最多 512 个地址槽；灯具数量由模式通道占用、效果和装载预算共同决定。建议先以 16 灯、32 场景、8 个列表为代表性测试目标，**不是已通过的指标或新的硬编码上限**；最终只公布测过的范围 |
| 设备 | 微雪 ESP32-S3-RS485-CAN 一个明确板卡版本，受限包自主播放；GATT 下发／控制，RS485 有线到灯具；无需电脑持续刷新 DMX |
| 日常操作 | 电脑可操作盒子已安装节目；盒子断开电脑后持续运行，冷启动后可以本地选择节目、开始／推进、停止，并显示当前节目和状态。冷启动不偷偷开播 |
| 工程交接 | 原子保存、恢复、配灯表、节目单；可复制包含所需资源的完整工程目录并在另一位置打开。暂不要求新加密扩展名 |
| 交付物 | 可安装的软件、明确固件／板卡版本、机壳及连接标识、线缆／电源说明、已验证工程、支持矩阵、备份恢复说明和售后诊断入口 |

首单卖的是一个已限定、可维护的使用场景，不宣传为全面替代 MA3／Titan／Depence。保留完整平台源码和能力边界，不为这个版本另起简化内核。

## 暂不作为首发前置

- 专业 UE 渲染包、完整光学、激光与机械运动控制、多路输出、多控台冗余、所有型号灯具、完整 GDTF／MVR 导入。
- 云账户、效果商城、支付、自动订阅、协同编辑、手机／平板原生版、ARM 盒子、专业推子台。
- 电脑音乐与设备 DMX 的正式同步、视频监听／投影控制、蓝牙音箱同步、多音轨。

已有音乐和三维能力继续保留在开发／扩展组装中。首发默认路径不依赖其启动；若把它们作为可用功能附给客户，仍须通过该范围的客户验收，不能以“选配”放行已知运行问题。纯灯光首发的组件开关或独立打包需沿既有可选能力实现并验证，不能假定已经有合格的无 UE 发行版。

这改变的是**推荐销售版本的承诺范围和任务排序**，不是删除原 H1–H5 验收项。原音乐／唯一三维全目标保持未完成，后续独立关项。

## 六个交付门与工作顺序

下表工时是单一实施会话的集中工程工作日估计，含相关验证，不含采购、证书办理、用户现场等待或新硬件缺陷。D0 起点是范围与现场资源可用；不是自动承诺发售日期。先走 R0、R1，软件独立项可以在硬件等待时推进。

| 交付门 | 工作和代码落点 | 出口证据 | 估计 |
| --- | --- | --- | --- |
| R0 冻结基线和版本 | 从当前提交选一个候选；保留现有内部构建来源绑定，建立首发能力清单、原生代表工程与准确固件组合；确认无 UE 的编排／设备操作可用。落点 `tools/desktop/`、`apps/desktop/`，必要的 UI 能力投影 | 一份来源清楚、可重建的候选；无 UE／无音乐也能打开、编辑、保存、生成包；记录全部发行前缺项 | 1–2 天 |
| R1 一款真灯和真实输出 | 核对板卡、接线、测量条件；在已有 Port／Driver／Runtime 上完成正式输出组装；11 通道档案实测，先一灯再小组。落点 `apps/esp32-player/src/board/`、`stagemaster-output-port`、档案／编译模块 | 差分 DMX 测量、粗细轴／调光／色轮／停止值与实灯一致；断 GATT 后持续播；输出失效可被观测。保留完整 11 通道占用，声控自走／未知宏不可执行 | 3–5 天 |
| R2 完整操作闭环 | 打通“选择设备→检查→生成→安装→准备→显式执行”；本地面板作为 Runtime 输入适配，最小按键和节目／状态反馈。落点正式设备／包组件、`apps/desktop/src/` 设备服务、固件输入适配 | 普通用户能找设备、知道安装到哪一版；不把安装当播放；拔掉电脑、设备重新上电后可本地选播／推进／停；不必改 JSON 或开发配置 | 3–5 天 |
| R3 故障和持续运行 | 同一固件／包测最坏合法负载、坏包、安装中断、断电恢复、连接反复、看门狗和完整内存；复用既有测量工具 | 8 小时起步压力＋24 小时冻结候选离线运行；资源不持续增长，无意外复位／错帧／重复执行／数据损坏；故障按声明策略恢复 | 2–4 天，包含运行观察 |
| R4 客户发行和维护 | 标准 Mac 安装包、签名／公证、实际系统范围、安装升级回退、资源交接、诊断导出、凭据发放恢复与依赖告知；不新建云平台 | 无开发环境的另一用户环境安装运行；权限拒绝能恢复；工程不丢；明确软件／固件兼容；凭据不靠开发者目录或共享测试密钥 | 3–5 天，与 R1–R3 穿插 |
| R5 独立使用和首单 | 固定候选进入一个场地；1–2 位未参与开发的操作者按交付说明完成代表任务；问题按交付风险收敛 | 完成“建／改并保存节目”“下发和电脑断开后选播”“异常恢复”三任务及实际排练；无开发者代点、无未解决的停止销售级问题 | 2–3 天工程工作＋现场观察 |

**合计约 14–24 个集中工程工作日。** 有真实板卡、灯具、测量工具、Mac 客户条件和及时协作时，以 **3–5 周达到受控付费试点**为合理规划；预留返工后，首批可重复交付以 **4–6 周**作排期参考。首个 R1 完成后按测量结果重估。没有这些外部条件就不能报确定日期；“所有成熟控台功能”不在该工期内。

若前两天发现 R1 的关键测量或实灯完全不可用，立即列出准确缺项并推进 R2 的用户流程、R4 的打包／资料，不回去无边界优化效果和三维。

## 首项可以立即执行的工单

下一实施会话先开 **R0 首发候选与交付路径**，不要从旧 AUDIO-020 表单重新开始。预期一天内给出三个具体产物：

1. 一个来源绑定的当前内部候选和“桌面版本／固件角色／节目包版本／档案版本”的可核对清单；使用原构建和记录工具，不开发新的发布管理平台。
2. 一份真实无音乐小工程，按已知灯型能力定义场景／三步列表，核对软件执行与设备包的语义一致。缺失的实际默认值先列清，不用通用演示灯冒充已适配。
3. 一份最多一页的 R1 现场清单：确切板卡、RS485 端子和灯具接线、11 通道模式与地址、供电、测量工具、允许的受控试验范围。未知条件只阻塞相关实物动作。

需要产品代码改变时在对应任务写清问题、范围和验收。涉及公共接口、时钟、控制权、输出使能或持久格式，先写小型 ADR 再实施。当前授权是评估和计划，本次不刷机、接灯或选择签名身份。

## 操作体验只补四处

1. **目标可见。** 编辑预演、电脑软件输出、设备自主输出始终显示名称、节目和状态；“未输出”与“已连接”分开。采到软件帧不显示为物理 DMX 合格。
2. **下发连续。** 复用现有生成、安装、运行组件，增加一个有状态的任务流程。取消、失败、重连回到准确步骤；明确目标设备和包的版本，最终“开始播放”保持显式动作。
3. **本地可用。** 最小实体输入处理去抖、长按、误触、按住上电、无节目／坏节目和控制接管；面板反馈来源是实际 Runtime 状态。停止与熄灯不同，按灯型定义停止值，不能一律全部置零。
4. **能交接和报修。** 工程及资源整体复制有校验，地址冲突／未知档位可定位；提供设备／软件版本、最近错误和脱敏日志的简单导出。首版不开发自动上传诊断云。

这些属于现有流程的整合，不重绘整套 UI，也不在组件内另写安装器、灯效引擎或控制权。

## 商业安全和发行的最小工作

沿 ADR-101，暂不选定最终商业授权算法、加密格式、期限或收费政策。要在 R4 前完成一页商业规则决定：卖软件还是绑定套装、首批如何开通、换电脑／换盒子如何恢复、哪些能力允许离线。由用户决定权利和合同承诺，实施会话实现边界。

建议优先评估现成密码库、每设备独立凭据、离线可验证权益和人工签发／交付方式，避免首单先做账户计费平台；这是备选，不表示本次已经选定算法或永久离线政策。程序代码签名、连接认证和商业权益分别验证。禁止把开发 SoftwareAcceptance、固定测试密钥或放宽会话期限作为生产授权。

完整防复制／量产密钥方案未定时可以继续内部试验，但不能默认已经满足用户要求的商业保护。首批销售前必须明确保护范围和剩余风险；不承诺“无法逆向”。

Mac 发行采用 Tauri 和 Apple 的成熟签名／公证流程；内部 ad-hoc 包不替代客户发行。证书准备与硬件验证同期启动，避免最后才发现外部条件未具备。参考 [Tauri macOS 签名](https://v2.tauri.app/distribute/sign/macos/)和 [Apple Developer ID](https://developer.apple.com/developer-id/)。实际账号、证书使用及对外发布另按授权执行，本计划不自动操作。

硬件首单还要交付合适外壳、清楚的端子／电源标识、可靠接线与维修换机方法，按实际销售地域和产品分类核对合规要求。开发板可用于受控验证，不把开发板出厂资料等同整机商品验收；量产定制 PCB 不必前置到软件闭环。

## 必须保留的测试门槛

| 类别 | 最小验证集合 |
| --- | --- |
| 数据 | 新建／打开／修改／撤销重做／保存重开；拷贝工程与资源换位置；损坏／缺失／磁盘失败不覆盖原件；升级与回退的格式兼容 |
| 执行 | 源工程和安装后同节目一致；人工／自动步骤、暂停继续、停止、重复请求、旧回执、失联重连；编辑和保存不改变已装运行版本 |
| 灯具 | 地址边界与重叠、完整通道占用、粗细轴、实际方向／零点、真实色轮与调光、默认值、禁止声控自走／未知宏；选定灯型所有允许档位实灯确认 |
| 输出 | UART 配置、BREAK／MAB／帧时序按既有 DMX 契约与采用的标准测量；记录间隔分布和最坏值。目标 40 Hz 的可用配置须实测，不将平均频率等同抖动合格；已有超时／看门狗门槛不放宽 |
| 设备 | 开机无隐式播放；本地选播／停、远程输入权移交；断无线持续播；最大声明包、非法包、安装中断、真实掉电、恢复旧完整包；启动／运行／安装的完整内部堆、PSRAM、双核栈与队列峰值 |
| 持续 | 8 小时为开发压力起点；冻结候选补 24 小时离线运行与故障矩阵。事先固定负载、采样方式和允许阈值，报告最坏值、复位原因和资源趋势；24 小时不是多年寿命证明 |
| 客户 | 干净安装、首次权限拒绝／恢复、升级／回退、无开发工具依赖、无孤儿高负载进程；三项独立用户任务和现场排练 |

停止销售级问题：丢工程、未知／错误输出、停止不可达、重复执行、错误设备安装、静默丢效果、资源耗尽／失控重启、凭据绕过、普通客户无法安装。任何一项未解决，不以“试点”替代出口。普通排版、可绕开的低频辅助操作按已知问题排入下一版。

历史 GATT 过期、音频预留／循环拒绝等分别判断是否命中首发运行链。涉及认证、输出、数据或进程资源的未解释失败须有确定修复或可验证的隔离；纯可选模块的问题可以阻止该模块发售，不牵连经过隔离验证的纯灯光版本。不能删除失败记录或以偶然绿色关闭。

## 执行节奏和资源

开发由用户指定的 6.1 Sol 会话单写者实施；不自动开新会话或子代理。用户／现场协作者负责灯具接线确认、实测观察、客户和商业规则；阶段大边界才召回 Astra，不逐项审批。

每周只报告：当前候选、六门各自已过／部分／未过、一个实际用户任务的结果、剩余阻塞与下一项。完成依据是同一可追溯版本的能力，不是提交／文档／测试用例数量。局部改动先做相关回归，候选冻结再跑全量，不每个说明文字变动都重新编译 UE 或整板长测。

需要尽早落实的外部条件只有：一套可测板卡与真实灯具及测量工具、一份明确首单场景／支持灯型、一个无开发工具的 Mac 验收环境、签名发行条件、至少一位独立操作者和商业保护范围。缺项分别管理，普通代码、文档和局部 UI 工作自主进行。

## 后续版本顺序

1. 第一批稳定后：补齐首单其余灯型和更顺畅的现场编程；若客户主要是随场灯光师，优先电脑执行到实际输出节点和音乐同步，届时重新排期。
2. 专业预演：接续现有 PREVIS／DESKTOP 任务，完成当前 UE 组装、发行、生命周期、代表灯型光学和性能；不重建渲染框架。
3. 商业云：Fastify＋PostgreSQL＋对象存储，先设备／权益和资源分发，复用离线校验安装，再加效果库和协作。
4. 平板／手机、ARM、多端和实体控台：复用工程、Rust 语义及控制契约，逐个产品组装实机交付。

如果首批客户实际购买的是专业三维展示，上述纯灯光套装不是其 MVP，应以 UE 客户发行和渲染可信度替换 R1–R3 的优先顺序并重新估时；不同时维持三个“首版”。
