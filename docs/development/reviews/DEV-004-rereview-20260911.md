## 尚未满足的契约

### DEV004-R1 / P2：晚到的 cancel 仍可覆盖全局后端状态

位置：[runner.py](../../../tools/local-worker/local_worker/runner.py) 第 568–586 行，重点为锁外的 `set_backend`。
cancel 在 job 锁内读取 backend，再于锁外写全局状态；这次写入可能晚于请求完成及终态写入。确定性交错复现得到：

```text
job_state=cancelled, job_backend=finished, global_backend=still_running
```

此时实际请求已结束，但下一次生成会被全局状态拒绝。锁住两份文件各自的写入不能保证跨记录的逻辑顺序。

收尾要求：全局后端状态应由当前生成周期的明确负责人维护；最小实现可以让 cancel 只登记取消请求，由持有生成锁的执行者更新后端。若其他入口需要写全局状态，必须校验当前活动周期并防止旧任务的延迟写覆盖新状态。补齐“取消登记后、后端写入前暂停；执行者完成；再恢复取消”的回归，同时确保旧任务不会覆盖下一任务的 unknown 状态。沿用 DEV-004 原子取消与状态一致性条款。

### DEV004-R2 / P2：关闭型连接的响应读取仍突破完整 deadline

位置：[model.py](../../../tools/local-worker/local_worker/model.py) 第 94–100、120–138 行。
在 HTTP/1.0 或声明关闭的响应中，`getresponse()` 之后响应对象仍持有可读连接，但 `HTTPConnection.sock` 可以已经清空。watchdog 仅关闭后者不能及时中断响应读取；读取继续沿用最初设置的 socket timeout。

真实回环复现：总时限 0.5 秒，服务端在 0.35 秒后发送响应头和首字节，再暂停响应体。实际约 **0.855 秒**才返回超时，超过本次 0.2 秒测试容差。原测试持续每 80ms 给出字节，使读取循环有机会检查时钟，未覆盖这段阻塞窗口。

收尾要求：截止时能中断实际正在读取的传输资源，或每个阻塞步骤准确使用剩余预算；覆盖关闭型连接与 keep-alive，以及等待响应头之后只剩少量预算的情况。辅助线程必须有界清理。此项仍是 DEV-004 的完整请求 deadline 条款。

### DEV004-R3 / P2：响应提前 EOF 被当作完整提案接纳

位置：[model.py](../../../tools/local-worker/local_worker/model.py) 第 134–152 行。
`read1()` 返回空字节后直接形成完整响应，没有核对声明长度是否读完。复现发送可解析的提案 JSON 共 411 字节，声明 `Content-Length: 431` 后提前关闭，Runner 实际得到：

```text
state=candidate_ready, response_incomplete=false, backend=finished
```

这是传输未完成，JSON 可解析不能证明 HTTP 响应完整。该路径错误发布候选，也跳过了未知后端的恢复边界。

收尾要求：按照响应 framing 判断完整性，提前 EOF／截断必须保存已收字节并标记 incomplete，终态 failed、backend unknown，不得发布候选；覆盖长度已知的提前 EOF 与分块响应截断，保留合法 EOF 定界响应的正常行为。沿用 DEV-004 第四项“不完整响应不得伪装完整”的契约。
