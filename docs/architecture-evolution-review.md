# 架构再评估：扩展边界与落地约束

日期：2026-09-11。审查基线：架构 v0.4、模块伪 API 0.2、当前四个 Rust crate，以及实体控台、外部音视频、UE 预演、场地采集和云端要求。修订结果进入[架构 v0.5](architecture.md)与[伪 API 0.3](module-api/README.md)。这是源码／接口审查和设计修订，没有实机、跨设备或运行性能结论。

## 1. 结论与保留项

**主技术栈和核心分工可以保留，但 0.2 接口存在实际的扩展阻碍，不能直接冻结成永久工程格式或公开协议。** 主要问题是把启动、手动操作、正式节目、监看连接和云端交付绑得过紧；另一个风险是宏观文档已经很丰富，实际 Rust 代码仍未实现这些边界。

继续采用 Rust＋TypeScript，保留 Tauri／React、Fastify／PostgreSQL／对象存储。灯光求值、工程编辑、外部控制、监看、硬件控制面、仿真和渲染各有权威状态。UE 和固件只在具体适配包内使用所需语言。当前没有发现需要推翻主技术栈的仓库证据，也没有新增框架选型。

用户随后要求专门比较 Rust 与 C++26，已另做[核心语言复评](core-language-rust-vs-cpp.md)，包含官方现状与本机工具链核查；结论保留 Rust 主核心。TS 接口样例不改变原生核心约束，C++26 的版本号也不作为实时性或性能证明。

完整架构需要明确长期身份、依赖方向、时间和失败含义；不需要现在实现全部业务，也不需要每项功能独立进程。首期只实现一套内置服务和一种实际适配仍然成立，前提是替换它不要求改 Cue 语义或永久数据身份。

## 2. 用未来场景反查当前接口

| 场景 | 审查时的阻碍或缺口 | 修订原则 |
| --- | --- | --- |
| 控台开机，尚未载入 Show，面板用于设置／盲编 | `SurfaceCoordinator.attach(..., ActiveRun)` 要求先运行节目 | 操作会话先建立；实际播放映射再绑定运行上下文 |
| 演出前单独测试媒体服务器 | ExternalControlLease 强制持有 ActiveRun | 手动设备控制与节目自动控制采用不同上下文，相同目标仍统一仲裁 |
| 视频 Seek 后，旧位置动作尚在发送队列 | 外部租约有计划代次，没有同步组代次 | 节目驱动动作携带 TransportCursor，真正发送前再次验证 |
| 摄像机／NDI 源重启，只恢复监看 | 带 generation 的 MonitorSourceRef 进入持久 Route | 保存稳定目录键，使用时解析；监看布局独立于执行绑定 |
| 手机上保存工程，另一台机器继续编排 | PackageManifest 必须有 targetId 相关 BuildArtifact | 工程交换包独立导出；执行包另含目标产物与安装绑定 |
| 一个目标有多个执行域，或多个播放节点 | compile 未指定域，activate 接口又混有多域 partial 结果 | 编译、准备与激活明确同一个域；多域协调逐项跟踪 |
| 空运行节点显示状态 | snapshot 接受 RunCursor，却只返回 ActiveRun | 状态区分 idle／active，不虚构运行计划 |
| 只有监看、预演或执行能力的节点 | 聚合客户端和组装示例容易被实现成必须装齐服务 | 能力协商、按角色组装；客户端组件注入窄服务 |
| 一份资源用于场地、高斯外观、图纸与媒体 | AssetInfo 只描述音视频流 | 通用资源身份与类型化元数据分开；不是所有资源都有 streams |
| 网络分区后主备都认为自己应输出 | 文档有输出租约，但没有真实隔离证据 | 输出边缘验证所有权，无法隔离旧发送者时不宣称自动热备 |

## 3. C01—C10：具体修订与剩余门槛

### C01 · P1 · 连接、操作权与节目生命周期分开

0.3 新增宿主签发的 OperatorSessionRef。硬件 attach 依赖操作会话；播放映射依赖相应 ActiveRun，外部参数映射由协调器取得外部控制权。连接、身份、业务授权和 OutputLease 是四件不同的事。

ExternalControlContext 区分 manual 与 show：前者绑定操作会话，后者绑定 TransportCursor。手动调试会产生真实外部动作，仍检查目标范围、动作权限、外部工程上下文、截止时间和租约；不能用 manual 绕过节目自动控制的代次检查。服务端按调用入口和控制权政策限制使用方式。

工程关闭、UI 断开、面板拔出、操作会话注销、控制租约到期和节目停止分别处理。硬件协调器回收它拥有的临时手势与租约，不无条件停止运行中的全部 Playback。

**已修订：** shared／surface／external 契约与调用样例。**待实现：** 宿主认证会话、范围仲裁、开机／卸载／重连生命周期。

### C02 · P1 · 永久身份与连接身份分开，版本只影响自己的范围

持久对象保存稳定逻辑引用；设备重启、连接代次、租约和 GPU 句柄属于运行时解析结果。0.3 将 MonitorSourceKey 与 MonitorSourceRef 分为不同类型，删除执行 Route 中的 monitor-surface；MonitorBindingSpec 交给独立监看布局存储。相同名称不能自动匹配为同一来源；明确重新绑定后才改变稳定键指向。

执行能力修订改名为 executionCapabilityRevision，仅由执行所需的语义／协议／资源能力变化触发。监看格式、面板灯环、渲染质量使用各自能力修订，不让插入摄像机导致灯光重新编译或失效。若节目明确把某个反馈作为运行条件，它才成为该计划的显式必需依赖。

目标目录先列出执行域，再按 targetId＋domainId 查询能力和运行游标；executionCapabilityRevision 属于该域，不是所有节点功能共用的全局版本。共享物理资源变化确实影响多个域时，由依赖索引明确使相关域失效。

硬件持久映射保存逻辑页、控件和目标 ID；SurfaceBinding 是解析后的运行时绑定，可以包含 ActiveRun，不能直接把它序列化当永久面板档案。场地标定、输出映射、节目修订、控制面页层与预演配置分别版本化。

**已修订：** 稳定监看键、执行路由与能力字段。**待实现：** 配置存储、依赖索引及失效范围验证。

### C03 · P1 · 动作的因果顺序与多种时钟必须完整

一次外部自动动作至少验证：运行实例／计划、同步组及 TransportGeneration、外部系统连接／工程上下文、控制租约、序号与截止时间。Seek、循环重启或重新装载使相关旧动作失效；另一同步组的合法动作继续。已经交给对端的动作未必可撤回，要报告实际发送／未知状态，不能声称本地取消等于物理撤销。

队列合并也有边界：只在同一目标、同一控制权、同一映射／播放代次、没有离散动作屏障的连续段内合并绝对值。编码器增量求和不能越过 Go、Record、模式切换或释放；否则“转动 → Record → 再转动”会记录错误值。释放／禁用有保留容量，溢出触发明确重同步。

引擎 tick、DMX 刷新、编码器扫描、外部时间码、监听采样和 UE 帧率是不同速率；它们通过有时基和误差预算的数据协作。单调时钟仅负责对应时域推进，不保证网络和实物同时动作。跨节点时间映射需记录测量时刻、有效期与不确定度。

**已修订：** 外部 show 上下文必须包含同步组代次。**待补齐：** 时钟查询／映射、核心命令 deadline DTO、因果屏障和延迟测量；在跨端控制与虚拟时钟原型中完成，不能只留在文字中。

### C04 · P1 · 激活的原子范围限定为一个执行域

0.3 的 BuildArtifact 和 compile 明确 domainId；prepare 检查目标、域、运行游标和全部必需执行依赖，activate 只切换该域的本地逻辑计划。一次成功只证明该域计划已切换；多个 Universe 的物理发送和外部动作分别报告。

多节点／多域部署使用上层协调记录，每个参与者保留准备句柄、期望代次和实际结果。允许提前准备并按时刻请求激活，但必须报告部分成功／未知和中止边界；补偿是新的动作，不等于恢复已经发生的演出。不能把数据库事务延伸为全场原子事务。

计划切换要定义贡献、Fade／相位、正在按住的 Flash、现场 Override、控制面映射和旧帧的迁移。默认先支持可验证的单域显式切换；不以“有 activate API”暗示无缝切换已完成。

**已修订：** 单域类型及示例；移除单域返回值中的多域 partial。**待实现：** 状态迁移、输出排空／隔离，以及未来多域协调服务。

### C05 · P1 · 云端交付和资源不能绑死某台控台

0.3 分为两种包：project 保存可编辑修订和必要资源，不要求现场设备或已编译计划；deployment 固定目标域产物、执行绑定和资源。云端发布返回有类型的包，设备分配只接受 deployment；服务端仍按权威清单核验类型和适用目标，不能信任客户端标签。

资源身份与场景对象分开。AssetInfo 可描述媒体、几何、场地外观、文档等；元数据、派生算法／版本、源资源和质量变体通过有版本 schema 建模。复制低质量代理不改变灯具或场地逻辑身份，派生缓存可重建，必要原始资源不得当缓存清理。

云端同步的工程分支与设备发布是不同流程。同步保留共同祖先、分支头、删除记录和冲突；不能用“上传包成功”替代离线编辑合并。初版用分支／副本加显式合并即可，分支／资源清单契约需在首个持久格式和同步协议中细化。

程序、插件、设备固件及 Show 有各自版本和升级状态机。外部播放器素材的部署独立确认；StageMaster 工程包和代理完整，不证明外部系统已准备正式媒体。

**已修订：** 两类包、导出、发布／分配类型、通用资源类别和未上报设备状态。**待实现：** 清单依赖闭包、格式迁移、分支同步、垃圾回收和分发对账。

### C06 · P2 · 按节点角色组装，避免一个必须装齐的总程序

| 节点角色 | 需要的模块 | 不以其存在为前提 |
| --- | --- | --- |
| 编排端 | 工程／会话服务、存储、编辑 UI | ActiveRun、DMX、UE、云连接 |
| 现场执行节点 | 计划接纳、时钟、运行核心、必需输出／外部适配、状态 | 编辑 UI、GPU 预演、云数据库 |
| 控制面节点 | 输入／反馈、映射、认证连接、控制服务代理 | 本地节目求值、媒体解码 |
| 监看节点 | 源解析、接收／呈现、查看授权 | 外部设备控制权、灯光输出权 |
| 预演节点 | 场景、仿真、渲染、只读来源 | 本地 Show 正在真实运行 |
| 云端／后台工作节点 | 元数据、资源、分发；按任务加载编译或重建 | 本地设备驱动、现场 tick |

同一台电脑可以合并多个角色。角色是组装和资源预算边界，不规定每格必须一个进程。首次连接协商实际服务契约与权限；StageClient 只是客户端代理聚合，组件依赖所需的 ProjectApi／ControlApi／MonitorApi，而非任意读取全部服务。

**已修订：** 连接中声明服务契约与独立操作会话。**待实现：** 可选服务注册、窄客户端依赖、桌面／无界面构建与缺服务行为；Rust 组装示例不再被视为所有宿主必选清单。

### C07 · P1 · 当前 Rust 数据流必须真正落下边界

当前 `stagemaster-dmx` 仍导入 `stagemaster_engine::OutputSnapshot`，其中含动态 BTreeMap 与每属性 trace Vec；同一 crate 又管理 FixtureProfile 和配适。引擎仍是静态 Playback 值容器，没有预分配 tick、准备／激活或持续输出。这些是可直接在源码看到的依赖和缺失，不是新性能实测。

源码依据：[DMX 模块](../crates/stagemaster-dmx/src/lib.rs)、[执行与合成模块](../crates/stagemaster-engine/src/lib.rs)；既有问题及此前验证见[代码审查](architecture-review.md)。

下一条代码闭环应让领域／配适产生编译映射，运行核心写入独立数值帧，DMX 编码只读该帧与映射，诊断通过旁路索引展开。允许先在现有 crate 内完成逻辑分层，再按编译／依赖需要拆包；不为凑模块数批量建空 crate。

每条通路明确队列容量、超载行为和资源所有者；监看与大资源导入进入工作层。日志、GPU 或面板反馈过载不能让灯光 tick 等待。单进程模块化解决代码依赖，独立进程解决部分崩溃隔离，资源争用仍需实测。

**本轮状态：** 确认并保留此前代码审查问题，没有修改产品 Rust 实现。必须通过虚拟时间和压力场景后，才能将“实时核心”作为已实现能力。

### C08 · P2 · 预演共享语义与场景，不共享现场执行权

统一稳定灯具／单元、场景对象、坐标系、单位、安装层级、标定及版本；仿真响应和 UE 对象作为派生结果。图纸、采集、预演和输出不得各存一份可独立修改的灯位真相。

独立预演支持外部控台或录制输入，不能强制先激活 StageMaster Show；盲编使用独立时间和状态。现场监看来源、离线参考、仿真生成画面分别标记；只有真实扫描接口可用时才接对应激光几何，显示逼真不等于实物准确。

动态桁架姿态、视觉插值和机械响应不能悄悄写回安装标定。重建／渲染后端可替换；固定输入、模型版本、随机种子和恢复政策，仍分别声明逻辑回放一致性与图像近似。

**本轮状态：** 保留已有正确边界；中立 Scene／SimulationSource DTO 尚未进入类型检查，需在首个预演原型前补齐。这不是核心 API 已覆盖全部预演功能。

### C09 · P1 · 输出互斥、设备策略与网络分区独立验证

客户端操作租约、运行所有者和物理端口所有权不能合并。主备切换需要在有效输出边缘阻断旧发送者，不能仅靠两台主机互相判断心跳。没有可验证的隔离措施时，先提供明确停用／交接流程，不宣称自动无缝热备。

外部控制租约仅能仲裁经过 StageMaster 的调用；不能阻止操作员在第三方软件面板操作，或其他厂商控台直接发信号。记录实际变化与来源证据，按设备能力检测冲突／重同步，不能许诺对外部系统的全局排他。

Blackout、Release、暂停、禁用端口、关闭设备各有语义；激光、舞台机构和特效设备的本地保护独立存在。模拟范围与真实控制权限分开配置，不因添加一个仿真模型就自动开通真实执行。

**本轮状态：** 边界已明确；首期单输出所有者，真实主备、隔离与设备故障策略须另有设备证据。

### C10 · P1 · 接口演进要有契约，不能靠“以后加字段”

协议封装、服务 API、工程 schema、执行语义、设备档案、仿真模型和固件分别版本化。0.3 仍是可破坏修改的设计草案；连接里的服务契约列出可协商版本与 schema，最终编码和兼容矩阵在公开协议前固定。

新增协议驱动一般不修改 Cue／效果语义；新增设备参数通过已注册的类型、单位、范围和能力描述；新增效果求值规则则需要语义版本和执行一致性样例。不能把所有扩展都变成 `execute(string)`，也不能要求每增加一种厂商参数就重写整个核心枚举。

未知可选扩展保留原始载荷和引用元数据；客户端不理解它时只能做已证明不破坏其依赖的操作。未知必需执行语义拒绝发布。Rust／TS 生成物、运行时解码与兼容样例同源维护，单纯 tsc 通过不证明线缆协议正确。

动态插件先选版本化消息／受控任务边界；若 SDK 必须本地绑定，限制在适配包，显式约定内存与释放责任，不把 Rust 原生对象布局当永久二进制插件接口。第三方代码可先静态注册，无需现在建设完整插件商城或进程框架。

**已修订：** 服务契约声明及无循环的共享类型。**待实现：** schema 生成／运行时校验、兼容矩阵、模块依赖检查。

## 4. 冻结什么，暂缓什么

现在确定：权威状态归属、永久与临时身份、单域激活范围、外部动作代次、工程包与执行包、节点角色、失败及权限含义。

首个持久格式／公开 API 前验证：单位与值表达、分支／资源清单、迁移和未知扩展保留、协议协商、时钟与命令截止条件。只验证首批真实用例所需的语义，不等待全部 MA3／Titan 功能完成。

允许后续选型：主板／MCU、真实控制面协议、监听后端、UE 的具体接入、云厂商、插件装载方式、主备部署方式。它们受现有边界约束，不能把 SDK 对象和厂商地址写进长期节目语义。

| C-A2 | 配置／持久化原型 | 监看重连、换面板、调整预演质量不改变灯光计划；必需执行依赖变化可见 |
| C-A3 | 虚拟时钟／控制原型 | Seek 后旧外部事件被拒；转动→Record→转动保持次序；缺 release 能收回原手势 |
| C-A4 | 编译／激活原型 | 域 A 的产物不能激活到域 B；单域切换失败保留正确状态；外部失败单独报告 |
| C-A5 | 存储／交付原型 | 无设备可导出工程；另一端继续编辑；执行包单独编译；缺资源不伪报就绪 |
| C-A6 | 节点组装／构建 | 无界面目标不依赖 UI／UE／云服务；纯监看客户端无设备控制权限 |
| C-A7 | 引擎与输出原型 | 数值帧不依赖 trace；有界队列、诊断／导入压力和旧帧到达行为可重复验证 |
| C-A8 | 预演原型 | 外部来源不需要 ActiveRun；坐标与场地修订一致；预演无真实输出权 |
| C-A9 | 实机与主备阶段 | 断开／重启／网络分区时旧发送者不能继续占有输出；达不到则不开放自动热备 |
| C-A10 | 首个公开格式／协议前 | 支持版本互通、未知可选内容保留、未知必需内容拒绝、错误不会静默降级 |

本轮只提供 C-A1／C-A2／C-A5 等场景的可类型检查调用及反例，并修正相应声明；上述运行验收全部待实现。已有 Rust 缺陷和原型状态继续见[实现状态](implementation-status.md)。
