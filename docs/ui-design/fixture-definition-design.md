# FIXTURE-001：灯具定义与个人灯库设计

2026-09-24；基线 `9c76803`。依据 [ADR-009](../development/decisions/PRODUCT-ADR-009-fixture-definition.md)。用户要求可复用功能、自定义通道、辨别同型号不同版本，并吸收成熟控台经验。本文是完整设计与后续验收依据。2026-09-27：[FIXTURE-002](../development/tasks/FIXTURE-002-profiles-patch.md) 已实现工程内调光／RGB 线性建档、使用中保护、显式换灯和批量配适；以下完整个人库、复杂灯具、虚拟调光和实灯测试不因此视为完成。

## 2. 统一功能，但保留设备差异

| 层次 | 内容 | 用户操作 |
| --- | --- | --- |
| 标准能力／建档组件 | 亮度、RGB／RGBW 混色、快门／频闪、水平／俯仰、色盘、图案盘等；属性类型、单位与作用域 | 选择这台灯具具备的功能；复用组件 |
| 灯具档案 | 厂家／型号、硬件与固件变体、各模式、功能映射、默认值、轮盘、资源、来源与验证记录 | 复制相近档案，只改不同的通道或档位；保存新修订 |
| 工程内灯具 | 引用档案修订与模式；编号、名称、输出域、起始地址、安装位置与单灯校准 | 添加同类灯、批量配适和摆位；不重复制作档案 |

例如，一台帕灯和一台摇头染色灯都能提供 RGB 混色。帕灯的红色可能是第 1 通道，摇头灯的红色可能是第 8 通道，后者还可能带单独的细调通道。编排界面使用同一套颜色操作，档案负责差异。这里的编号只是设计说明，不是任何真实型号的通道表。

功能身份包含所属灯头／发光单元和轮盘：一条灯带有多个 RGB 单元，两片图案盘也各自独立，不能用一个全局 `red` 或 `gobo` 字段覆盖全部。组件是建档时的复用机制，工程执行不依赖在线查询组件最新版。

颜色需要保留“颜色意图”与设备实现的区别。混色灯、固定色盘和多色 LED 可呈现统一选色入口，但固定色盘只能提供其实际颜色；近似替代应明确显示。图案档位引用具体轮盘和稳定身份，不能认为不同灯的“图案 3”就是同一个图案。换灯时可匹配标准能力，缺失／近似能力需列出并由用户决定，不承诺无损替换。

## 3. 通道表必须表达的内容

| 情况 | 定义要求 |
| --- | --- |
| 连续功能 | 原始数值范围与属性范围／方向；有依据的角度、频率等物理单位；未知测量值不得伪造 |
| 粗调＋细调 | 显式分辨率、字节顺序和各自相对位置；不能假定相邻；界面从第 1 通道显示，内部零基偏移在边界转换 |
| 一个通道多个功能 | 分段定义关闭、打开、频闪、随机频闪等；记录每段边界、类型和默认／代表值 |
| 色盘／图案盘 | 命名档位、有效区间、代表值、颜色／图像；定位、抖动、连续旋转分别描述 |
| 条件功能 | 当前通道的含义受另一个通道／功能区间影响；依赖显式建模，冲突和循环可检测 |
| 多单元／多轮盘 | 各单元和部件的稳定身份、属性路径、控制与几何关联；首期不支持的组合明确拒绝执行 |
| 默认、定位、关闭、退出测试 | 各自定义且可不同；不把全零等同于熄灯、打开快门或安全恢复 |
| 复位／点灯／关灯等命令 | 独立显式动作和保持时间等条件；不能作为普通可渐变滑块或默认值混入节目 |

连续属性可在规定功能段内插值；档位切换与触发动作使用独立规则。不能在两个色盘档位间盲目线性走值，经过频闪／复位区间后再到目标。档位代表值须在有效区间内，默认可推荐区间中部，但要允许按手册／实测修正。

虚拟总亮度是派生能力：灯本身只有 RGB 时，可通过缩放各颜色分量表达亮度，不额外占用 DMX 通道。须在核心定义合成顺序、曲线和参与分量；有原生总亮度时默认用原生通道，避免重复缩放。不能仅在界面额外乘一次值，导致保存、预览和设备播放不同。

静态模式是灯具菜单里的通道模式；运行中的条件功能是模式内部的行为，两者不能混为一谈。配适界面要提醒核对设备当前模式，不能仅修改软件档案就声称实物已经切换。

## 4. 建档工作区

入口在“灯具”资源区的“灯具库 → 新建／复制编辑”；配适发现不匹配时可直接“创建变体”，带入原档案及当前实例上下文。搜索或导入已有档案优先，保留从空白建立的路径。导入只在相应解析、校验与资源处理已经接通后开放。

采用一个工作区而非连续深层弹窗：左侧是功能与模式，中央是通道表和所选通道的数值分段，右侧是功能参数、档位及验证结果。常见组件先显示最少必填项；条件关系、物理曲线和多单元在需要时展开。关闭后保留原编排选择，草稿和已发布档案修订分开。

主流程：

1. **选来源**：搜索已有档案、导入、复制相近档案或新建；填写可辨识的型号／变体。年份只是辅助信息。
2. **选功能**：勾选总亮度、RGB、快门、水平／俯仰、色盘、图案盘等；按需增加多个单元／轮盘。
3. **填通道**：建立模式，填各功能相对位置、分辨率与范围；旁边实时显示通道占用及问题。
4. **标区间**：用分段条或精确数值填写开关／频闪／档位。颜色提供色块，图案可附实物照片和名称；没有图片时用清晰的名称，不编造图案。
5. **验证**：离线看输入属性对应的通道值；有说明书按表核对，具备设备输出能力后才进入单独的实灯测试。
6. **保存复用**：保存个人灯库修订，再选择哪些工程内灯具采用；批量添加只设数量、名称和配适，不重复建档。

建档中的区间、组件和模式编辑支持撤销；一个拖动提交一次修改。相对通道和最终绝对地址同时可查，不能让使用者把第 8 通道误填成全局第 8 地址。混选不同档案时，公共能力可统一编辑，各自特有档位另行呈现，不显示虚假的统一当前值。

## 5. “边测边建”的边界

测试台要允许保持多个通道的已知值。例如固定总亮度和快门，再测试颜色；单独推红色通道没有亮光，并不证明该通道无用。支持精确输入、逐级调整、标记区间起止和记录观察；原始设定值只能标为“已发送／待发送”等，不能冒充灯具实际状态反馈。

未知、明确无作用、尚未测试要分开记录。资料缺失时用户手动建立假设并核验，软件可以提示结构错误，但不能靠普通 DMX 输出自动识别所有功能。禁止默认全通道扫满：未知功能可能触发复位等动作。测试本身必须显示目标设备、输出域／地址及当前控制状态。

后续设备测试会话须通过控制网关获得限定范围的控制权，禁止与现场播放争抢同一设备范围。用户显式启用物理输出；有限会话、停止入口、连接中断与租约失效均由输出端执行预先确认的退出策略。涉及保持时间的命令单独触发。没有经过核对的初始／退出值时，不宣称能够自动安全测试；本轮不打开串口或输出。

离线建档允许保留未完成草稿；可播放档案必须通过目标能力校验。尚未识别的区间可保留为“未知”，不得把它转换为已支持功能。只有明确受限的能力子集及基线全部通过校验时才允许发布，并携带未验证项；涉及未知必要条件的节目拒绝编译。真实灯具验证与结构校验是两种状态，不能用绿色“校验通过”混淆。

## 6. 模块、存储与云端

| 边界 | 职责和约束 |
| --- | --- |
| 档案领域／校验（Rust） | 属性作用域、模式、区间与依赖、默认值、精度及合法性；限制大小与复杂度，不执行任意脚本 |
| 档案库／导入适配 | 草稿、不可变修订、来源／作者／资源／验证记录；解析 GDTF／OFL 后给出支持情况；商业再分发前核对对应许可 |
| 工程服务 | 固定档案快照及依赖；升级差异预览、引用迁移、地址冲突、原子提交与撤销；不自动切换现场版本 |
| 编译／执行与 DMX 编码（Rust） | 先按类型合成属性，再按经过校验的映射求出通道；预编译必要表与依赖，避免实时线程解析文档、图片或查询云端 |
| 界面／宿主 | 标准编辑命令、区间显示、照片资源选取、错误定位；Mac 和未来 iPad 复用语义，平台文件／连接能力单独适配 |
| 测试会话／控制网关／输出仲裁 | 在限定目标与有效控制权下发送诊断值；遵循停止和失效策略，不能给普通界面组件暴露任意整帧旁路 |
| 预演适配 | 读取已求值属性和可选物理描述；支持程度独立声明，不因能控 DMX 就承诺准确光学模拟 |

工程保存实际采用的固定档案及必要资源。档案本体可在一个工程中由多台实例共用；避免每台灯重复复制图案图片。联网可同步个人灯库和下载新修订，下载本身不改变工程。多人提交或离线修改形成独立修订，冲突不靠覆盖本地文件解决。分享入口和服务另立工单，不将联网作为本地建档的前提。

已有伪 API 的 `FixtureLibrary`、`ProjectService`、`ControlGateway` 等保留边界；新建／修订／诊断会话的精确命令和错误码需独立契约审查后添加，本次不虚构已实现的方法。主机将必要映射、求值结果或受限执行结构编译进设备包，具体取决于播放器能力；ESP32 不需要存放完整灯库、轮盘照片和三维模型。

## 7. 实施顺序与验收

现有 `stagemaster-dmx::ChannelMapping` 只有单属性、粗细偏移、默认值和混合方式；工程校验目前只支持归一化属性，并要求每个属性恰有映射。直接套用它不能表达虚拟总亮度、离散档位或条件关系。先形成正式版本变更和迁移规则，不能一边放宽校验一边宣称已支持复杂灯具。

1. **最小建档闭环**：自定义亮度／RGB，8／16 位、非相邻粗细通道、可复用档案与模式、校验、真实保存重开及批量配适；先离线核对编码。随后增加虚拟总亮度，验证完整合成链路。
2. **常见摇头灯**：水平／俯仰的物理范围与方向、色盘／图案盘档位、快门／频闪功能段与自动参数按钮；具备条件依赖的实物必须等相应语义实现后接入，不能用错误的简化档案勉强控制。
3. **设备与高级能力**：在输出链路具备停止／控制权之后接受控建档测试；独立推进条件功能、多单元、GDTF 导入及精细物理描述。依据实际选定灯具决定细项次序，不把“支持所有灯具”作为首版出口。

后续必要验收：同一种颜色能力映射两套不同通道；非相邻粗细通道和字节边界；功能区间边界与离散切换不穿越禁用段；条件冲突／循环；虚拟亮度不重复缩放；重复组件不串属性；不同模式的地址占用；修改灯库后旧工程含义不变；显式升级失败不留下半个修改；离线资源完整；未知必要能力拒绝编译；测试退出／失联／争抢由输出端处理。

档案编辑不必等待 UE 或云端。总体工作区继续按 UX-006 推进；真实复杂灯具编辑、共同指向与输出接入按上述契约依赖展开。当前交付不含新增产品按钮、导入器、硬件试验或实际测试结果。
