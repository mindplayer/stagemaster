# UX-009／010：按需组件工作台

2026-09-24；基线 `76f1598`／main。用户要求继续优化组件化界面，并明确以现代、熟悉、易上手的创作软件体验为目标。沿用已选的舞台画布与时间线方向，在既有可拖目标设计基础上提供可操作的 [组件工作台](component-workspace.html)。这是独立交互设计资料，正式 Tauri 入口保持原状；用户没有选择 UX-008 三图中的某一张。

## 设计判断

专业功能按实际任务组织，界面首先呈现正在编辑的内容。默认是舞台、时间线和少量属性入口；选中片段后，颜色、亮度、指向、渐变在同一位置展开，一次展开一个编辑器。灯具建档具有完整工作面，返回编排保留片段、参数、编辑器和时间位置。

参考的是具体操作机制，不用“最流行”代替可用性验证：

- [Figma UI3 设计说明](https://www.figma.com/blog/behind-our-redesign-ui3/)强调内容与工具的层级、减少界面占用；借鉴稳定画布、收敛工具和按需面板。
- [Figma 属性侧栏](https://help.figma.com/hc/en-us/articles/360039832014-Design-prototype-and-explore-layer-properties-in-the-right-sidebar)围绕所选对象提供相应属性；借鉴明确编辑目标和固定编辑位置。
- [CapCut 官方操作说明](https://www.capcut.com/resource/how-to-use-capcut)的素材、时间线选择与编辑工具分工，延续用户认可的剪映式编排方式。
- [Final Cut Pro 快捷键](https://support.apple.com/guide/final-cut-pro/keyboard-shortcuts-ver90ba5929/mac)采用 ⌘Z 撤销、⇧⌘Z 重做；本稿采用该熟悉组合，并兼容 Ctrl。输入框保留原生文本撤销，不抢占输入操作。
- [WAI-ARIA 展开组件模式](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/)规定明确按钮、展开状态与内容关联；本稿补齐对应属性及收起后的焦点回到入口。

界面以低对比结构线、克制的选中色、清楚的文字层级区分内容。专业概念仍采用中文领域术语，不为简洁隐藏编辑范围、连接状态和错误；复杂能力通过组件承载，不能无限扩充常驻按钮。

## 当前可体验内容

| 区域 | 本稿行为 |
| --- | --- |
| 编排工作台 | 两个片段独立保留参数；时间尺拖动定位；资源区可收起；舞台可扩大 |
| 颜色与亮度组件 | 颜色预设、原生取色、RGB 与亮度调整；空间图同步反馈 |
| 共同指向组件 | 拖目标点、键盘微调、坐标输入；八台安装位置固定；一次拖动一次撤销，Esc 取消 |
| 渐变组件 | 输入渐入／渐出时间，更新示意包络 |
| 布置工作区 | 调整台体宽深和过道宽度，联动空间示意；返回编排恢复属性面板 |
| 灯具定义工作区 | 修改十个通道的编号与名称、编辑快门三段区间；重复编号和区间错误阻止保留草稿 |
| 草稿与历史 | 保留／还原本稿灯具草稿；参数修改撤销重做；组件关闭与工作区往返保持上下文 |

功能组件与工作区容器共用一份局部设计状态。正式实现时沿用“组件接收编辑目标与能力、发出应用命令”的约束：React 不取得灯具语义解释、工程写入、现场时钟和输出控制权。此文件中的交互对象不是新增产品公共 API 或工程格式。

## 复用优先

用户再次明确要吸收成功经验，已写入根开发规则。既有 React／Tauri、工程编辑组件、时间线手势实现和保护测试继续复用；本稿使用浏览器原生按钮、数字输入、取色器和滑块，图标由宿主现有图标库提供。

正式产品的复杂弹层、菜单、焦点和键盘管理，优先验证 [Radix Primitives](https://www.radix-ui.com/primitives/docs/overview/introduction) 的无样式、可渐进采用组件，沿用我们的视觉令牌。若后续需要统一更复杂的表单、列表选择和拖放，再与 [React Aria](https://react-aria.adobe.com/) 比较；两者目前只是已核对能力的候选，不同时引入。采用前按实际用到的组件测构建增量、键盘行为和 Tauri WebView，不能凭库名断言包体或兼容性。当前没有新增依赖、切换技术栈或重建组件框架。

## 验证

本机内置浏览器完成：颜色修改后进入灯具定义并返回；布置与编排往返恢复指向面板；两个片段独立参数；时间位置保持；通道冲突和快门区间重叠提示；草稿保留与还原；键盘微调和撤销重做。

持续改进补充：按官方机制核对后新增 ⌘Z／⇧⌘Z、展开状态和焦点保持；取消时间尺拖动可恢复原位置，窗口失焦也取消未提交的定位手势。修复刷新恢复面板后，收起时没有入口焦点的问题。

在隔离预览子页面中按住指针移动，横向数值由 0.0 更新到 2.2，松手保持，单次撤销恢复 0.0；另一次拖动中 Esc 恢复原值。时间尺拖动更新至 15.3 秒。检查约 1024、736、305 像素内容宽度；窄窗口重排，无横向溢出。窄窗口资源区修正为可收起的横排，避免响应式样式隐藏后按钮无法展开。无浏览器脚本错误，脚本语法检查通过。

## 尚未实现

空间图是理想投影与指向关系，不包含三维引擎、镜头自由旋转、真实光学、灯具校准或运动学。时间线目前验证选择和定位，不执行节目或求值渐变。灯具定义只有上述编辑子集，不支持增删能力、模式管理、图案盘档位、导入、真实档案保存或输出测试。“保留草稿”只保存本交互稿的局部状态，可由会话宿主恢复，不写工程文件。

没有产品代码、Schema、核心契约、依赖、设备或部署变更；不运行无关产品测试。正式接入仍需真实数据与命令、MacBook 应用视口和性能验收。下一步按用户对具体操作的反馈收敛，再以最小真实能力接入工作台；无需继续等待静态三选一才能优化设计。

## UX-010：编辑恢复与明确撤销范围

2026-09-24；基线 `2c878ef`。本轮核对 [WAI 表单通知](https://www.w3.org/WAI/tutorials/forms/notifications/)的字段错误关联、具体纠正提示，以及 [Photoshop 文档历史](https://helpx.adobe.com/photoshop/desktop/get-started/set-up-toolbars-panels/manage-image-states.html)的操作历史和可撤销还原。以下为本项目的适配判断，不声称照搬参考软件：

- 灯具库的独立草稿拥有独立撤销；节目中的片段与场地共用节目历史。撤销按钮说明对应对象与属性；撤销后显示受影响的编辑目标，保留另一工作区的选择。
- 不合法的数字、空值和名称保留为字段草稿，空间图继续使用有效值。字段附近显示修正要求，可纠正、恢复或用 Esc 取消；切换页面和宿主恢复不悄悄清空输入。
- 有错误时显示“待修正”入口，能定位原片段、通道或场地字段。通道重复、快门区间不连续／重叠仍阻止保留档案，并关联到相关字段。
- 通道行保持 DOM 身份，避免字段失焦提交引起重绘，吞掉紧接着的点击。快捷键也覆盖焦点因按钮变为不可用而回到页面的情形，文本输入仍保留原生撤销。
- 发送给宿主的局部快照使用独立副本，忽略近期自身快照的回显，避免回显重置正在使用的历史。

验证记录见 [UX-010 工单](../development/tasks/UX-010-editing-recovery.md)。本轮已经测试：空通道跨工作区保留与纠正、越界坐标跨片段定位与刷新恢复、灯具与节目撤销互不覆盖、场地撤销回到布置、按钮撤销后的快捷键重做、连续点击、目标拖动与时间尺取消；约 1440／1024／736／305 像素内容宽度无横向溢出。

历史仅保留于本次打开的交互稿，各范围最多 60 步；刷新恢复参数和字段草稿，不恢复撤销历史。输入错误的恢复规则和两个编辑范围只用于交互设计，正式多文档命令／持久化契约仍需产品接入时评估。当前未新增文件存储、复杂灯具业务或真实输出。
