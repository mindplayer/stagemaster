# UX-008：可扩展工作区与最新视觉提案

2026-09-24；基线 `d5890c6`／main。用户担心此前“舞台＋左右栏＋时间线”难以承载持续增加的功能，要求基于灯具定义、场地创建及完整目标重新设计。本文保留三张静态布局提案与信息架构；后续按组件化和现代创作式体验的反馈，已在 [UX-009](component-workspace-design.md) 实现独立可切换设计稿。未认定用户选择某张静态图，没有替换正式入口。

## 目标与不变部分

当前使用者是灯光师，设备是 MacBook；未来 iPad 需准备适配。保留用户已选的深蓝灰／青色视觉语言、舞台画布和剪映式时间编排，以及中文业务术语。重点调整功能归属和布局承载方式，不重新做一轮技术选型。

旧骨架能承载日常选灯和编排，但让所有任务共用一张固定窄属性栏，会让灯具功能分段、批量配适和场地布局变得拥挤。新原则是：以任务组织大工作区，以对象组织区内编辑；常用参数就地修改，复杂对象可以完整打开，返回后保留原编辑上下文。工作区数量不随每种设备或协议增加。

| 布置 | 二维平面／三维舞台 | 场地、台体、观众区、过道、桁架与灯位；尺寸和摆位 | 多舞台、底图、扫描、屏幕／投影面、观察视点；按 UX-007 的创建规则 |

## 复杂任务如何打开与返回

- **灯具建档**：在“灯具”中打开某档案，主工作面容纳功能列表、通道表、区间条与定义参数；无需同时常驻时间线。草稿修订与工程采用的版本分别显示；退出恢复原配适表行或编排对象，应用修订按 FIXTURE-001 审查影响。
- **效果深入编辑**：编排右侧或横向参数条只放常用值，曲线／顺序可以扩大成主编辑面，仍保留所编辑片段、作用灯组与预览入口。返回后时间线位置和缩放不变；没有独立重复的效果状态。
- **场地布局**：布置时收起时间线，空间画布和尺寸参数占主位；选舞台、观众区或过道得到对应参数。切回编排不把布置选择自动当成片段目标。
- **监看**：按需打开，来源状态明确；可占主画布的一部分或暂时放大。关闭仅改变布局，不停止外部媒体或改变节目时钟。
- **现场与编排**：各自保持工作区状态；切换页面不执行场景、不激活工程、不取得控制权。现场操作需要真实接通与明确运行对象，禁止复制旧图中的模拟执行底栏。

顶层文件菜单只管理新建、打开、真实保存、版本与工程信息。“记录场景”“保存档案修订”“保存工程”“激活节目”各有明确目标，不能压成一个万能保存按钮。当前片段与舞台选灯各有独立上下文，普通改选不会重定向片段。

## 扩展与跨端约束

### 以功能组件组织界面

用户进一步明确：以前通过前端组件封装功能来保持页面清晰，希望沿用这个思路。以下是本会话据此细化的方案，不代表已实现组件或用户已选定三张图中的某张。

组件分三层：基础控件（数值、滑块、选择器）、功能组件（颜色编辑、图案选择、指向、曲线、通道区间、监看）、工作区容器（决定当前任务需要哪些组件及其位置）。同一颜色编辑组件可用于场景、预设和灯具测试界面，但接收各自明确的编辑目标、能力描述和控制权限，不共享隐式写入对象。

界面的清晰度取决于组件的显示时机、占用空间和一致操作规则。常用参数内嵌；深入编辑可展开侧面板或主编辑面；短暂选择才使用弹层。入口可发现、展开可返回，不连续叠加弹窗。功能增加优先扩展相应组件，必要时增加任务内编辑面，不默认增加一级导航或常驻一整栏。

组件输入为明确的对象身份、快照、可用能力及编辑上下文；输出为应用编辑意图，工程规则仍由 Rust 维护。选择、草稿、撤销和版本由共同的应用编辑流程协调；组件关闭／卸载不能丢失未提交编辑、重复提交或停止已激活节目。布局收起、取消编辑、停止预览和停止现场执行必须是不同动作。监听／监看的资源订阅按自身生命周期释放。

首轮按真实任务验证：选灯后展开颜色组件，编辑当前片段并返回；打开灯具档案的通道区间组件，修改草稿后返回编排；切换组件后片段、选灯、播放头和未保存状态正确保留。同一对象的参数摘要与详细编辑读取同一状态，不维护两份数值。尚未实现的功能组件不放进正式产品当占位。

工作区提供固定的导航、主编辑面、可选资源区、属性区及辅助面板位置。未来模块贡献适用的对象编辑器和能力项，普通组件经既有应用命令调用 Rust；不设计任意插件执行系统，不让模块自行写工程或绕过输出控制。渲染后端更换不改变导航和业务归属。

面板布局、滚动、打开标签与选择属于本地工作状态；节目、档案引用和空间对象属于工程；控制权、运行时钟属于现场状态。未来 Mac／iPad 共用对象与命令，不强求共享同一套面板尺寸，也不让远端切页修改本机正在编辑的位置。

按 MacBook 的 1440×900、1366×768 实际逻辑视口验证后再确定比例。设计图高度不能当作真实可用空间。较窄窗口先收起资源或次要面板，保证主任务；侧栏／参数面板支持恢复默认布局。未来触控通过布局和输入适配进入，不前置 iPad 开发。

## 视觉检查与实施前待修

- 三图已逐张目视检查：中文主任务入口、片段目标、保存状态和离线预览身份可辨；没有正式现场执行底栏、教学展板或开发提示。
- 第一图与第二图的光束画面只能代表空间意图，尚未验证真实角度、遮挡、配光或物理灯具；第二图曲线图和数值不作为领域算法依据。
- 第三图画出了九个可辨光源，但所选灯组标为八台；属于生成瑕疵。采用时须按真实灯具对象修正，不能把图像当权威几何或灯数。
- 三图各有旧参考遗留的深浅渐变、时间刻度／片段比例和个别文字细节；需在选型后的代码设计稿中统一令牌、精确位置及可读性。像素尺寸和图片存在不代表布局、交互或性能通过验收。
- 灯具定义完整编辑页、布置页、现场页和监看展开态目前只有本文布局规则，未生成或实现，不声称三图已验证完整软件承载能力。

后续 UX-009 已验证编排 → 灯具档案 → 返回编排以及布置往返的上下文保持；监看等完整能力仍待实施。设计稿与正式产品入口分开，实际能力接入逐项走真实数据与命令，不把设计样例带入交付软件。
