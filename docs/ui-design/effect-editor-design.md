# UX-006：以效果创作为中心的编排界面

2026-09-23；基线 `9d81cc3`，main 干净工作区。本文是界面与交互设计，尚未实现。依据 [ADR-007](../development/decisions/PRODUCT-ADR-007-effect-editing-first.md)；已有工程读写与核心职责不变。

2026-09-24 最新澄清：当前按 MacBook 设计、开发和验收；用户暂无 iPad，未来主力定位仅用于提前保留适配空间。按修订后的 [ADR-008](../development/decisions/PRODUCT-ADR-008-ipad-primary-authoring.md)，不前置 iPad 布局或真机验证。最新[总体框架与共同指向](workspace-framework.md)将舞台／时间线结构收敛为当前推荐，新增整组光束持续跟随目标点的交互设计；三张既有图保留参考，不代表用户已选择其中某张。

## 设计判断

主界面应帮助灯光师完成“选择灯具 → 做出效果 → 安排时间 → 反复调整”。主导航按工作任务组织，不按 Rust 模块、工程 JSON 字段或数据库对象组织。专业概念仍在，但不要求用户先学习整套对象关系才能开始创作。

当前桌面入口的配适表、场景属性和保存功能是有效产品能力；它们的页面层级不作为未来主界面的模板。此前选定的舞台画布和剪映式时间线继续作为起点。本轮先定义交互规则和视觉候选，不抢先扩展业务层，也不把静态设计图里的能力当作已经交付。

“最优”是待任务验证的目标。优先顺序：修改对象和后果清楚、连续操作顺畅、结果容易辨认、精确输入可用，然后才是装饰和可定制程度。好看的舞台图片不能证明可用性，也不能证明灯光仿真正确。

## 一套工作流，两个任务入口

| 位置 | 用户任务 | 展示规则 |
| --- | --- | --- |
| 编排（默认） | 制作效果、安排片段、检查节目 | 舞台、时间线和固定属性区是主工作面；配适与资源管理按需打开 |
| 现场（能力接通后） | 看清运行状态、选择下一条、执行和临时调整 | 关键操作固定位置；进入现场视图本身不启动输出；编辑选择不改变待执行对象 |
| 配适／工程设置 | 灯具类型、地址、输出映射、工程信息 | 工作区内的辅助视图，可扩大成表格处理批量任务；返回编排保留选择、时间和缩放 |

初期不做任意窗口拼装、插件市场式首页或全部功能入口。各区域可折叠、调整大小和恢复布局即可。能力未接通时正式软件不展示假按钮；设计稿可以表达目标状态，但只放在开发资料中。

## 编排界面的稳定结构

推荐以“空间与时间一体编排”为默认布局；深入修改曲线时，在同一编辑上下文展开“效果塑形”；时间编排密集时允许扩大时间线。这是当前设计建议，三张候选的视觉选择尚待用户反馈，并不预先要求实施三个完整页面。

| 区域 | 回答的问题 | 设计约束 |
| --- | --- | --- |
| 顶部窄工具栏 | 正在编辑什么工程，保存了吗？ | 工程名、保存状态、撤销重做；新建／打开等收进文件菜单；不让品牌和文件操作占据主视觉 |
| 左侧资源 | 可以选择和复用什么？ | 灯具／灯组、场景／效果按当前任务切换；紧凑列表；不常驻多层目录树 |
| 中央舞台 | 哪些灯参与，结果怎样？ | 灯具可点选、框选，序号和选中边界明确；简洁布置图优先；未来专业三维渲染通过独立视图替换 |
| 右侧属性 | 现在修改谁，改哪些参数？ | 顶部固定显示编辑对象与目标范围；常用参数顺序稳定；批量混合值明确；精确数值可直接输入 |
| 下方时间线 | 什么时候开始、持续多久、怎样衔接？ | 片段位置／长度与变化曲线可见；只展开当前需要的属性通道；可放大编辑区 |
| 预览控制 | 当前查看哪一刻？ | 一套预览播放头与播放控制；持续显示离线预览身份；不再放一条争夺视觉的模拟现场执行栏 |

舞台观察、片段安排和参数修改共享上下文。折叠资源区不取消选择，放大曲线不重置播放头，切换视角不重排灯具的效果顺序。双击放大只作为加速入口，必须有可见的等效操作。

## 效果编辑的核心：时间变化与灯具顺序

灯光效果的编辑需要同时回答以下问题。这里描述用户任务，不把它们直接冻结成新的工程字段或引擎算法。

| 问题 | 首层表达 | 深入表达 |
| --- | --- | --- |
| 作用在哪些灯上？ | 灯组名、灯数、舞台高亮 | 可查看并调整明确的灯具顺序；选中与被效果引用的对象分别显示 |
| 改什么属性？ | 亮度、颜色、位置等适用属性 | 只显示对象支持的参数；部分支持显示数量与处理范围 |
| 怎样变化？ | 恒定、渐变、呼吸、追逐等可辨认起点 | 展开曲线／步骤；基础参数与曲线是同一内容的两种表达，不维护两套互相漂移的值 |
| 多快、多强？ | 上下限、周期／时长 | 数值输入、局部曲线、缓入缓出；计量单位明确 |
| 各灯怎样错开？ | 从左到右、反向、对称和间隔 | 编号排序与小型错开图；不要求普通操作先理解相位公式 |
| 在节目中何时发生？ | 片段起点、终点、进入／退出渐变 | 精确时间、标记与关键帧；局部效果时间与节目时间明确区分 |

渐变持续时间、循环周期、各灯之间的错开时间和整个片段长度不是同一件事。不能用一个“速度”旋钮含糊覆盖。空间顺序也不应默认等于 DMX 地址顺序。

动态效果先提供少量可塑形的基本形式。普通创作不以节点图、代码表达式或上百个预设选择页为前提；高级关系编辑在需求成立后单独加入。静态场景继续可独立使用，不强迫简单操作上时间线。

## 必须一致的交互规则

### 选择与修改范围

同时维护“正在编辑的片段／场景”和“舞台上选中的灯具”。两者相关但不能混为一个全局 selection。选中时间线片段，舞台标出该片段的目标；在舞台改选灯具，不得悄悄把已有片段重定向到新灯具。

- 属性区标题始终显示写入目标，例如“蓝色呼吸 · 当前片段”；下面显示“逆光 · 8 台”。
- 无片段时选灯可检查属性和建立新效果草稿；创建新效果必须有明确动作。不能一次普通点选就污染工程。
- 多选显示共同值或“多个值”，无记录／不支持／释放不能显示成 0。批量修改前能看清实际适用灯数。
- 灯具位置拖动与参数调节的把手不同；编排视图默认选灯，不让随手拖动意外修改舞台布置。布置编辑有明确入口。

### 即时反馈与保存

- 修改当前片段在有效范围内即时反馈到离线预览，完成手势产生一次可撤销编辑。编辑不增加第二个“应用”按钮；保存工程仍有真实磁盘含义。
- 新效果草稿使用“加入时间线”或“记录场景”完成归属；不能用“保存”同时表示记录对象、写文件和激活现场。
- 拖动进行中由界面维护临时手势状态，Rust 接收明确的编辑／预览请求；实际灯光结果由共享核心求值。绘制曲线手柄不等于前端实现灯光引擎。
- 校验失败时回到最后有效状态，错误靠近具体字段并保留可修正输入。不得保留一个看似已经保存的失败值。
- 拖动结束、取消、失焦、弹窗、关闭和宿主断连的行为须在实施工单中覆盖；已有未保存保护必须保留。

### 时间线

- 拖片段内部改变开始时间；拖边缘默认裁切持续范围，保留效果周期；改变播放速度使用单独明确的“伸缩”操作。
- 移动不默认挤动后续片段；吸附只在可见目标附近生效，可临时关闭；显示吸附线，不把每次移动硬量化。
- 播放头始终跟手，放大围绕当前编辑位置；支持边缘自动滚动、撤销和 Esc 取消。原 UX-004 的连续拖动保护保留。
- 改开始时间与改变周期内的起始位置是不同操作；裁切是否保持相位、重叠怎样合成，需由核心契约定案后实现，不从视频剪辑软件机械照搬。
- 轨道是组织与观察手段；同一灯具不同属性可有不同来源。不能用“画得更高的轨道自动胜出”偷渡控制权规则。同属性重叠应能展开查看来源／冲突。
- 关键帧默认通过明确按钮创建；移动播放头后普通改值不能悄悄录出动画。启用自动记录时状态持续可见，且不可因换页改变。
- 时间线和按触发顺序排列的场景列表可以共存，但不能承诺任意条件分支都能无损换成线性片段。它们共享对象身份，不强制互相转换。

### 复用与传播

从效果库拖入默认建立独立可编辑的片段实例；“保存为效果”把当前做法变为可复用资源。已存在的预设引用必须保留其身份与来源；修改实例不得无提示地修改共享预设。

修改共享资源必须明确显示引用范围，例如“引用于 6 个片段”；普通操作不反复弹确认窗。实例、共享资源、磁盘保存、现场运行版本分别表示，不能靠一个保存按钮隐式联动。以上为设计意图；具体复制／引用／覆盖规则在对应领域契约先审查后实施。

## 主任务走查：八台逆光做蓝色呼吸并错开

1. 在舞台或灯组列表选中八台逆光；两处同样高亮，属性区显示灯数和支持属性。
2. 选择亮度变化的呼吸起点，颜色设为冷蓝；直接调整下限 20%、上限 80%、周期 2 秒。
3. 在灯具顺序条选择从左到右，间隔 0.25 秒；舞台标出顺序，离线预览能看出错开。高级相位数值不挡在前面。
4. 将效果加入主节目，开始 4 秒、持续 10 秒；时间线上可见 4–14 秒的片段。修改片段不会改效果库的原始资源。
5. 调整进入／退出渐变，循环预览局部；拖动周期控件时舞台、曲线和时间线保持当前选择与缩放。
6. 撤销上次修改，保存并重开；片段和灯具目标不变。此时仍是编排，未授权现场输出。

这是未来验收脚本，不是本轮已经跑通的功能。设计图使用同一组示例，仅作视觉讨论；示例不加入正式软件。

## 展示与跨端约束

- 保留深蓝灰底与青色操作强调，降低大片高饱和控件。灯光颜色表达创作内容，边框／标记表达选择，文字和形状共同表达状态。
- 正文和控件文字目标 14–16 px，时间使用等宽数字。常用点击区域目标不小于 32 px，触控目标约 44 px；精细拖点可采用较小视觉点与较大命中区。
- 舞台先显示能准确对应对象的二维／简化视图；装饰性光束不得被当成照度或真实灯具反馈。光学预演是独立能力，不能成为选灯和做效果的前提。
- 当前按 MacBook 工作区检查 1440×900、1366×768 逻辑视口、窗口调整和字体放大。区域可以折叠和调整，为未来平板重排保留空间；不为未确定的 iPad 尺寸先重做布局。
- iPad 是未来主要编排端的目标，届时应承担已支持范围内的选灯、效果／曲线和时间线编辑、保存与交付；触控／Pencil 另行适配。当前保持共享对象、命令和宿主边界，不提前实现移动页面。手机继续按任务提供适合小屏的操作。
- 面板大小、折叠、滚动、选择和悬停是本地界面状态；节目、效果内容、灯具顺序是工程内容；现场时钟和控制权属于运行态。可共享命令，不强迫不同端同步当前页面和光标。
- 音频／视频以后作为参考与监看区域接入同一时间上下文，不把监听返回当主时钟，不在本轮加入剪辑／混音／视频合成能力。机构控制沿用独立运行与故障约束，不照搬灯光推子行为。

## 虚幻引擎如何进入这个界面

用户在本轮再次提出：让虚幻承担灯光预演，甚至包括类似专业控台的空间建模。结论是可以纳入，继续采用[既有 UE5 方案](../ue5-professional-previsualization.md)的独立后端边界，并把舞台画布明确设计为可交互的空间视图。

| 用户看到的能力 | UE 可承担的实现 | 舞台大师保留的权威内容 |
| --- | --- | --- |
| 搭舞台、摆桁架／灯具／屏幕 | 三维显示、拾取、移动旋转控件、网格吸附、镜头 | 稳定对象 ID、尺寸、位置、层级、资源引用和工程修订 |
| 选灯、框选、编组 | 命中检测与高亮，把稳定 ID 返回应用层 | 选择上下文、编组命令、权限及撤销 |
| 看亮度、色彩、光束、运动、遮挡 | 虚拟灯具、材质、雾与光束渲染、设备响应仿真 | Rust 已求值的属性、节目时刻和来源；不可在 UE Sequencer 再编一套正式节目 |
| 看屏幕和投影效果 | 显示外部监看返回或离线参考，呈现空间表面 | 来源、时钟映射、媒体身份；正式音视频播放和处理仍在外部系统 |
| 调效果后立即观察 | 渲染共享核心的新状态并回报新鲜度 | 参数合法性、效果曲线和实际可执行含义 |

“空间建模”首期按舞台搭建理解：尺寸化基本形体、导入模型、布置灯具／桁架、对齐吸附、分组和视点。多边形雕刻、复杂网格编辑不作为编排的必经功能。UE 的 Modeling Mode 是编辑器工具，不能推定安装引擎就自动得到可分发给客户的舞台建模软件；需要自己的简洁交互和运行时工具。[Epic 建模模式说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/modeling-mode-in-unreal-engine)

原生 UE 画面并非一个可直接放进 React 的普通组件。产品层定义一致的舞台交互；桌面可先验证独立 UE 进程／窗口，不能把该进程方案直接搬到 iPad。未来移动阶段再验证本地空间编辑和基本预览，后端尚未锁定；本地 UE 原生集成另做实测，专业画质也可来自远端 UE。串流依赖主机与连接，不能成为基本编排的必需条件。[Epic Pixel Streaming 说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-pixel-streaming-in-unreal-engine)

UE 模块可以使用必要的 C++／蓝图适配，其规模限制在渲染与交互桥接，不改变 Rust＋TypeScript 主框架。关闭／崩溃／降帧时，编辑与输出不能等待 UE；同机资源争用仍需实测。普通控制端与 ESP32 不携带三维场景和 UE 运行时。

当前做界面时只固定三项约束：舞台选中对象与属性区联动；空间修改进入同一可撤销工程命令；预演显示来源与时刻。舞台视图应能在简化与专业渲染之间替换，不因此改掉时间线和效果编辑习惯。本轮不安装 UE、不实现桥接、不承诺已有 MA／Depence 同级预演精度。

## 三维拖动：视角、摆位与光束目标

2026-09-23 追加，基线 `d8b94ba`。用户反馈 MA3 的三维拖动体验不佳，希望舞台可以直观拖动。以下是本产品的交互建议，不推断 MA3 不顺手的具体原因，也不把 UE 渲染能力等同于现成好用的操作。

### 观察舞台

默认围绕当前舞台或明确聚焦的对象观察；镜头保持水平，避免日常拖动导致翻滚。旋转中心持续稳定，不因指针偶然划过另一个物体而跳变。首次打开显示完整有效舞台，不被远处辅助对象拉成一个小点。

| 操作 | 鼠标建议默认值 | Mac 触控板建议默认值 |
| --- | --- | --- |
| 旋转观察 | 右键拖动，围绕当前焦点旋转 | 按住 Option 双指滑动；另有可见旋转工具 |
| 平移画面 | 中键拖动，或空格＋左键拖动 | 双指滑动；空格＋单指拖动作为替代 |
| 拉近／拉远 | 滚轮朝指针所指区域缩放 | 双指捏合；可见缩放控件作为替代 |
| 聚焦对象 | 选中后按 F，或点击“聚焦所选” | 相同可见操作与键盘入口 |
| 找回舞台 | “显示整个舞台” | 相同可见操作 |
| 切换观察方向 | “正视／俯视／侧视／透视” | 相同可见操作 |

这是首轮待测映射；触控板事件、系统手势、右键菜单与跨宿主差异需实机核验后固定。右键只有未形成拖动时才弹菜单；导航手势不改变对象选择，不写入工程撤销历史。镜头距离有合理边界，缩放速度随尺度适配；避免穿过目标后突然反向、无限接近后卡死。正交视图与透视视图切换保留观察目标。

### 放置物体

普通编排状态下点灯就是选灯。进入明确的“布置”操作后，选中物体出现可直接拖的轴／平面／旋转把手；不要求先到工程表里输入三个坐标。

- 拖动平面把手沿地面或选定工作平面移动；拖轴把手只改对应方向。三维屏幕上的二维位移必须有明确约束，不能猜测深度。
- 高度可通过垂直把手调整，并在旁边输入精确米数；位置和角度既能拖动也能输数值。拖动起点保留抓取偏移，不在按下时把物体中心吸到指针上。
- 吸附目标和距离显示在物体附近，可临时关闭；安装在桁架上的灯具可沿已明确的安装轴调整。吸附规则不能因镜头旋转而改变。
- 多选整体移动保留相对位置；锁定的桁架／场地不能被普通选灯误移。重叠或被遮挡对象可通过对象列表定位，不强制反复转镜头。
- 一次手势是一条撤销；Esc 返回手势前位置。拖动时先显示临时变换，提交后以应用层校验结果为准；失败恢复原位置。每次指针事件不等待文件写入或云端请求。

### 调光束指向

用户已明确要求一组摇头灯共同照向一个点，并在拖动该点时持续跟随。采用“指向”工具中的“共同指向”，与移动灯具安装位置的“布置”、镜头“聚焦所选”和“光学调焦”明确区分；不使用含糊的“对焦”名称。它是三维工作区首要验收任务，完整流程见[总体框架](workspace-framework.md)。

目标沿明确的平面／高度拖动，每台灯分别求解角度；普通拖动不默认录制轨迹。编辑范围、手势提交／取消、共享目标传播与路径编排的关系在总体框架中统一表达。后续目标数据与角度求解仍须先完成正式契约工单。

该能力依赖灯具安装姿态、轴向、零位／范围与校准，以及核心的角度求解；不可把拖一个光锥模型当作正确 pan／tilt。越界、无解或多种转动路径必须有明确结果。初期只考虑离线预览，进入真实输出另经已有控制边界；未实现前不展示可执行入口。

### 不同舞台与保存

先区分不同场地工程和同一场馆的多个舞台区域，避免用户仅提到“其他舞台”就提前冻结新工程结构。各工程／区域应能保留布置、命名视点和适当的观察范围；切换时显著显示当前舞台名称，不沿用另一舞台的选择或变换手势。

日常镜头、临时选择和面板布局保存在本地界面状态；用户显式保存的“观众席／舞台侧面”等命名视点可成为工程内容。镜头切换不启动另一个节目，不改变灯具配适；舞台模型也不进入 ESP32 受限播放包。

### 跟手验收

优先验证“绕舞台观察 → 聚焦一台灯 → 沿桁架移动 → 改高度 → 撤销 → 找回全舞台”。当前以 MacBook 鼠标／触控板验收；iPad 手指／Pencil 留到未来移动阶段，建议保存在 ADR-008。输入动作独立于业务命令，避免以后另造编辑逻辑。不用高画质截图替代手感测试。持续拖动时以反馈及时为先，可降低阴影／雾质量；帧率降低不能让指针位移丢失或积压成松手后继续移动。

先做视角和摆位这条小闭环，再做光束目标工具；空间交互状态独立于 UE 后端，后端重连后可以恢复。以上尚无可运行实现，也未承诺具体设备的三维性能。

## 验收方法：看任务表现，不只看截图

| 任务／性质 | 达标观察 | 证据要求 |
| --- | --- | --- |
| 可发现性 | 用户能找到选灯、做效果、加入时间线、修改和撤销；不需要解释内部模块 | 用户实际操作记录；记录停顿、误点和需要提示的位置，不预先声称容易 |
| 范围清楚 | 用户随时说得出正在改哪个片段、哪些灯、是否影响共享资源／现场 | 至少覆盖多选、混合值、引用对象和切换视图 |
| 连续操作 | 做完上述八灯任务，不因基本参数调整反复离开编辑上下文 | 录屏或操作轨迹；往返页面是诊断信号，不把点击次数当唯一指标 |
| 时间精度 | 片段位置与数值一致；吸附、裁切、取消与撤销可预测 | 真实界面输入和工程结果对照；不能用截图推断数值语义 |
| 跟手程度 | 指针、曲线和播放头在拖动时稳定同步 | 在当前电脑记录帧时间和输入延迟；初始目标常见拖动约 60 帧/秒、输入到视觉反馈 p95≤50 ms；作为待测目标，不是已达性能或 DMX 时序承诺 |
| 稠密场景 | 24／128／512 台灯、多个灯组与几十条轨道时仍能定位对象 | 真实或测试数据负载；不预建 512 个独立常驻参数面板；这些数值是界面测试档位，不是首版输出能力 |
| 键盘与触控 | 不靠悬停才能发现关键操作；焦点可见、无陷阱、文本输入不误触快捷键 | 实际键盘走查与触控适配；对比度另作工具检查，不从图片宣称无障碍合规 |

## 界面实施边界与顺序

先选定布局并检查操作规则，再实施编排界面外壳与已存在的真实编辑能力。顺序是：选择联动／稳定属性区 → 时间线手势与编辑事务 → 小范围效果塑形／Rust 预览闭环。每一项单独形成可验收工单；选择和布局不要求先完成所有动态效果、音视频或设备通信。

呈现层按 StageViewport、TimelineView、EffectInspector、ResourceBrowser 分工；应用层持有明确的编辑上下文并协调命令；平台层继续经 ApplicationHost；Rust 仍维护工程合法性、效果及时间语义。这里是职责说明，未新增模块实现、公共 API、依赖或 JSON 字段。

允许先写高质量的设计资料，不允许为了可点击而在正式入口造一套 TS 内存业务、假保存或假输出。未来可交互验收若使用局部测试夹具，必须与正式运行清楚分开，不能用它冒充业务完成。

## 依据与限制

继承 [UX-001](interaction-display-research.md) 和用户已选的[舞台画布](visual-directions.md)，本轮于 2026-09-23 核对以下官方机制；以下迁移判断属于本项目设计推论：

- [Shapr3D 自适应界面](https://support.shapr3d.com/hc/en-us/articles/7873882619548-Adaptive-user-interface)：依据选择提供工具，启发固定位置的上下文操作；不复制会随推荐变化的现场关键按钮布局。
- [DaVinci Resolve 编辑页](https://www.blackmagicdesign.com/products/davinciresolve/edit)：片段直接裁切、属性检查器和片段内曲线；用于缩短参数与时间之间的来回操作，不继承全部媒体语义。
- [Ableton Live 12 自动化与包络](https://www.ableton.com/en/live-manual/12/automation-and-editing-envelopes/)：参数随时间变化与包络编辑的专业参考；不能据此认定舞台控制已定义合成、记录或恢复规则。

本轮检查了当前原生桌面空白入口并直接查看旧视觉基准；没有执行完整可用性审计。新图为 Image Gen 静态布局提案，没有交互、精确求值或硬件输出。详细图像记录与修正项见[视觉候选](effect-editor-visuals.md)。
