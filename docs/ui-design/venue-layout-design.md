## 判断与成熟经验

采用“在平面上定范围和尺寸，三维同步生成，随时拖动或输入精确数值”的方式。常见场地几分钟能否搭好须实际验证，不作完成时间承诺。用户不必先学顶点、法线、网格或游戏引擎编辑器。

## 入口与主流程

在现有舞台工具栏进入“布置”。左侧切换成可添加的对象，中央保留舞台画面，右侧显示所选对象参数；时间线暂时收起以腾出空间，退出布置后恢复原来的片段、播放头和面板大小。

常用添加入口：空间、舞台、观众区、过道、桁架／灯位、屏幕／遮挡物；墙体与门洞在空间编辑中按需出现。用户先选“房间”或“舞台”再画轮廓，不必画完一个没有用途的矩形，再去寻找转换命令。对象选中后就能改尺寸，创建与后续修改是同一套工具。

新建时提供两条逐步开放的路径：

- **按尺寸搭建**：没有图纸时直接画或填尺寸；常用形状可选，所有生成对象都可继续编辑。
- **根据图纸搭建**：有平面图时先导入、校准尺度和方向、锁定底图，再沿轮廓描绘。具体文件格式随真实导入能力开放，不摆空入口。

近期场地和用户保存模板接通后提供“复用场地”。模板由用户主动选择，生成真实可编辑对象；不把预置舞台、灯组或节目塞进每个空白工程。流程不强制顺序：已有场馆可直接添加舞台，露天舞台不必先建四面墙。

## 1. 场地：组合空间，各自定轮廓与高度

场地内允许多个房间、走廊和开放区域，楼层／空间组按需添加。舞台、观众区和装置属于空间中的内容，无舞台项目也能创建。第一版使用简化几何，重点是准确尺寸、位置与连接，不要求建筑施工建模。

1. 点“添加空间”，选室内房间或开放区域；矩形可拖出后填宽深，异形可逐点画闭合轮廓，支持 L 形等凹多边形。异形以各段边长编辑，外接矩形长宽只作范围参考。
2. 为这个空间填写“地面标高”和“净高”，明确相对于场地或楼层的基准。房间 A 地面 0 米、净高 3 米，房间 B 地面 0.6 米、净高 4.2 米，各自独立；露天没有顶面。舞台台面高度另算，不混入房间净高。
3. 继续添加相邻房间，利用边／点吸附对齐；墙厚作为真实尺寸处理。连接时明确共用墙或保留独立墙，不能在两房间之间重复生成重叠墙体。点墙添加门洞，填写宽、高和底边标高；用同一空间工具画转折走廊。几何门洞不自动关联电机设备。
4. 左侧按房间／可选楼层组织对象，选房间聚焦，选灯具显示灯具属性；顶部保留“查看全场”。面板显示当前编辑空间，房间切换保留各自观察位置与尚未提交的字段草稿。
5. 多房间共用工程坐标，可整体查看或跨房间选灯；灯组与设备输出分配独立。调整房间边界不缩放灯位；移动房间的附属对象与共享连接影响先预览，再一次提交和撤销。

空间的净轮廓、墙体等物理构件及空间连接分别维护。敞开大厅可划两个功能区域而不砌墙；相邻房间可以共用一面墙；柱子、门洞和连接不只画成装饰线。修改共用墙须同步检查两侧房间与洞口，不能留下两份矛盾几何。坐标与引用约束见 ADR-010。

高低地面、斜顶、夹层和跨层挑空不能永远压成一个高度数值。契约预留分段／表面几何，界面后续按需提供局部地面、顶部与剖面编辑；首期先接通各自平地／平顶、不同标高和净高的多房间。楼层仅作组织与基准，上下重叠的投影不等于实际空间冲突。

图纸路径先选两个已知距离的点，输入实际长度，再指定参考方向与位置；整张图以受控变换对齐到工程坐标。额外已知尺寸用于复核。透视现场照片不能按一条标尺当作准确平面图，扫描流程按[真实场地采集](../venue-capture-design.md)处理。

底图默认锁定且可调整透明度，显示单位与比例；可切换不同图层。导入几何必须明确单位、地面、方向和来源，预览确认后才进入场地。DWG／DXF、MVR、通用网格和扫描各有不同语义，不承诺导入后都是可改尺寸的参数对象。

## 2. 舞台：画形状，给台面高度

首版从矩形开始；后续增加圆形、T 形／伸出台和闭合多边形。常用形状是可编辑的构造方式，不是固定装饰模型。

1. 点“舞台”，在俯视图拖出范围；拖动时显示宽、深，右侧可直接输入米数。
2. 指定台面高度；三维立即出现台体。顶面有高度把手，拖动与数值字段同步。
3. 明确舞台前沿和朝向，自动显示中心线；尺寸变化以显示的固定边／锚点为基准，不无提示向两侧扩张。
4. 需要副台或延伸台时，增加一个舞台块并吸附边缘，保留各自高度；不为了一个 T 形台先学习布尔建模。
5. 楼梯、坡道、护栏等后续作为附着对象加入，保留关联对象和连接面；重新调整台面后由依赖规则更新，不把它们焊死成不可编辑网格。

台面标高与台板厚度／裙边不同：用户主要输入“台面距场地地面多高”，不能把厚度误当离地高度。灯架高度、观众楼层、悬空装饰同样必须标明测量基准。量测标签始终显示真实单位。

## 3. 观众区：圈区域，自动排布

观众区先是一块有用途、地面高度和朝向的空间；椅子或人物是其生成内容。没有排座需求时，只画区域也能做灯光覆盖和视点检查。

| 类型 | 首层参数 | 深入编辑 |
| --- | --- | --- |
| 站席 | 区域轮廓、朝向、人物显示开关 | 可选人群分布疏密；装饰人物不代表售票人数或核定容量 |
| 平地坐席 | 区域轮廓、座椅尺寸、座位中心间距、排中心间距、朝向 | 错排、弧形排列、分区与排座编号；间距类型写清楚，另可换算净距 |
| 阶梯／看台（后续） | 区域轮廓、首排地面高度、每排升高、排距 | 分层、转角、独立入口；不能靠倾斜一张贴椅子的平面冒充台阶 |
| 桌席（后续） | 区域轮廓、桌椅组合、桌间距 | 主通道、组合方向和局部例外 |

操作步骤：点“观众区” → 圈范围 → 选站席／坐席 → 拖朝向箭头或选择观看对象 → 调间距。坐席默认朝向用户指定的舞台，不因移动任意灯光目标点而转向。环绕舞台用多个分区表达，各区可有不同朝向和高度，不能全局只存一个“观众在舞台前面”的布尔值。

首期座位布局只负责空间表达，不扩展成票务系统。显示“已生成座位数”，只统计实际落入边界并避开排除区的完整座位，不能用面积除以一个常数冒充逐座计数。

## 4. 过道与空地：独立画，自动避让

点“过道”，在观众区画一条线并设置宽度，或直接画一个空白区域。中央通道、横向通道、控台区、摄影区、柱子周围空地都能用这种方法明确表达；它们可以先于或晚于座位区创建。

- 区域、过道或间距变化时，自动重新排布；所有座椅占地轮廓需完全避开排除区，不能仅检查座椅中心点。
- 默认保持原行列基准和中心间距，仅移除冲突座位；不为了填满空间悄悄压缩间距或把所有座位重新挪位。
- 排除区域按明确楼层／地面范围生效，上层包厢不应因下层同位置控台区而被删掉。
- 整区移动时，显式附属的局部过道可随之移动；场馆柱子等固定障碍不跟随。关联对象在属性区可见，不靠图层名称猜测。
- 拖动时先用轻量轮廓反馈，复杂重排在后台合并计算，过时结果不得覆盖新输入；松手提交一次事务，取消／撤销恢复原布局。
- 局部挪椅、删座、命名视点等例外必须有稳定引用或覆盖规则；若重排无法保留，在提交前列出具体影响，不静默清空人工调整。首版可先不开放逐座定制。

这里的空白区只约束场地生成。观众区、禁照区域和激光安全限制是不同的对象／规则，不能因为画了观众区就自动给所有灯具加禁照，或把过道避让当作输出保护。

## 5. 三维检查与灯光编排衔接

二维与三维读取同一批对象和尺寸，切视图不生成副本。在三维中可看台高、桁架高度、遮挡关系和观众视角；在平面中更容易精确画轮廓和排布。默认一个主视口，按需临时分屏，不常驻两套拥挤窗口。

室内默认提供屋顶隐藏和当前房间隔离，完整视图可随时恢复；后续增加邻房淡显、按楼层查看与可拖剖切面，解决墙顶挡住灯具的问题。上述操作只影响编辑画面的显示与拾取，不修改真实几何、已实现的光学遮挡或任何播放状态。二维拾取限定当前楼层／编辑平面；三维目标贴面需显示命中的房间和表面，避免选到楼上地板或邻房墙后。

“从这里看”可以在某观众位置建立观察视点；眼点高度独立可调，明确相对于该区域地面或座位基准。命名视点保存到工程，普通浏览镜头留在本地状态。观察视点本身不执行任何灯光动作。

进入“指向”工具后，点击舞台面得到世界空间中的目标点，接已有[共同指向流程](workspace-framework.md)。若目标明确附着于舞台，其位置应由舞台局部坐标和变换导出；独立世界目标不随舞台移动。属性区显示关联对象，移动舞台或改变台面高度时可查看受影响目标／灯位与需要复核的校准。

观众区可供未来受光覆盖、摄影机／投影视点和遮挡分析使用，但只画出区域不能声称已完成照度、可视率或光学安全计算。

## 模块和持久化准备

以下是下一阶段契约要覆盖的内容，尚不定义新的 JSON 类型或伪装成已有 API。

| 模块边界 | 需要保留的信息 | 关键约束 |
| --- | --- | --- |
| 场地对象／应用编辑 | 多空间轮廓、地面／顶部、物理构件、洞口／连接、稳定身份、变换、关联和修订 | 空间归属与变换附着分开；共享墙只有一份权威几何；舞台与观众区通常并列，不能把整个观众席设成舞台的子节点 |
| 参数生成器 | 舞台轮廓／高度、座位布局、排除规则、生成器版本及局部覆盖 | 保存可再编辑的参数；渲染网格是可重建缓存。逻辑生成与引用规则由共享 Rust 领域模块维护，计算不进入 DMX 实时线程 |
| 资源与导入适配 | 底图、外部网格、材质、源文件身份、单位和转换 | 外部网格可作为整体对象操作；未识别参数语义时不假称能重新排座或改台高 |
| 三维后端 | 对象实例、简化／精细几何、拾取与显示 | 同一把椅子复用网格并实例化；远处简化／隐藏人物，性能变化不影响座位逻辑和计数 |
| 场地模板／修订 | 用户保存的可复用场地、版本及资源依赖 | 工程固定引用具体修订或显式副本；改一个场馆模板不能自动移动其他节目的灯具 |

继承[工程坐标约定](../project-format/README.md)：右手系、米和度，导入／渲染适配器负责转换。舞台前沿和观看方向是对象的局部参考，不能因为图上朝上就修改全项目轴定义。移动／旋转显示与重设坐标基准必须分开；重设基准应保持已存在对象的世界关系，并审核校准及外部引用。

场地视觉资源不进入 ESP32 播放包；只有被编排引用、影响角度求解的必要布局／校准参与编译。目标点关系、参数生成器和场地修订需正式架构说明后才能扩展持久化格式。现有 `StageNode` 变换不足以表示全部创建语义。

## 分步交付与验收

1. **空间基础闭环**：从矩形快捷创建开始，但领域契约与验收覆盖两个不同净高／地面标高的房间、凹多边形、共用墙／门洞与走廊连接；俯视编辑与简化三维同步、当前房间／全场查看、隐藏屋顶、取消／撤销和真实保存重开。可以拆小工单，不能把一个全局宽深高作为最终格式。
2. **舞台与观众闭环**：在上述空间内添加矩形舞台、台高、站席或直排坐席区、过道；继续多舞台块、底图校准、桁架批量布灯和场地复用。新增能力不要求无舞台项目补建舞台。
3. **后续增强**：按层查看／剖切、局部高低地面和斜顶／夹层、弧形座位／看台、局部座位编辑、复杂导入／扫描、专业 UE 预演；分任务接入，不拖慢基本搭建。

多空间验收夹具：L 形房间 A 地面 0 米、净高 3 米，房间 B 地面 0.6 米、净高 4.2 米，通过有明确洞口的连接组织；检查各房间尺寸、门洞底边和高差，不能把跨房间可通行性自动假定为已验证。调整一侧共用墙后两侧关系与洞口一致，取消／撤销及保存重开后身份和坐标不变。切房间和隐藏屋顶不改灯具属性；复制房间生成新对象身份，不复制通道地址形成冲突。多层扩展另验同 XY 不同 Z、挑空和局部顶部，不能仅按平面相交拒绝。

验收任务使用独立夹具：创建一个有明确尺寸和高度的舞台，生成左右两个坐席区，中间留过道；改变舞台宽度不移动未附着的观众区，改变过道宽度只排除相交座位；切三维检查台高、回到平面继续编辑；撤销和保存重开保持一致。随后验证共同指向拾取的是台面而非场地下方地板。

异常范围至少包括零／负尺寸、未闭合／自交轮廓、过窄区域、完全被排除区覆盖、重叠楼层、超大实例数量、导入单位错误、资源缺失和旧版生成结果迁移。标定与输出验证另立任务，不用三维截图代替实测。
