# StageMaster 工程格式 0.1.0-draft.1

这是声光电与互动机构的**完整分层设计草案**，包含字段 Schema、两个工程及其现场绑定、一个部署清单示例。它为新增能力提供共同的数据基础；音乐播放、视频回传、电机执行仍需对应模块和设备适配器。DESKTOP-001 已由独立 Rust 工程模块及桌面工作台实现灯光编辑子集读写；完整多领域能力仍待逐模块接入。

本次决定见 [PRODUCT-ADR-005](../development/decisions/PRODUCT-ADR-005-multidomain-project-format.md)，实施记录见 [PROJECT-001A](../development/tasks/PROJECT-001A-format-design.md)。字段仍处草案阶段，不能作为已发布的永久兼容承诺。

## 1. 三层文件与云端

| 层 | 保存什么 | 谁使用 |
| --- | --- | --- |
| stagemaster.project | 可编辑的节目含义、对象关系、时间线、资源引用、能力需求 | 电脑／手机／平板／Web 的共享编辑与 Rust 领域模块 |
| stagemaster.site-binding | 指定工程修订与现场端点目录、输出口、监看流、面板、已调试的机构配置之间的映射 | 现场准备、部署编译与适配器 |

工程不会塞进音视频字节，也不保存密码、IP 会话、串口句柄、正在执行的位置、真实限位状态、实时编程器或到期许可证。现场绑定也不内嵌秘密：endpointCatalogKey 在受控设备目录中解析，连接参数和凭据在独立配置／秘密存储中维护。换现场修改绑定，节目对象身份可以保持。

云端仍用 Fastify 管理业务接口，PostgreSQL 管理身份、权限、修订和文件索引，对象存储保存工程快照、素材及发布包。工程语义校验／编译复用 Rust。云端有文件不代表现场已经激活；工程编辑、上传、发布、安装、激活各有状态和确认点。

未来加密的 .show 类容器可以装载同一 JSON 正文及资源。**正文格式版本、执行语义版本、容器版本、授权版本独立**；这里没有定义加密算法或把可编辑 JSON 当成有效许可。

requires 的本草案能力键为 lighting.basic、lighting.positioning、lighting.effects.basic、media.external、motion.external、io.logic、automation.rules、timeline.basic、stage.layout、stage.spaces、stage.rigging、monitoring、surface.mapping，版本均为 1。这些是**格式能力声明**，不表示现有程序已实现全部模块。EFFECT-001 的 `lighting.effects.basic`／`lighting.effects.keyframes` 已接入 Rust 编辑／编译／预览，具体两端曲线、顺序与时钟语义见[场景动态效果](../module-api/lighting-effects.md)；已支持最多 32 个循环关键帧，不含摇头运动。

## 3. 身份、资源、精确时间与单位

- 持久对象用小写 UUIDv4 字符串；全工程对象身份不能重复。重命名／重编号／重新配适不换身份；真正复制新对象生成新身份并重写引用。修订身份和对象身份承担不同职责，示例的规则化 UUID 仅为便于审查。
- 引用必须存在且种类正确。sceneId 不能指向同为 UUID 的预设；预设引用仍是引用，不能保存时偷偷烘焙成值。跨工程复制需要显式映射；不允许依赖名字碰撞来合并。
- revisionId 指向完整不可变快照，parentRevisionIds 用于修订谱系。它们不是服务器时间、内容摘要或冲突自动解决算法。相同修订不得承载不同内容，保存时需版本检查。
- 资源身份与 sha256 分开；摘要绑定确切文件字节，不对任意 JSON 排版约定“自然相同的哈希”。正文签名／规范编码另属容器协议。byteLength 为字符串表示的 u64；下载必须核对长度和摘要。
- locator.kind=package 为包根下受限相对路径；catalog 为目录键、对象键和固定修订。不能自动访问工程里任意 URL；目录解析、权限、下载缓存和可用性在资源模块处理。
- requiredFor 分编辑、编译、参考预览和外部播放。缺少参考视频可以显示不可预览，缺少执行必需资源必须拒绝发布。media 元信息不替代实际媒体探测。

时间用以下形式表示 1.5 秒：

~~~json
{ "ticks": "1500", "ticksPerSecond": "1000" }
~~~

整数刻度使用字符串，跨 JSON／JavaScript／Rust 不依赖浮点精度；刻度限定 i64，时长非负，时基为 1..1000000000。Schema 先约束词法，数值范围由校验器再检查。字节数量限定 u64。运算须检查溢出，不能在 Rust 中用未经检查的 i64 相乘。

音乐采样时基可写 48000，视频 30000/1001 帧率可用时基 30000、每帧 1001 刻度表达。frameRate 分子／分母是媒体属性，不是把秒改成浮点。外部时码帧号、丢帧计数格式、偏移和输入协议由时钟适配配置解释；不得把显示时码文字直接当运行时间。

节目位置、媒体入点、运行单调时间、授权可信时间是四件事。Time 允许负数供需要预卷的语义使用，但媒体入点在本草案中必须非负；时间线开始和时长使用 Duration。sourceIn + duration 不得越过素材长度。不同分母精确比较；设备编译时若需量化，明确报告误差、超过目标容差则拒绝。

值使用带 kind 的分支：归一化整数 0..65535、布尔、i64 整数字符串、文本、枚举选择、带单位的十进制字符串。物理量不得用归一化调光值表达；毫米／角度／速度单位必须匹配。十进制不用指数、负零、前导零或多余小数尾零。机电目标“200 mm”是请求，不代表实测位置。

## 4. 灯光语义

profiles 固定灯具模式及其修订，记录属性类型、默认值、HTP／LTP 混合规则和 DMX 通道映射。本草案编码支持归一化属性的 u8 与粗细双通道 u16-be，offsets 从 0 起；粗细顺序不能凭相邻地址猜测。POSITION-001 增加可选 positioning 两轴模型及实例 zeroCorrection，使用 `lighting.positioning@1` 能力门控；字段、静态目标烘焙和量化语义见[位置接口](../module-api/positioning.md)。现有复杂灯具功能范围、子灯、条件模式和效果器未在此简化档案中完整建模，后续由独立能力／版本扩展；不能声称已实现 GDTF 导入。

2026-09-24 的 [ADR-009](../development/decisions/PRODUCT-ADR-009-fixture-definition.md) 与[灯具定义设计](../ui-design/fixture-definition-design.md)补充了可复用能力、硬件变体、功能区间、轮盘档位、虚拟属性及个人灯库的方向。它们是后续契约扩展依据，尚未改变本草案、Schema 或 Rust 支持范围；实施需明确版本、迁移和编码行为，不能仅取消现有重复映射校验。

patches 的逻辑线路号和地址从 1 起，线路号不是物理串口。每只灯具一次配适，足迹不得越过 512 通道，同一输出域／线路不得重叠；不支持共享地址合并。现场绑定再把逻辑线路映射到物理口或网络端点。

场景中的属性 set 可以引用字面值或预设；release 明确撤销当前列表持有的该属性，不等于“写零”。省略属性的含义由列表决定：inherited 继承此前列表状态，isolated 每步重新建立本列表贡献。释放后由其余合法来源混合，最后才落到档案默认值；HTP 默认值不得成为持续下限，保留 CORE-002 的修复含义。

steps 数组顺序决定执行顺序，number 只是显示编号。同列表的 1／1.0 也不能共存。每步在 delay 后开始灯光渐变并发出该步动作；after.wait 从本步渐变结束计时，最后一步等待完成后结束或循环；manual 等待操作员推进。外部动作另有完成／失败状态，不能拿渐变结束冒充外部动作已经完成。

一个编译计划对同一属性的无明确混合来源冲突必须拒绝。多执行器优先级、复杂效果、跨列表同步、动态编程器和录制编辑命令仍由后续独立契约完善；当前文件不通过随意排序来制造隐含优先级。

## 5. 音视频、投影、激光与监看

media.systems 声明外部系统类别、逻辑输出域、适配契约和外部工程固定修订；media.objects 用稳定对象身份对应外部系统的资源／播放列表／预设。地址和厂商命令封装在适配器，正文不保存自由脚本、任意 OSC 路径或驱动指令。

支持的设计动作是播放、暂停、停止、定位和调用登记的外部预设。正式混音、视频解码合成、投影几何校正、激光扫描及设备内部保护继续由对应专业系统承担。未来新增本机播放服务也应作为同类模块接入，另行评估性能与许可，不重写工程其余部分。

media.reference-clip 只服务编排参考和本地预览，不隐式启动现场设备。真正现场播放必须有显式 media.play 动作；同一时刻发送两条动作不保证两台设备采样级同步。适配器应协商可提前排程、时钟精度、启动准备和实际误差；达不到节目要求时编译或现场准备应报告不满足。

monitoring.sources.tap 区分参考、输出前、系统输出后、采集和物理观察。媒体服务器输出回传只能证明该取样点有画面，不能证明投影机已经照到幕布；物理结果需摄像机／传感器反馈。反馈过期显示未知／陈旧，不能继续显示为当前现场。监看音频默认静音，操作员再选择本地监听，避免自动扩声／回授。

## 6. 电机与密室联动

motion.controllers 指向独立机构控制器及固定外部配置。axes 保存轴身份、单位、允许申请的行程、位置反馈、就绪条件与已调试运动参数组的键。动作只表达绝对目标和速度；加减速、归零过程、制动和闭环策略由选定控制器参数组维护。首版不提供任意相对移动、在线自由调参或无反馈盲运行。

控制器实际范围是最终上限；JSON 的 requestedTravel 不能扩大真实限制。机构运行前须验证外部配置摘要、反馈新鲜度、位置、就绪状态和本地使能，不能因工程里写了 requiresLocalArming=true 就认定已使能。控制器丢连接或控制权租约失效时，执行已经现场调试的停止策略，停止方式不能由通用软件武断统一。

**急停、人员保护、限位、门禁逃生与制动保持必须由独立现场保护链负责。** 普通 motion.stop 是正常停止请求，不能冒充急停；io.outputs 仅限非安全业务输出。示例中的按钮申请滑台移动，工程条件不是安全认证，也不能作为密室出口释放的唯一依据。激光的光学保护同样不能由普通节目动作或网络授权代替。

conditions 使用三值逻辑：真、假、未知。断线、反馈过期或不可确认得到未知；NOT 未知 = 未知，AND 有假则假、否则含未知为未知，OR 有真则真、否则含未知为未知。只有最终结果为真才允许动作；不能先把未知转成假再取反。stableFor 要求持续稳定，新鲜度以接收端单调时间和适配器序列／质量为依据，不信任任意远端墙钟。

rules 默认未使能，只在入口的 ruleIds 清单内、当前运行与操作员使能后生效；上升沿从已观察到的假到真触发。未知后恢复为真、加载时已经为真、重连首次采样均只重建基准，不算新上升沿。once-per-run 限制一轮运行只触发一次；重置、重新使能与停止后再运行必须是显式操作。去抖与冷却不能替代安全保护。

停止、卸载或切换入口会撤销其规则的使能与待发动作。场景／时间线复用同一规则定义时，触发状态属于运行实例，不写回文件。示例保留完成指示灯动作供后续增加“位置到达”条件，**并未把“移动请求已发送”当作“已经到位”来点亮它**。

## 7. 时序、失败、定位和节目结束

- 时间线区间为 [start, start+duration)；动作在运行从前向后跨过其时刻时最多调度一次，每轮循环使用新的运行代次。新启动包含零时刻事件；循环末端事件应排在时长之前。endActionIds 在整个节目结束时运行，不在每轮循环重复。
- syncGroups 使用内部单调时钟或配置的外部时码。失锁按 hold／stop-group 处理，恢复先对齐与确认，不能补发期间所有动作。跨设备不是一张 JSON 就能获得统一硬实时调度。
- 定位重建灯光状态、参考画面与播放头；不补发途中机构／继电器／外部播放动作。需要外部媒体定位时由操作员发出明确 media.seek。机械实际位置不能因播放头跳转而被“重建”。
- maxLateness／onLate=block 限制计划动作可接受的迟到；不在网络恢复后突发执行过时动作。ackTimeout 从发送计时，completionTimeout 从发送计到业务结果确认，须不短于确认期限。媒体播放动作的完成是播放已确认，不是素材播完；机构完成依赖实际反馈到位。适配器必须定义明确确认级别，不支持时不能返回虚假成功。
- 超时 block 停止推进相关节目／后续业务动作，进入待处理；notify 仅适用于编译器批准的非关键动作。机构移动不能选 notify。两者都不关闭保护链，停止和收尾通道始终可用。onUnknownOutcome=reconcile-no-retry 表示结果不明先查询／人工核对，禁止自动再移动一次。
- 同一时刻多个动作按数组顺序请求，仍可能部分成功；跨域动作没有原子成功保证。不能同时给同一执行对象下达冲突请求。需要顺序完成依赖时使用明确反馈条件，而不是误认为数组后项会等待前项完成。
- 控制权租约、请求身份、去重窗口、时钟代次和动作结果属于运行协议，不能从工程静态 id 推导出全局“恰好一次”。播放包冻结依赖，编辑操作不会改变正在执行的版本。

entryPoints.completion 声明有限节目、完成当前循环或由操作员结束。自然结束后执行收尾动作；shutdown.maxTail 是收尾阶段的最长等待，不能拿它替代整个节目的时长证明。有限节目仍要验证手动等待、联动分支和外部动作不会无限延伸；没有结束边界的入口不能直接进入 24 小时临时包。

临时包按 [PRODUCT-ADR-004](../development/decisions/PRODUCT-ADR-004-relayed-device-authorization.md) 的规则：当前文件、受限离线签发、设备首次完整接受开始计时、重复上传／断电不重置，提前提示，到期允许已开始的节目走完已证明有限的结束路径，随后禁止新播放。循环完成当前轮；不能通过倒带或循环续期。到期后不得启动新的互动移动任务，已有动作的完成／正常停止及必要收尾按冻结计划处理。工程只描述结束路径，**有效期、签名和设备绑定由外层授权协议验证**。

onControlLeaseLoss 指现场控制权丢失，区别于仍处有效收尾许可内的商业授权到期。任何许可证状态都不能撤销急停、停止、逃生或保护功能。ESP32 断电后可信计时和生产密钥保护仍是 AUTH-001 的真实硬件验证项。

## 8. 空间、面板与扩展

STAGE-001 按 [ADR-023](../development/decisions/PRODUCT-ADR-023-rigging-assembly.md) 实施水平直桁架／灯杆：`constructions[].shape.kind:rig`、外尺寸、世界中心／水平角和空间归属；`stage.attachments` 保存灯具与支撑体的唯一关联，旧工程省略时为空。有支撑体或非空挂接时必须声明 `stage.rigging@1`。世界灯位是唯一坐标源，关联变换／解除／删除保护由 Rust 原子命令负责，见[场地 API](../module-api/stage-spaces.md)。网格可由工程重建并送入内嵌 UE，不保存第二套三维场地数据。

空间布局使用右手坐标：X 向右、Y 向前、Z 向上，位置为米、角度为度。节点变换按局部缩放、绕固定 X/Y/Z 轴顺序旋转、再平移后组合到父节点；列向量表示为 T × Rz × Ry × Rx × S。父级不能成环，缩放为正。UE、MVR 或未来扫描重建场景通过适配器转换坐标系；高斯场景和模型放资源，不内嵌到每个灯具对象。

surfaces 保存逻辑页面和控制绑定，实体 MIDI／USB／串口／GPIO 对应关系在现场绑定与适配器。按钮可以启动入口或动作，推子／编码器只连续调整可连续控制的属性；推子拾取、相对增量、电动回授均读取权威状态，避免接管跳值和回授回环。机构点动／保持运行型面板不沿用普通按钮绑定，须另设具备保护要求的能力契约。

扩展必须有反向域名命名空间、版本、required-semantic 或 optional-metadata 角色、引用清单和 payload。会改变输出的内容必须是必需语义；未知必需语义可作为未支持内容查看，但拒绝编译。未知可选元数据应保留；客户端不能在删除对象后留下扩展暗藏的断裂引用，不理解引用改写时只读或拒绝该编辑。

核心字段禁止随意增加。新效果器、更多灯具映射、外部系统参数和后续媒体处理能力，通过明确的新版本／能力和迁移样例扩展；不能把核心业务都塞入一个无约束 payload。

## 9. 实施边界、接口与部署验证

生产路径为“严格解析 → 结构检查 → Rust 领域检查 → 已校验编辑快照 → 保存或按目标编译”。不要每个输出周期解析原始 JSON；实时执行器只读经过验证、容量受限的执行计划。接口职责示意如下，尚不是已有 API：

~~~rust
parse_project(bytes: &[u8]) -> Result<ProjectDocument, ParseDiagnostics>
validate_project(document: ProjectDocument, capabilities: &CapabilityRegistry)
    -> Result<ValidatedProject, DomainDiagnostics>
compile_entry(project: &ValidatedProject, binding: &ValidatedSiteBinding,
              entry: EntryPointId, target: &TargetCapabilities)
    -> Result<PlaybackPlan, CompileDiagnostics>
~~~

运行激活还要验证包完整性、目标身份、能力版本、资源预算、现场准备、控制权和授权。Schema 与上述设计期检查都不能授予执行权。

| 目标 | 计划承担 | 不能默认获得 |
| --- | --- | --- |
| 首版 ESP32-S3 单路盒 | 选定入口的灯光依赖、静态值／渐变／受限列表、1 路 DMX | 完整媒体、任意规则、电机保护、完整专业工程解释 |
| 后续 ARM 设备 | 在实测能力和适配器支持下，承担更多独立编排与外部控制 | 因为 CPU 更强就自动安全或具备所有协议 |
| 桌面／移动／Web | 相同格式与编辑规则，按平台提供参考预览和控制入口 | 浏览器直接保证 DMX 物理时序或取得硬件控制权 |

部署依赖必须闭合到所选入口的灯具档案、预设、场景、规则、条件、动作、资源和设备。只抽灯光时若入口还必须联动电机，不得静默丢弃电机；应选择独立灯光入口或明确重编排。单设备清单只描述该设备计划；分布式部署的协调事务、同步保证和故障接管需要后续协议，当前不假装已支持多设备统一激活。

编辑工程可保存未配适灯具或暂缺参考资源，发布所选依赖时再要求满足执行条件。保存用完整快照及原子提交／恢复机制，加载失败不激活半个工程；这些读写行为尚待 PROJECT-001 实现。旧 A0 的数值 ID／界面原型 JSON 不直接视为本格式，只能经明确导入映射和测试转换。
